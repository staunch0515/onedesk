# 4. 数据源（PostgreSQL）

“数据源”插件（`org.onedesk.datasource`）管理到 PostgreSQL 的连接。**所有查询一律只读**：每条语句在只读事务里运行并回滚，一次只能一条，只允许以 `SELECT`、`WITH`、`VALUES`、`TABLE`、`EXPLAIN`、`SHOW` 开头；含 psql 反斜杠命令（如 `\copy`）的会被拒绝。

> 只读是软件层的保护，防不住数据库超级用户本来就能做的事（例如 `COPY … TO PROGRAM`、`dblink`）。**请用只读数据库账号连接。**

新建：顶栏“新建”→“数据源”。页面上的操作：测试连接、保存、保存并测试、导入连接串、备份到本机。

## 两种连接方式

目前只有这两种（源码里没有别的，例如没有内置的 ssh 隧道端口转发）：

### 直连

本机的 `psql` 直接连数据库。字段：

| 字段 | 说明 |
|---|---|
| 主机、端口 | 默认 `localhost`、`5432` |
| 数据库、用户 | |
| 密码 | 只写进钥匙串，不存在数据源里；页面上之后不再显示 |

要求：本机有 `psql`。OneDesk 会在这些地方找它：`/Library/PostgreSQL/*/bin`、`/opt/homebrew/opt/libpq/bin`、`/opt/homebrew/bin`、`/usr/local/bin`（以及系统路径）。没有的话先装（例如 `brew install libpq`）。找不到时测试连接会提示“无法运行程序”。

### 经 ssh（`docker exec psql`）

用于数据库跑在**服务器上的 Docker 容器**里的情况：OneDesk 用本机的 `ssh` 登录服务器，在容器里执行 `psql`。字段：

| 字段 | 说明 |
|---|---|
| ssh 主机 | 写 `~/.ssh/config` 里的名字（也可以是主机名） |
| 容器 | 运行 PostgreSQL 的 Docker 容器名 |
| 数据库、用户 | 容器里 psql 用的 |

要点：

- ssh 以 `BatchMode` 运行，**从不询问密码**：必须用密钥或 ssh-agent 免密登录。先在终端里 `ssh <ssh 主机>` 能直接进去，再来这里配。
- 服务器上要有 `docker`，容器里要有 `psql`。
- 这种方式没有“密码”字段（容器内连接，由容器里的配置决定）。
- 本机要有 `ssh`（macOS 自带）。

字段值只能用字母、数字和 `. _ - @ :`，且不能以 `-` 开头；否则页面会提示“为空或含有不允许的字符”。

## 导入连接串

页面上“导入连接串”可以一次填好字段。接受：

```
postgres://用户@主机:5432/库
ssh://ssh主机/容器?user=用户&db=库
```

**不要在连接串里写密码**；导入后在密码栏里单独填。

## 语句超时

插件设置里的“语句超时（毫秒）”，默认 30000（30 秒）；超过的语句由数据库取消。一次查询默认最多取回 1000 行，超出会截断并在摘要里标注。

## 备份到本机

只对“经 ssh”的数据源可用。把服务器上的库拷成你本机 Docker 容器里的一个**新库**：

1. 检查本机容器和 `docker`；2. 在服务器上 `pg_dump` 并下载（转储文件存进 `plugin-data/org.onedesk.datasource/backups/`）；3. 拷进本机容器；4. 新建库；5. `pg_restore`；6. 自动新建一个指向这个新库的直连数据源。

需要填：本机新库名（小写字母、数字、`_`）、本机容器、本机端口、本机用户。**这个库必须还不存在，已有的库绝不会被改动。**需要本机装了 Docker Desktop（或 OrbStack），本机容器里的 PostgreSQL 版本不能低于服务器的。任何一步失败都会停下并说明停在哪一步。

这是“备份数据库”的功能，和第 2 章的“备份 OneDesk 自己的数据”不是一回事。

## 默认数据源与环境

一条保存的 SQL 用哪个数据源，按这个顺序找：

1. 这条 SQL 自己选的；
2. 当前**环境**里名为 `datasource` 的参数；
3. 工作区配置里的 `datasource.default`。

三处都没有时运行会提示“没有数据源”。这样同一条 SQL 在“测试”环境和“生产”环境下会连不同的库。环境参数的设置方法见第 3 章。
