# 5. 保存的 SQL 与查询目录

## 保存的 SQL

“保存的 SQL”插件：新建 → 写 SQL → 保存 → 在数据源上只读运行 → 看结果。

### 参数 `:name`

在 SQL 里写 `:名字` 就是一个参数，运行前页面上会出现对应的输入框：

```sql
SELECT * FROM orders WHERE created_at >= :since AND status = :status
```

- 字符串、带引号的名字、`$$…$$`、注释里的 `:xxx` 不算参数；`::` 是 PostgreSQL 的类型转换，也不算。
- 值会被当作字面量安全代入（不是拼文本），所以写 `:status` 时不要自己再加引号。
- 参数值也可以来自**环境**里同名的参数；页面上填的优先。
- 页面上的时间输入按 **UTC**，并有“现在 / 今天 00:00 / 昨天 00:00 / 7 天前 / 本月初”这几个快捷项。
- 必填、数字、日期、枚举取值等不符合时，会在运行前提示（例如“参数 :since 必须是日期”），不会发到数据库。

### 选数据源

页面上的“数据源”留空 = 先用环境的数据源，再用工作区的默认数据源（第 4 章）。

### 结果与历史

- 页签：**结果**、**实际发出的 SQL**（代入参数之后真正发出去的）、**历史**。
- 表格结果可以导出 CSV（工作区开了“禁止导出”时不可用）。
- 每条资源保留最近的运行记录（最多 200 次）；想长期留某次结果，用“保留此结果”。

### 用 AI 写

SQL 页面有“用 AI 写”，见[第 6 章](06-ai.md)。AI 的回答只是**提议**，要你按“接受”才会进编辑器，而且是未保存的修改。

## 查询目录

“查询目录”插件（`org.onedesk.catalog`）把你**授权的一个文件夹**里的 `.sql` 文件建成一份只读目录。文件是源头，OneDesk 不改文件；适合团队把查询放在 git 里共享。

### 授权文件夹

在插件页面授权一个文件夹（插件需要读文件，所以要你明确点头）。工作区打开和“重新索引”时会读取其中的 `.sql`。

### 查询文件的写法

每个 `.sql` 以一段 YAML 头开始，两种写法都行：

```sql
/* ---
id: sales.orders.recent
title: 最近的订单
description: 某个时间之后下的订单
datasource: 生产只读
tags: [sales]
params:
  - name: since
    type: datetime
    required: true
    description: 从这个时间起
  - name: status
    values: [paid, refunded]
--- */
SELECT * FROM orders WHERE created_at >= :since AND status = :status
```

```sql
-- ---
-- id: sales.top
-- params: [n]
-- ---
SELECT * FROM customers LIMIT :n
```

- `id` 必填：字母、数字、`_`、`-`，用 `.` 分段；目录树按前两段分组。重复的 id 只留第一个。
- 参数类型：`text`、`number`、`date`、`datetime`、`time`、`enum`（写了 `values` 就是 enum）。
- `datasource`（可选）指定它用哪个数据源（名称或 id）；不写则按“环境 → 工作区默认”。
- 头部有问题的文件会被跳过，在“跳过的文件 / 索引报告”里列出原因（缺 id、头没结束、参数名不合法……），不会拖垮其余查询。
- 页面顶部会警告：正文用了但头里没声明的参数、声明了没用的参数。

### 映射：`{{实体}}`

团队的查询里可以写 `{{order}}`、`{{order.total}}` 这样的占位符，由**映射文件**换成真实的表名和列名（这样表改名只改一处）。映射文件是授权文件夹顶层的 `mapping.yaml`（或 `.yml`/`.json`），也可以在插件设置里指定完整路径。占位符没有映射时，运行前会提示“以下占位符没有映射”。

页面上的“实际 SQL”页签显示代入映射之后的查询。有“时间版本”的表还可以填“截至时间”（UTC）。
