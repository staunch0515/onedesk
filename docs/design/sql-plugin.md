# 设计：SQL 插件（sql，用于验收框架）

状态：草案，待确认。未确认前不写代码。
依据：docs/requirements.md I.0a–I.0d、I.4、I.5、I.10；docs/decisions.md D147、D160、D163、D168、D169、D170、D171、D172；sqlpool 现有功能（CLAUDE.md 与代码）。

## 1. 目的

SQL 插件是框架的验收样本：它要求树、标签页、环境、参数、结果区、历史、AI 接口、数据源资源、插件页都正常工作。能做到的，网址、笔记、提示词也能做到；做不到的，说明框架哪里不够。

## 2. 与 sqlpool 的功能对照

| 功能 | sqlpool 现状 | OneDesk 落点 | 验收方式 |
|---|---|---|---|
| 保存 SQL（名称、说明、备注） | 有 | sql 资源（kind `sql`），body 含 SQL 正文，name、description、tags | 新建、编辑、搜索 |
| SQL 分组树 | 有（可分组、可建子组） | 资源树，分组为树节点，支持全部展开、全部折叠 | 树操作测试 |
| 参数表单（类型化，带提示） | 有 | 参数来自 SQL 中的 `:name` 声明，类型由参数定义给出，说明放在悬停图标里 | 表单生成测试 |
| 变量替换（环境参数） | 有 | 参数先从当前标签页的环境取值，取不到才让用户填写 | 环境覆盖测试 |
| 环境树（父子、覆盖、面包屑） | 有 | 环境树（I.4），每个标签页选择自己的环境 | 切换环境、父参数可见 |
| 执行（只读、超时、行数上限） | 有 | 数据源资源指向 PostgreSQL；执行在只读事务中进行；行数和超时有上限 | 写语句被拒绝，超时返回错误 |
| 结果表格（排序、列宽、表头三态） | 有 | 结果区（I.0d），表格组件（I.7） | 排序、列宽保存 |
| 保存结果 | 有 | 结果保存为该 SQL 的一次执行记录（历史），可回看 | 保存后重启仍在 |
| 执行历史（每个 SQL 200 次，可复用参数） | 有 | 执行历史（I.5） | 复用参数再执行 |
| 导出 CSV（UTF-8 BOM，无目录时让用户选） | 有 | 结果区的导出动作；选择目录时才用系统对话框 | 导出文件用 Excel 打开不乱码 |
| 导出 .sh | 有 | 导出动作，生成的文件使用当前环境的参数值 | 生成脚本可运行 |
| 显示最终执行的 SQL 文本 | 有 | 执行前在结果区显示参数代入后的文本 | 文本与实际执行一致 |
| AI 分析结果 | 有（需求中提到） | 结果区发送给 AI 接口；先以 Markdown 预览，可编辑后发送；分析结果保存，并与执行记录关联 | 分析结果出现在该执行记录下 |
| AI 生成 SQL | 有 | 在标签页中生成，失败的错误留在结果区 | 生成失败时错误可见 |
| 服务器命令（同 SQL 的分组、编辑、参数） | 有 | 与 SQL 同一个插件，用 kind `command`，行为一致 | 同样的测试 |
| 数据库连接 | 有 | 数据源资源（D168），密码只存名字（钥匙串） | 连接失败有原因提示 |

## 2a. 树与历史的位置（已定稿的方向）

SQL 插件体现三棵树，每棵树只放同一性质的内容：

1. **资源树**：保存的 SQL 和服务器命令，按分组排列。每个 SQL 节点下有一个"历史"子节点。
2. **环境树**：环境节点，可以有子环境，子环境继承父环境的参数。标签页选择的是这棵树里的环境。
3. **数据源树**：每条数据库连接是一个节点，按项目或用途分组。数据源仍然是资源（D168），只是放在自己的树里，和硬盘文件的做法一致。

另外，插件页属于插件树；工作区配置树不属于 SQL 插件。

### 执行历史的位置

- **每个 SQL 节点下的"历史"子节点**：展开后列出这条 SQL 的每次执行，按时间倒序。
- **点开某次执行**：在标签页中打开，显示当时的参数、最终执行的 SQL 文本、结果和 AI 分析（如果有）。可以"复用参数"再次执行，或保存为结果。
- **SQL 标签页的结果区**：列出这条 SQL 的历史，可以直接切换。
- 历史按 SQL 分开，不做一个总历史表。如需要跨所有 SQL 的总历史，另建一棵"历史"树，按日期分组，作为后续功能。

## 2b. SQL 标签页的布局

一个 SQL 标签页从上到下分五块。风格沿用现有界面的标题区、操作区、内容区，颜色和间距只用设计 token。

```
┌───────────────────────────────────────────────────────────────┐
│ 标题区   [SQL 图标] 本周活跃用户           [标签] [分组：报表] │
│          说明：按周统计登录用户                                │
├───────────────────────────────────────────────────────────────┤
│ 操作区   [运行]  [保存结果]  [AI 分析]  [导出 CSV ▾]  [更多 ▾]  │
│          环境：[测试 ▾]     数据源：[Quizbuks 测试库 ▾]        │
├───────────────────────────────────────────────────────────────┤
│ 参数区   开始日期 [2026-11-01]  结束日期 [2026-11-15]  ⓘ        │
│          （参数来自 SQL 中的 :name 声明，值先从环境取）          │
├───────────────────────────────────────────────────────────────┤
│ SQL 编辑区（占满可用高度）                                     │
│   select ...                                                  │
│   from ...                                                    │
│   where created_at between :start and :end                    │
├═══════════════════════════════════════════════════════════════┤  ← 可拖动
│ 结果区  [结果] [最终 SQL] [历史] [AI 分析]          [收起 ▾]   │
│   表格（可排序、可调列宽），底部显示行数和耗时                  │
└───────────────────────────────────────────────────────────────┘
```

每一块的内容：

- **标题区**：SQL 名称、说明、标签、所在分组。点分组名可以回到资源树中该节点。
- **操作区**：运行（主按钮）、保存结果、AI 分析、导出（CSV、.sh）、更多（复制、重命名、移动、删除）。环境和数据源是这个标签页自己的选择，每个标签页各自选择。
- **参数区**：由 SQL 中的 `:name` 声明生成表单。参数值先从当前环境取，取不到才需要填写。每个参数右侧的图标悬停显示说明。
- **SQL 编辑区**：占满剩余高度。先用等宽字体的文本编辑，语法高亮以后再做。
- **结果区**：默认在下方，可以拖动高度或收起。四个页签：结果（表格）、最终 SQL（参数代入后的文本）、历史（本 SQL 的执行列表）、AI 分析。失败的原因显示在结果区。

这个布局只是 SQL 插件的标签页。其他插件的标签页使用同样的标题区、操作区、内容区和结果区，内容不同。

## 3. 参数规则

- 参数语法统一为 `:name`（sqlpool 也是这个写法；CLAUDE.md 要求统一）。
- 参数值用数据库驱动的绑定方式传入，不做字符串拼接。sqlpool 目前用字面量替换，OneDesk 改为绑定，这是一个决定，需你确认（D173）。
- 同一个参数名在一个 SQL 里只声明一次，类型由声明给出。

## 4. 不做的事

- 不做 schema 浏览器、不做写操作（sqlpool 也不做）。
- 不做行级权限复制（由数据库账户负责）。
- 不做 MySQL、SQLite 驱动（sqlpool 也未做）。
