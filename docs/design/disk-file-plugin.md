# 设计：导入硬盘资源插件（disk-file，基础版）

状态：草案，待确认。未确认前不写代码。
依据：docs/requirements.md I.10b；docs/decisions.md D157。

## 1. 目标与边界

- 把本机文件和文件夹的路径登记为资源，便于统一搜索、分组和打开。
- 只保存路径和基本信息，不复制、不读取、不索引文件内容。
- 不监听文件系统变化；文件变动靠用户手动"刷新"或重新导入。

## 2. 资源结构（kind: disk-file）

| 字段 | 类型 | 说明 |
|---|---|---|
| path | text，必填 | 绝对路径，标准化后保存（去掉末尾斜杠，展开符号链接前的原始路径） |
| isDirectory | boolean | 是否文件夹 |
| size | number | 字节数，文件夹为空 |
| modifiedAt | text | 最后修改时间（ISO 8601） |
| extension | text | 扩展名，小写，无点 |
| missing | boolean | 最近一次检查时路径不存在 |

资源的 name 默认为文件名或文件夹名；group 默认为所在文件夹名；tags 由用户填写。

同一路径只允许一条资源。以路径作为去重依据。

## 3. 动作

- **import-folder**：输入文件夹路径（或通过选择对话框获得），参数"包含子文件夹"（默认否）。遍历后为每个条目创建或更新资源。输出：新增、更新、跳过的数量。
- **reveal**：在访达中显示该路径。路径不存在时返回失败，并把资源标为 missing。
- **open**：用默认应用打开。同样处理不存在的情况。

## 4. 视图

- 表单：路径、名称、分组、标签、说明。路径字段只读（要改路径就重新导入）。
- 详情：路径、大小、修改时间、是否存在。missing 为真时显示醒目的提示，并给出"移除资源"按钮。

## 5. 宿主能力 `files`（D157，需确认）

```
files.pickFolder(): Promise<string | null>           // 系统选择对话框，取消返回 null
files.list(path, { recursive }): Promise<FileEntry[]> // 只返回元数据，不读内容
files.stat(path): Promise<FileEntry | null>          // 不存在返回 null
files.reveal(path): Promise<void>                     // 在访达中显示
files.open(path): Promise<void>                       // 用默认应用打开

FileEntry = { path, name, isDirectory, size, modifiedAt, extension }
```

- 清单声明 `requires.files: true`，安装时由用户确认。
- 只能访问用户通过选择对话框授权过的路径，或授权路径之下的内容。授权范围在应用里记录，可撤销。
- `list` 设上限（例如单次 10,000 条），超过时返回截断标记，插件提示用户缩小范围。
- 不提供写入、删除、重命名能力。

## 6. 错误与边界

- 没有权限或路径不在授权范围内：返回 `permission`，不静默失败。
- 路径不存在：资源标为 missing，不删除资源。
- 符号链接：记录链接本身的路径；不沿链接递归，避免循环。
- 特殊文件（设备文件、套接字）：跳过，计入"跳过"数量。
- 中文和含空格的路径：全部按 UTF-8 处理，原样保存。

## 7. 测试

- 单元：路径标准化、去重、扩展名提取、missing 标记。
- 集成：用临时目录导入，改名或删除文件后刷新，结果正确；超过上限时截断。
- 界面：导入一个文件夹，列表出现对应资源；reveal 和 open 在删除文件后给出失败提示。

## 8. 待决定

1. 授权范围：是每次选择一个文件夹就授权一次，还是整体授权一次后可以随时撤销？（建议：每次选择文件夹即授权该文件夹，在设置页可查看和撤销。）
2. 重新导入时，已删除的文件：标为 missing 还是自动移除？（建议：标为 missing，由用户决定移除。）
3. 同一文件在两个工作区的导入：互不影响，因为工作区数据彼此隔离。确认即可。
