# 书的公开规范（OneDesk Book）草案 0.1

> **状态**：草案 0.1，2026-11-26。按 OneDesk 第②–⑧步已经实现、并由测试验证的做法整理（`docs/redesign/book.md` §13–§26）。待用户确认。
>
> **目的**：让任何程序——不只是 OneDesk——都能读、写、显示、发布、导入一本书。规范只规定**书的结构、角色、接口、文字写法、发布的文件格式**，不规定界面长什么样、程序怎么写。
>
> **读法**：“必须”是要求；“应该”是建议，不做要说明理由；“可以”是允许。例子不是规范的一部分。

---

## 0. 范围

**规定的**：
1. 书的数据模型：资源、类型、树（§2）；
2. 书怎么装订：页的顺序、部分、子书（§3）；
3. 角色：每一页在书里担当什么，标准角色和扩展角色（§4）；
4. 角色之间怎么配合：接口 `onedesk.book/1`（§5）；
5. 编号（§6）；
6. 正文的写法：引用、嵌入、计算、脚注、题注、索引词、引注（§7）；
7. 版次、印次、版本（§8）；
8. 发布的文件：资源包 `.odpack`（§9），导入后的只读副本（§10）；
9. 保留字段和指纹（§11）、签章（§12）；
10. 可执行的书（可选部分，§13）；
11. 一本书依赖的插件（§14）；
12. 符合性（§15）。

**不规定的**（各实现自己决定，或以后的版本再定，§16）：界面、排版和打印、书的服务器和插件市场的网络协议、多设备同步。

## 1. 术语

| 术语 | 意思 |
|---|---|
| **资源** | 书里的一切东西：书本身、每一页、每一道题、每一份记录。有编号、类型、名字、说明、标签、正文 |
| **类型**（kind） | 资源的种类，全名 `<插件编号>:<短名>`，如 `org.onedesk.book:cover` |
| **插件** | 提供类型和它们的逻辑的程序包。插件编号是反向域名，如 `org.onedesk.book` |
| **书** | 一种资源，只负责**装订**：它下面有哪些页、按什么顺序、每页担当什么角色 |
| **页** | 书下面的资源。任何资源都可以是页 |
| **角色** | 一页在书里担当的职责（封面、目录、正文、附录……），由它的类型决定 |
| **部分** | 前面的部分 `front`、正文 `body`、后面的部分 `back`、不进阅读 `none` |
| **实现者** | 提供某种类型、并为它实现接口 `onedesk.book/1` 的插件 |
| **出版者** | 发布书的工作区（人或单位） |
| **读者** | 导入书的工作区 |

## 2. 数据模型

### 2.1 资源

每个资源必须有：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 文字 | 编号，全局唯一（OneDesk 用 32 位十六进制）。发布、导入时**不变** |
| `kind` | 文字 | 类型全名 |
| `name` | 文字 | 名字；同一个父节点下应该不重名（引用按名字找） |
| `parent` | 文字或空 | 父资源的编号；书的根是空 |
| `pos` | 整数 | 在兄弟里的顺序（小的在前） |
| `description` | 文字 | 说明，可以空 |
| `tags` | 文字数组 | 标签 |
| `body` | 对象 | 正文：键 → 值（JSON），键的含义由类型的插件决定 |

可以有：`rev`（版本号，每次修改加一）、创建和修改的时间与修改人、修订历史。

### 2.2 字段的声明

插件在清单里为类型声明正文字段的性质（只列和书有关的）：

| 声明 | 意思 |
|---|---|
| `type` | `text`、`longtext`、`number`、`boolean`、`date`、`ref`（指向另一个资源的编号）、`attachment`（文件）…… |
| `refs: true` | 这个文字字段里的 `[[…]]`、`![[…]]` 是引用（§7.1） |
| `withheld: true` | 保留字段：学生版里不带（§11） |
| `secret` | 密钥，**必须**不出现在正文、资源包和导出里；只存在系统的钥匙串 |

### 2.3 文件（图片）

- 文件按内容存放，编号是内容的 SHA-256（64 位十六进制小写）；
- 附件字段的值是 `{ blob, name?, type, size, width?, height? }`；
- 文字里的图片写 `![说明](blob:<编号>)`。

## 3. 书：装订

1. 书**必须**只负责装订：页的顺序和每页的角色。怎么浏览、编号、发布，**必须**由担当那个角色的页负责（§4）。
2. 书下面的节点按 `pos` 排；分组（篇、章）是容器，它下面的页也按 `pos` 排。
3. 读的顺序是：`front` → `body` → `back`，同一部分里按树的顺序；`none` 的页不进阅读（如封面、目录）。
4. 页放进书时，应该落在它的部分里（不能把附录放在正文前面）；“一本书最多一页”的角色（`single`），书里已有一页时应该拒绝第二页。
5. **子书**：书里的书。它不展开自己的节点，而是由外层目录向子书的目录要它的目录项（§5.4），整本作为外层的一项。
6. 没有实现接口的资源放进书里，按**正文**处理，显示它被嵌入时的样子（§7.1）。

## 4. 角色

### 4.1 角色的描述

每种类型的角色用一个对象描述（接口 `roles` 返回，§5.2）：

```json
{ "kind": "cover", "role": "cover", "part": "none", "single": true, "container": false, "numbering": "none", "edition": "teacher" }
```

| 键 | 值 | 必须 | 说明 |
|---|---|---|---|
| `kind` | 短名 | 是 | 实现者自己的类型 |
| `role` | 文字 | 是 | 标准角色（§4.2）或扩展角色（§4.3）的名字；不认识的按 `body` |
| `part` | `front` / `body` / `back` / `none` | 是 | 不认识的按 `body` |
| `single` | 布尔 | 否 | 一本书里最多一页；默认否 |
| `container` | 布尔 | 否 | 它下面的节点也进阅读；默认是 |
| `numbering` | `level` / `letter` / `none` | 否 | 按层级、按字母（A、B、C）、不编号；默认 `level` |
| `edition` | `teacher` | 否 | 只进教师版（§8.3）；其他值忽略 |

### 4.2 标准角色

| 角色 | 部分 | 最多 | 编号 | 职责 |
|---|---|---|---|---|
| `book`（子书） | body | — | 按层级（“第一册”） | 只装订 |
| `cover` 封面 | none | 1 | 无 | 书名（就是书的名字）、副书名、著者、封面图、简介；书被引用、在列表里显示时的样子 |
| `colophon` 版权页 | front | 1 | 无 | 出版者、书号、版本说明、版次印次、发布记录、分不分学生版和教师版；**发布只从这里**（§8） |
| `preface` 前言（序、前言、致谢） | front | — | 无 | 书外的话 |
| `toc` 目录 | none | 1 | 无 | 浏览（连续、分页）、编号、阅读位置、交叉引用、导出。**换一种目录就换一种读法**（课本目录、流程目录） |
| `figures` 图表目录 | front | 1 | 无 | 列出全书的图、表、公式 |
| `body` 正文页 | body | — | 按章 | 内容、脚注、题注、索引词、引注 |
| `group` 分组（篇、章） | body | — | 按层级 | 只是容器 |
| `appendix` 附录 | back | — | 字母 | 容器，自己编“附录 A”，里面编“A.1” |
| `references` 参考文献 | back | 1 | 无 | 文献条目、正文引注的显示（顺序编码制或著者-出版年制，GB/T 7714） |
| `reference` 文献条目 | none | — | 无 | 一条文献 |
| `index` 索引 | back | 1 | 无 | 收集正文里标出的词，按语言的顺序排（中文按拼音） |
| `afterword` 后记 | back | — | 无 | 书外的话 |

### 4.3 扩展角色（已有的）

实现者可以定义新角色。下面是 OneDesk 已有的，其他实现遇到时**应该**按表里的部分和编号处理；不认识的按正文：

| 角色 | 提供者 | 部分 | 职责 |
|---|---|---|---|
| `calc` 计算页 | 公式 | body | 参数和计算，可以被引用和调用（§7.3） |
| `question` 题 | 练习 | none | 题干、空、选项、答案（保留字段）、讲解（保留字段）、判法、分值 |
| `practice` 练习页 | 练习 | body | 在书上直接作答、当场判 |
| `test` 测验页 | 练习 | body | 卡片；在自己的作答页上作答、交卷、判分；答案时机：每题答完、交卷后、老师公布 |
| `toc`（课本目录） | 练习 | none | 一种目录：按课浏览，显示进度和得分 |
| `answers` 答案附录 | 练习 | back，`edition: teacher` | 全书答案；勾选测验“公布”，重印学生版带上答案 |
| `template` 文书模板 | 文书 | none | 带填写项的格式 |
| `document` 文书 | 文书 | body | 照模板写、在文中填写、签名定稿、修订、作废 |
| `series` 系列 | 文书 | body（容器） | 同一模板写的很多份，按时间或填写项排 |
| `step` 步骤页 | 流程 | body | 运行什么、给它的值、期望、条件、等人确认 |
| `toc`（流程目录） | 流程 | none | 一种目录：从上到下执行步骤（§13） |
| `setup` 账簿启用表 | 账簿 | front，最多 1 | 单位、启用日期、计价方法、经管人员和交接、已结账的月份 |
| `toc`（存货目录） | 账簿 | none | 一种目录：存货、结存、预警 |
| `account` 账户（存货） | 账簿 | body（容器） | 档案、期初；下面是账页 |
| `sheet` 账页 | 账簿 | body | 一页最多 100 行；只由记账写；过次页、承前页 |
| `voucher` 单据（入库单、出库单、盘点表） | 账簿 | none | 审核（签章）、记账、红字冲销 |
| `register` 单据簿 | 账簿 | back | 按月放单据 |
| `report` 报表（收发存汇总表） | 账簿 | back | 期初、收入、发出、期末；月末结账 |

**加功能就是加角色**：新的玩法必须做成新的类型和角色，不在“书”上加开关和模式。

## 5. 接口 `onedesk.book/1`

### 5.1 规则

1. 角色之间通过这个接口配合，**只按角色找**：调用方先在书的子树里找到担当那个角色的页，再调用那一页的实现者；**必须不**写死某个插件。
2. 接口调用是**纯计算**：只读，不写任何东西；应该在 5 秒内答完。
3. 不兼容的修改必须升到 `onedesk.book/2`。
4. 调用不能成环（A 问 B，B 又问 A）：调用方可以把自己的角色表随调用带过去（§5.4 `roles`）。

### 5.2 `roles`

- 按实现者调用。输入 `{}`。
- 返回 `{ "kinds": [角色描述…] }`（§4.1）。

### 5.3 `outline`

- 按资源调用：一页里有什么。输入 `{}`（资源由调用决定）。
- 返回：

```json
{
  "headings": [{ "text": "勾股定理", "level": 2 }],
  "figures": [{ "type": "figure", "caption": "直角三角形", "of": "三角形图" }],
  "cites": [{ "keys": ["张三2020"], "note": "第 12 页" }],
  "terms": [{ "term": "三角形", "sub": "勾股定理" }]
}
```

- `figures[].type`：`figure`、`table`、`equation`；`of` 是题注上面那个嵌入的名字（没有就不给）。全部按出现的顺序。

### 5.4 `entries`

- 目录实现。两种调用：
  - **按目录**：输入 `{ "depth": 0, "settings": {…}? }`，调用的资源是目录页；`depth` 是这本书在外层书里的深度；`settings` 是外层的编号设置（子书没有目录时用）。
  - **按书**：输入 `{ "book": "<书的编号>", "roles": { "<插件>": [角色描述…] } }`，调用时指定插件；用于另一种目录借用书的编号（课本目录、流程目录），`roles` 是调用方自己的角色表，被调用方用它而不再反问。
- 返回：

```json
{
  "items": [{ "key": "p21", "resource": "p21", "title": "第二章 秒的认识", "number": "第二章", "level": 1, "part": "body", "book": false, "args": {} }],
  "figures": [{ "type": "figure", "number": "2-1", "caption": "钟面", "item": "p21" }],
  "terms": [{ "term": "秒", "sub": null, "item": "p21" }],
  "cites": [{ "keys": ["张三2020"], "notes": [null], "item": "p21" }]
}
```

- `items` 按阅读顺序；`level` 从 1 开始；`book: true` 是子书的书名项；`args` 是显示这一项时交给它的参数（如这一章的编号前缀，供它编“图 2-1”）。最多 20 000 项。

### 5.5 `number`

- 目录实现。输入 `{ "targets": ["<资源编号>", …] }`。
- 返回 `{ "labels": { "<编号>": "第三章" | "图 2-1" | "式（2-3）" } }`；不在书里的不给。

### 5.6 `cite`

- 参考文献实现。输入 `{ "cites": [{ "keys": ["张三2020"], "notes": ["第 12 页"] }] }`。
- 返回 `{ "labels": ["[3: 12]", …] }`，和输入一一对应。

## 6. 编号

### 6.1 正文

- 按深度：书下面第一层是第 1 层；每个上级下面分别计数，分组、正文页、其他资源一起数。
- 三种方式（由目录的设置决定）：
  - **中文**：有层级名称的层编“第一章”“第二节”；更深的层编数字路径“2.1.3”；
  - **数字**：“2”“2.1”“2.1.3”；
  - **不编号**：只有名字。
- 层级名称默认“章,节”（各语言有自己的默认）。
- 子书单独计数，不占章的号：“第一册”“第二册”。
- 目录项的标题是“编号 + 空格 + 名字”。

### 6.2 附录

- “附录 A”“附录 B”；附录里的东西编“A.1”“A.1.1”。

### 6.3 图、表、公式

- 按章编号：“图 2-1”“表 2-1”“式（2-1）”；附录里“图 A-1”。
- 前言、后记、不编号的角色不编号。

## 7. 正文的写法

正文是 Markdown（CommonMark + 表格），加上下面的约定。引用写在声明了 `refs: true` 的字段里才算数。

### 7.1 引用和嵌入

| 写法 | 意思 |
|---|---|
| `[[名字]]` | 引用另一个资源；在书里显示成它的编号（如“第三章”“图 2-1”） |
| `[[名字#标题]]` | 引用它的一节 |
| `![[名字]]` | 嵌入：在这里显示它被嵌入时的样子 |
| `![[名字#标题]]` | 嵌入它的一节 |

- 名字找不到时显示为断开的引用，不报错。
- 引用记录的是目标的编号，目标改名后引用仍然指向它。

### 7.2 题注、脚注、索引词、引注

| 写法 | 意思 |
|---|---|
| 嵌入或图片**下面**一行 `图：说明`；表格**上面**一行 `表：说明`；公式下面 `式：说明` | 题注，编“图 2-1　说明”。英文 `Figure:`、`Table:`、`Equation:`，日文 `図：`、`表：` 也认 |
| `正文[^1]` 和单独一行 `[^1]: 注释` | 脚注，编号在一页里从 1 开始 |
| `{{索引:勾股定理}}`、`{{索引:三角形/勾股定理}}` | 索引词（二级用 `/`）；阅读时不显示；英文 `{{index:…}}` |
| `[@张三2020]`、`[@张三2020, 第 12 页]`、`[@a; @b]` | 引注；显示成什么由参考文献页决定 |

### 7.3 计算

| 写法 | 意思 |
|---|---|
| `![[摄氏转华氏 \| C=37]]` | 嵌入一次计算：公式、代入的值、结果 |
| `[[=摄氏转华氏 \| C=37]]` | 行内只显示结果（“98.6 °F”） |
| `[[=入院记录 \| 项=体重]]` | 向任何实现了嵌入的类型要一个值 |

- `|` 后面是 `名字=值`，用逗号分开；值里可以有环境的值 `{{名字}}`（§7.4）。
- 计算由被引用的类型完成（它的插件），书和目录不计算。

### 7.4 环境的值

- `{{名字}}`：按读者当前的**环境**（一组名字和值，比如“生产”“张三 · 第 2 次住院”）填进去；换环境，书里的值跟着变。
- 这个写法是正文页、笔记这些类型的约定；别的类型可以有自己的写法（如 HTTP 请求的 `:名字`、练习的 `{{?}}`、文书的 `{{?名字 | …}}`），由它们的插件说明。
- `{{secret:名字}}` 是密钥，**必须**不显示出来。

## 8. 版次、印次、版本

### 8.1 版次和印次

- **发布新版**：版次加一、印次回到 1；把这一版的书原样**存档**（之后不变）。
- **重新印刷**：用那一版的存档，印次加一。作者之后改的内容要到下一版才出现。
- 只有**版权页**能发布；没有版权页的书不能发布。

### 8.2 发布记录

版权页记每一次：版次、印次、版本、时间、文件、说明（如“公布到 第一单元测验”）。

### 8.3 学生版和教师版

- 版权页可以设“分学生版和教师版”（默认分）。
- **教师版**：整本书。
- **学生版**：不带角色写了 `edition: "teacher"` 的页（和它们下面的），不带保留字段（§11）。
- 不分时只印一种（学生版的规则，但不排除任何页）。

## 9. 资源包 `.odpack`

### 9.1 文件

- 一个 **zip** 文件，条目**只存储、不压缩**（方法 0），文件名 UTF-8；读的时候遇到压缩、加密的条目必须拒绝。
- 里面：
  - `package.json`：书和它的资源（§9.2）；
  - `blobs/<编号>`：用到的文件（§2.3），编号必须等于内容的 SHA-256。

### 9.2 `package.json`

```json
{
  "format": 1,
  "publisher": "<出版者工作区的编号>",
  "publisherName": "某学校数学组",
  "root": "<书的编号>",
  "title": "数学三年级（上）",
  "edition": 2,
  "printing": 3,
  "variant": "student",
  "publishedAt": 1795600000000,
  "resources": [
    { "id": "<编号>", "kind": "org.onedesk.book:book", "parent": null, "pos": 0, "name": "数学三年级（上）", "description": "", "tags": [], "body": {} }
  ],
  "sealed": [
    { "resource": "<题的编号>", "field": "answers", "salt": "<随机>", "hashes": ["<十六进制>"], "value": "8" }
  ]
}
```

| 键 | 说明 |
|---|---|
| `format` | 格式版本，现在是 1 |
| `publisher` / `publisherName` | 出版者的编号和名字 |
| `root` | 书的编号；`resources` 的第一项必须是它，`parent` 为空 |
| `edition` / `printing` | 版次、印次（从 1 起） |
| `variant` | `student`、`teacher`；出版者自己的存档是 `archive` |
| `publishedAt` | 毫秒时间戳 |
| `resources` | 书和它下面的全部资源，父节点在子节点之前；最多 50 000 个 |
| `sealed` | 保留字段的指纹和原文（§11），只在学生版里 |

- 整个文件最大 512 MB。

### 9.3 存档

出版者在发布新版时，把书原样存成 `variant: "archive"` 的包，留在自己那里（OneDesk 放在 `<工作区>/packages/<书的编号>/e<版次>.odpack`），之后的重印都从它出。存档不能导入。

## 10. 导入：只读副本

1. 导入前应该先给读者看：书名、出版者、版次印次、版本、资源数，是第一次导入还是更新。
2. **拒绝**导入的情况：
   - 出版者就是自己（`ownPackage`）；
   - 这里已有另一个出版者的同一本书（`otherPublisher`）；
   - 这里已经是这一印次或更新的（`notNewer`）；
   - 编号被别的东西占了（`taken`）。
3. 导入后是**只读副本**：资源编号不变，记下来源（出版者、版次印次、版本）；用户和插件都不能改、不能删一部分、不能往里加、不能把里面的拖出去；**整本**可以移动、删除。
4. **更新**：同一出版者、同一本书、更新的版次或印次：内容整体换成新的；包里没有了的删除（进废纸篓）；书的根留在读者放的位置。读者自己的东西（作答、错题、笔记）不受影响。
5. 整本删了以后可以再导入（任何印次）。

---

## 11. 保留字段和指纹

1. 类型可以把字段声明为保留字段（`withheld: true`，如题的答案、讲解）。
2. 学生版里保留字段的三种处理：
   - **公布了**（这次印刷 `reveal` 了它）：原文照常带上；
   - **需要当场判**：类型给出“可接受的写法”（`seal`，由类型先规范化，如 `1/2` → `0.5`），包里带指纹和原文；
   - **其他**：不带。
3. **指纹**：`SHA-256( 盐 ␟ 资源编号 ␟ 字段 ␟ 写法 )`（`␟` 是 U+001F），十六进制小写；每个字段一个随机的盐。
4. **原文**：导入时必须存进读者的**钥匙串**，不进数据库；数据库里只有指纹。判对错用指纹（同样规范化后比对）；到了作者定的时机才从钥匙串取原文显示。
5. 指纹能被挨个试出来，原文也能被懂技术的人取出：**只适合练习**。正式考试应该不带任何答案，由出题人那边判（或用“老师公布”）。

---

## 12. 签章

1. 插件可以给自己类型的资源加**签章**：一个名称（如“书写”“审签”“作废”）和签名人、时间。签章的含义由插件决定。
2. 第一个签章落下时：
   - 资源变成**只读**（改、恢复历史、删除都拒绝；可以移动）；
   - 它里面的嵌入和计算**取快照**：之后显示这份资源时，里面的引用给出签章时的结果，不重新算。
3. 撤下签章（“修订”）必须写**理由**；撤下后恢复可改，快照丢弃；每次加章、撤章都记下来（谁、何时、理由、当时的版本）。
4. 资源包和只读副本不带签章（签章属于工作区）。

## 13. 可执行的书（可选部分）

实现这一部分的程序称“支持可执行的书”。

### 13.1 步骤页 `step`

| 正文键 | 意思 |
|---|---|
| `text` | 说明（Markdown，可以嵌入） |
| `target` | 要运行的资源的编号；空：人做的一步 |
| `inputs` | 每行 `名字 = 值`，交给被运行的资源（代替它的同名参数）；值里可以有 `@步骤名.值名`、`{{环境的值}}` |
| `expect` | 期望，每行一条，全部成立才算通过 |
| `when` | 条件，一条；不成立就跳过 |
| `confirm` | 一句话；写了就在这一步运行之后停下，等人确认 |

### 13.2 比较的写法

`左 运算 右`，运算是 `=`、`≠`（`!=`）、`>`、`<`、`≥`（`>=`）、`≤`（`<=`）、`包含`（`contains`）；或 `左 为空`、`左 不为空`（`empty`、`not empty`）。两边是 `@…`、`{{…}}` 或直接写的字（可以加引号）；两边都像数字时按数比，否则按字比。**不做计算**。

### 13.3 值

- 被运行的资源给出结果（文字或表格）和**数据**（名字 → 值）。
- `@步骤名` 是那一步结果的文字（表格是第一行）；`@步骤名.值名` 先在数据里找，再在表格第一行按列名找；更深的写 `@步骤名.json.version`。
- 值名应该用各语言都给出（如 `status` / `状态码`）。

### 13.4 流程目录

- 一种目录（`toc` 角色）：按目录的顺序一步步执行；条件不成立跳过；运行失败或期望不成立就停；遇到“等人确认”在运行后停下。
- “继续”：等确认的，记下确认人和时间再往下；失败的，重跑那一步。
- 不做循环、跳转、并行。

### 13.5 运行记录

每次执行一份：书、开始和结束时间、运行人；每一步的状态（完成、失败、跳过、等确认、已确认）、时间、用时、给它的值（密钥不记）、输出（文字最多 64 KB、表格最多 200 行）、数据、期望和条件的结果、确认人。可以导出成报告。

## 14. 书依赖的插件

- 书里的类型来自插件，读者要有这些插件才能完整使用一本书。
- **0.1 要补的**：`package.json` 应该增加 `plugins: [{ "id": "org.onedesk.exercise", "version": ">=0.1.0, <1.0.0" }]`，列出书里用到的全部类型的插件和版本范围；导入时缺的插件应该提示安装（以后从插件市场自动装）。OneDesk 现在的实现还没有写这个字段。
- 读者没有某个插件时，那些页应该显示成卡片（名字、类型），不应该丢失数据；有了插件后恢复正常。

## 16. 还没定的（以后的版本）

1. **书的服务器**：作者把书发布到服务器、读者付费后使用、更新的协议（文件格式就是 §9，不变）。
2. **插件市场**：插件的发布、安装、签名和版本（和 §14 配合）。
3. **多设备**：一个人在几台设备上使用同一本书的方法（先讨论，找到最好的方法再定）。
4. **排版和打印**：版面、分页、页眉页脚；导出 PDF、EPUB。
5. **导入现有的书**：EPUB、Word、图书馆的编目记录等，按角色拆分（每种来源一个导入插件）。
6. **更多业务账簿**：库存账本的角色已加进 §4.3（`book.md` §27–§28）；财务账簿、合同簿等以后照这个样子加。
