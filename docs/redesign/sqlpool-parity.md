# sqlpool 功能对照：OneDesk 的验收条件

状态：已由用户确认为验收条件（2026-11-15）。
依据：sqlpool 的代码和文档（`/Users/zhongpingxue/quizbuks/sqlpool`，以代码为准，文档已落后于代码）；`docs/redesign/kernel-design.md` 第 3 稿。

sqlpool 是 OneDesk 的前身。OneDesk 成功的验证条件是：**sqlpool 现有的全部功能，都能用插件在 OneDesk 上做出来，内核里不出现任何 SQL、数据库、ssh 的字样。**

本文件做三件事：列全 sqlpool 的功能；逐项说明在 OneDesk 里由哪个插件、靠内核的哪个机制实现；指出内核设计目前满足不了的地方。

## 1. 结论

- **内核和框架的骨架能满足。** sqlpool 的功能我列了 90 项：62 项用现有设计直接能做；27 项要靠内核补上 13 处中的某一处；1 项（MCP 服务）所依赖的部分还没有设计。没有一项需要改变骨架（进程、数据模型、写入管线、沙箱、版本绑定都不用动）。
- **需要补的 13 处**见第 4 节（编号 X1–X13）。都是“给已有机制加一种情况”，已经写进内核设计（D238–D246）。
- **有一项只有方向，没有设计**：给 Claude Desktop 用的 MCP 服务（第 3 节 K 组）。现有的进程结构能承载它，但“AI 接口”这一块还没设计，必须在阶段 6 之前补上。
- 之前的 `docs/design/sql-plugin.md` 只列了 17 项功能，不到实际的四分之一。它不能再作为验收依据，以本文件为准。

## 2. 拆成哪些插件

sqlpool 是一个整体的程序。搬到 OneDesk 上按“一类东西一个插件”拆开，互相通过依赖和导出配合：

| 插件 | 提供什么 | 依赖 |
|---|---|---|
| 数据源 | 数据源类型和数据源树；直连和经 ssh 两种连法；测试连接；只读执行（供别的插件调用）；备份到本机 | — |
| SQL | 保存的 SQL：类型、编辑页、`:name` 参数、运行、结果页签 | 数据源 |
| 查询目录 | 从文件夹读入的查询文件：同步、头部信息、占位符与映射、时间切片、检查、另存为保存的 SQL | 数据源、SQL |
| 表 | 映射里的表：表树、表页、按列取数、五种版本查询 | 数据源、查询目录（映射） |
| 服务器命令 | 经 ssh 在服务器上运行的命令 | — |
| 本机脚本 | 在这台电脑上运行的 bash 脚本，可导出为 .sh | — |
| AI | 分析结果、生成语句；资料索引；密钥和模型设置 | — |
| AI 接口（MCP） | 让外部的 AI 客户端只读地搜索、查看、运行 | 待设计 |

环境、收藏、标签、搜索、运行历史、保存的结果、标签页、结果区、设置页不是插件，是内核和外壳自带的。

## 4. 内核设计需要补的地方

每条都已写进 `kernel-design.md`，括号里是章节和决定编号。

| 编号 | 缺什么 | 为什么 sqlpool 需要 | 怎么补 |
|---|---|---|---|
| X1 | 外部程序只有“下载并校验”一种来源 | `ssh`、`docker`、`bash` 是系统里装好的；PostgreSQL 的连接程序是随插件一起发的 | 外部程序分三种来源：随插件包自带、下载、系统自带。系统自带的按名字声明，由内核在固定的几个位置找（不依赖终端的 PATH）（7.5，D238） |
| X2 | 表格结果只能经插件内存交给内核；导出由各插件自己做 | 几万行的结果、几 MB 的命令输出 | 输出可以是“一个数据文件的句柄”，由宿主直接读；对内置的表格和文字类型，导出 CSV、复制由框架统一提供（§8、9.5，D239） |
| X3 | 插件表单里的密码没有去处；密钥每次都读钥匙串 | 数据源的密码、AI 的 API 密钥是在表单里填的 | 表单的“密钥”字段由框架直接写进钥匙串，资源里只存名字，值不经过插件；内核在一次运行期间缓存读过的密钥（7.5、9.3，D240） |
| X4 | 参数类型没有“引用资源”；表单字段没有日期、时间、枚举 | 环境指定数据源；默认数据源；时间参数和枚举参数 | 参数类型加“资源引用”；表单字段加日期、时间（可带预设值）、枚举（§6.1、9.3，D241） |
| X5 | 结果区的按钮和页签只能由页面所属的插件声明 | “分析”按钮要出现在所有插件的结果上 | 插件可以对内置输出类型贡献结果区动作；用户点了，这一次运行的结果才交给它（9.5，D242） |
| X6 | 搜索只有“全部词都命中”的子串扫描 | 资料索引有几千篇文档；要按相关度挑文档 | 搜索从一开始就用全文索引（三字符分词，更短的词退回模糊匹配，与 sqlpool 相同）；给插件的查询加“命中任一词、按相关度排序、可限定类型”（§10，D243） |
| X7 | 没有跨资源的运行列表；保存的结果没有名字 | “最近运行”“保存的结果”两个面板 | 内核自带一棵“运行记录”树（全部、已保存两种筛选）；运行加名称字段（§5、§8，D244） |
| X8 | 不能打开“还没创建的资源”；打开标签页不能带初始内容；没有“先保存再运行” | 新建语句、从历史打开、保存并运行 | 打开目标加 `new:`；打开时可带初始页面状态；动作可声明“运行前先保存”（9.1、7.2，D245） |
| X9 | 插件不能往树的工具栏加按钮 | 表树的“一层/两层”切换 | 树的清单声明里可以带工具栏命令（§5，D245） |
| X10 | 文字节点只能整块一种颜色 | 终端样式的输出里 stderr 要另一种颜色 | 文字节点支持按行标色（9.3，D245） |
| X11 | “AI 接口”没有设计 | MCP 服务 | 单独设计，阶段 6 开始前完成。方向见下 |
| X12 | 页面框架没有右侧信息面板 | 每个编辑页右边的属性面板 | 页面框架加信息面板：名称、位置、说明、标签、创建和修改记录，由框架提供（9.3，D246） |
| X13 | 插件激活的条件里没有“工作区打开时” | 查询目录启动时同步 | 清单 `activation` 可以声明“工作区打开后”（7.2，D245） |

### X11 的方向（不是设计）

sqlpool 的 MCP 服务是一个独立的命令行程序，Claude Desktop 通过标准输入输出与它交谈，应用没开也能用。OneDesk 的进程结构可以这样承载它：

- 一个很小的命令行程序，Claude Desktop 启动它。应用开着时，它连到主进程，由主进程转给对应工作区的工作进程；应用没开时，它自己启动一个无界面的工作进程。两种情况下跑的都是同一个内核。
- 操作者类型是 `ai`。只能看到标记为“对 AI 可见”的资源，只能运行插件声明为“AI 可用”的动作，使用用户事先指定的环境，受 `ai.policy` 约束，每次调用进审计。这些位置内核设计里都留了。
- 还没定的：工具清单怎么从插件的声明生成；“对映射过的表运行任意 SELECT”这种自由度较大的工具如何声明和约束；一次只能接一个工作区还是多个。

## 5. 作为验收条件怎么用

1. 第 3 节的每一行是一个验收点。阶段 6 结束时逐行检查，结果只有三种：通过、不通过、按新需求改了行为（需写明改成了什么）。
2. 检查的方式是在真实运行的 OneDesk 里把这一行的事做一遍，而不是看测试是否通过。
3. 用同一份查询目录、同一个 PostgreSQL，在 sqlpool 和 OneDesk 里各跑一遍，结果的行必须相同。
4. 内核源码里搜索 `sql`、`postgres`、`ssh`、`docker`、`psql`，除了本文件名和注释外不得有命中（并入 `pnpm lint`）。
5. 做某一行时发现内核又缺东西，记入 decisions.md 并回到内核补，不在插件里绕过（D188 的规则）。
