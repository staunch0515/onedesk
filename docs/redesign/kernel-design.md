# OneDesk 内核设计

状态：待批准。批准前不写代码。
依据：`docs/requirements.md`、`docs/decisions.md`（D01–D207）、`docs/redesign/plan.md`。
范围：整体结构、内核（数据、写入、资源与树、参数、插件、运行、页面、搜索、协议）和插件接口的形状。外壳界面见 `docs/design/ui-spec.md`；各插件的设计在各自阶段补齐。

## 1. 设计原则

1. **内核不认识任何具体功能**。内核里只有机制：资源、树、参数、插件、运行、历史、权限、审计、页面。
2. **一个概念一种机制**（I.0c）。本设计中的合并：
   - 分组、环境、配置项都是资源，共用同一套树、历史、搜索、版本化。
   - 环境、工作区配置、插件设置共用同一套参数。
   - 动作执行、后台任务、导入、同步共用同一套“运行”。
   - 自定义视图节点和自定义标签页共用同一套“隔离界面”。
3. **每一次修改只有一个入口**。权限检查、历史、审计、事件在这个入口里一次完成，任何调用方都绕不过去。
4. **能力写在清单里，行为写在代码里**。内核只读清单就知道一个插件提供什么、需要什么。
5. **拒绝优先**。权限判断拿不准时拒绝；每一种拒绝都有测试（H 节）。

## 2. 进程与分层

```
┌─ 桌面应用（Tauri，一个）──────────────┐      ┌─ 浏览器（网页访问）─┐
│ 窗口 A：界面（React）                 │      │ 同一套界面代码       │
│ 窗口 B：界面（React）                 │      └──────────┬──────────┘
│ Rust 侧：只管窗口、启动内核进程、转发  │                 │ WebSocket
└──────┬──────────────────┬─────────────┘                 │
       │ 本机套接字        │                               │
┌──────▼───────┐   ┌──────▼───────┐                       │
│ 内核进程      │   │ 内核进程      │◄──────────────────────┘
│ 工作区“个人” │   │ 工作区“甲公司”│   每个进程：
│              │   │              │   · 内核库（Rust）
│ 插件沙箱 × N  │   │ 插件沙箱 × N  │   · 一个工作区数据库文件
└──────────────┘   └──────────────┘   · 每个已激活插件一个 JS 沙箱
```

- **内核库** `onedesk-kernel`（Rust，不依赖 Tauri）：全部内核逻辑。
- **内核进程** `onedesk-host`：为一个工作区运行内核库，对外提供协议。带窗口时由桌面应用启动；不带窗口单独运行就是“无界面服务器”（I.10d）。
- **桌面应用**：只负责窗口、菜单、系统对话框，以及把界面的请求转发给对应的内核进程。
- **界面**：只通过协议客户端工作，不知道对面是本机套接字还是 WebSocket（I.10c“界面代码共用”）。

一个工作区同一时间只被一个内核进程打开（锁文件）。再次打开同一工作区时，把已有窗口提到前面。“在当前窗口打开另一个工作区”= 窗口改连另一个内核进程；“新窗口打开”= 新窗口连新的内核进程（I.10）。

依赖方向：`界面 → 协议 → 内核进程 → 内核库 → 插件沙箱`。内核库不得出现任何插件的 id、类型名或逻辑（`pnpm lint` 检查，延续现有规则）。

## 3. 数据

### 3.1 目录

```
~/Library/Application Support/onedesk/
  app.db                       应用级：工作区列表、工作区模板、插件索引（只有这三样，D153）
  plugins/<插件id>/<版本>/      插件包（多版本并存，所有工作区共用，I.10）
  programs/<名称>/<版本>/       插件声明的外部程序（下载并校验后放这里）
  workspaces/<工作区id>/
    workspace.db               该工作区的全部数据
    blobs/                     大的运行结果、附件
    backups/                   启动快照，保留 7 份
    lock
```

现有的 `onedesk.db` 在第一次启动新版本时移到 `workspaces/default/workspace.db`，再按迁移文件升级（规则 6：只新增迁移，旧库升级有测试）。

### 3.2 工作区数据库的表

| 表 | 内容 | 说明 |
|---|---|---|
| `resources` | 所有节点：资源、分组、环境、配置项 | 见 3.3 |
| `revisions` | 每次修改一行：资源、序号、时间、操作者、操作、改前、改后、对应的 git 提交 | 修改历史与恢复的唯一来源 |
| `audit` | 审计记录，只追加 | 数据库触发器禁止修改和删除 |
| `runs`、`run_artifacts` | 运行记录及其附属内容（如 AI 分析） | 每个资源保留最近 200 次；“保存结果”的不清理 |
| `refs` | 资源之间的引用 | 保存时重建，用于显示失效引用 |
| `param_decls` | 每个资源声明了哪些参数 | 环境页据此自动列出参数（I.4“不需要手动增删”） |
| `resource_meta` | 收藏、最近使用时间、使用次数 | 属于本机，不进入版本化 |
| `plugin_storage` | 插件自己的键值存储 | 按插件隔离 |
| `ui_state` | 标签页、布局、展开状态、列宽 | 界面状态，不版本化、不同步（I.0b） |
| `secret_names` | 密钥名字 | 值只在钥匙串，账户名为 `<工作区id>/<名字>` |
| `outbox` | 待处理的后续工作（如待提交到 git 的修改） | 重启后不丢 |
| `meta` | 结构版本、工作区 id 和名称 | |

### 3.3 资源

```
id            稳定 id
kind          类型，写成 “插件id:类型名”（如 org.onedesk.link:link）；内核自带的写成 core:group 等
tree          所在的树
parent_id     父节点；空表示在树的根下
pos           同级中的顺序
name, description, tags, body(JSON)
visibility, ai_visible, origin(original/subscribed/copied), origin_ref
external_key  外部来源的唯一键（如文件路径）；同一类型内唯一，用于“重复导入只更新”
state         ok / missing（源头不存在）/ conflict（有冲突，只读）
rev           修改序号（乐观并发）
created_at, created_by, updated_at, updated_by     操作者见 4.1
deleted_at    删除只做标记：搜索和树里消失，历史保留，可恢复
```

与第一版的差别：`group` 字符串改为 `tree + parent_id + pos`；类型名带插件 id（上万个插件时不撞名，升级插件不改变已有资源的类型，I.6）；增加操作者、外部键、状态、软删除。

内核自带三种类型，它们是机制，不是功能：

- `core:group`：分组，只有名字，可以放任何节点。
- `core:env`：环境节点，body 是参数表。
- `core:config`：配置节点，body 是参数表。

## 4. 写入管线

所有修改——来自界面、插件、导入、git 拉取、AI——都变成一条**命令**，交给同一个入口：

```
execute(调用上下文, 命令)
  1. 确定操作者
  2. 权限：调用方有没有这项能力；当前环境的策略允不允许
  3. 校验：类型的字段定义、乐观并发、树的规则
  4. 一个数据库事务内：写数据 + 写 revisions + 写 audit + 写 outbox
  5. 提交后：发事件；更新搜索文本、引用、参数声明
```

第 4 步保证“改了数据却没有历史或审计”不可能发生。写入由一个专用线程串行执行；读取用独立的只读连接，不被写入阻塞。

### 4.1 操作者

```
{ type: user | core | plugin | ai | git | sync,
  id:   插件为发布版 id（org.x.sql@1.2.0）,
  source: manual | scheduled | ai }
```

对应 I.6（createdBy、updatedBy、调用来源）和 I.13（审计的操作者）。

### 4.2 历史与恢复

- 每条命令在 `revisions` 留下改前和改后的字段。恢复 = 一条新的命令，把字段写回去，所以恢复本身也在历史里（I.4）。
- 父环境改了某个参数后子环境标“已变化”：子环境覆盖一个参数时，记下它当时看到的父值的序号；父值的序号变大即为“已变化”。
- 开启 git 后（阶段 7）：版本化模块读 `outbox`，把纳入版本化的类型写成文件并提交，提交号写回 `revisions`。仓库里的外部改动作为操作者为 `git` 的命令进入同一条管线（D203）；两边都改过则把资源标为 `conflict`。git 不可用时 `outbox` 积压，恢复后补提交（I.9）。

### 4.3 审计

`audit` 的一行：序号、时间、操作者、操作类型、对象、改动摘要、结果（成功或失败及原因）。密钥和口令的值在进入管线之前就被替换成名字，所以不可能写进去。失败的命令也记一行。

## 5. 树

树是内核机制，也是插件的扩展点。一棵树由清单声明，有两种来源：

- **存储树**：节点就是 `resources` 表里 `tree` 等于这棵树的行。资源树、环境树、配置树、数据源树属于这种。移动、排序、重命名、删除都是内核命令。
- **提供树**：节点由插件的代码按需给出（`children(父节点)`）。文件树（内容来自硬盘）属于这种；插件树由内核自己从插件索引给出。

另外，一个类型可以声明“我的子节点由我提供”。SQL 节点下的“历史”、综合节点下的资源引用，都用它，不需要新机制。

节点交给界面时的形状（界面不认识类型，只画这些）：

```
{ key, label, icon, 可否展开, 状态(正常/停用/失效/冲突), 徽标,
  打开目标(见 §9), 右键项(命令 id 列表), 可否拖动, 接受哪些节点放入 }
```

- **拖拽**（I.0g）：是否可拖、能放到哪里写在类型的清单声明里，界面据此直接显示“可放/不可放”，不需要来回询问；放下后做什么由该类型所属的插件处理（存储树的默认处理是移动，由内核完成）。
- **右键**（D197）：右键项是命令，由节点所属类型的插件在清单里声明。
- **互不包含**（D163）：一个资源只属于一棵树；类型在清单里声明自己放在哪棵树里。
- **综合节点**（I.10f）：综合插件的类型，body 里是一组资源引用，子节点由插件提供。移除引用不动资源；引用的资源被删时显示为失效引用（§10）。

## 6. 参数、环境、配置

### 6.1 一套机制，三处使用

参数节点的 body：

```
{ description, params: { 名字: { type: text|number|boolean|list|secret, value, based_on? } } }
```

| 用处 | 存放 | 控制范围 |
|---|---|---|
| 环境 | 环境树的 `core:env` 节点 | 一个标签页 |
| 工作区配置 | 配置树的 `core:config` 节点 | 整个工作区 |
| 插件的启用、固定版本、设置项 | 每个插件一个参数节点，显示在插件页 | 该插件在本工作区 |

因为它们都是资源，历史、恢复、审计、版本化、同步都不用另做。

### 6.2 取值

`resolve(名字, 标签页)`：从该标签页选的环境节点开始，沿父链向上找，返回值和“来自哪一层”。找不到就返回“没有”，由插件决定怎么办（通常是让用户在表单里填，I.0f）。`secret` 类型只返回名字；值只有声明过该密钥的插件通过 `secrets` 能力才能拿到。

占位符的语法由插件定义（D182）。插件告诉内核“这个资源用到了哪些参数（名字、类型、说明）”，内核记进 `param_decls`，用来生成参数表单、悬停说明，以及在环境页自动列出参数。

### 6.3 策略：只能加严

保留前缀的参数由内核解释。每个策略参数在内核里登记一条合并规则：

| 种类 | 合并 | 例 |
|---|---|---|
| 禁止类开关 | 任何一层禁止即禁止 | `protection.readonly`、`protection.no_export` |
| 允许名单 | 各层取交集 | `network.allow` |
| 等级 | 取最严的一级 | `ai.policy` |
| 插件开关 | 工作区启用且各层都未停用才算启用 | `plugin.<id>.enabled` |

生效值 = 工作区配置 与 环境父链 逐层合并。子层写了更宽的值不报错但不生效，界面标出“被上层限制”。具体有哪些策略参数、界面如何提示，在阶段 1 开始时列全（I.12 把它列为待设计）。

## 7. 插件

### 7.1 包、身份、版本

- 包 = 一个文件夹：`manifest.json`、逻辑入口 `main.js`、可选的界面入口、语言文件、可选的外部程序声明。
- 稳定 id `org.example.sql`；发布版 id `org.example.sql@1.2.0`（I.6）。
- 包放在应用级的 `plugins/<id>/<版本>/`，多版本并存。`app.db` 里有全部清单的索引，启动时只读索引；插件搜索查的也是索引（上万个插件，I.6）。
- 每个工作区自己决定：启用与否、用哪个版本、是否固定（存在该插件的参数节点里，§6.1）。升级 = 切到新版本，旧版本保留，可切回；资源不受影响。
- 内置插件随应用发布，首次启动时装进同一个位置，之后与外部插件完全一样。
- 安装时显示清单里的全部权限，用户确认后才能启用（D158）。安装、启用、停用、升级、卸载都是命令，进审计。

### 7.2 清单（apiVersion "2"）

```
id, version, apiVersion, name, description, icon
main            逻辑入口
requires
  network       允许访问的主机
  secrets       要读取的密钥名
  files         是否需要文件能力（范围由用户在插件页授权）
  programs      外部程序：名称、版本、下载地址、校验值
  plugins       依赖：稳定 id + 版本范围
contributes     本插件提供什么（全部是声明，不含代码）
  kinds         类型：字段、所在的树、图标、默认动作、页面、拖拽规则、右键项、是否自供子节点
  actions       动作：标题、适用类型、输入、输出类型、快捷键
  pages         页面：操作区放哪些动作、结果区有哪些页签
  trees         树：名称、图标、存储树还是提供树
  outputs       结果区的输出类型
  nodes         自定义视图节点（见 §9.4）
  commands、menus   命令面板和“新建”下拉里的项
  locales       每种语言一份文字；语言插件另外提供外壳的文字
  settings      设置项（类型化参数的定义）
exports         允许依赖方使用的扩展点
```

清单里的名称、标题都写成文字的键，按当前语言取值，缺失回退英语（I.1）。清单严格校验：未知字段、格式错误、依赖不满足、id 重复都不加载，并在插件页给出原因（G.4）。

### 7.3 依赖与复用（I.0e）

B 依赖 A 并且 A 导出了某个扩展点时，B 可以：把自己的类型放进 A 的树；给 A 的类型加动作；用 A 的页面和输出类型；读 A 的类型的资源。没有导出的一律不可用。

### 7.4 沙箱

- 每个已激活的插件在内核进程里有一个独立的 JS 运行环境（QuickJS）。里面没有网络、没有文件、没有定时器以外的任何系统能力；唯一能做的是调用宿主 API。
- 内存有上限；执行可被中断（激活超时、动作取消、死循环）。一个插件崩溃或超时不影响内核和其他插件。
- 插件之间不共享内存，只能经宿主 API 互相调用（并受 7.3 约束）。
- **惰性激活**：启动时一个插件也不运行。第一次需要某个插件的代码时（运行它的动作、渲染它的页面、展开它提供的节点）才激活。只显示树和列表不需要激活任何插件，因为图标、名称、拖拽规则都在清单里。

需要技术验证的点：JS 引擎对 ES 模块、异步宿主函数、中断和内存上限的支持（阶段 0）。备选是纯 Rust 的 JS 引擎 Boa。

### 7.5 宿主 API

插件拿到的 `host` 对象。每个调用都进 §4 的管线或权限检查，操作者是该插件的发布版 id。

| 入口 | 作用 | 限制 |
|---|---|---|
| `resources` | 读、建、改、移动、删除资源 | 写：只限自己的类型；读：自己的和依赖导出的 |
| `params` | 按名字从当前标签页的环境取值 | 密钥类型只给名字 |
| `actions` | 调用动作 | 自己的和依赖导出的 |
| `runs` | 报告进度、读历史、附加内容（如 AI 分析） | 只限自己的资源的运行 |
| `storage` / `settings` | 插件自己的键值存储 / 读自己的设置 | 按插件隔离 |
| `secrets` | 按名字取密钥的值 | 只限清单声明的名字 |
| `network` | 发 HTTP 请求 | 清单白名单 ∩ 环境的 `network.allow`；每次调用进审计（I.10h） |
| `files` | 列目录、读信息、新建、改名、移动、复制、移到废纸篓、打开、在访达中显示、选择文件夹 | 只限用户在插件页授权的文件夹之内（D184）；路径先规范化再比较 |
| `process` | 运行清单声明的外部程序，流式读输出，可取消 | 只限声明过且校验通过的程序 |
| `events` | 订阅资源变化、运行结束 | 只收到自己能读的类型 |
| `ui` | 打开标签页、用系统浏览器打开、复制文字、通知 | 链接只允许 http、https、mailto |
| `i18n` | 取本插件当前语言的文字 | |

代码这一侧，插件只给清单里声明过的东西提供行为：

```ts
export default definePlugin({
  activate(host) {
    host.actions.handle("run", async (ctx, input) => { ... });          // 动作
    host.pages.handle("editor", { render(ctx) { ... } });               // 页面内容
    host.kinds.handle("sql", { parameters(res) {...}, validate(body) {...},
                               describe(res) {...}, children(node) {...}, drop(ev) {...} });
    host.trees.handle("files", { children(node) { ... } });             // 提供树
  },
});
```

给清单里没有的东西注册行为会被拒绝。

## 8. 运行

动作执行、后台任务（导入文件夹、同步、拉取）是同一种东西：**运行**。

```
runs: id, 资源, 动作, 标签页, 环境, 操作者, 来源, 开始/结束时间,
      状态(running/success/error/cancelled), 参数, 摘要(行数、消息), 错误, 输出, 是否保存
```

- 发起：`run.start(动作, 资源?, 输入, 标签页)` 立即返回运行 id；执行在后台，界面不卡（G.6、I.5）。
- 过程：插件用 `ctx.progress(...)` 报进度，内核把它作为事件推给界面（结果区和状态栏）。用户可以取消；插件被停用时它的运行自动取消。
- 结果：输出类型为 text、table、link、files、none，或插件提供的类型。内核校验输出与声明一致后存入 `runs`。大的输出存 `blobs/`，表格默认只存前 1,000 行（可调）。
- 历史：每个资源保留最近 200 次（I.5）。点历史 = 以这次运行为目标打开一个标签页（I.5“必须打开对应页面”）。“复用参数”= 用这次运行的参数再发起一次。
- 失败不抛到界面外：未知动作、插件停用、输入不合法、策略禁止、插件出错、输出类型不符，都是一条 `error` 状态的运行，原因留在结果区（I.0d）。
- 运行的开始和结束都写审计。

## 9. 页面、视图、标签页、结果区

### 9.1 打开目标

标签页只是某个目标的显示（I.0b）。目标是一个地址：

```
resource:<id>          资源、分组、环境、配置项
plugin:<稳定id>         插件页
run:<运行id>            某次运行
node:<树>/<节点key>     提供树里的节点（如一个文件夹）
page:<插件id>/<页面id>  独立页面（欢迎页、审计页）
```

内核负责把目标解析成：标题、图标、面包屑（在树中的路径）、用哪个页面、操作区有哪些动作、结果区有哪些页签。界面只管画。

### 9.2 标签页上下文

每个标签页在内核里有一份上下文：`{ 目标, 环境, 页面状态 }`，存在 `ui_state`。

- 环境是内核认识的唯一字段：动作在哪个标签页发起，就用哪个标签页的环境取参数、判策略。
- 页面状态是页面所属插件自己的一小块数据（例如 SQL 页当前选的数据源），内核只负责保存和恢复。
- 标签的开合、顺序、固定属于界面状态，同样存在 `ui_state`。

### 9.3 页面内容：视图树

页面内容由插件的 `render(ctx)` 返回视图树，内核校验后交给界面画。`ctx` 里有资源（含未保存的草稿）、页面状态、环境、最近一次运行、当前语言。

基础节点仍是四种：form、table、text、link（D207）。在此之上需要两点改动，否则 SQL 页面做不出来：

1. **字段可以绑定**。form 的字段可以写 `bind: "body.sql"`，表示它编辑的是资源的这个字段。草稿、未保存标记、⌘S 保存、关闭前询问都由框架统一处理，输入时不需要每个字符都问插件。字段类型里有代码/长文本，可以声明“占满剩余空间”（I.7）。
2. **节点可以发事件**。按钮、表格行等可以带一个事件名，触发时内核调用插件的 `onEvent`，插件改页面状态，内核重新 `render`。

操作区不属于视图树：它由清单里页面的声明给出（哪些动作、顺序），框架保证位置、样式和“最多四个，其余进更多”（I.0h）。

### 9.4 插件自带界面

基础节点画不出来的（播放器），插件在清单的 `nodes` 里声明一个自定义节点，并提供一个界面入口文件。宿主把它装进一个隔离的 iframe：没有宿主页面的访问权、不能直接联网，只能通过消息收数据、发事件；设计 token 由宿主注入，保证外观一致。

“插件提供的标签页类型”（D175）= 内容只有一个自定义节点的页面，不是另一种机制。此项在阶段 8 实现；接口位置现在就留好。

### 9.5 结果区

- 页签由页面的清单声明决定，默认是“结果”和“历史”。插件可以加页签（如“最终 SQL”“AI 分析”），每个页签是一个对某次运行的 `render`。
- “结果”页签按输出类型选择画法：内置五种类型由框架画；插件提供的输出类型由该插件给出视图树。
- 工具栏右端的收起、展开、清空，以及高度的拖动和记忆，由框架提供（I.0h）。

## 10. 搜索与引用

- **搜索**（I.5、I.10a）：只在本工作区内。多个词必须同时满足；短词也能搜到（子串匹配，对中文有效）；可按类型过滤；排序依次为：名称命中优先、收藏优先、最近使用优先。同一入口也搜命令和插件索引。第一版沿用子串扫描（1 万条实测 20–60 ms）；搜索做成一个可替换的模块，数据量上去后换索引不影响调用方。
- **引用**（I.10a）：保存资源时，内核从三处取引用写入 `refs`：类型为“引用”的字段、文字里的 `[[名称]]`、指向 `onedesk://resource/<id>` 的 Markdown 链接。目标不存在或已删除时，`refs` 里保留这一行，界面显示为失效引用，不静默消失。

## 11. 语言与错误

- 内核不含任何界面文字。错误是 `{ code, 键, 参数 }`；界面用当前语言的文字文件把它变成句子，缺失回退英语，不显示键名（I.1）。
- 外壳的文字由语言插件提供；功能插件自带自己的文字（D193）。内核只提供“按插件、按语言、按键取文字，带回退”的查表。
- 当前语言是工作区配置里的一个参数（D192），改了立即发事件，界面重画。

## 12. 协议

界面与内核之间只有一种协议，可以跑在本机套接字或 WebSocket 上：

- 请求/应答：`{ id, method, params }` → `{ id, result | error }`。
- 事件：界面订阅主题（某棵树、某个资源、某次运行、通知），内核推送。
- 方法按机制分组：`workspace.*`、`tree.*`、`resource.*`、`params.*`、`plugin.*`、`run.*`、`page.*`、`search.*`、`audit.*`、`secrets.*`、`ui.*`、`data.*`（导出导入）。
- 每个连接对应一个操作者。本机桌面窗口直接可信；WebSocket 连接在正式的网页访问里需要口令和加密（阶段 9），开发和测试阶段只监听本机并使用一次性令牌。
- 密钥的值只能写入，协议里没有读出密钥值的方法。
- 类型以 Rust 为准，TS 类型由它生成并入库；`pnpm check` 检查生成结果是否最新（H 节“生成的文件随源码重新生成”）。

## 13. 安全边界

| 边界 | 做法 |
|---|---|
| 插件 ↔ 内核 | 沙箱内无任何系统能力；宿主 API 每次调用都检查清单声明、依赖导出、环境策略 |
| 插件 ↔ 插件 | 独立运行环境；存储按插件隔离；只能用对方导出的扩展点 |
| 插件界面 ↔ 宿主页面 | 隔离的 iframe，只有消息通道 |
| 工作区 ↔ 工作区 | 不同进程、不同文件、钥匙串账户带工作区 id；内核没有任何跨工作区的接口 |
| 网络 | 清单白名单；重定向逐跳复查；环境可以再收紧 |
| 文件 | 只在授权文件夹内；路径规范化、解析符号链接后再判断；删除默认进废纸篓 |
| 外部程序 | 只运行清单声明的；下载后校验，不通过则插件不启用并说明原因（D188） |
| 密钥 | 只在钥匙串；数据库、清单、导出、审计、git、协议应答中都没有值 |
| 审计 | 与数据同一事务；触发器禁止改删 |

## 15. 测试

- **内核**（`cargo test`，只用内存库和临时目录）：管线（事务、历史、审计一致）、资源与树、参数取值与策略合并、清单校验、版本与依赖、搜索、引用、导出导入、迁移（含第一版旧库）。覆盖率 ≥ 80%。
- **沙箱**：每一种越权各一个“被拒绝”的测试：未声明的主机、授权文件夹之外的路径（含 `..` 和符号链接）、未声明的密钥、未导出的扩展点、未声明的外部程序、死循环、超内存。
- **协议**：契约测试，TS 客户端与 Rust 两侧对同一组样例。
- **性能**：1 万条搜索 < 200 ms；冷启动到看到树 < 2 s；1 万个清单时启动只读索引。
- **界面**：Playwright 用浏览器连真实内核进程；截图入库。另外每个阶段结束都真实启动桌面应用点一遍（H 节）。

## 16. 本设计不包含

- 界面的具体规格（已有 ui-spec.md 草案，阶段 4 开始前定稿）。
- 各插件的设计（SQL、硬盘文件已有草案，需按本设计修订）。
- git 的仓库文件格式、同步、网页访问正式版、家庭服务器、外部服务器、发布订阅、AI 接口（I.12 的待设计项）。本设计只保证它们需要的接入点存在：`outbox`、`conflict` 状态、操作者类型 `git`/`sync`/`ai`、协议的 WebSocket 传输、资源的 `origin` 和 `ai_visible`。
