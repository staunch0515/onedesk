## 1. 病历书写系统做什么（对照）

| 病历系统里的东西 | 它是什么 | 通用的说法 |
|---|---|---|
| 病历模板（入院记录模板、首次病程记录模板） | 科室维护的标准格式，写病历时从它开始 | **文书模板** |
| 一份病历（张三的入院记录） | 从模板生成，医生填写 | **文书** |
| 数据元 / 结构化元素（体温、血压、过敏史、诊断） | 文中的填写项，有类型、单位、取值范围、可选项 | **填写项** |
| 宏元素（姓名、性别、年龄、住院号、入院日期） | 自动带出，不用手填 | **环境里的值**（`{{名字}}`），已有 |
| 计算元素（BMI、体表面积、评分量表总分） | 由别的填写项算出 | **调用公式**，参数取本文的填写项 |
| 引用（首次病程记录引用入院记录的主诉、现病史；引用检验结果） | 从别的文书或数据里取内容 | **嵌入**（`![[…]]`），已有 |
| 常用语 / 知识库片段 | 插入一段标准文字，插入后可以再改 | **插入片段**（复制，不是引用） |
| 提交、上级审签、归档 | 写完锁定；改动要留痕、写理由 | **状态、签名、锁定、修订记录** |
| 质控（必填项、数值范围、时限：入院记录 24 小时内完成） | 检查文书是否完整、及时 | **检查规则** |
| 病历夹（病案首页、入院记录、病程记录、出院小结…） | 一个患者一次住院的全部文书，有固定顺序 | **档案**，就是 `embed-book.md` 里的“书” |
| 打印（固定版式、页眉页脚、续打） | 纸质归档 | **导出 / 打印**，以后做 |

## 2. 和 OneDesk 已有概念的对应

**患者就是环境。** 这一点很关键：
- 环境树：`科室 → 患者 → 本次住院`。环境参数就是宏：`姓名`、`性别`、`出生日期`、`住院号`、`入院时间`、`床号`。
- 环境会继承：科室的参数（科室名、主任）、患者的参数（姓名）、这次住院的参数（入院时间），下层都能取到。
- 打开一份文书时选“张三 · 第 2 次住院”环境，文中所有 `{{姓名}}` 等都会填上，而且只有这一处地方需要维护。

**文书就是资源，模板就是另一个资源**（规则 1、3）。档案就是书（D481 的设计）。

## 3. 需求

### 3.1 文书模板与文书

1. 文书模板是资源，正文里混着**自由文字**、**填写项**、**环境里的值**、**嵌入**、**计算**。
2. 从模板“新建文书”：复制模板的正文和结构，**之后模板再改，已经写好的文书不变**（和嵌入的“活引用”相反，见 3.5）。
3. 文书记着它来自哪个模板、哪个版本，模板的信息面板里能看到用它写了多少份。
4. 模板可以在模板里嵌入公共段落（比如各科都用的“体格检查”段落），用的是 `![[…]]`。

### 3.2 填写项（结构化数据）

1. 填写项写在正文里，有名字、类型、单位、取值范围、可选项、是否必填、默认值。
2. 类型：文字、数字、日期、时间、单选、多选、是非、长文字。
3. **编辑时**：填写项在正文里显示成输入控件（数字框、下拉、日期），其余是普通文字，像填一张有说明的表。
4. **阅读时**：只显示填好的值；没填的显示成灰色的“未填”。
5. 填写项的值**存成结构化数据**（名字 → 值），不只是文字：可以被检查、被计算、被别的文书引用（比如出院小结引用入院时的“体重”）、被搜索、被 AI 读取。
6. 填写项可以引用环境的值作默认值：`默认={{体重}}`。

### 3.3 计算

1. 文中可以调用公式：`[[=BMI | 体重=@体重, 身高=@身高]]`，`@名字` 是**本文**的填写项。
2. 填写项一变，计算结果马上跟着变（编辑时也是）。
3. 公式就是 `embed-book.md` §20 设计的公式资源，不另做一套。
4. 评分量表（几个单选项的分数相加）也是一个公式：参数是各项的分数。

### 3.4 插入片段（常用语）

1. 片段是资源（一段文字，可以带填写项）。
2. 在编辑时插入，是**复制一份**进来，插入后可以随意改，和原片段再无关系。
3. 和“嵌入”是两回事：嵌入是活的、不能在原地改；片段是一次性的、可以改。两者在输入 `[[` 后的候选列表里分开显示：“引用”和“插入”。

### 3.5 状态、签名与锁定（这类系统的核心）

1. 文书有状态：**草稿 → 已提交 → 已签名（锁定）**，另外还有**作废**。
2. **签名**：记录签名人、时间。签名后不能直接修改。
   - 签名人第一版就是当前用户，记在审计里；
   - 真正的电子签名（证书、手写板）以后再说。
3. **签名时冻结引用**：
   - 签名的那一刻，文中所有嵌入、计算、环境里的值都**取一次快照**存进文书；
   - 之后被引用的原文改了、环境改了，已签名的文书显示的仍是签名时的内容。法律文书必须这样。
   - 草稿阶段仍是活的。
4. **修订**：已签名的文书要改，必须点“修订”，写修订理由。
   - 生成一个新的修订版，旧版保留只读，修订记录里能看到谁、何时、为什么、改了什么。
   - 修订完再次签名。
5. **多级签名**（可选）：比如“书写 → 上级审签”，每一级签过才算完成。级数和名称在模板里定。

### 3.6 检查（质控）

1. **必填**：必填的填写项没填，不能提交，并指出缺哪几项。
2. **范围**：数字超出范围标黄提醒（比如体温 45 ℃），不阻止，由人确认。
3. **时限**：
   - 模板里可以写“在环境参数 `入院时间` 之后 24 小时内完成”；
   - 到期未签名的文书出现在一个“待办/超时”列表里。
4. 检查规则写在模板里，文书继承。

### 3.7 档案（书）

1. 档案是 `embed-book.md` 里的“书”：一次住院一个档案，下面按固定顺序放各份文书；文集可以是“一个患者的历次住院”。
2. 档案页有目录，能连续阅读、导出。
3. **病程记录这种“同一模板写很多份、按时间排”的**：
   - 档案里可以放一个“系列”，点“新增一份”就按模板生成；
   - 按填写项里的时间排序，连续阅读时连成一篇。

### 3.8 图片与附件

1. 文书里可以贴图（伤口照片、心电图截图），走 `embed-book.md` §15 的附件设计。
2. 签名后，附件和正文一起锁定。

### 3.9 AI

1. AI 对话可以帮着写某一段，比如“根据填写项写一段现病史”。它读得到填写项的值和环境里的值，结果仍要“应用”后才进文书（D479）。
2. 已签名的文书，AI 只能读，不能应用修改。

## 4. 不做的（至少第一版）

- 和医院 HIS、LIS、PACS 等外部系统对接（以后可以由插件通过网络或数据库做）。
- 医学术语库、ICD 编码库（可以作为一份资源导入，由选择项引用；第一版不内置）。
- 真正的 CA 电子签名、手写签名板。
- 打印版式设计器、续打。
- 多人同时编辑同一份文书。

## 5. 分层：哪些归内核，哪些归插件

| 能力 | 内核（通用，不认识“病历”） | 插件 |
|---|---|---|
| 填写项 | 视图节点增加“文中的输入控件”，值存成结构化数据，检查必填和范围 | “文书”插件解析填写项的写法，画编辑和阅读两种视图 |
| 模板 → 文书 | “从资源新建”时复制正文和结构，记下来源和版本 | 文书插件提供“新建文书”的入口 |
| 计算 | 带参数的引用（D482 §20）；参数可以是本文的填写项 | 公式插件 |
| 片段 | 候选列表区分“引用”和“插入” | 任何类型的资源都可以被当作片段插入（取它的正文） |
| 状态、签名、锁定 | **通用的“锁定”**：锁定后的资源只读，只能“修订”生成新版；签名记录进审计 | 文书插件定义状态流转和签名级数 |
| 冻结引用 | 锁定时把嵌入和计算结果的快照存进资源；锁定的资源按快照显示 | 不用管 |
| 检查 | 必填、范围由内核在提交时检查；时限的待办列表是外壳的一个通用视图 | 文书插件把模板里的规则交给内核 |
| 档案 | 一次读取一棵子树 | 书插件 |

## 7. 建议的先后顺序

| 步 | 内容 | 为什么先做 |
|---|---|---|
| ① | **填写项 + 文书模板 → 文书** | 结构化文书的基础；没有它就只是普通笔记 |
| ② | **带参数的引用和公式**（§20，参数可取 `@填写项`） | 计算元素依赖填写项 |
| ③ | **状态、签名、锁定、冻结引用、修订** | 这类系统最核心的“法律效力”部分 |
| ④ | **检查**（必填、范围、时限待办） | 依赖填写项和状态 |
| ⑤ | **档案（书）和系列** | 把文书组织起来 |
| ⑥ | **图片与附件** | 独立，可以随时插进来 |
| ⑦ | 片段插入、AI 帮写 | 锦上添花 |

每一步都先写详细设计给你确认，再开发。

# 插件划分设计（D484，待确认）

## 9. 原则

1. **内核只加通用能力**：每项能力都至少有两个插件会用，而且不认识“病历”“公式”“书”。
2. **插件之间不直接调用**：一律通过内核的通用机制配合，比如嵌入、带参数的引用、附件、锁定。这样哪个插件没装，别的照常工作，只是那一块显示成卡片。
3. **每个插件一件事**：图片只管图片，公式只管计算，书只管装订，文书只管填写和签名。
4. **先做能单独用起来的**：图片和书不依赖文书，先做出来就能用。

## 10. 内核要补的通用能力

| 编号 | 能力 | 说明 | 谁用 |
|---|---|---|---|
| K1 | **附件** | 每个资源可以带文件，按内容哈希存在工作区 `blobs/`；`host.attachments.add/list/remove`；导出导入带上；换掉的旧文件留到资源彻底清除，修改历史可以恢复 | 图片、笔记（贴图）、文书（附图）、书（导出） |
| K2 | **图片视图节点** | `{ type: "image", resource?, attachment, alt?, width? }`；界面通过 `attachment.read` 取文件内容，不经过插件 | 图片、笔记、文书、书 |
| K3 | **带参数的引用** | `![[x \| a=1]]`、`[[=x \| a=1]]`；`embed(ctx, { section, args, inline })`；参数可以取环境的值（`{{名字}}`），也可以取**本文的填写项**（`@名字`，由显示它的页面交给内核）；结果缓存 | 公式、文书（计算元素）、SQL（带参数的结果表） |
| K4 | **文中的填写项** | 新视图节点 `flow`：一段 Markdown 加上其中的输入控件（`{{?名字}}` 的位置），控件和表单字段一样绑定到 `body.<…>`，值存成结构化数据；内核按字段声明检查必填和范围 | 文书；以后任何“带说明的表”都能用 |
| K5 | **从资源新建** | `new:<kind>?from=<id>`：复制那个资源的正文，记下来源和版本（资源的 `origin`）；来源的信息面板里能看到“用它新建了 N 份” | 文书（从模板写）；书的“系列”（新增一份）；以后任何“复制一份再改”的场景 |
| K6 | **锁定与修订** | 资源可以被锁定：只读，记录锁定人和时间（审计）；锁定时把嵌入、带参数引用的结果、环境的值**取快照**存进资源，之后按快照显示；要改只能“修订”：写理由、生成新的修订版，旧版只读保留 | 文书（签名）；以后合同、报告等任何需要定稿的内容 |
| K7 | **读取一棵子树** | `host.resources.tree(id, { depth, offset, limit })`：按树上的顺序一次读出下面的结构（不含正文），可以分批 | 书（目录、连续阅读、导出）；文书（档案里的系列） |
| K8 | **插入片段** | 候选列表里分开“引用”和“插入”；插入时取那个资源的嵌入内容（文字），复制进正文。只是外壳的功能 | 任何资源都可以当片段 |

已经有的、直接用的：嵌入（D481）、精确引用（D482）、环境和模板、AI 对话（D479、D480）、事件（`host.events`）、插件存储。

## 11. 插件

### 11.1 图片 `org.onedesk.image`（内置）

| 项 | 内容 |
|---|---|
| 类型 | **图片**：放在资源树，可以拖动，声明 `embed` |
| 新建 | 选文件（系统对话框，只收 png/jpeg/gif/webp），或把图片拖进窗口、粘贴截图 |
| 页面 | 图片本身，下面一行显示尺寸、大小、格式；说明写在信息面板 |
| 被引用 | `![[电路图]]` 显示图片；`![[电路图 \| 宽=小]]` 指定大小（小/中/大/原始）；行内 `[[=电路图]]` 只显示名字 |
| 操作 | 替换图片（进历史，可恢复）、在 Finder 中显示（导出一份到授权文件夹） |
| 依赖 | K1、K2 |
| 给 AI | 只给说明文字，不发图片 |

**笔记贴图**（改笔记插件，不另做插件）：
- 在笔记里粘贴截图，存成这篇笔记的附件，并插入 `![截图](附件:截图-1.png)`；
- 阅读时显示，用的是 K2；外部地址的图片照旧不加载。

### 11.2 书 `org.onedesk.book`（内置）

| 项 | 内容 |
|---|---|
| 类型 | **书**：接受任何子节点，树上的结构就是书的结构；书里的书是子书（文集） |
| | **系列**：书里的一个节点，下面是同一个模板写的很多份，比如病程记录；点“新增一份”按模板新建（K5），按某个填写项的值或创建时间排序 |
| 页面 | 左边目录（可点），右边连续正文，滚动加载；正文里每一节的标题旁有“打开” |
| 编号 | 书的设置里定层级名称（默认“编、章、节”，子书称“册”，或数字 1.1.1）；编号在阅读和导出时生成，不写进内容 |
| 被引用 | `![[鲁迅全集]]` 显示目录（书名、各册各章）；`![[某书#第三章]]` 嵌入那一章的连续正文 |
| 导出 | 整本或某一册，导出成一个 Markdown 文件，带目录、编号，嵌入已展开、图片作为附件文件一起导出到授权文件夹；PDF 以后 |
| 依赖 | K7、嵌入；导出图片用 K1 |
| 给 AI | 把书或某一章拖进对话当资料：发送展开后的全文，有长度上限 |

### 11.3 公式 `org.onedesk.formula`（内置）

| 项 | 内容 |
|---|---|
| 类型 | **公式**：`名字 = 表达式` 一行或几行；参数从公式里认出；每个参数可以填说明、单位、默认值 |
| 页面 | 公式、结果单位和小数位、参数表、试算 |
| 被引用 | 块 `![[BMI \| 体重=70, 身高=1.75]]`；行内 `[[=BMI \| 体重=@体重, 身高=@身高]]`（`@` 取本文的填写项，K3） |
| 评分量表 | 也是一个公式：`总分 = 意识 + 呼吸 + 循环 + …`，每项的分数来自单选填写项的值 |
| 计算 | 插件自己解析，不执行代码（§20.5 的规则不变） |
| 依赖 | K3 |

即 `embed-book.md` §20 的设计，补上“参数可以取 `@填写项`”。

### 11.4 文书 `org.onedesk.document`（外置，经插件市场安装）

| 项 | 内容 |
|---|---|
| 类型 | **文书模板**：正文（Markdown）里写填写项 `{{?体温 \| 数字, ℃, 35~42, 必填}}`、环境的值 `{{姓名}}`、嵌入、计算；另有：签名级数（如“书写、审签”）、时限规则（如“`入院时间` 后 24 小时”） |

## 16. 第①步“图片”的详细设计（K1、K2、图片插件、笔记贴图；待确认）

### 16.1 和 §10 的一处调整：附件按内容存，由字段引用

写详细设计时发现：图片常常在资源**还没保存**时就要放进去（新建图片时选文件、在未保存的笔记里粘贴截图）。如果附件挂在“资源 id”下，就得先保存才能贴图，不符合“新建未保存时一切照常”（规则 1）。所以改成：

- **文件按内容存**：上传一个文件，得到它的内容哈希（SHA-256，下称“文件号”），文件存在工作区 `blobs/` 里。同样的文件只存一份。
- **资源用字段引用文件号**，就像引用另一个资源一样。保存时内核记下“这个资源用到了这个文件”。
- **没有任何资源用到的文件**：上传后 24 小时内没有被保存进任何资源，就删掉（比如贴了图又没保存）。
- **用过的文件**：只要资源还在（包括它的修改历史），文件就留着，所以历史可以恢复；资源彻底清除后，再没有别处用到时删掉。

§10 的 K1 因此改为“**按内容存的文件 + 附件字段**”，能力不变。

### 16.2 内核（K1）

**存储**：
- 文件放在 `<工作区>/blobs/<前两位>/<文件号>`。
- 新迁移 `0016_blobs.sql`（只新增，附升级测试，规则 6）：
  - `blobs(hash, type, size, width, height, created_at)`；
  - `blob_uses(resource_id, hash)`：记录哪个资源（含它的任何历史版本）用到了哪个文件。只增不减，资源彻底清除时一起删。

**收什么**：
- 只收 png、jpeg、gif、webp，**按文件开头的字节判断**，不看扩展名；
- svg 可能带脚本，第一版不收；
- 单个最大 20 MB；一个资源最多引用 200 个文件；
- 宽高由内核从文件头读出（不解码整张图）。

**资源怎么引用文件**：
1. **附件字段**：清单里类型的字段可以声明 `{ "type": "attachment", "accept": ["image"] }`。值是 `{ "blob": 文件号, "name", "type", "size", "width", "height" }`。保存时内核检查文件号存在、类型符合，并记进 `blob_uses`。
2. **正文里的图片**：声明了 `refs: true` 的文本字段里，写 `![说明](blob:文件号)` 就是引用这个文件。保存时内核同样记下。外部地址的图片照旧不加载。

**协议**（只有用户和界面能调用，插件不能上传）：
| 方法 | 用途 |
|---|---|
| `blob.put { data }` | 上传一份内容（base64），用于粘贴、拖入。返回 `{ blob, type, size, width, height }` |
| `blob.put { path }` | 上传用户在系统对话框里选的文件。用户自己选的就算同意，和授权文件夹（D184）同理 |
| `blob.read { blob, resource? }` | 取一个文件给界面显示，返回 `{ type, data }`。只给两种：`resource` 现在或历史上用到它的；本客户端刚上传、还没保存的 |

**导出和导入**：导出工作区时，所有被用到的文件写进导出文件夹的 `blobs/`；导入时一起带回，文件号不变。

**给插件**：
- `ctx.resource` 里附件字段的值照常可以读，里面有文件号、类型、大小、宽高；
- 插件读不到文件内容，也不需要读：显示交给图片节点。

### 16.3 内核（K2）：图片视图节点

```js
{ type: "image", id, blob: "文件号", alt?: "说明", width?: "small" | "medium" | "large" | "original" }
```

- 内核检查：这个文件号是这个页面的资源（或这个嵌入视图的资源）用到的，否则 `pluginError/badOutput`。
- 宽度只有四档，不写像素（规则 3）：小、中、大是设计系统里定好的宽度，原始是图片本身的大小但不超过页面宽度。
- 界面用 `blob.read` 取内容显示，带缓存。图片可以点开看大图，按 Esc 关闭。

### 16.4 界面

1. **附件字段的控件**（`FieldKind::Attachment`）：
   - 一个放图片的区域：没有图片时显示“拖入图片、粘贴，或选择文件”；
   - 有图片时显示缩略图和文件信息，可以“替换”“移除”；
   - “选择文件”打开系统对话框（桌面版新增 `pick_image_file`，只列 png/jpeg/gif/webp；浏览器演示版填路径）。
2. **笔记里贴图**：
   - 在声明了 `refs: true` 的编辑框里粘贴图片，或把图片文件拖进去：上传后在光标处插入 `![图片](blob:文件号)`；
   - 说明可以改成自己的文字。
3. **Markdown 显示图片**：`![说明](blob:文件号)` 显示成图片（用 `blob.read`），宽度为“中”，可以点开看大图；其他地址的图片照旧只显示说明文字。
4. **新组件**（设计系统）：`ImageView`（显示、四档宽度、点开看大图）、`ImageDrop`（放图片的区域）。

### 16.5 图片插件 `org.onedesk.image`（内置）

**清单**：
```json
{
  "id": "image", "label": "kind.image", "icon": "image", "tree": "resources", "page": "image",
  "newName": "kind.image.new", "draggable": true, "embed": true,
  "defaults": { "image": null },
  "fields": { "image": { "type": "attachment", "accept": ["image"] } }
}
```
- 菜单“新建”里有“图片”。

**页面**：
- 一个附件字段（§16.4 第 1 条）。保存前也能选、能贴、能看。
- 已经有图片时，下面显示一行：`1920 × 1080 · PNG · 1.2 MB`。
- 说明写在信息面板里。

**被引用**（`embed`）：

| 写法 | 显示 |
|---|---|
| `![[电路图]]` | 图片（宽度“中”），下面一行说明（资源的说明） |
| `![[电路图 \| 宽=小]]` | 指定宽度；`宽` 可以是 小、中、大、原始（英文界面也接受 small、medium、large、original） |
| `[[电路图]]` | 普通链接 |

**AI**：只读得到名称、说明和图片信息（尺寸、格式），不发图片内容。

### 16.6 笔记插件的改动

## 17. 第①步“图片”的实际做法

与 §16 的不同和补充：

- **上传的那一行进写入管线**：文件先写到 `blobs/`，再由管线命令 `BlobPut` 记下这一行（并清掉一天前上传、没人用的文件），审计里只记类型和大小。
- **谁能读**：
  - 内核在保存时记下资源用到的文件，`blob.read` 只给这些资源；
  - 刚上传还没保存的，只给上传它的那个客户端。
  - 界面里每个页面、每个嵌入块都说明自己是哪个资源（`BlobScope`），图片按那个资源去读。
- **导入**：导出里的 `blobs/` 先导入（内容和文件名对不上的跳过），之后导入的资源记下它们用到的文件。
- **宽度**：小、中、大是设计系统里的三个宽度（240、480、720，`tokens.css`），原始宽度不超过页面；看大图最高到窗口的 75%。
- **Markdown 里的图片**：`![说明](blob:文件号)` 先显示说明文字，读到文件后换成图片（中等宽度），点击看大图。其他地址照旧不加载。
- **贴图**：在声明了 `refs: true` 的编辑框里（笔记正文等）粘贴或拖入图片，上传后在光标处写入 `![Image](blob:…)`（中文界面是“图片”）。
- **选择文件**：桌面版新增系统对话框 `pick_image_file`；浏览器演示版没有这个按钮，只能拖入或粘贴。
- **图片插件**（`org.onedesk.image`，内置）：
  - 页面只有一个附件字段；
  - 被嵌入时显示图片（宽度“中”）和资源的说明。`宽` 参数的处理已经写好（小、中、大、原始，英文也行），等第③步带参数的引用生效后起作用。
- **测试**：
  - 内核：`crates/kernel/src/blobs.rs`（类型判断、宽高、base64、正文里的 `blob:`）、`crates/kernel/tests/images.rs`（按内容存、只收图片、超大拒绝、选择的文件、审计不含内容、谁能读、附件字段必须是已存的文件、页面的图片节点、历史里的旧图、清除、一天后清掉没人用的、导出导入）、`manifest.rs`（附件字段的声明规则）、迁移 0016 的升级测试；
  - 插件：`plugins/org.onedesk.image/main.test.ts`；
  - 外壳：`src/design/components/image-view.test.tsx`；
  - 界面（真内核，从“新建”开始）：`e2e/images.spec.ts`。新建图片，保存前拖入，看到预览和尺寸；保存后重新打开仍在，点开看大图；替换后旧图仍能从历史读到；新建笔记，粘贴截图，阅读时显示；`![[Circuit]]` 嵌入图片。

### 18.1 这一步做什么、不做什么

| 做 | 不做（放到后面） |
|---|---|
| 书和文集：树上的结构就是书的结构；书里的书是子书 | **系列**（同一模板写的很多份）：要等第④步“从资源新建”（K5），和文书一起做 |
| 书的页面：目录 + 连续正文，滚动加载 | 交叉引用编号（“见图 2-1”） |
| 编号：层级名称可以设，子书重新编号 | 导出 PDF、Word、EPUB |
| 被嵌入：整本显示目录，`#章名` 嵌入那一章的正文 | 在书的页面里直接编辑正文（点“打开”去原资源编辑） |
| 导出成一个 Markdown 文件，图片一起导出 | AI 读整本书的全文（第一版只给目录，见 §18.8） |

### 18.2 例子

```
资源树
└─ 📖 鲁迅全集                 ← 书（文集）
    ├─ 📖 呐喊                  ← 书（子书，“第一册”）
    │   ├─ 📝 自序
    │   ├─ 📝 狂人日记
    │   └─ 📝 孔乙己
    └─ 📖 杂文集                ← 书（“第二册”）
        ├─ 📁 坟                 ← 分组 = 第一编
        │   ├─ 📝 灯下漫笔        ← 笔记 = 第一章
        │   └─ 🖼️ 插图一          ← 图片 = 第二章（显示图片）
        └─ 📁 热风               ← 第二编
            └─ …
```

### 18.3 内核（K7）：读取一棵子树、读取别人的内容

插件现在只能一层一层地读自己的资源，书却要读任何类型的子节点和它们的内容。新增两个宿主接口：

| 接口 | 返回 | 说明 |
|---|---|---|
| `host.resources.tree(id, { offset?, limit? })` | 按树上的顺序（先上后下、先父后子）把 `id` 下面的全部资源列出来：`[{ id, name, kind, kindLabel, icon, depth, parent }]`，加上 `next` | 一次最多 2000 个，`next` 接着读；不含正文 |
| `host.resources.embed(id, { section?, args? })` | 和界面的 `resource.embed` 一样：那个资源的嵌入视图（文字、表格、链接、图片节点） | 用的是显示它的标签页的环境；导出时用 |

- **权限**：两者都需要清单里新的 `requires.contents: true`，在安装时作为一项权限列给用户看，叫“读取其他资源的内容”。只有 `requires.resources` 的插件读不到。
- **只读**：两者都不能写；在 AI 运行里也可以用，但只给 AI 可见的资源。
- **导出图片**：新增 `host.files.writeBlob(blob, path)`，把一个存着的文件写到授权文件夹里（要 `requires.files`）。文件号必须是某个资源用到的，插件拿不到不该看的文件。

### 18.4 新的视图节点 `sequence`：连续正文

书的正文可能有几千节，不能一次画出来，也不能都塞进插件的返回值里。所以由插件给出**清单**，外壳负责按需加载、显示：

```js
{ type: "sequence", id, toc?: true, items: [
  { key, title: "第一章 灯下漫笔", level: 2, resource?: "资源 id", number?: "第一章", book?: true }
] }
```

- `title`：这一项的标题（插件已经加好编号）。`level`：层级，从 1 开始，决定标题大小和目录缩进。
- `resource`：有正文的项（笔记、图片、任何资源），外壳显示它的**嵌入视图**（和 `![[…]]` 一样，D481）；没有的项（分组、子书的书名）只显示标题。
- `book: true`：子书的书名页，标题更大，前面空一段。
- `toc: true`：外壳在左边画目录（可以折叠）。点目录，正文滚到那里；正文滚动时，目录标出当前位置。
- 外壳**只加载看得见的部分**（加上前后各几项），一节一节地请求 `resource.embed`。
- 嵌入正文里的 Markdown 标题会**下移**到这一项的层级之下：比如第 2 层的笔记里的 `#`，按第 3 层显示，最多到第 6 层。
- 内核检查：最多 20000 项；`resource` 必须是存在、可以引用的资源；`level` 是 1–9。
- 每一节标题旁有“打开”，在新标签页里打开那个资源去编辑。

### 18.5 书插件 `org.onedesk.book`（内置）

**清单**：
```json
{ "id": "book", "label": "kind.book", "icon": "book-open", "tree": "resources", "page": "book",
  "newName": "kind.book.new", "draggable": true, "accepts": ["*"], "embed": true,
  "defaults": { "levels": "编,章,节", "subName": "册", "numbering": "chinese" } }
```
- `requires`：`resources`、`contents`、`files`（导出用）。
- 菜单“新建”里有“书”。

**页面**：
```
┌ 鲁迅全集 ─────────────────── [环境 ▾] │ 保存  导出  ┐
│ 编号 [中文 ▾]  层级名称 [编,章,节]  子书称 [册]         │
│ ┌ 目录 ──────────┐ ┌ 正文 ─────────────────────────┐ │
│ │ 第一册 呐喊     │ │ 第一册  呐喊                    │ │
│ │   自序         │ │ 自序                    [打开]  │ │
│ │   狂人日记     │ │ （自序的内容）                  │ │
│ │ 第二册 杂文集   │ │ 狂人日记                [打开]  │ │
│ │   第一编 坟    │ │ …                               │ │
│ └───────────────┘ └────────────────────────────────┘ │
└──────────────────────────────────────────────────────┘
```
- 上面一行是书的设置（保存在书的资源里）。
- 下面是一个 `sequence` 节点（带目录）。
- 书里还没有东西时，显示“把章节拖到树里的这本书下面”。

**编号**（`numbering`）：

| 值 | 分组、子书、普通资源的标题 |
|---|---|
| `chinese`（默认） | 按层级名称：第一层“第一编”，第二层“第一章”，第三层“第一节”；更深的用“1.2.3”；子书“第一册” |
| `arabic` | “1”“1.1”“1.1.1”；子书“1” |
| `none` | 只用名称 |

- 编号由插件在画页面和导出时算出，**不写进任何资源**，所以在树上调整顺序后，编号自动跟着变。
- 子书从头编号，它自己的设置（层级名称等）对它下面生效；没设的用上一级书的。
- 层级是从书往下数的深度：书下面直接的分组或笔记是第一层。

**被嵌入**（`embed`）：

| 写法 | 显示 |
|---|---|
| `![[鲁迅全集]]` | 目录（带编号的列表，每项可以点开） |
| `![[鲁迅全集#灯下漫笔]]` | 那一项（以及它下面的全部）的连续正文，用 `sequence` 节点（不带目录） |
| `![[鲁迅全集 \| 层=2]]` | 只列到第 2 层的目录（带参数的引用在第③步生效） |

**导出**（操作栏“导出”，一次运行）：
- 先选导出到哪个授权文件夹（选择框，列出文件插件里授权过的文件夹），文件名默认是书名。
- 写出 `书名.md`：书名、目录、带编号的标题、各节的正文（嵌入展开成文字；表格写成 Markdown 表格）。
- 用到的图片写进同一文件夹的 `书名-图片/`，正文里的图片改成相对路径。
- 已经有同名文件时，问是否替换。
- 运行结果给出文件位置，可以“在 Finder 中显示”。

### 18.11 因为课本（§19）补的地方

书本身不认识“题”，下面这几条都是通用的：

1. **书里的嵌入可以交互**：书的正文里嵌了一道题或一个测验时，显示的是可以作答的样子（内核 K11，§21.2）。这样学生在书上直接做题，不用另外打开。
2. **书可以是只读副本**（K9，§21.2）：学生那里的书和它下面的一切都只读。页面照常显示，“打开”打开的也是只读的资源。编号、目录、导出照常工作。
3. **导出分两种**：
   - **学生版**：密封的内容（答案、讲解）不导出；
   - **教师版**：只有作者自己的工作区能导出，密封的内容放在每个测验后面，或者集中放在书末（导出时选）。
4. **书不加和题有关的设置**：“答案什么时候给”等都放在测验里（§19.4），测验没设时用练习插件的默认值。书只管装订。

# 课本与测验（D485，待确认）

> 用户 2026-11-25：书可以是一本课本，里面有学习内容，也有试题；学生直接在书上做题，书能给出正确答案。以小学数学练习为例想清楚。
> 用户定的几条：
> - 答案在答题前**不能**被学生看到；
> - 书以后**通过网络**发给学生，学生的工作区里有书的**只读副本**；
> - 答完题就可以给答案，**什么时候给在写书时定**；
> - 现在只有一台电脑：老师和学生**各用一个工作区**；老师改课本不影响学生答题；**答案放在老师的课本里，老师觉得需要时再公布**（第二轮，同日）；
> - **记录成绩和错题**；
> - **每次测验、每道题都是资源**。

## 19. 需求

### 19.1 谁做什么

| 角色 | 在哪里 | 做什么 |
|---|---|---|
| **作者**（写课本的人、老师） | 自己的工作区 | 写讲解（笔记）、出题、编测验，组织成书；发布给学生；以后出新版 |
| **学生** | 自己的工作区，里面有书的只读副本 | 读书，在书上做题；交卷后看对错、答案、讲解；看自己的成绩和错题，错题再练 |
| **老师收作业**（以后） | 老师的工作区 | 收到学生交回的作答，看全班成绩、批改主观题 |

### 19.2 题型（以小学数学为例）

| 题型 | 例子 | 怎么判 |
|---|---|---|
| 口算 | `3 + 5 =`、`72 ÷ 8 =` | 比数值 |
| 填空（一题多空） | `7 × (  ) = 56`，`(  ) 里最大能填几：4 × (  ) < 30` | 每空比数值，可以有几个都算对的答案 |
| 比较 | `38 ○ 83`、`1 千米 ○ 999 米` | 比符号 `>` `<` `=` |
| 单位换算 | `3 米 = (  ) 厘米`，`2 时 15 分 = (  ) 分` | 比数值 |
| 找规律 | `2, 4, 6, (  ), 10` | 比数值 |
| 选择 | 单选、多选 | 比选项；多选可以设“选对一部分给一半分” |
| 判断 | `0 除以任何数都得 0。( )` | 对 / 错 |
| 应用题 | “12 个苹果平均分给 3 人，每人几个？”分成“列式”和“答”两个空 | “答”比数值，可以带单位（`4`、`4 个` 都对）；“列式”可以给几个都算对的写法（`12÷3`、`12/3`），也可以设成“老师批” |
| 竖式、画图、连线、作图 | | **第一版不做** |

判题的规则由作者按题定：
- **按数值**（默认）：`0.5`、`1/2`、`½` 都算对；
- **按写法**：比如要求“化成最简分数”，`2/4` 就不对；
- **几个答案都对**：列出来；
- **老师批**：不自动判，交卷后显示“待批”。

### 19.3 一道题有什么

- 题干：一段 Markdown，可以有图片（`![[…]]`）、公式。
- 空：在题干里标出位置，一题可以有几个空。
- 正确答案（每空一个或几个）、判题规则、分值（每空或整题）。
- 讲解：可以有图片。
- 提示：答题时可以点开看，可以设“看了提示扣分”。
- 知识点（可以有几个）、难度（1–5）：用来统计和选错题。

### 19.4 测验

- 一组题，有顺序，可以分几个大题（“一、口算”“二、填空”）。
- 一道题可以出现在好几个测验里（同一个资源，改一次到处变）。
- **设置**（写书时定）：
  - **答案什么时候给**：老师公布（默认） / 交卷后 / 每题答完；
  - 能做几次（不限 / 1 次 / N 次），成绩取最高还是最后一次；
  - 限时（可以不限）；
  - 交卷前能不能改已经填的答案。
- 测验可以放在书里任何地方：一节后面的“练一练”就是一个小测验。

### 19.5 作答、成绩、错题

- **作答**：学生每做一次测验，就有一份作答，记着每道题填了什么、对不对、得几分、什么时候开始和交卷、用了多久。交卷后不能再改。
- **成绩**：每个测验每次的得分；按书、按章汇总；按知识点看正确率。
- **错题本**：做错过、而且之后没再做对的题，按知识点、按章分组。可以“再练一次”（把这些题当一次新的测验做）。再练做对了的，从错题本里拿掉，但保留历史。
- **书上的样子**：做过的测验在书上显示“上次 85 分 · 第 2 次”，可以“再做一次”“看上次的作答”。

### 19.6 答案在答题前看不到

1. **答案和讲解只在老师的课本里**。默认（“老师公布”）学生那里**什么都没有**：没有明文，也没有能用来核对的东西。
2. 学生交卷后显示“已交卷，等老师公布答案”。
3. 老师觉得需要时，对某个测验（或一个单元、整本书）点“公布答案”，学生拿到后：
   - 自动判分；
   - 显示 ✓ ✗、答案、讲解；
   - 进成绩和错题本。
4. 作者也可以对某个测验改成：
   - **“交卷后”**：交卷就判、就给答案；
   - **“每题答完”**：每道题答完就判、就给答案。

   这两种要在学生那里当场判，所以答案要提前跟着书发过去（加密），限制见 5。
5. 要说清楚的限制：只有“老师公布”能做到真正看不到。另两种，懂技术的人可以从学生的电脑里取出钥匙，范围很小的答案（`3 + 5`）也能挨个试出来。所以这两种只适合练习，**正式测验用“老师公布”**。

### 19.7 发给学生，以及老师改课本

**现在只有一台电脑，用两个工作区**（OneDesk 已经能建多个工作区，并在两个窗口里同时打开）：

```
同一台电脑
├─ 工作区“老师”（窗口一）
│   └─ 📖 数学三年级（原件：可以改，有答案）
│        │ ① 发布 → 书的文件（第 N 版，不含答案）
│        │ ③ 公布答案 → 答案文件（某几个测验的答案）
│        ▼
└─ 工作区“学生”（窗口二）
    ├─ 📖 数学三年级  🔒 只读 · 第 N 版   ← ② 导入书的文件
    └─ 作答树：练一练 · 第 1 次 · 待公布 → ④ 导入答案文件后 100 分
```

1. **发布**：老师在原件上点“发布”，得到一个版本（版本号、发布时间、发布人），存成一个书的文件。
2. **导入**：学生的工作区导入这个文件，出现书的**只读副本**：
   - 能读、能做题；
   - 不能改，也不能删其中一部分，只能整本移除。
3. **老师改课本不影响学生答题**：
   - 老师随时可以改原件，学生那里不变，直到老师再发布、学生再导入新版。
   - 学生更新到新版后，作答、成绩、错题都还在，因为题的编号不变。
   - **正在做的测验不受更新影响**：作答记着它是在哪一版开始的，用的是那一版的题；交卷、判分都按那一版。
   - 新版里删掉或改了的题，旧的作答里还能看到当时的题干和自己的答案。
4. **公布答案**：
   - 老师对某个测验点“公布答案”，得到一个答案文件，学生导入。
   - 答案按版本给：同一道题在第 2 版和第 3 版答案不同时，各自的作答按各自的版本判。
   - 老师那里记着每个测验公布到了哪一版。
5. **以后接上网络**：
   - “发布”“导入”换成订阅，学生自动收到新版；“公布答案”直接送到学生那里；
   - 学生可以把作答交回老师。
   - 资源、版本、作答都不用改。
6. **老师自己试做**：在原件上直接做，作答照样记下，答案当场显示（原件里本来就有答案）。

### 19.8 出题要快

- 在测验页面里一行一行地写，每行存成一道题，不用一次次地“新建”。
- **快速写法**：粘贴或输入 `3 + 5 = (8)`、`7 × (8) = 56`，括号里的就是答案，一次生成很多道口算、填空题。
- **随机出题**（以后）：一个“出题模板”，比如“两位数加法，和不超过 100”，每次生成不同的题，答案自动算。随机题的答案能从题目算出来，所以不保密，只适合练习。
- **AI 出题**：在 AI 对话里说“按第三单元的知识点出 10 道应用题”，结果“应用”后成为一道道题（D479 的“应用”）。

### 19.9 第一版不做

- 竖式、画图、连线、作图题；手写输入。
- 老师收作业、批改、全班成绩（要网络）。
- 网络发布和订阅（先用文件）。
- 防作弊（切屏、监考）。
- 随机出题、从题库随机抽题。

## 20. 设计：资源

### 20.1 四种资源

| 资源 | 谁写 | 在学生那里 | 里面有什么 |
|---|---|---|---|
| **题** | 作者 | 只读副本 | 题干、空、判题规则、分值、提示、知识点、难度；**答案、讲解（密封）** |
| **测验** | 作者 | 只读副本 | 题的列表（引用题，可以分大题）、设置（§19.4） |
| **作答** | 学生 | 自己的 | 哪个测验、哪一版、第几次、每道题每空的答案、判定、得分、时间、状态（作答中 / 已交卷）。**§26 起改为通用的“记录”**（范围是这个测验），练习插件不再单独做这个类型 |
| **错题本** | 自动 | 自己的 | 不是存下来的资源，而是练习插件的一个页面，从作答里算出来 |

成绩也不另存，从作答里算。

### 20.2 放在哪里

**作者那里**：
```
资源树
└─ 📖 小学数学三年级（上）           ← 书
    ├─ 📁 第一单元 时、分、秒
    │   ├─ 📝 秒的认识               ← 讲解
    │   ├─ ✏️ 练一练                 ← 测验（小）
    │   │   ├─ ❓ 1 分 = (  ) 秒      ← 题（测验下的子资源）
    │   │   └─ ❓ …
    │   └─ ✏️ 第一单元测验            ← 测验，也引用了“练一练”里的两道题
    └─ 📁 题库                        ← 普通分组，放公用的题
```
- 测验里新写的题存成测验的子资源。
- 引用别处的题，不移动它。
- 树上题目默认收起；题多的测验在树上只显示“20 道题”，点开才列出来。

**学生那里**：
```
资源树
└─ 📖 小学数学三年级（上）  🔒 只读 · 第 3 版   ← 只读副本，结构同上
作答树（练习插件的树）
└─ 小学数学三年级（上）
    ├─ 练一练 · 第 1 次 · 100 分
    └─ 第一单元测验 · 第 2 次 · 85 分
   （树顶上有“成绩”“错题本”两个页面）
```

### 20.3 题的写法

题干是 Markdown，空用 `{{?}}` 标出（和文书的填写项同一种写法，§3.2；这个写法由练习插件定义）：

```
7 × {{?}} = 56
38 {{?比较}} 83
12 个苹果平均分给 3 人，每人几个？
列式：{{?列式}}　答：每人 {{?}} 个
```

- 选择题、判断题没有空，用信息面板里的“选项”和“题型”。
- 每个空的答案、判题规则在题的页面里填（一空一行）。
- 快速写法里，括号中的值就是答案：`7 × (8) = 56` 存成题干 `7 × {{?}} = 56`，答案 `8`。

### 20.4 作答的过程

1. 学生在书上或测验页面里点“开始”：新建一份作答（作答中）。作答记下测验是**哪一版**。
2. 每填一空，存进作答。
3. 交卷：状态变成“已交卷”，之后只读。
4. 判分和给答案，按测验的设置：

| 设置 | 交卷时 | 之后 |
|---|---|---|
| 老师公布（默认） | 显示“等老师公布答案” | 导入答案文件后：判分、显示答案和讲解、进成绩和错题本 |
| 交卷后 | 判分、显示答案和讲解 | — |
| 每题答完 | 每道题答完就判、就显示（交卷前就看到） | 交卷时算总分 |

5. 主观题（判题规则是“老师批”）：第一版在老师公布答案后显示“参考答案”，学生自己对照，不计分。等以后能交回作业，再由老师批。

## 21. 设计：插件和内核

### 21.1 插件：练习 `org.onedesk.exercise`（外置）

| 项 | 内容 |
|---|---|
| 类型 | **题**、**测验**（资源树，能放进书）；**作答**（插件自己的树“作答”） |
| 页面：题 | 编辑：题干、每空的答案和判题规则、讲解、提示；右边预览学生看到的样子；“试做”按钮 |
| 页面：测验（作者） | 题的列表：一行一题，可以直接写新题、用快速写法、从别处引用、拖动排序、分大题；设置写在信息面板 |
| 页面：测验（学生） | 作答：一题一题往下做；顶上是进度、用时，“交卷”；交卷后显示 ✓ ✗、得分、答案、讲解 |
| 页面：成绩、错题本 | 作答树顶上的两个页面 |
| 被嵌入 | `![[练一练]]`：在书里直接作答（K11）；`![[某道题]]`：单独一道题也能在书上做，记进这本书的“随堂作答”；作者那里显示带答案的样子 |
| 依赖 | K11（可作答的嵌入）、K10（密封）、K9（只读副本里能用）；书、图片、公式插件**没装也能用**，只是对应的嵌入显示成卡片 |
| 给 AI | 题和测验：只给题干，不给密封的内容；作答：给学生自己的答案和对错 |

**为什么外置**：和文书一样，这是一类用户才需要的（教和学），不是人人都用的基础（D456）。

### 21.2 内核新增的三项通用能力

都不认识“题”“答案”“学生”，其他插件也能用：

| 编号 | 能力 | 说明 | 别的用处 |
|---|---|---|---|
| **K9** | **发布与只读副本** | 把一棵子树发布成一个**版本**（资源包文件，带发布人、版本号）；在另一个工作区导入后成为只读副本：资源编号不变；用户和插件都不能改、不能删其中一部分，只能整本移除或更新到新版；信息面板显示“只读 · 来自 … · 第 N 版”。以后加网络订阅，包的格式不变 | 文书模板库发给全科室；公司的制度手册；任何“一人写、多人用”的内容 |
| **K10** | **密封字段** | 清单里的字段可以声明 `sealed: true`。发布时，这个字段的值不进包；按设置，要么什么都不带（默认，等公布），要么换成两样东西：（1）**指纹**：每个可接受的值各一个，加盐哈希，用来核对；（2）**密文**：用这个版本的钥匙加密的原值。<br>宿主接口：<br>• `host.sealed.check(资源, 字段, 值)` → 对 / 错（插件先把值规范化，如 `1/2` → `0.5`，发布时也用同样的规范化）；<br>• `host.sealed.open(资源, 字段)` → 原值，只有拿到钥匙才行。<br>钥匙存在钥匙串里（硬性规则 7）。在作者自己的工作区里，密封字段就是普通字段 | 文书里只给审核人看的内容；带标准答案的考核表 |
| **K11** | **可交互的嵌入** | 嵌入视图里可以有输入框、选择、按钮。用户操作交给**被嵌入资源的类型**的 `embedAct(ctx, { section, key, value })` 处理，插件返回新的嵌入视图。插件在这里可以写自己的资源（作答），不能写嵌入它的那个资源 | 书里嵌的清单可以打勾；嵌入的表单可以直接填 |

**K9 的版本**：
- 发布时，内核把这一版的内容存一份在老师的工作区（不能改）。这样老师继续改原件，也能给旧版公布答案。
- 学生的工作区更新到新版时，正在用的旧版题目（有作答引用的）保留一份只读的旧版，作答按它显示和判分；没有作答引用的旧版直接丢掉。

**密封的内容怎么到学生那里**（K10）：

| 设置 | 书的文件里 | 学生什么时候能判、能看 |
|---|---|---|
| **老师公布**（默认） | **什么都没有** | 老师“公布答案”生成答案文件：这几个测验、这一版的**答案原文**。学生导入后才能判、能看。这种最安全：学生那里事先没有任何东西可以试 |
| 交卷后 / 每题答完 | 指纹 + 密文，钥匙也随书发，存进学生工作区的钥匙串 | 插件到时候调用 `sealed.check` 判、`sealed.open` 取原文。普通学生看不到；懂技术的人能取出钥匙 |
| 正式考试（以后，网络） | 什么都没有 | 判题在老师那边做 |

所以 K10 的宿主接口是：
- `host.sealed.check(资源, 字段, 值)`：判对错。如果答案已经公布，用原文判；否则用指纹判；两样都没有，返回“还不能判”。
- `host.sealed.open(资源, 字段)`：取原文。答案已经公布，或者有钥匙，才拿得到。
- **公布**：老师那里的 `sealed.release(资源列表, 版本)` 生成答案文件，只有用户操作能调用，插件不能自己公布。
- **导入**：学生那里导入答案文件，内核核对它和副本是同一个发布人、同一版。

### 21.3 已有的能力，直接用

- 书（§18）：装订、编号、连续阅读，在只读副本里照常工作。
- 嵌入（D481）、精确引用（D482）：测验引用题，书嵌测验。
- 图片（§16）：题干和讲解里的图。
- AI 对话和“应用”（D479、D480）：AI 出题。
- 插件存储、事件：成绩、错题的索引。

# 活书：书的五个阶段（D486，待确认）

> 用户 2026-11-25：课本这样的书，在 OneDesk 里已经不只是用来读的书，而是一本**可以执行的书**。照这个思路设计更通用的书，可以逐步升级：第一个书插件只读，第二个多一点功能，第三个再多一点，最后一个是可执行的“活”书。

## 24. 思路

### 24.1 书的每一节，能做的事越来越多

| 一节能 | 例子 | 从哪一阶段起 |
|---|---|---|
| **显示** | 笔记、图片 | B1 |
| **算** | 公式、带参数的表格，跟着书的参数变 | B2 |
| **让读者填** | 题、清单、填写项 | B3 |
| **判和反馈** | 判对错、到时候公布答案 | B4 |
| **运行** | 发 HTTP 请求、跑 SQL 查询、执行命令、问 AI，结果留下来给后面的节用 | B5 |

### 24.2 书插件自己始终很薄

书只管四样东西，“活”的能力都来自放进书里的资源：

1. **顺序**：树上的结构。
2. **参数**：读者在书顶上设的值。
3. **记录**：读者“走一遍”书留下的东西。
4. **运行**：按顺序把一节节跑下去。

一节能不能算、能不能填、能不能运行，由**那一节的资源类型**决定：公式能算，题能填，HTTP 请求能运行。书插件不认识任何具体类型，只按通用的约定和它们配合。所以以后任何插件加一种新的“能运行的东西”，放进书里就能用，书不用改。

### 24.3 一个书插件，分五个阶段升级

- 书始终是**同一个插件、同一种资源**，每个阶段发一个新版本，多一样能力。
- 用户的书不用迁移，旧书自动拥有新能力。
- 不做五种不同的书：那样同一件事会有五个入口，违反“一个功能一个入口”。

## 25. 五个阶段

### B1 阅读的书（只读）= §18

- 树上的结构就是书的结构；子书（文集）；编号；目录；连续阅读；按章嵌入；导出 Markdown。
- 例子：文集、产品手册、规章制度。
- 内核：K7（读子树、读内容）、`sequence` 节点。

### B2 会算的书

- **书的参数**：书的信息面板里定义参数（名字、默认值、说明、单位），读者在书的顶上直接改。
- 书里的模板 `{{名字}}`、公式 `[[=BMI | 体重=@体重]]`、带参数的嵌入，都按这些参数**当场重算**。
- 参数的取值顺序：
  1. 读者在书顶上改的值；
  2. 标签页选的环境；
  3. 书里写的默认值。
- 例子：
  - 食谱（“份数 = 6”，用量全部跟着变）；
  - 工程手册（换一组设计参数，所有计算重算）；
  - 报价书（数量、折扣）。
- 内核：K3（带参数的引用）；书的参数作为一层环境交给嵌入。
- 插件：公式（§11.3）。
- 读者改参数**不留下任何东西**，关掉就没了。要留下来的是 B3。

### B3 能填的书

- 书里的节可以让读者填：题的空、清单的勾、表格的格子、文书的填写项。
- 读者填的东西**不写进书**，写进一份**记录**（§26）。一本书可以有很多份记录：第 1 次、第 2 次，或者每个人一份。
- 例子：
  - 练习册（自己做）；
  - 上线前检查清单（20 项逐项打勾、写备注）；
  - 病人档案（文书）。
- 内核：K11（可交互的嵌入）、**K12 记录**。
- 插件：练习（题、测验）、文书。

### B4 会反馈的书

- **判**：填的东西和标准对照，给出 ✓ ✗、分数。
- **密封**：标准答案在读者那里看不到。
- **公布**：到时候才给答案。
- **发布**：书发给别人，别人那里是只读副本，作者改书不影响读者；按版本更新。
- **统计**：从很多份记录里算成绩、错题、正确率。
- 例子：
  - 课本和测验（§19–§21）；
  - 员工培训手册（读完、考完才算完成）；
  - 制度手册发给全员（每人确认“已读”）。
- 内核：K9（发布与只读副本）、K10（密封与公布）。

### B5 活书（可以执行）

- 书里的节可以**运行**：凡是有“动作”的资源（HTTP 请求、SQL 查询、命令、脚本、AI 提示），在书里都有“运行”按钮。结果直接显示在这一节下面，并**存进记录**。
- **值往下传**：一节运行的结果，后面的节可以用。比如 `@查版本.第一行.版本号`、`@登录.token`。
- **期望**：一节可以写期望，比如 `@状态码 = 200`。运行后自动判 ✓ ✗，和 B4 的判题是同一回事：题是人来答，期望是机器来答。
- **运行这一章 / 运行全书**：从上到下一节节跑。第一版只支持四种走法：
  1. **按顺序**往下跑；
  2. **条件跳过**：比如 `@环境 ≠ 生产` 时跳过这一节；
  3. **等人确认**：一节写“请检查上面的结果，没问题再继续”，人点“继续”才往下；
  4. **失败就停**，可以从停的地方继续。

  不做循环、不做跳转，不让书变成编程语言。
- **记录就是报告**：跑完一遍，记录里有每一节的输入、输出、✓ ✗、时间、谁跑的，可以导出成一份报告。
- 例子：
  - **运维手册**：选环境“生产” → ① 查当前版本（SQL）→ ② 调健康检查接口（HTTP，期望 200）→ ③ 等人确认 → ④ 执行发布命令 → ⑤ 再查版本（期望新版本号）。跑完的记录就是这次发布的操作记录。
  - **每周数据报告**：点“运行全书”，各节的查询全部重跑，生成这一周的记录，导出发给领导。
  - **接口测试书**：每节一个请求加期望，跑完看哪些 ✗。
  - **新人入职书**：读、填、考、在测试环境里真的跑一遍命令，全在一本书里。
- 内核：
  - 已有的动作和运行（§4.3、`runs`）；
  - 新增 **K13 在书里运行**：动作的输入可以取记录里前面节的值；运行挂在记录上；“运行全书”由书插件一节节调用。

## 26. 记录（K12）：把“作答”通用化

课本里的“作答”（§20）就是记录的一种。通用之后：

| 项 | 内容 |
|---|---|
| 是什么 | 读者把一本书（或书里的一部分，比如一个测验）“走一遍”留下的东西 |
| 是资源吗 | 是。内核自带的通用类型“记录”（像“分组”一样，内核自带，不属于任何插件），放在内核的树“记录”里，按书分组 |
| 里面有什么 | 走的是哪本书、哪一部分、哪一版、第几次；参数的值；**每一节的状态**（填了什么、判定、运行编号、输出的值）；开始、结束时间；谁 |
| 状态 | 进行中 → 已完成（交卷、跑完）；完成后只读 |
| 谁来写 | 节的资源类型的插件通过 K11 的 `embedAct(ctx, …)` 返回这一节的新状态，**由内核写进记录**。插件不能直接改记录，也不能改别的节的状态 |
| 谁来读 | 书的页面（显示每节的状态）；统计页（成绩、错题）用 `host.records.list({ 书或类型, … })` 读；AI 读得到自己能看的记录 |
| 和运行的关系 | B5 的每次运行仍是一条运行（`runs`），记录里只存它的编号和输出的值 |

这样，练习插件不再自己做“作答”类型：
- 学生点“开始”测验，就是新建一份记录，范围是这个测验；
- 成绩和错题本从记录里算。

文书的“一份病历”不同：它是从模板新建出来的独立资源（K5），因为要签名、锁定、被引用。所以“一份文书”不是记录，“写一份”和“走一遍”是两回事。

## 27. 节的约定（各插件怎么让自己在书里“活”起来）

都写在 `host.kinds.handle(kind, { … })` 里，全部可选；没写的就只显示：

| 处理函数 | 作用 | 阶段 |
|---|---|---|
| `embed(ctx, { section, args })` | 显示，已有（D481）。`ctx.params` 里有书的参数，`ctx.record` 里有这一节在记录里的状态 | B1、B2 |
| `embedAct(ctx, { section, key, value })` | 读者在嵌入里操作，返回 `{ view, state? }`：新的样子、要存进记录的这一节的状态 | B3 |
| `values(ctx, { state })` | 这一节对外的值，如 `{ 得分: 85 }`、`{ 状态码: 200, token: "…" }`，后面的节用 `@节名.值` 取 | B3、B5 |
| `check(ctx, { state })` | 判对错，返回每一项的 ✓ ✗ 和得分；可以用 `host.sealed.check` | B4 |
| 动作（已有，§4.3） | 有动作的类型在书里显示“运行”。运行时 `input` 里能取到 `@…` 的值，输出由内核存进记录 | B5 |
