# AI 对话（ai-chat）设计稿

> 状态：用户 2026-11-25 确认 §10 全部按推荐；第一步已实现（D479，实际做法见 §11）。第二步（§8.2 工具调用）待做。
> 取代：`ai-assist.md` §9（D462）的对话框、D470 的“按说明直接生成”，以及 AI 工作台的“分析”页。`onedesk.ai.chat/1`（服务商接口）和 SQL 用的 `onedesk.ai.generate/1` 保留。

## 1. 要解决的问题

1. **说明只能用一次。** D470 之后，“用 AI 写”把资源的**说明**当作唯一的要求。说明写的是这个资源长期是什么，所以每次生成的结果都差不多，没有地方说“这一次要什么”。
2. **只能一问一答。** 生成的提议不满意，只能改说明再来一次。不能接着说“再加一个排序”“刚才那样不对”。
3. **AI 不知道其他系统的情况。** 发给 AI 的只有当前页面的字段。查询结果、命令输出、别的文档，AI 都看不到。

## 2. 思路：把“分析”升级成“AI 对话”资源

AI 工作台现在有“分析”类型：一个标签页，有将要发送的内容、参考文档、发送、回答和历史。把它升级成 **AI 对话**（kind 仍属于 `org.onedesk.ai`，名称改为“AI 对话”）。和 AI 的多轮来回都在这个标签页里进行。

| 东西 | 放在哪 | 作用 |
|---|---|---|
| **说明** | 信息面板（不变） | **长期背景**，每轮都带上 |
| **这次的话** | 对话页底部的输入框 | **这一次的要求**，每轮不同 |
| **资料** | 对话页顶部的资料栏 | 其他资源的内容和最近一次运行的结果 |
| **目标** | 对话的一个属性 | 回答可以“应用到”的那个资源 |
| **环境** | 标签页的环境选择（不变） | 模板取值，资料的运行结果和 AI 查询都在这个环境下 |

七条规则（spec §0）在这里的对应：

| 规则 | 怎么满足 |
|---|---|
| 是资源，有信息面板 | 对话是资源，在资源树里，可以拖动。新建未保存时也有信息面板 |
| 每页可选环境 | 对话页有环境选择 |
| 天生是模板 | 说明和每轮的话里，`{{名字}}` 取环境的值 |
| 参数直接加 | 不涉及 |
| 不重复入口 | 全系统只有一个 AI 入口，见 §6 |
| AI 按说明生成 | 说明是背景。对话为空时直接发送，等于“按说明生成” |
| 不乱加东西 | 见 §9 不做的 |

## 3. 页面

```
┌ AI 对话：订单查询 ─────────── [环境：生产 ▾] │ 发送  清空对话  ┐
│ 目标：订单库查询 ↗                                            │
│ 资料： [订单库查询 ×] [docker ps ×] [接口文档 ×]  拖资源到这里  │
│ 连接：LocalOllama · 模型：qwen2.5 · 这个环境要求先预览再发送     │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ 我  最近一小时有没有卡住的订单？                             │ │
│ │ AI  有 37 笔状态是 pending，都来自支付渠道 B……               │ │
│ │ 我  把这些订单和支付记录对上，写成查询                       │ │
│ │ AI  ```sql SELECT … ```                                     │ │
│ │     [应用到 订单库查询]                                      │ │
│ └──────────────────────────────────────────────────────────┘ │
│ [ 这次要说的……                                    ] 回车发送  │
└──────────────────────────────────────────────────────────────┘
```

- **输入框**：回车发送，Shift+回车换行，不弹对话框。
- **预览**：环境的 `ai.policy` 是 `preview`（默认）时，第一次回车不发送，而是在对话里显示“将发送的全文”（说明、资料、历史、这次的话，已打码），再按“发送”才发出。是 `allow` 时直接发，是 `off` 时拒绝并说明原因。和现在一样。
- **回答**：以 Markdown 显示，逐字出现（沿用 `runs.partial`）。可以取消。
- **清空对话**：删掉全部轮次，说明、资料和目标保留。要确认。
- **历史**：每轮都是一次普通运行，运行历史照旧。对话本身存在资源里（§7），所以下次打开还在，资源的修改记录也能恢复。

## 4. 资料：让 AI 看到其他资源

- **怎么加**：从任何资源树把资源拖到对话上，可以拖到树里的对话节点，也可以拖到页面的资料栏。用的是 D478 后综合节点同样的 `drop`。资料栏里点 × 去掉。
- **发送什么**：每份资料发送下面几项：
  - 名称、类型、说明；
  - **正文**：通过 §8 的 `pages.fields` 读取资源页面上的字段值；
  - **最近一次运行的结果**：在**这个标签页的环境下**的那次。表格取前 N 行，文字取前 N 字。
- **综合节点**：拖进来等于把它里面的每一项都当作资料。最多展开一层，最多 20 项。
- **打码和截断**：沿用 AI 工作台现有的规则：
  - 敏感列整列打码，邮箱和长数字串打码；
  - 行数和单元格字数有上限；
  - 资料总量受“参考资料预算”限制，超出的部分不发，并在预览里注明。
- **AI 可见**：只有信息面板里勾了“AI 可见”的资源才能作为资料发送。拖进来的资源没勾时，资料栏把它标灰，提示“未允许 AI 查看”，点一下可以打开它的信息面板。
- **参考文档**：AI 工作台原有的“参考文档”（文档文件夹）变成普通资料，不再单独一栏。

## 5. 回答怎么回到别的资源：目标与“应用到”

- 对话可以有一个**目标**资源，从 §6 的按钮打开时自动设好。目标默认也是第一份资料。
- 发送时，AI 拿到目标页面的字段清单：名称、类型、格式、当前值，和现在 `onedesk.assist/1` 的 `fields` 一样。AI 被要求用一个约定的代码块给出对目标的修改。
- 回答里出现这样的修改时，下面显示 **“应用到 目标名”**。点了以后：
  1. 打开（或切到）目标的标签页；
  2. 把修改作为**未保存的修改**放进去，改动的字段带标记；
  3. 用户照常“保存”或“撤销”。
- 目标的标签页里已经有未保存的修改时，先问“用 AI 的版本替换未保存的修改吗？”。
- 没有目标的对话（直接新建的）只聊天，没有“应用到”。

## 6. 唯一的入口：工具栏的“AI 对话”按钮

- 现在各页工具栏上的 **“用 AI 写 / 用 AI 填写”** 改为 **“AI 对话”**。点了以后：
  - 这个资源已经有以它为目标的对话：打开那个对话；
  - 还没有：新建一个对话（名称“AI：资源名”），目标和第一份资料都是这个资源，环境和当前标签页相同，然后打开。说明为空。
- **新建一个资源**时（还没保存），按钮同样可用。对话的目标是那个未保存的标签页，“应用到”把内容放进这个新建页。
- 对话为空时直接按“发送”，会用目标的说明作为要求，效果等于原来的“按说明生成”。所以原来的一键生成不单独保留。
- **字段旁的 ✨ 按钮删除**（D462 ④），以免同一功能有两个入口。插件写的 `assist: { hint, format, off }` 照旧有效：`hint` 和 `format` 进字段清单，`off` 的字段不发给 AI，也不能被“应用到”修改。
- “分析”结果动作（在运行结果上点“分析”）改为：新建一个对话，资料是那次运行所属的资源，输入框里预填“分析这次的结果”，不自动发送。

## 7. 数据

对话资源的 body：

```jsonc
{
  "target": "资源 id 或空",
  "refs": ["资源 id", …],            // 资料，最多 20 个
  "connectionId": "",                 // 空：环境 → 工作区默认（不变）
  "turns": [
    { "role": "user", "text": "…", "at": "2026-11-25T10:00:00Z" },
    { "role": "assistant", "text": "…", "model": "…", "usage": "…", "runId": "…",
      "apply": { "values": { "body.text": "…" } },   // 有对目标的修改时
      "steps": [ { "tool": "run", "label": "运行 订单库查询", "ok": true } ] } // 第二步（§8.2）
  ]
}
```

- 最多 200 轮，每轮文字最多 20000 字。满了以后，提示新建对话或清空。
- 发送时，历史从最近一轮往前取，直到用完 token 预算。没发的轮次在预览里注明“只发送了最近 N 轮”。
- **不存**：将发送的全文（每次按当前资料重新组装）、资料的内容（每次重新读）。
- 旧的“分析”资源：第一个正式发布版之前不保证旧数据（D460）。旧的 `request` 变成输入框里的草稿，`docs` 丢弃。

## 8. 实现

### 8.1 第一步：对话、资料、目标

**协议和接口的变更**（规则 10，需要你同意）：

1. **视图节点 `conversation`**：
   - 结构是 `{ id, turns: [{ role, text, note?, actions?: [{ id, label }] }] }`；
   - 外壳把它画成对话；`text` 按 Markdown 显示，`note` 是灰色小字（模型、token）；
   - `actions` 是这一轮下面的按钮，发送以 `id` 为名的页面事件，`context.turn` 是轮次序号，和表格的 `rowActions` 一样；
   - 现有的 `text` 节点画不出“哪句是谁说的”，也放不了每轮的按钮，所以要新增。
2. **页面事件的新结果 `apply: { target, values }`**：外壳打开目标的标签页，把 `values` 作为未保存的修改放进去，按 §5 处理冲突。
   - 只有实现了 `onedesk.assist/1` 的插件可以返回它。
   - 字段必须是目标页面上可编辑、没有 `assist.off` 的字段，否则拒绝。
3. **宿主接口**：
   - `host.pages.fields(resourceId)`：内核渲染那个资源的页面，返回可编辑字段 `[{ name, label, kind, format, hint, value }]`（已保存的值）。新建未保存的目标由外壳在发送时把字段带过来。
   - `host.runs.latest(resourceId, envId?)`：那个资源在某环境下最近一次运行的结果摘要。
   - 两者都要求 `requires.resources`；AI 运行里只能读 AI 可见的资源。
4. **`onedesk.assist/1` → `onedesk.assist/2`**：
   - 外壳的“AI 对话”按钮调用实现者的命令 `openChat { target, envId }`，返回对话资源 id，外壳打开它；
   - `assist.start` 和对话框删除；
   - `assist.provider` 保留，决定按钮显不显示。

**AI 工作台**：
- `analysis` 类型改为对话（id 不变，名称和图标改）；
- 页面按 §3 渲染；
- `drop` 加资料；
- “发送”组装请求，调用现有的 `onedesk.ai.chat/1`，传 `messages`（Anthropic 和 Ollama 已支持多轮 `messages`）；
- 回答里认出约定的修改代码块，存成 `apply.values`。

**外壳**：
- 画 `conversation` 节点和每轮按钮；
- 处理 `apply`；
- 工具栏按钮改为“AI 对话”，删除 `parts/assist.tsx` 的对话框和字段旁的 ✨。

### 8.2 第二步：让 AI 自己去查（工具调用）

- **工具**：AI 回答前可以调用**和 MCP 完全相同的只读工具**：搜索、读资源、运行带 `ai: { readOnly: true }` 的动作、各插件的 `aiTools`。内置和外部的 AI 用同一套工具，同一套限制（D448/D450/D451）：只看 AI 可见的、不能写、不能读密钥、限流、审计。运行在这个标签页的环境下。
- **新接口**：
  - `onedesk.ai.chat/1` 增加可选的 `tools` 输入和 `toolCalls` 输出，Anthropic 和 Ollama 插件实现；
  - 宿主接口 `host.ai.tools()` 和 `host.ai.call(name, args)`，由内核转到 MCP 的工具处理，操作者是 `Actor::Ai`。
- **对话里显示**：每一步显示成“查了 订单库查询 ▸”，可以展开看参数和结果（打码后的）。每轮最多 8 次工具调用，超过就停下来回答。
- **预览**：`preview` 策略下，每次工具结果发给 AI 之前**不再逐次确认**，只在第一次发送时确认。理由是工具只读，范围已经被“AI 可见”限定。（**待你定**，见 §10。）

## 9. 不做的

- 用 AI 生成或修改插件本身。
- AI 写入资源：AI 只给提议，写入永远要人点“应用到”再“保存”。
- 跨对话的长期记忆：对话之间不共享，要共享就把资源作为资料拖进去。
- 语音、图片、附件文件：资料只能是资源。要用文件，先在文件插件里打开它，它就是资源。
- 多个目标：一个对话只有一个目标。
- 对话导出或分享：和整个系统一样，单机。

## 10. 需要你定的

1. **对话放在资源树的哪里**：
   - 从“AI 对话”按钮新建的对话，**推荐放在目标资源的旁边**（同一个分组里，紧跟目标），用户可以随意移走。
   - 另一种是统一放进根上自动建的“AI 对话”分组，不会把业务分组弄乱，但离目标远。
2. **字段旁的 ✨ 删除**，只留工具栏的“AI 对话”，可以吗？
3. **第二步的预览**：工具查到的结果发给 AI 前，要不要每次都让人确认？推荐不用（§8.2），只在第一次发送时确认。
4. **协议变更**：§8.1 的四处，加上 §8.2 的工具接口，可以吗？
5. **顺序**：先做第一步，验收后再做第二步，可以吗？

## 11. 第一步的实际做法（D479）

与 §1–§8 的不同和补充：

- **资料只能拖到树里的对话节点上**（kind 的 `drop`），页面上的资料栏是一张表（名称、类型、AI 是否可见、“去掉”），不接受拖放。要在页面上拖放，需要外壳另加支持，没有做。
- **新对话放在目标的紧上方**（同一分组，`resources.move` 的 `before`）；目标在别的树里时放在资源树的根上。未保存的新页面每个标签页一个对话，名字取信息面板里写的名称。
- **点“AI 对话”就允许 AI 查看这个页面**（打开它的“AI 可见”，并提示可以在信息面板里关掉）：内核只让 AI 工作台读 AI 可见的资源，而用户点这个按钮就是同意。
- **预览**：`ai.policy = preview` 时，第一次发送的运行结果就是将发送的全文（结果区），插件记下它的指纹；内容不变再按一次才真正发送。内容变了（话、资料、历史、连接）就再预览一次。
- **目标的当前内容**：发送时外壳把目标标签页的值（已保存的值加上正在输入的，不含密钥字段）和信息面板里的说明带给运行；标签页没开着就用已保存的值。目标本身不再作为资料重复发送。
- **AI 怎么给出修改**：系统提示要求回答末尾用 `onedesk-apply` 代码块给出 JSON（字段名 → 完整新内容）；目标只有一个可编辑的代码字段时，回答里唯一一个该语言的代码块也算；内核再按目标页面过滤一次，只留下可编辑的文本字段。
- **“保存分析”（K6，挂在运行下）删除**：对话本身就是资源，保存在资源里。“分析”结果动作改为新建一个对话：被分析的结果（打码后）作为资料（`runText`），说明是默认的分析要求，产生结果的资源也加入资料；不自动发送。
- **参考文档**仍由“更新参考文档”同步成资源，在对话里作为普通资料拖进来；对话不再按关键词自动挑文档（`generate` 仍会）。
- 视图节点里一轮下面的小字叫 `caption`（`note` 是插件名，架构检查不允许出现在内核里）。
- 清除对话是页面上的一个运行操作（带确认），因为页面事件不能要求确认。
