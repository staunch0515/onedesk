# Vioros 功能对照：OneDesk 的验收条件

状态：已由用户确认为验收条件（2026-11-15）。
依据：Vioros 的代码（`/Users/zhongpingxue/quizbuks/repo_vioros`，版本 0.2.1）；`docs/redesign/kernel-design.md` 第 3 稿；requirements.md I.10g、decisions.md D188–D190。

Vioros 是一个完整的独立应用：浏览对象存储里的视频、播放、从链接下载、上传本地视频。它保持原样，不为接入而改动。接入 OneDesk 的方式是一个插件，经 Vioros 的网关工作，界面用 OneDesk 的树、标签页、结果区。

验证条件是：**Vioros 现有的全部功能，都能用一个插件在 OneDesk 上做出来，内核里不出现任何视频、对象存储、yt-dlp、ffmpeg 的字样。**

它和 sqlpool 考验的是不同的地方。sqlpool 考的是资源、参数、环境、历史；Vioros 考的是：内容不在本地库里（在远端的存储桶）、大文件、长时间运行并可取消的外部程序、以及基础节点画不出来的界面（播放器）。

## 1. 结论

- **骨架能满足。** 我列了 56 项功能：32 项用现有设计直接能做；22 项要靠内核补上 6 处中的某一处（其中多数是因为整个文件夹页由插件自己画，依赖同一处）；2 项按新需求不照搬（托盘图标、Windows 版）。
- **需要补的 6 处**见第 4 节，已写进内核设计（D248–D252）。都不动骨架。
- **文件夹页由插件自己画。** Vioros 的文件夹页（列表、播放器、信息、分栏）基础节点拼不出来，由插件作为自己的标签页类型来画，做法与 Vioros 现在相同：界面模块直接加载到页面里，用普通的 `<video>` 播放插件目录里的本机文件。
- 网关（Cloudflare Worker）在服务器上，不属于 OneDesk，原样保留。

## 2. 插件的形态

一个插件：**视频库**。

| 它提供 | 用内核的什么 |
|---|---|
| 一种资源类型“网关连接”：地址、公开地址、个人令牌 | 连接资源即网络授权（D233）；令牌是表单的密钥字段（D240） |
| 一棵树“存储桶”：文件夹逐层展开 | 提供树，子节点由插件向网关取，分批给出 |
| 文件夹页：视频列表 + 播放器 + 信息，由插件自己画 | 插件提供的标签页类型：页面里面怎么排、怎么分栏是插件自己的事，框架只给位置、设计 token 和通信通道 |
| 动作：取视频信息、下载链接、上传本地视频、另存到本机、删除、改信息、复制链接 | 运行（进度、取消、历史） |
| 三个外部程序：yt-dlp、ffmpeg、deno | 由插件负责（带来、下载、更新、核对都是插件的事）；内核只要求在清单里声明名字，并在安装时提示 |
| 设置页：工具是否就绪、连接状态 | 插件页 |

存储桶里的视频**不是 OneDesk 的资源**：它们不存进工作区的数据库，每次都向网关现取。所以它们没有 OneDesk 这一侧的历史、收藏和标签，这与 Vioros 现在的行为一致。

## 3. 逐项对照

“结果”一列：**有** = 现有设计直接能做；**补** = 需要第 4 节里的某一条；**不搬** = 按新需求不照搬。

## 4. 内核设计需要补的地方

每条都已写进 `kernel-design.md`。

| 编号 | 缺什么 | 为什么 Vioros 需要 | 怎么补 |
|---|---|---|---|
| Y2 | 插件没有自己的文件夹 | 播放缓存、下载的临时文件、插件自己的外部程序 | 每个插件在工作区里有一个自己的目录，不需要用户授权，别的插件读不到（7.5，D248） |
| Y3 | 运行外部程序时不能设环境变量；程序互相找不到；不能问“在不在” | yt-dlp 要自己调用 ffmpeg 和 deno；设置页要显示工具是否就绪 | 运行时可设环境变量和工作目录；同一插件的程序互相可见；可以查询某个程序是否就绪。程序本身的获取、更新、核对由插件负责，内核不管（7.5，D238、D249） |
| Y4 | 只能选文件夹；不能接收从系统拖进来的文件 | 上传本地视频 | `files` 增加“选择文件”；用户选中或拖进来的文件，对这一次操作可读；拖拽机制增加“来自系统的文件”这种来源，由目标所属的插件决定接不接（7.5、§5，D250） |
| Y6 | 插件自己画页面的接口还只有设计 | 整个文件夹页（列表、播放器、信息、分栏）由插件自己画 | 界面模块直接加载到页面里；框架给位置、设计 token 和基础组件、调用自己动作的通道、保存界面状态的地方；本机文件只开放插件自己的目录（9.4，D217） |
| Y7 | 没有一处能看到所有进行中的运行 | 底部任务条 | 外壳加任务面板：列出进行中和刚结束的运行，显示进度，可以取消、复制结果链接、清除已结束的（§8，D252） |
| Y8 | 危险动作的确认只能由插件自己想办法 | 删除视频 | 动作可以在清单里声明“执行前确认”和提示文字，由框架弹出统一的确认（7.2，D252） |

（Y1、Y5 已撤销：分栏和图片是标签页内部的事，由插件自己的页面处理，不是内核要补的东西。）

## 5. 已知的取舍

插件的界面模块与外壳在同一个页面里运行，没有隔离（内核设计 9.4）。安装视频库插件时会明说它带有自己的界面代码和外部程序，由用户确认。

## 6. 作为验收条件怎么用

1. 第 3 节的每一行是一个验收点。阶段 8 结束时逐行检查，结果只有三种：通过、不通过、按新需求改了行为。
2. 检查的方式是在真实运行的 OneDesk 里，连同一个网关、同一个存储桶，把每一行的事做一遍。
3. 在 OneDesk 里上传的视频，用 Vioros 原应用能正常列出和播放；反过来也一样。
4. 内核源码里搜索 `video`、`r2`、`bucket`、`yt-dlp`、`ffmpeg`，不得有命中（并入 `pnpm lint`）。
5. 做某一行时发现内核又缺东西，记入 decisions.md 并回到内核补，不在插件里绕过（D188）。
6. Vioros 自己的仓库和发布方式不因此改动（I.10g）。
