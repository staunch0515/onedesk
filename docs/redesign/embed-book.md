# 通用嵌入与书（embed-book）设计稿

> 状态：用户 2026-11-25 确认 §9 全部按推荐；第一步（通用嵌入）已实现（D481，实际做法见 §10）。
> §11–§17 是第二轮设计（D482）：精确引用、带参数的引用、公式、图片，以及新的先后顺序。**待用户确认 §17 后再开发**；书（§4）排在它们之后。

## 1. 要解决的问题

1. **资源之间只能链接，不能引用内容。** `[[名称]]` 只是一个能点开的名字。公式、法律条文、标准条款、共用的说明、一张表，都不能直接显示在另一个资源里。要显示就只能复制，原文一改，各处就不一致了。
2. **大的结构化内容没有办法“装订”。** 一本书由很多节组成，每节是一篇笔记，但现在只能一节一节打开：不能从头到尾连着读，没有目录和编号，不能导出成一份。
3. **书还可以套书。** 一部文集下面有很多本书，书下面有卷、章、节。这种多层结构要在 OneDesk 里清楚地表达出来，并且每一层都能单独读、单独导出。

做法分两层：**内核层**做一个通用的“嵌入”，不认识任何具体内容；**插件层**做“书”，用树上的结构加上嵌入，把内容装订成书和文集。

## 2. 例子

```
资源树：「鲁迅全集」                       ← 文集（一本“书”，里面是书）
├─ 📖 呐喊                                 ← 书
│   ├─ 📝 自序
│   ├─ 📝 狂人日记
│   └─ 📝 孔乙己
├─ 📖 彷徨
│   └─ …
├─ 📖 杂文集
│   ├─ 📁 坟                               ← 分组 = 一级标题（编/卷）
│   │   ├─ 📝 灯下漫笔
│   │   └─ 📝 论“费厄泼赖”应该缓行
│   └─ 📁 热风
│       └─ …
└─ 📁 公共素材（不在书里，只被引用）
    ├─ 📝 人物小传
    └─ 📝 注释：未庄
```

```
资源树：「劳动合同范本」
├─ 📖 劳动合同
│   ├─ 📝 第一条 合同期限
│   ├─ 📝 第二条 工作时间        正文里：![[劳动法#第三十六条]]   ← 直接显示法条原文
│   └─ …
└─ 📝 劳动法（另一处的资源）
```

## 3. 通用嵌入（内核与外壳）

### 3.1 写法

| 写法 | 意思 |
|---|---|
| `[[名称]]` | 链接（现在就有），显示成可以点的名字 |
| `![[名称]]` | **嵌入**整个资源的内容 |
| `![[名称#标题]]` | 嵌入其中**一节**：从名为“标题”的那个标题开始，到下一个同级或更高级的标题为止 |

- 写在任何声明了 `refs: true` 的文本字段里（笔记正文、参考文档、AI 对话的回答等）。
- 名称的规则和 `[[ ]]` 一样（D321–D330）：
  - 原文不改写，显示时换成目标的当前名字；
  - 改名后自动跟着改；
  - 目标删除后显示“引用的内容已不存在”；
  - 先写名字，后建资源也能连上。
- 引用表多记两项：这是不是嵌入、引用的是哪一节。
- 原文的信息面板里，“被引用”分成“链接”和“嵌入”两类。改法条之前，就知道哪些合同会跟着变。

### 3.2 显示：由被嵌入资源的插件决定

内核不认识“法条”“公式”。它只知道“资源 A 嵌入了资源 B 的某一节”，并把怎么显示交给 B 的插件：

- **插件提供嵌入视图**：在 `host.kinds.handle(kind, { embed(ctx, { section }) })` 里返回一小段**只读视图树**。用的是现有的视图节点，有大小上限。
  - 笔记：返回那一节的 Markdown，按当前环境填好 `{{名字}}`。
  - SQL 查询：返回语句，或者最近一次运行的结果表。
  - 网址：返回一张卡片。
- **插件没有嵌入视图时**：外壳统一显示成一张卡片（图标、名称、说明），点了打开。所以任何资源都能被嵌入，不会出错。
- **找不到那一节**：显示“找不到“第三十六条”这一节”，并给出整篇的链接。

外壳在 Markdown 里遇到 `![[…]]`，就向内核要这块内容：新方法 `resource.embed { source, target, section?, envId, locale }` → `{ view, title, icon }`。拿到后原地画出来，带一条细边框，标题可以点开原文。

### 3.3 规则

- **只读**：嵌入的内容不能在原地编辑。要改就点标题打开原文。
- **跟着环境**：被嵌入的内容按**当前标签页的环境**填充模板。同一条款模板，在“甲公司”和“乙公司”环境下显示不同的值。
- **防套娃**：最多嵌套 3 层。A 嵌入 B、B 又嵌入 A 时，第二次只显示链接卡片。
- **数量**：一页最多 100 个嵌入，滚动到哪里才加载到哪里。
- **AI**：AI 读一个资源时（资料、`pages.fields`、MCP 的 `describe`），嵌入会被**展开成文字**一起读到。前提是被嵌入的资源也允许 AI 查看；不允许的只给名字。
- **搜索**：搜索只按资源自己写的文字找，不按嵌入进来的内容找，避免一条法条出现在一百个搜索结果里。

## 4. 书与文集（插件 `org.onedesk.book`）

### 4.1 一本书就是树上的一个节点

- 新类型 **“书”**，放在资源树里（任何一棵）。它接受任何子节点：笔记、分组、别的书、任意资源。
- **树上的结构就是书的结构**，在树上拖动就是调整章节顺序。书不另外保存一份目录。
- 书里每种节点的意思：

| 树上的节点 | 在书里 |
|---|---|
| 分组 | 一级标题（编、卷、章，按深度往下一级） |
| 笔记 | 正文；笔记里自己的标题自动降到它所在的层级之下 |
| **书** | **一本子书**：有自己的书名页、目录和编号（从 1 重新开始）。这样就是文集 |
| 其他资源 | 它的嵌入视图（§3.2） |

- 一本书可以无限套书：文集 → 书 → 册 → ……

### 4.2 书的页面

```
┌ 鲁迅全集 ──────────────────── [环境 ▾] │ 导出  ┐
│ ┌ 目录 ─────────┐ ┌ 正文 ──────────────────────┐ │
│ │ 第一册 呐喊     │ │ 第一册 呐喊                 │ │
│ │   自序         │ │   自序                      │ │
│ │   狂人日记     │ │   ……                        │ │
│ │ 第二册 彷徨     │ │   狂人日记                  │ │
│ │ 第三册 杂文集   │ │   ……                        │ │
│ │   第一编 坟    │ │                             │ │
│ └───────────────┘ └─────────────────────────────┘ │
└──────────────────────────────────────────────────┘
```

- **目录**：一棵可以展开的树，点哪一项，正文就跳到哪里。
- **正文**：把下面的内容按顺序连起来，只读。滚动到哪里才加载到哪里，几千节的大书也不卡。每一节的标题旁有“打开”，点了在新标签页里编辑那一节。
- **在文集里打开一本子书**，看到的就是那一本。每一层都能单独读、单独导出。

### 4.3 编号

- 书的信息面板里（或书的设置里）定 **层级名称**：
  - 中文样式：`编, 章, 节` → “第一编”“第一章”“第一节”；
  - 数字样式：→ “1”“1.1”“1.1.1”；
  - 子书的称呼（`册` / `卷` / 不编号）。
- 编号在阅读和导出时生成，**不写进笔记**，所以调整顺序后编号自动跟着变。
- 子书的编号从头开始；文集给每本子书编号，比如“第一册”。

### 4.4 书的信息和环境

- 书名、作者、版本、出版年等写在**书的环境参数**里（D473 已经支持树、分组、资源的默认环境）。正文里用 `{{书名}}`。
- 子书继承文集的参数，并可以覆盖。比如文集里定了 `作者`，每本书再写自己的 `书名`。

### 4.5 导出

- 第一版导出成**一个 Markdown 文件**：带编号、目录，嵌入已展开。可以导出整部文集，也可以只导出其中一本。
- 写到你授权过的文件夹（文件插件的授权）。
- PDF、Word、EPUB 放到以后（需要排版库，要另外定）。

### 4.6 和 AI

- 某一节：照旧在那一节上点“AI 对话”。
- 整本书或某一章：把书或分组拖到对话上当资料，发送的是它展开后的全文（有长度上限，超出的部分在预览里注明）。
- 第二步之后，AI 也能自己去查书里的内容（用的是 D480 的工具）。

## 5. 不在第一版里的

- **交叉引用编号**：“见公式 3.2”“图 2-1”这类，要给书里的公式、图、表编号，再在正文里引用编号。放在第三步。
- **公式类型**：排好版的数学公式，需要加排版库（如 KaTeX，MIT），按规则 9 先记录。作为一个单独的插件，放在第三步。第一版里公式可以先写在笔记的代码块里。
- **文本展开**：在 SQL 这类纯文本字段里插入共用片段，运行时展开（写法如 `{{@片段名}}`）。这是“运行时替换”，不是“显示”。放在第三步。
- 导出 PDF、Word、EPUB。
- 多人协作、批注、修订记录之外的版本比对。

## 6. 实现

### 第一步：通用嵌入

- **协议**：新方法 `resource.embed`；`RefInfo` 增加 `embed`、`section`。
- **内核**：
  - 引用解析认识 `![[…]]` 和 `#标题`，引用表增加两列（只新增迁移文件，规则 6）；
  - 调用插件的 `embed` 处理函数，检查返回的视图节点，处理深度、循环和大小上限；
  - 给 AI 读取时展开嵌入。
- **清单**：类型可以声明 `"embed": true`（和 `drop` 一样，声明了才能注册处理函数）。
- **笔记插件**：提供 `embed`，按标题取节。
- **外壳**：在 Markdown 里画嵌入块；信息面板的“被引用”分成链接和嵌入两类。

### 第二步：书

- 外置插件 `org.onedesk.book`，或者内置（见 §9 第 3 条）：
  - 类型“书”；
  - 页面：目录加连续正文，滚动加载；
  - 编号、层级名称；
  - 导出 Markdown。
- 可能需要的内核接口（要确认）：
  - 一次读取一棵子树的结构（现在只能一层一层地读）；
  - 一次取一批资源的嵌入视图。

### 第三步

交叉引用编号、公式插件、文本展开 `{{@}}`、更多导出格式。

每一步都按规矩来：先写测试，在真内核里从“新建”开始走一遍，`pnpm check` 通过后再提交。

## 7. 和已有规则的关系

| 规则（spec §0） | 怎么满足 |
|---|---|
| 一切都是资源 | 书是资源，章节是现有的分组和笔记，素材是资源 |
| 每页可选环境 | 书的页面、嵌入内容都按标签页的环境显示 |
| 插件是模板 | 嵌入内容、书的正文都填 `{{名字}}` |
| 一个功能一个入口 | 引用内容只有 `![[ ]]` 一种写法；书的结构只在树上调整 |
| AI 按说明生成 | 不涉及；AI 能读到展开后的全文 |
| 不乱加东西 | 第一版只有嵌入、书、目录、编号和 Markdown 导出 |

## 8. 风险

- **大书的性能**：几千节、几十万字要连着显示，必须滚动加载，导出也要分批读。第二步会用 5000 节的假数据测试。
- **嵌入太多时的性能**：一个合同嵌入几十条法条，每条都要调一次插件。会按页面批量请求，并做上限。
- **笔记标题降级**：笔记里的 `#` 标题在书里要按层级往下降。超过 6 级的一律按 6 级显示。

## 9. 需要你定的

1. **写法**：用 `![[名称]]` / `![[名称#标题]]`，可以吗？
2. **引用的粒度**：按标题取一节够不够？还是还要能引用某一段（需要在段落后面加标记，如 `^条款36`）？推荐先按标题，以后再加。
3. **“书”插件内置还是外置**：推荐**内置**。书是组织内容的基础方式，和笔记、综合节点同一级。
4. **默认的层级名称**：推荐中文样式“编、章、节”，子书称“册”，每本书可以改。
5. **顺序**：先做第一步（通用嵌入），验收后做第二步（书），可以吗？

## 10. 第一步的实际做法（D481）

- **写法和引用表**：
  - `![[名称]]` 和 `![[名称#标题]]` 写在声明了 `refs: true` 的文本字段里；`\![[…]]` 是普通链接。
  - `#` 前面是名字，后面是节；`#` 在开头或结尾时属于名字（如 `C#`）；有资源恰好叫 `名称#标题` 时它优先。
  - 引用表**没有加列，也没有新迁移**：记的仍是写下的原文（含 `#标题`），是不是嵌入在读取时从原文判断。`refs.outgoing` / `refs.incoming` 增加 `embed`、`section` 两项。
  - 改名后显示新名字，节保留；先写后建的引用，建了同名资源就连上（`名称#…` 也一样）。
- **嵌入只做块级**：单独占一行的 `![[…]]`（不在代码块里）画成嵌入块；写在句子中间的 `![[…]]` 显示成链接。
- **显示**：
  - 新协议方法 `resource.embed { id, section?, envId?, locale? }` → `{ id, name, icon, kindLabel, description, view?, sectionMissing?, refs }`。
  - 清单的类型声明 `embed: true` 后，才能注册 `kinds.handle(kind, { embed(ctx, { section }) })`。
  - 返回的视图只能有 `text`、`table`、`link` 节点，最多 512 KB；不声明的类型只返回卡片需要的信息。
- **外壳**：
  - 设计系统新组件 `EmbedBlock`：标题点了打开原文，左边一条强调色。
  - `MarkdownText` 增加 `renderEmbed`。
  - 嵌入块里的 Markdown 再按被嵌入资源自己的引用画（`refs`），最多 3 层；同一资源在外层已经显示时只显示链接卡片（防循环）。
  - 原文或引用变了，嵌入块跟着刷新（订阅 `resource:<id>`）。
  - 信息面板的“引用”里，嵌入标“嵌入”和“› 节名”。
- **笔记插件**：
  - 声明 `embed`，按标题取节：从这个标题到下一个同级或更高级的标题，代码块里的 `#` 不算标题，标题比较不分大小写。
  - 按显示它的标签页的环境填 `{{名字}}`。
- **AI**：
  - AI 工作台读页面（`pages.fields`）时，字段原文保持不变（带着 `![[…]]` 标记，修改时保留），另附 `embeds: [{ mark, name, section, text }]`：每个嵌入行显示的文字，只给 AI 可见的资源，只展开一层，一个字段最多 50 个。
  - 对话的系统提示里列出这些内容，并要求修改时把这些行原样保留。
  - MCP 的 `describe` 还没展开嵌入。
- **测试**：
  - 内核：`crates/kernel/src/refs.rs`（解析）、`crates/kernel/tests/embed.rs`（引用表、改名、先写后建、按节显示、按环境填充、缺节、没有嵌入视图的类型、视图检查、必须声明、写作辅助读到的嵌入）；
  - 插件：`plugins/org.onedesk.note/main.test.ts`、`plugins/org.onedesk.ai/chat.test.ts`；
  - 外壳：`src/design/components/markdown-text.test.tsx`、`src/workbench/parts/embeds.test.ts`；
  - 界面（真内核，从“新建”开始）：`e2e/embed.spec.ts`，覆盖嵌入一节、按环境填充、原文修改和改名后跟着变、点标题打开原文、原文信息面板显示“嵌入”、缺节、目标不存在、嵌入自己。

# 第二轮设计（D482，待确认）

## 11. 为什么要第二轮

用户 2026-11-25 提出两个问题：
1. 书里定义了一个公式（如摄氏度换算华氏度），能不能在**别的书里拿来计算**一个温度？现在的嵌入只能显示，不能计算。
2. `![[名称]]` 是按名称引用的，名称会不会变？书多了以后，重名怎么办？

另外，图片也是一种要引用的内容，但系统现在**不能保存和显示图片**：资源的内容是 JSON，视图节点里没有图片；Markdown 为了安全不加载图片；导出格式里的 `blobs/` 文件夹还没有用上。

这几件事和书都有关系：书里会有公式、图片，会被别的书引用，章节标题会大量重名。所以先把它们设计好，再做书。

## 12. 精确引用：写的是名字，连上的是那个资源

### 12.1 现在的规则（不变）

- 第一次认出引用之后，记住的是资源本身（id），不再靠名字找（D323）。
- 改名：显示新名字，引用不断（D321）。
- 再建一个同名的：已经连上的引用不会被抢走。
- 删除后彻底清除：同名的新资源也不会自动接上（D330）。

### 12.2 要补的：第一次写下的那一刻不能猜错

现在如果有两个资源都叫“第一章”，内核按“同一分组优先，否则树里最靠上的”挑一个（D322），可能不是你想要的。补三件事：

1. **可以写路径**：`[[物理手册/附录/摄氏转华氏]]`。
   - `/` 分开的是从树根（或任意一层）往下的名字，从后往前匹配：只要最后几层对得上就算。名字本身含 `/` 时写成 `\/`。
   - 嵌入、节、参数都照常加在后面：`![[物理手册/附录/摄氏转华氏#说明]]`。
2. **输入时选定**：在支持引用的编辑框里（笔记正文等）输入 `[[` 或 `![[`，弹出候选列表。
   - 每个候选显示名称、类型和所在位置，比如“物理手册 › 附录”。
   - 选中后，插入**能唯一确定它的最短写法**：名字没有重复就只写名字，有重复就带上必要的上级。
   - 这是外壳的编辑功能，插件不用改。
3. **重名提醒**：保存时，如果某个引用写的名字同时对得上多个资源：
   - 信息面板的“引用”里标出“有 3 个同名，现在连到的是 物理手册 › 附录 › 摄氏转华氏”；
   - 旁边有“改成带路径的写法”，点一下把原文改成唯一的写法。
   - 不弹框、不阻止保存。

### 12.3 内核要做的

- 解析路径写法，按“从后往前”匹配上级的名字。
- 搜索结果（`resource.search` 和 `host.resources.search`）给出每个结果的**位置**（上级名字的列表），候选列表和重名提醒都用它。
- 引用信息（`RefInfo`）增加 `ambiguous`：写下的名字当前对得上几个资源（大于 1 时才给）。

## 13. 带参数的引用：一处定义，处处计算

### 13.1 写法

| 写法 | 显示 |
|---|---|
| `![[摄氏转华氏]]` | 公式本身（现在的嵌入） |
| `![[摄氏转华氏 \| C=37]]` | 嵌入块：公式，加上这次的计算 `C = 37 → F = 98.6` |
| `[[=摄氏转华氏 \| C=37]]` | **行内结果**：在句子里只显示 `98.6 °F`，可以点开看公式 |
| `[[=摄氏转华氏 \| C={{室温}}]]` | 参数取当前标签页环境里的 `室温` |

- `|` 后面是 `名字=值`，用逗号分开。值可以是数字、文字（含空格时用引号）或 `{{环境参数}}`。
- **不嵌套**：第一版里，参数不能是另一个调用的结果。以后需要再加。
- 节和参数可以一起用：`![[税率表#2026 \| 收入=120000]]`。

### 13.2 内核：只负责把参数交出去

- 引用解析认识 `|` 和 `[[=…]]`：名字在 `|` 和 `#` 之前；参数原样记在引用表的原文里（和节一样，不加列）。
- `resource.embed` 增加 `args`（名字到值的表，`{{…}}` 已经按标签页的环境填好）和 `inline`（行内）。插件的 `embed(ctx, { section, args, inline })` 返回：
  - 块：和现在一样，`{ view }`；
  - 行内：`{ text }`，一行，最多 200 字；出错时 `{ text, error: true }`，外壳把它标红。
- 被引用的插件自己检查参数，缺了或不合法就在结果里说明。内核不认识“公式”，也不认识参数的含义。
- **任何类型都可以带参数**：
  - 公式：算一个值；
  - SQL 查询：嵌入它带参数的结果表（运行用的是那个资源保存的语句，只读）；
  - 税率表、单位换算、标准条款里的金额：都是同一个机制。
- **缓存**：同一个资源、同一个版本、同样的参数和环境，结果缓存起来，原文一改就失效。

### 13.3 和已有规则的关系

- **环境**：参数里的 `{{…}}` 和被引用内容里的模板，都按**显示它的标签页的环境**填。
- **AI**：读页面时，带参数的引用展开成“调用写法 → 结果”。
- **反查**：原文的信息面板里，“被引用”标出“调用”，并显示每处用的参数。改公式之前，就知道会影响哪些计算。

## 14. 公式插件（内置 `org.onedesk.formula`）

### 14.1 一个公式就是一个资源

```
┌ 摄氏转华氏 ─────────────── [环境 ▾] │ 保存 ┐
│ 参数                                            │
│   名字   说明      单位   默认值                │
│   C      摄氏温度   °C     20                   │
│ 公式                                            │
│   F = C × 9 / 5 + 32          单位 °F  小数 1位  │
│ 试算   C [ 37 ]   →   F = 98.6 °F               │
└─────────────────────────────────────────────────┘
```

- **参数**：名字、说明、单位、默认值；直接在表里加行（规则 4 的做法）。
- **公式**：一行或几行，后面的行可以用前面算出的名字，最后一行是结果：
  ```
  K = C + 273.15
  F = C × 9 / 5 + 32
  ```
- **试算**：页面上直接填参数看结果。这是视图状态，不保存，不进运行记录。
- 默认值可以写 `{{环境参数}}`，跟着环境变（规则 3）。
- 说明写在信息面板里；AI 按说明可以写出公式（规则 6）。

### 14.2 计算

- 插件**自己解析表达式**，不执行任何代码，不用 `eval`：
  - 数字、`+ - × / ^ %`、括号；
  - 常用函数：`abs round floor ceil min max sqrt pow exp ln log10 sin cos tan`；
  - 常数：`pi`、`e`。
- 错误（缺参数、除以零、不认识的名字）给出能看懂的说明。
- 单位第一版只是文字标签，不做单位换算检查。

### 14.3 被引用时

- `![[摄氏转华氏]]`：显示公式和参数表。
- `![[摄氏转华氏 | C=37]]`：显示公式，加上这次的参数和结果。
- `[[=摄氏转华氏 | C=37]]`：只给结果 `98.6 °F`。

### 14.4 公式的显示

- 第一版用**等宽文字**显示公式：`F = C × 9 / 5 + 32`。乘号、除号、上标用 Unicode 显示。
- 排版成教科书那样的数学公式，需要一个排版库（如 KaTeX，MIT 许可）。按规则 9 要先记录依赖，所以放到以后，单独决定。

## 15. 图片

### 15.1 为什么只做一个插件不够

- 资源的内容是 JSON：图片转成文字塞进去，体积大三分之一，还会进搜索索引、修改历史和每一次读取。
- 视图节点里没有图片；插件也没有办法把文件交给界面。
- 界面不能直接读硬盘（安全规则：读硬盘的只有内核，而且只读授权过的文件夹）。

所以分两层：**内核提供“附件”和图片节点，插件负责“图片”这种资源。**

### 15.2 内核：附件

- **附件存储**：每个资源可以带附件（文件）。
  - 文件内容存在工作区的 `blobs/` 文件夹里，按内容的 SHA-256 命名：同样的图片只存一份。
  - 新表 `attachments`：属于哪个资源、名字、类型、大小、哈希。只新增迁移，并附升级测试（规则 6）。
- **宿主接口**（需要清单里 `requires.attachments`）：
  - `host.attachments.add(resourceId, { path })`：从授权文件夹里的文件添加；
  - `host.attachments.add(resourceId, { bytes, name, type })`：给粘贴、截图用，内容用 base64 传；
  - `list`、`remove`。
- **限制**：
  - 第一版只收 png、jpeg、gif、webp，按文件内容判断，不看扩展名；svg 能带脚本，第一版不收；
  - 单个 20 MB，每个资源最多 200 个附件。
- **历史与导出**：
  - 换一张图片记进修改历史；旧图片在资源被彻底清除之前一直保留，所以能恢复。
  - 导出工作区时，附件写进 `blobs/`；导入时一起带回。
- **给界面**：新协议方法 `attachment.read { resourceId, name }` 取文件内容。界面用它显示，不经过插件。

### 15.3 视图节点 `image`

- 写法：`{ type: "image", id, resource?, attachment, alt?, width? }`。
  - `resource` 省略时是当前资源；
  - `width` 是 `小`、`中`、`大`、`原始`，不用像素，规则 3 不许写死像素。
- 内核检查：那个附件确实存在，而且插件可以读它（自己的资源，或者它正在画的资源）。
- 文件插件的“硬盘文件”如果是图片，也用这个节点显示：内核从授权文件夹里读，不复制成附件。

### 15.4 图片插件（内置 `org.onedesk.image`）

- 新类型“图片”：
  - 新建时选文件（系统对话框），或者把图片拖进窗口、粘贴截图；
  - 页面显示图片、尺寸、大小，说明写在信息面板里。
- **被引用**：`![[电路图]]` 显示图片；`![[电路图 | 宽=小]]` 指定大小（用的就是 §13 的参数）。
- **笔记里贴图**：在笔记里粘贴截图，就成为这篇笔记的附件，并自动插入 `![截图](附件:截图-1.png)`。
  - Markdown 只显示**本资源附件**里的图片；外部地址照旧不加载（安全不变）。
  - 要在多处用的图，建成“图片”资源再引用；只在一篇里用的截图，留作这篇的附件。
- **AI**：图片不发给 AI，只发说明文字。以后服务商接口支持图片时再说。

## 16. 新的先后顺序

| 步 | 内容 | 主要改动 |
|---|---|---|
| ① | 精确引用（§12）：路径写法、输入时选定、重名提醒 | 内核引用解析、搜索给位置、外壳编辑框 |
| ② | 带参数的引用和公式插件（§13、§14） | 引用解析、`resource.embed` 加参数、公式插件 |
| ③ | 图片（§15）：附件、`image` 节点、图片插件、笔记贴图 | 内核附件和迁移、协议、外壳、两个插件 |
| ④ | 书（§4） | 书插件；它用到上面的一切 |

每一步都单独设计确认的细节（插件清单、协议字段），先写测试，在真内核里从“新建”开始走一遍，然后再交给你验收。
