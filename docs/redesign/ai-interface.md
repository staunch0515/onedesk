# AI 接口（MCP）设计——待用户确认（2026-11-19，第四个协调会话起草）

对应 `sqlpool-parity.md` 的 X11 和 K 组；`dev-plan.md` 阶段 6 “先做”。**用户确认前不开发。** 文末 §8 是需要你拍板的几处，其余是我按现有设计的默认做法。

## 1. 要解决什么

让外部的 AI 客户端（Claude Desktop、Claude Code 等支持 MCP 的程序）**只读地**用 OneDesk 里的东西：找到保存的查询、看它要什么参数、用指定环境运行它、读结果；sqlpool 现在的 MCP 服务有五个工具（`search_queries`、`describe_query`、`run_query`、`list_tables`、`run_sql`），日常就是这么用的。OneDesk 版要做到同样的事，但：
- 不认识任何具体插件——工具由插件声明，内核按声明生成；
- AI 只能碰用户标记过的东西，每次调用都留审计；
- 应用开着或没开都能用。

## 2. 进程怎么走

- 新增一个很小的命令行程序 `onedesk-mcp`（随应用一起打包，在 `.app` 里），Claude Desktop 的配置里写它的路径；它通过标准输入输出说 MCP。
- 应用开着：它连到主进程（本机套接字，按用户身份校验），主进程转给对应工作区的工作进程——和窗口一样是一个“连接”，只是操作者不同。
- 应用没开：它自己启动一个无界面的工作进程（同一个内核、同一个工作区锁规则），用完退出。应用此时启动会等它释放锁（或反过来）——沿用现有的“一个工作区一个工作进程”。
- 跑的都是同一个内核，所以权限、审计、插件沙箱完全一致。

## 3. 谁能看到什么

- 操作者类型 `ai`（内核早已留了位置）。
- **资源**：只看得到标了“对 AI 可见”的资源（资源已有 `ai_visible` 字段；信息面板加一个开关，默认关）。
- **动作**：只能运行插件在清单里声明为“AI 可用”的动作，且只能是**只读**的（清单声明 `ai: { readOnly: true }`，插件对它负责；内核再拒绝 AI 操作者的一切写入命令）。
- **环境**：用户在工作区配置里指定“AI 用的环境”（一个引用参数）；AI 不能选别的环境，也看不到环境里的密钥值（插件运行时照常取密钥，结果里不回显）。
- **策略** `ai.policy`（工作区配置）：总开关（默认关）、每分钟调用上限、单次结果行数上限、是否允许“自由查询”（见 §8 第 2 条）。
- **审计**：每次调用记一条（工具名、参数摘要、结果行数、耗时、成功与否），审计页可按操作者 `ai` 过滤。

## 4. 工具从哪里来

内核提供几种固定的“通用工具”，插件只声明“我的哪些东西可以接到这些工具上”：

| 工具 | 做什么 | 来自 |
|---|---|---|
| `search` | 按文字找对 AI 可见的资源（名称、说明、标签、正文），可按类型过滤 | 内核（全文索引） |
| `describe` | 一条资源的说明、类型、参数（名字、类型、必填、说明、可选值） | 内核 + 插件的参数声明 |
| `run` | 用“AI 用的环境”运行一条资源上声明为 AI 可用的动作，给参数，取回结果（表格或文字，按上限截断） | 内核的运行机制 |
| `get_run` | 读一次运行的结果（长结果分页） | 内核 |
| 插件工具 | 插件额外声明的只读工具（如“列出映射过的表及字段”） | 插件清单 `aiTools`，由插件实现，运行在沙箱里 |

插件额外工具的名字自动加插件前缀，避免撞名；参数用 JSON Schema 声明，内核校验后才交给插件。

## 5. 和 sqlpool 的对应

`search_queries` → `search`；`describe_query` → `describe`；`run_query` → `run`；`list_tables` → 表插件的 `aiTools`；`run_sql` → 见 §8 第 2 条。

## 6. 安全上的底线

- 默认全关：总开关关、资源默认不可见、动作默认不可用。
- AI 操作者的任何写入、删除、安装、改设置、读密钥值的请求，内核一律拒绝（不靠插件自觉）。
- 结果在离开内核前按策略截断。内核无法从任意结果里认出密钥值，所以“结果里不出现密钥”靠代入规则（`{{secret:…}}` 只在宿主里代入，插件拿不到值、也不回显），审查时专门查。
- `onedesk-mcp` 只接受本机标准输入输出，不开网络端口。

## 7. 要做的东西（确认后排进第十八轮）

内核：操作者 `ai` 的连接与权限检查、通用工具、`ai.policy`、审计；清单 `ai` 声明与 `aiTools`；无界面工作进程的启动方式。主进程/打包：`onedesk-mcp` 程序与连接校验。外壳：资源的“对 AI 可见”开关、工作区配置里的 AI 设置页、审计过滤。插件：SQL、查询目录、表插件的 AI 声明。测试：用一个假的 MCP 客户端（标准输入输出）连真内核跑每个工具和每条拒绝。

## 8. 需要你决定的

1. **一次连几个工作区？** 我的默认：`onedesk-mcp` 启动参数指定一个工作区（不指定就是默认工作区）；要用多个就在 Claude Desktop 里配多条。
2. **“自由查询”（sqlpool 的 `run_sql`：AI 自己写 SELECT 跑在映射过的表上）要不要？** 我的默认：**要，但默认关**——作为表插件的一个 `aiTools`，只在 `ai.policy` 打开“允许自由查询”后可用；仍然只读执行（`BEGIN READ ONLY … ROLLBACK`、超时、行数上限），并沿用 sqlpool 的词法检查（只允许单条 SELECT/WITH）。
3. **应用没开时也能用？** 我的默认：能（与 sqlpool 一样）。代价是要处理“AI 正在用时打开应用”的等锁；如果你更想要“只在应用开着时可用”，实现会简单一些。
4. **资源默认对 AI 不可见、要逐条打开**，还是**按类型或分组一次打开**？我的默认：两种都给——信息面板逐条开关，加上分组节点上“对 AI 可见（含下级）”。
