## 0. 必须遵守的原则

1. **书只负责装订。**
   - “书”这个类型只管两件事：书里有哪些页、按什么顺序；每一页担当什么角色。
   - 书的代码里**不写**任何角色的逻辑：怎么浏览、怎么编号、怎么发布、答案什么时候公开，都不写在书里。
2. **逻辑放在担当它的角色里。**
   - 实体书里哪一部分负责这件事，OneDesk 里就由那一类页负责：
     - 浏览和编号是**目录**的事；
     - 版本和发布是**版权页**的事；
     - 书给人看的样子是**封面**的事；
     - 引文是**参考文献**的事。
   - 同一个插件提供的几种角色，代码也分开写，互不伸手。
3. **加功能就是加角色，换功能就是换角色。**
   - 新的玩法一律做成新的页类型，比如“课本目录”“答案附录”“运行页”。
   - 不在书上加开关、加设置、加模式。
   - 想换一种浏览方式，就换一个目录页。
4. **先问实体书怎么做。**
   - 设计任何一个功能，先看实体书和出版规范里有没有现成的做法，有就照做，例如：
     - 结构：前面的部分、正文、后面的部分；
     - 编号：章节号、附录号、图表号；
     - 版次和印次；
     - 学生用书和教师用书；
     - 参考文献的著录规则（GB/T 7714）；
     - 书名页和版本记录（GB/T 12450）。
   - 实体书没有的东西（比如能运行的页），也按“它在书里担当什么角色”来想。
5. **内核不认识书。**
   - 书和各角色之间，通过书插件定义的**插件接口** `onedesk.book/1`（spec §3.5 的 `implements` / `uses`）配合。
   - 内核只提供通用能力：读子树、读内容、连续显示的视图节点、发布与只读副本等（§10）。
   - 内核里不出现“书”“目录”“章”这些词（硬性规则 1）。
6. **任何资源都能当页。**
   - 没有实现书接口的资源（笔记、图片、SQL 查询……）放进书里，都按**正文**处理，用嵌入（D481）显示。
   - 它本来能做的事，在书里照样能做（比如 SQL 查询能运行）。
7. **产品要求照旧**（spec §0）：
   - 一切都是资源，都有信息面板；
   - 每页可选环境；
   - 一个功能一个入口；
   - 不乱加东西；
   - 不显示内部名字；
   - 从“新建”开始真走一遍。

## 1. 参照：实体书的结构

| 部分 | 实体书里的组成 | 担当的角色（§3） |
|---|---|---|
| **前面的部分** | 封面、书名页、版权页（版本记录）、序、前言、目录、插图目录 | 封面、版权页、前言、目录、图表目录 |
| **正文** | 篇、章、节；正文；图、表、公式、例题；脚注 | 正文页；篇、章用分组 |
| **后面的部分** | 附录、参考文献、索引、后记、（课本的）习题答案 | 附录、参考文献、索引、后记、答案附录 |
| **套书** | 丛书、文集、多卷书（第几卷第几册）、配套练习册、教师用书 | 子书；版权页里的“版本”（学生版、教师版） |

几条照搬的规矩：
- **顺序固定**：前面的部分 → 正文 → 后面的部分。
- **编号**：
  - 正文编“第 X 章”；前言、序、后记不编号；附录编 A、B、C；
  - 图、表、公式按章编号（图 2-1、表 3-2、式（2-3））。
- **版次与印次**：内容改了是新的一版；内容不变、只是重新发一遍，是同一版的新一次印刷。
- **学生用书和教师用书**：教师用书多出答案和教学说明。

## 2. 书：只负责装订

| 项 | 内容 |
|---|---|
| 类型 | **书**（`org.onedesk.book` 的 `book`）：放在资源树，可以拖动；接受任何子节点；书里的书就是**子书** |
| 装订顺序 | 书按每一页的角色所在的部分（§3）维持“前面的部分 → 正文 → 后面的部分”。<br>• 往书里拖页时，落在它所属的部分之内；比如附录拖不到正文前面，会落到后面的部分的开头。<br>• 同一部分内的顺序就是树上的顺序，由用户拖动决定。<br>• 这是装订的规矩，所以由书管 |
| 打开书 | 看到的是它的**封面**页（§3.1）。没有封面时，显示书名和“开始阅读”。<br>“开始阅读”打开书的**目录**页的浏览（§4）。没有目录时，按装订顺序显示一个最简单的列表 |
| 被引用 | `![[书名]]` 显示封面给出的样子（§3.1）；`![[书名#第三章]]` 由目录解答（§4.5） |
| 新建 | “新建 → 书”：建好后自带一页**封面**、一页**目录**（实体书都有）。两页都能删、能换成别的类型 |
| 书自己存什么 | 只有名字。作者、版次等写在封面和版权页里，不写在书上 |
| 子书 | 子书有自己的封面、目录。外层的目录浏览到子书时，向子书的目录要它的内容（§4.4） |

## 3. 角色

每一页的角色由它的**类型**决定，类型在接口里声明（§5）。

| 角色 | 部分 | 一本书里 | 编号 | 由谁提供 | 带的逻辑 |
|---|---|---|---|---|---|
| **封面** | 前 | 最多 1 | 无 | 书插件 | 书给人看的样子 |
| **版权页** | 前 | 最多 1 | 无 | 书插件 | 版次、印次、发布、学生版和教师版 |
| **前言**（序、前言、致谢） | 前 | 不限 | 无 | 书插件 | 书外的话 |
| **目录** | 前 | 最多 1 | 无 | 书插件；别的插件可以提供别的目录 | 浏览、编号、阅读位置、交叉引用、导出 |
| **图表目录** | 前 | 最多 1 | 无 | 书插件 | 列出全书的图、表、公式 |
| **正文页** | 正文 | 不限 | 按章 | 书插件 | 内容、脚注、自己里面的图表 |
| **篇、章（分组）** | 正文 | 不限 | 按层级 | 内核的分组 | 只是容器 |
| （任何其他资源） | 正文 | 不限 | 按章 | 各插件 | 它本来的样子 |
| **附录** | 后 | 不限 | A、B、C | 书插件 | 自己的编号方式 |
| **参考文献** | 后 | 最多 1 | 无 | 书插件 | 文献条目、正文里的引注 |
| **索引** | 后 | 最多 1 | 无 | 书插件 | 收集标出的词 |
| **后记** | 后 | 不限 | 无 | 书插件（前言的一种） | 书外的话 |
| 练习页、测验页 | 正文 | 不限 | 按章 | 练习插件 | 作答、判分（§7） |
| 答案附录 | 后 | 不限 | A、B、C | 练习插件 | 只在教师版；公布（§7） |
| 课本目录 | 前 | 最多 1 | 无 | 练习插件 | 按课浏览、进度和得分（§7） |
| 计算页 | 正文 | 不限 | 按章 | 公式插件 | 参数和计算（§8） |
| 运行页、流程目录 | 正文、前 | — | — | 以后（§8） | 活书 |

**“最多 1”**：书里已经有一页目录时，再拖进一页目录，会提示“这本书已经有目录了，要替换吗？”。

### 3.1 封面

- **内容**：书名（就是书的名字）、副书名、作者（著、编、译，可以几位）、封面图（图片，D484）、一句简介。
- **页面**：照封面的样子排版显示；编辑时就是这些字段。
- **书的样子**：
  - 被 `![[书名]]` 引用、在资源列表里预览时，显示封面图、书名和作者；
  - 书的页面也显示它。
- 被引用时显示成什么样，是封面的职责；想换样子，就换一种封面。

### 3.2 版权页

- **内容**：书名、作者、出版者（可以是个人或单位）、版次和印次、发布记录、ISBN（可选）。
- **发布**（§6）在这里做：“发布新版”“重新印刷”；版本历史在这里看。
- **版本**：
  - 默认只有一种。
  - 课本可以设“学生版”“教师版”：在版权页里列出每种版本包含哪些角色的页。默认所有页都进两种版本，答案附录只进教师版。
- 没有版权页的书不能发布。第一次点“发布”时，自动加一页版权页。

### 3.3 前言、后记

- 普通的文字页（和正文页同一种写法），但**不编号**。
- 前言在“前面的部分”，后记在“后面的部分”，由它们选的种类决定：序、前言、致谢在前，后记在后。

### 3.4 正文页

专属于书的笔记，比普通笔记多三样：

1. **脚注**：`[^1]` 和 `[^1]: 注释的内容`。浏览时在这一页的末尾（以后可以由目录决定排成脚注还是尾注）。
2. **图、表、公式的题注**：
   - 写法：`![[电路图]]` 下面一行 `图：并联电路`，或者表格上面一行 `表：电阻值`。
   - 正文页把这些**告诉目录**（§5 的 `outline`），由目录编成“图 2-1”。
3. **索引词**：`{{索引:勾股定理}}`。阅读时不显示，由索引页收集。

- 拖出书外，正文页仍然是一篇能用的页，只是不再编号。
- 普通笔记放进书里也可以，只是没有上面三样。

### 3.5 附录

- 一个容器，像章一样，下面放正文页或任何资源。
- 编号方式由附录自己定：“附录 A”“附录 B”，里面的图编“图 A-1”。

### 3.6 参考文献

- **条目**：每条有作者、题名、出处、年份、类型（专著、期刊、网页……），按 GB/T 7714 的格式显示。
- **引注**：正文页里写 `[@张三2020]`。显示成什么样（“[3]”还是“（张三，2020）”），问参考文献页。
- **列表**：只列正文里引用过的，或者全部列出，由参考文献页自己设。

### 3.7 索引、图表目录

- **索引**：从全书各页收集索引词（§3.4），按拼音排序；每个词后面是出现的位置，点了跳过去。
- **图表目录**：从目录拿到全书图、表、公式的编号和题注，列出来。

## 4. 目录：浏览和编号

全书怎么读、怎么编号，都是目录的事。

### 4.1 浏览

目录页打开时，左边是目录树，右边是**浏览区**。书插件自带的目录有两种浏览方式，在目录页上切换，切换的结果是这一页的设置：

| 方式 | 样子 |
|---|---|
| **连续** | 从头到尾一页接一页往下滚，看得见的部分才加载（`sequence` 节点，§10） |
| **分页** | 一屏一页，“上一页”“下一页”，键盘左右键翻页；页码 `12 / 86` |

- 点目录里的任何一项，浏览区跳到那里。
- **阅读位置**：每个读者记住自己读到哪里，下次打开回到那里。
- 每一页标题旁有“打开”，在新标签页里打开那一页本身去编辑。

### 4.2 编号

- **目录汇总编号**：每种角色在接口里说明自己怎么编号（§5），目录按书里的位置把编号算出来。
  - 正文部分：按层级，层级名称默认“编、章、节”，更深的层用“1.2.3”；也可以选“1、1.1、1.1.1”或不编号。
  - 附录：按附录自己的方式（A、B、C）。
  - 前言、后记、封面等：不编号。
  - 图、表、公式：按章，“图 2-1”；附录里“图 A-1”。
- 编号**不写进任何页**；调整顺序后，编号自动跟着变。

### 4.3 交叉引用

- 正文页里写 `[[电路图]]`、`[[第三章的名字]]`，在书里显示成“图 2-1”“第三章”。
  - 被引用的东西在书里，显示编号；不在书里，照常显示名字。
- 显示什么，由正文页问目录（§5 的 `number`）。

### 4.4 子书

- 外层目录浏览到一本子书时，向子书的目录要它的目录项和编号。
- 子书**重新编号**，用它自己目录的设置；子书本身编“第一册”“第二册”，叫法在外层目录里设（默认“册”）。
- 文集、丛书、多卷书都是这样一层套一层。

### 4.5 被引用、导出

- `![[书名#第三章]]`：目录给出第三章的连续内容（不带目录栏）。
- `![[书名的目录]]`：目录页的嵌入，就是带编号的目录列表。
- **导出**：按目录的顺序和编号，把全书写成一个 Markdown 文件，图片放在旁边的文件夹（导出到授权文件夹）。
  - 导出是“按目录印一份”，所以由目录负责；
  - 书有几种版本时，导出前选导出哪一种（版本由版权页给出）。

### 4.6 别的目录

别的插件提供另一种目录，就换来一种读法：
- **课本目录**（练习插件，§7）：按课浏览，每课旁边是进度和得分。
- **幻灯目录**（以后）：一屏一页，全屏放映。
- **流程目录**（以后，§8）：从上到下一页页运行。
- **手册目录**（以后）：带搜索、只显示当前这一章。

## 5. 接口 `onedesk.book/1`

书插件定义这个接口。每种能放进书、又想担当角色的类型，由它的插件实现。下面是接口的动作，用 `host.interfaces.call` 调用：

| 动作 | 谁实现 | 谁调用 | 作用 |
|---|---|---|---|
| `roles` | 每个提供书页类型的插件 | 书、目录 | 返回 `[{ kind, role, part, numbering, single }]`：每种类型担当什么角色，在哪一部分，怎么编号，一本书里能有几页 |
| `outline` | 想被编号、被收集的类型（正文页、附录、练习页……） | 目录、索引、图表目录、参考文献 | 给出一页里面有什么：小标题、图表的题注、索引词、引注，以及它们的位置 |
| `number` | 目录 | 正文页（交叉引用）、图表目录 | 某一页或某个位置在这本书里的编号 |
| `entries` | 目录 | 外层书的目录（子书） | 这本书的目录项和编号 |
| `cite` | 参考文献 | 正文页 | 引注显示成什么 |
| `editions` | 版权页 | 目录（导出）、练习插件（公布） | 这本书有哪几种版本、每种包含哪些页 |

几条规矩：
- **只按角色找**：调用方先在书的子树里找到担当那个角色的页，再调用那个页的插件。从不写死某个插件的名字。
- **没实现接口的资源**：按正文、按章编号；`outline` 只取它的名字。
- **接口要定版本**：以后改不兼容就升到 `onedesk.book/2`。接口的修改由主会话决定，记进 decisions.md（硬性规则 10）。

## 6. 版本与发布（版权页）

- **发布新版**：版次加一；把整本书（按版权页定的版本）发布成文件。内核的 K9（§10）做实际的打包。
- **重新印刷**：内容没改、再发一遍时，印次加一。
- **读者那里**：导入后是书的**只读副本**，版权页显示“第 2 版第 1 次印刷 · 来自 某某”。作者改书不影响读者，直到读者导入新版。
- **一台电脑上**：作者和读者各用一个工作区，发布成文件、导入（`documents.md` §19.7 的流程不变）。以后接网络，换成订阅，文件格式不变。
- **学生版、教师版**：发布时选版本。学生版不含只进教师版的页（比如答案附录）。

## 7. 课本：练习插件加的角色

需求见 `documents.md` §19，仍然有效。按角色来分：

| 角色 | 带的逻辑 |
|---|---|
| **题**（资源） | 题干、空、判题规则、分值、提示、知识点；**答案、讲解**是“只进教师版”的字段（§10 的 K10） |
| **练习页** | 一节后面的“练一练”：几道题，书上直接做 |
| **测验页** | 一组题加上设置：答案什么时候给、能做几次、限时 |
| **作答**（资源，练习插件的树“作答”） | 学生做一次测验留下的：每题的答案、判定、得分、时间。**作答是练习插件自己的事，书不知道** |
| **答案附录** | 后面的部分；只进教师版。**公布答案**就是作者在答案附录里选“公布到第三单元”，然后重新印一次学生版：学生版里的答案附录多了已公布的那几个测验的答案，学生导入后自动判分 |
| **课本目录** | 按课浏览；每一课旁边显示进度和得分；“继续上次” |
| 成绩、错题本 | 练习插件的树“作答”里的两个页面，从作答里算 |

这样，**“老师公布答案”不需要任何特殊机制**：它就是答案附录进了学生版的新一次印刷。实体课本也是这样，答案在教师用书里，到时候才发给学生。

“交卷后”“每题答完”这两种马上就要判的方式，才需要把加密的答案提前发过去（K10 的指纹和密文，`documents.md` §21.2）。这两种只适合练习。

## 8. 活书：以后加的角色

- **计算页**（公式插件）：参数和计算，书里别的页可以引用它的结果。
- **运行页**：一个步骤，可以运行（HTTP、SQL、命令、AI……），结果传给后面的页，可以写期望（`@状态码 = 200`）。
- **流程目录**：一种目录。它的“浏览”就是从上到下一页页运行，有条件跳过、等人确认、失败就停，不做循环和跳转。跑一遍留下一份运行记录，可以导出成报告。

全部都是新的角色。书和书插件已有的角色都不用改。

## 13. 第②步详细设计：书和基本角色（已确认，已实现）

> 范围：book.md §11 第②步。做完后能用：文集、手册、带前言和附录的书，连续或分页阅读，编号，导出。
> 不在这一步：
> - 交叉引用、图表目录、参考文献、索引（第③步）。接口的 `number` 动作随交叉引用放到第③步。
> - 版权页和发布（第⑥步）。

### 13.1 这一步的角色和类型

都由书插件 `org.onedesk.book`（内置）提供。每种角色的代码各放一个文件（§0 第 2 条），书本身的文件里只有装订。

| 类型（短名） | 角色 | 部分 | 一本书里 | 编号 | 能放子节点 | 文件 |
|---|---|---|---|---|---|---|
| `book` 书 | 书（子书） | 正文 | 不限 | “第一册”（叫法由外层目录定） | 任何 | `book.js` |
| `cover` 封面 | 封面 | 不进阅读 | 最多 1 | 无 | 否 | `cover.js` |
| `toc` 目录 | 目录 | 不进阅读 | 最多 1 | 无 | 否 | `toc.js` |
| `preface` 前言 | 前言（序、前言、致谢） | 前 | 不限 | 无 | 否 | `text-page.js` |
| `afterword` 后记 | 后记 | 后 | 不限 | 无 | 否 | `text-page.js` |
| `page` 正文页 | 正文 | 正文 | 不限 | 按层级 | 否 | `text-page.js` |
| `appendix` 附录 | 附录 | 后 | 不限 | A、B、C | 任何 | `appendix.js` |
| 分组（内核） | 篇、章 | 正文（在附录里属于附录） | 不限 | 按层级 | 任何 | — |
| 其他任何资源 | 正文 | 正文 | 不限 | 按层级 | 照它自己 | — |

- **封面和目录不进阅读**：目录就是阅读本身；封面是打开书时看到的。
- 实体书的书名页和版权页合在第⑥步的版权页里。

### 13.2 书 `book`

| 项 | 内容 |
|---|---|
| 清单 | `tree: "resources"`，`page: "book"`，`draggable`，`accepts: ["*"]`，`embed: true`，`place: true`（§13.9 K-c），`defaults: {}`，没有字段 |
| 新建 | “新建 → 书”。保存后，书插件收到 `resource.changed`（`created`），在书下面建一页“封面”和一页“目录”（各自的 `newName`）。用户删掉它们也可以 |
| 页面 `book` | 封面给出的样子（§13.3），下面两个按钮：<br>• **开始阅读**：打开目录，从头开始；<br>• **继续阅读**：有阅读位置时才有，打开目录并回到上次的位置。<br>没有封面时显示书名；没有目录时，开始阅读按钮换成“加目录”。不放别的东西 |
| 装订（`place`） | 一页被拖进书、在书里拖动、在书里新建时，内核问书“它落在哪里”。书按这页的角色所在的部分（前、正文、后、不进阅读）把落点限制在那一部分之内：<br>• 封面、目录放在最前；<br>• 前言跟在它们后面，然后是正文；<br>• 附录、后记放在最后。<br>拖到别的部分里时，落到自己那一部分最靠近的位置。<br>“最多 1”的角色已经有了，再拖进来时提示“这本书已经有目录了”并拒绝（替换由用户先删再拖） |
| 嵌入 | `![[书名]]`：封面的样子。`![[书名#某一章]]`：交给目录（§13.4.6） |
| 代码 | 只有装订：角色表、`place`、新建时补两页、打开时把页面交给封面和目录 |

### 13.3 封面 `cover`

- **字段**：
  - 副书名（`text`）；
  - 作者（`text`，几位用顿号隔开，例：“鲁迅 著、张三 编”）；
  - 封面图（`attachment`，`accept: ["image"]`，D484）；
  - 简介（`longtext`）。
- **页面 `cover`**：一个表单，就是上面四个字段。书名就是外层书的名字，不在这里改，显示成只读的一行，旁边提示“书名就是书的名字”。
- **样子**：书插件里封面模块的一个函数 `face(书, 封面)`，返回：
  - 图片节点（有封面图时，宽度“中”）；
  - 一段 Markdown：`# 书名`、副书名、作者、简介。

  书的页面和 `![[书名]]` 都用它。以后换一种封面，换的就是这个函数。
- **没有封面时**：只显示书名。

### 13.4 目录 `toc`

#### 13.4.1 字段（目录的设置）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 编号 `numbering` | `enum`：中文、数字、不编号 | 中文 | |
| 层级名称 `levels` | `text` | `章,节` | 用逗号分开，从书下面第一层开始。更深的层用“1.2.3” |
| 子书的叫法 `volume` | `text` | `册` | 子书编“第一册”“第二册” |

这三项显示在目录页顶上的一行（紧凑的表单行），不放在别处。

#### 13.4.2 页面 `toc`

```
┌ 目录 ─────────────────────────── [环境 ▾] │ 连续/分页  导出 ┐
│ 编号 [中文 ▾]  层级名称 [章,节]  子书的叫法 [册]               │
│ ┌ 目录栏 ─────────┐ ┌ 浏览区 ───────────────────────────────┐ │
│ │ 前言             │ │ 第一章  秒的认识                [打开] │ │
│ │ 第一章 秒的认识  │ │ （正文页的内容）                       │ │
│ │   第一节 …       │ │ 第一节  …                       [打开] │ │
│ │ 附录 A 换算表    │ │ …                                      │ │
│ └─────────────────┘ └───────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```
- **操作栏**：
  - “连续 / 分页”是切换按钮，存在页面的视图状态 `view.mode` 里（§6.5），页面里不再放同样作用的控件；
  - “导出”是一个动作（§13.4.7）。
- **浏览区**：一个 `sequence` 节点（§13.9 K-d），带目录栏。
- **书里还没有可读的页时**，浏览区显示：“把正文页、笔记或任何资源拖到这本书下面”。
- **目录不在书里**（被拖出来了）时，显示：“这页目录不在任何书里”。

#### 13.4.3 目录项怎么算出来（`entries`）

1. 用 K7 的 `host.resources.tree(书)` 按树的顺序读出书下面的全部节点。
2. 定每个节点的角色：
   - 书插件自己的类型，查 §13.1 的表；
   - 别的插件的类型，如果它的插件实现了 `onedesk.book/1`，问它的 `roles`（每次计算每个插件只问一次）；
   - 都不是，就是正文。
3. 跳过“不进阅读”的（封面、目录）。子书不往下展开节点，而是问子书的目录要它的目录项（§13.4.5）。
4. 按部分排：前 → 正文 → 后；同一部分内按树的顺序（装订已经保证了这个顺序，这里再排一次是为了保险）。
5. 编号（§13.4.4），得到每一项：
   ```js
   { key, resource, title, number, level, part, book? }
   ```
   - `title` 是“编号 + 空格 + 名字”；
   - `level` 从 1 开始，是在书里的深度；
   - 子书的书名项带 `book: true`。
6. 最多 20 000 项，多的截断，目录栏最后一项写“（还有 N 项未列出）”。

#### 13.4.4 编号的规则

**正文部分**：
- 按深度：书下面第一层是第 1 层。每个上级下面分别计数，分组、正文页、其他资源一起数。
- **中文**：第 n 层有层级名称时编“第一章”“第二节”；超过层级名称的层数，编成从第 1 层起的数字路径“2.1.3”。
- **数字**：一律“2”“2.1”“2.1.3”。
- **不编号**：只有名字。
- **子书**单独计数，不占章的号：“第一册”“第二册”。

**附录**：
- 附录自己编“附录 A”“附录 B”（中文和数字都这样，不编号时只有名字）；
- 附录里的东西编“A.1”“A.1.1”。

**前言、后记**：不编号。

**图、表**（第②步只做题注，交叉引用在第③步）：
- 正文页里的题注按**它所在的第 1 层**编号：“图 2-1”“表 2-3”。附录里“图 A-1”。不编号时“图 1”“图 2”全书连续。
- 同一个第 1 层里，前面各页有几张图，这一页从后面接着编。前面各页的图表个数用 `outline` 算（§13.6），并缓存（§13.4.8）。

#### 13.4.5 子书

- 外层目录遇到子书：
  1. 子书的书名项：`第一册 呐喊`，`book: true`，`level` 是它的深度；
  2. 找子书里的目录：
     - 是书插件的目录，直接算（同一个插件里的函数调用）；
     - 是别的插件的目录，调用那个插件的 `entries`；
     - 子书里没有目录，用外层的设置算子书。
  3. 子书的项全部接在书名项后面，`level` 加上子书的深度。
- 子书里**重新编号**。
- 子书再套子书，照样一层层算；最多 8 层，更深的只列书名项。

#### 13.4.6 浏览

- **连续**：`sequence` 的 `mode: "scroll"`。外壳只加载看得见的部分，前后各多加载 3 项。
- **分页**：`mode: "pages"`。一屏一项：
  - 子书的书名项、只有名字的分组，单独占一屏，显示成大标题；
  - 底部“上一页 / 下一页”和页码 `12 / 86`，键盘左右键翻页。
- **每一项**：
  - 有 `resource` 的，外壳用 `resource.embed` 显示它（带 `args`，§13.9 K-e）；
  - 这一项的标题由外壳画（带编号），嵌入里的 Markdown 标题下移到这一项的层级之下（最多到 6 级）。
  - 标题旁有“打开”，在新标签页打开那一页。
- **阅读位置**：
  - 外壳在浏览区停下 1 秒后，发页面事件 `{ id, type: "position", key }`；
  - 目录把它存进插件存储 `pos:<目录 id>`（一个工作区一个人用，所以不分人）；
  - 打开目录时，`sequence.start` 就是这个位置；书的页面上“继续阅读”也用它。
- **环境**：浏览区里各页的模板 `{{名字}}`，按目录这个标签页选的环境填。
- **被嵌入**：`![[书名#第二章名]]` 或 `![[书名#第二章]]`：
  1. 书把嵌入交给目录；
  2. 目录在目录项里找名字或编号相同的那一项；
  3. 返回那一项和它下面的全部，组成一个 `sequence`（不带目录栏，`mode: "scroll"`）。

  找不到时 `sectionMissing`。

#### 13.4.7 导出

导出是目录的动作 `export`（`output: "text"`），因为导出就是按目录的顺序印一份。

1. **没有授权文件夹时**，结果写“先授权一个文件夹”，附带“授权文件夹”按钮（结果区动作，调用 `host.files.addRoot()`）。
2. **写到第一个授权文件夹**（以后第⑥步按版本选）：
   - `书名.md`；
   - 图片放进 `书名-图片/`；
   - 同名已有时，自动加“ 2”“ 3”，不覆盖。
3. **文件内容**：
   - `# 书名`；
   - 封面：副书名、作者、简介；
   - 目录（带编号的列表）；
   - 然后每一项：
     - 标题按 `level` 写成 `##`、`###`……；
     - 正文是 `host.resources.embed(项, { args })` 的结果：
       - 文字照写；
       - 表格写成 Markdown 表格；
       - 图片用 `host.files.writeBlob` 写进图片文件夹，正文里写相对路径；
       - 链接写成名字。
4. **结果**：
   - 文件位置；
   - 结果区动作“在访达中显示”。

#### 13.4.8 缓存

- 图表计数要读各页的 `outline`。
- 目录把每页的 `outline` 结果按“资源 id + 版本号（`rev`，K7 的树里带）”缓存在插件存储里：
  - 版本号变了才重算；
  - 最多 5000 条，超出时清掉最早的一半。
- 不用事件，因为别的插件的资源改了，书插件收不到事件；版本号已经够用。

### 13.5 前言、后记、正文页（`text-page.js`）

三种类型共用一个页面 `text`，和笔记一样有“阅读 / 编辑”：
- 编辑：正文字段（`longtext`，`refs: true`）；
- 阅读：Markdown。

前言多一个字段 `variant`（序、前言、致谢），在信息面板里改，决定它在目录里显示的名字（名字为空时）。

**正文页比笔记多的两样**（也在前言、后记里生效）：

1. **脚注**：`正文[^1]`，加上单独一行 `[^1]: 注释`。阅读时：
   - 正文里变成上标的编号 ¹；
   - 这一页末尾列出“注释”；
   - 编号在这一页里从 1 开始。
2. **题注**：
   - 紧跟在一个嵌入（`![[…]]`）、图片或表格**下面**的一行 `图：说明`，或**上面**的一行 `表：说明`；
   - 阅读时变成“图 2-1　说明”（在书里，按 `args` 给的编号）或“图 1　说明”（单独打开时，这一页里从 1 编）；
   - 写法“图：”“表：”是正文页这个插件定义的（硬性规则 5），英文写 `Figure:`、`Table:`，日文写 `図：`、`表：`，三种都认。

**被嵌入**（`embed`）：
- 返回阅读时的 Markdown（脚注、题注都已处理）；
- 收到 `args.book` 时，用里面的编号前缀和起始序号编题注。

**拖出书外**：照常能用，题注按这一页自己编号。

### 13.6 接口 `onedesk.book/1`（第②步的三个动作）

书插件在清单里同时 `implements` 和 `uses` 这个接口。以后的练习插件等也这样做。

| 动作 | 输入 | 返回（`data`） |
|---|---|---|
| `roles` | `{}` | `{ kinds: [{ kind, role, part, single, container, numbering }] }`<br>• `role`：`cover`、`toc`、`preface`、`afterword`、`body`、`appendix`，或实现者自己定的名字（不认识的按 `body`）；<br>• `part`：`front`、`body`、`back`、`none`（不进阅读）；<br>• `single`：一本书里最多一页；<br>• `container`：下面的节点也进阅读；<br>• `numbering`：`level`（按层级）、`letter`（A、B、C）、`none` |
| `outline` | `{ resource }` | `{ headings: [{ text, level }], figures: [{ type: "figure"\|"table", caption }] }`，按出现的顺序。第③步再加 `terms`、`cites` 和位置 |
| `entries` | `{ resource: 目录 id, depth, settings? }` | `{ items: [{ key, resource?, title, number, level, part, book? }] }`<br>• `depth`：这本书在外层书里的深度；<br>• `settings`：外层的编号设置（子书没有目录时用） |

**怎么找到实现者**：
- `roles` 按插件调用：`interfaces.call("onedesk.book/1", "roles", {}, { plugin })`；
- `outline`、`entries` 按资源调用：`{ resource }`，由内核找到这种资源的插件（§13.9 K-f）。

**书插件调用自己的类型时**，不经过内核，直接调用同名的函数，但输入、返回和接口完全一样。所以别的插件的目录、正文页，和书插件自己的处在同等地位。

### 13.7 清单要点

```jsonc
"requires": { "resources": true, "contents": true, "files": true },
"uses": ["onedesk.book/1"],
"implements": { "onedesk.book/1": { "actions": ["roles", "outline", "entries"], "kinds": ["book", "cover", "toc", "preface", "afterword", "page", "appendix"] } },
"exports": { "actions": ["roles", "outline", "entries"] },
"contributes": {
  "kinds": [ /* §13.1 的七种 */ ],
  "pages": [ "book", "cover", "toc", "text", "appendix" ],
  "actions": [
    { "id": "export", "kinds": ["toc"], "output": "text" },
    { "id": "roles", "output": "none" }, { "id": "outline", "output": "none" }, { "id": "entries", "output": "none" }
  ],
  "events": ["resource.changed"],
  "menus": { "new": ["book", "page", "preface", "afterword", "appendix", "cover", "toc"] }
}
```

- 附录的页面 `appendix`：显示“附录 A　名字”和它下面各项的列表（可以点开）。编号要从目录算，所以附录页问书的目录。
- 语言文件：`en-US`、`zh-CN`、`ja-JP` 三种。

### 13.9 内核：要加的通用能力

都不认识书（硬性规则 1）。每一项都改协议或清单，按硬性规则 10 记进 decisions.md。

| 编号 | 能力 | 内容 | 规则和限制 |
|---|---|---|---|
| K-a | 读子树 `host.resources.tree(id, { offset?, limit? })` | 按树的顺序（先父后子）列出下面的全部节点：`[{ id, name, kind, icon, depth, parent, rev }]` 和 `next` | 要 `requires.resources`；每次最多 2000 个；不含正文 |
| K-b | 读别的资源的嵌入内容 `host.resources.embed(id, { section?, args? })` | 返回和界面的 `resource.embed` 一样的东西 | 要新权限 `requires.contents`（“读取其他资源的内容”，安装时列出）；只读；用调用方所在标签页的环境 |
| K-c | 装订：清单 kind 的 `place: true` 和处理函数 `place(ctx, { node, before })` | 东西被拖进、移动到、新建在这种资源下面时，内核先问它落在哪里，返回 `{ before }`（或 `{ refuse: Label }`），然后**一次**写入 | 纯计算（只能读），1 秒内不返回就按用户拖的位置；必须有 `tree` |
| K-d | 视图节点 `sequence` | `{ type: "sequence", id, toc, mode: "scroll"\|"pages", start?, items: [{ key, title, level, resource?, args?, book? }] }`；外壳按需嵌入每一项 | 项最多 20 000；`level` 1–9；`title` ≤ 500 字；`args` ≤ 4 KB；可以出现在嵌入里（嵌入里的 `sequence` 不带目录栏），嵌套最多 3 层，已有的嵌入环检查照用 |
| K-e | 嵌入的参数 `args` | `resource.embed { id, section?, args? }` 把 `args` 交给 `embed(ctx, { section, args })` | 第③步“带参数的引用”（K3）的一部分，先做这一点 |
| K-f | 接口的两处扩展 | 1. `implements.<接口>.kinds`：几种类型都可以当锚点；`interfaces.call(…, { resource })` 按资源的类型找实现者。<br>2. `interfaces.call(…, { plugin })` 直接指定实现者。<br>3. **不在运行中也能调用**：在 `render`、`embed`、`place`、`children` 里调用时，对方以纯计算方式执行（只能读，写被拒 `pureCall`） | 调用深度 ≤ 4，不得成环（已有） |
| K-g | 写图片 `host.files.writeBlob(blob, path)` | 把一个存着的文件写到授权文件夹 | 要 `requires.files`；文件号必须被调用方能读的某个资源用到 |

## 14. 第②步的实际做法（和 §13 不同或补充的地方）

| 项 | 实际做法 | 为什么 |
|---|---|---|
| 编号的选项 | 字段 `numbering` 取 `words`（按层级名称）、`numbers`（1.1）、`none`；层级名称和子书的叫法留空时**按语言**取默认：中文“章,节”“册”，英文“Chapter, Section”“Volume”，日文“章,節”“巻”。中文、日文用“第一章”，英文用“Chapter 1” | 清单里的默认值是固定的，不能按语言变 |
| 图表计数的缓存 | 放在插件运行时的内存里（按资源 id + 版本号），不写插件存储 | 画页面时不写东西；运行时一直在，效果一样 |
| 书的页面 | 上面一个按钮：有阅读位置时是“继续阅读”，否则“开始阅读”（都打开目录，目录自己回到上次的位置）；下面是封面。没有目录时只有一行提示，没有“加目录”按钮 | 视图节点里没有“新建”按钮；在树上新建一页目录就行 |
| 封面怎么显示在书上 | 书的页面和 `![[书]]` 都是一个只有一项的 `sequence`：标题是书名，内容是封面的嵌入视图 | 封面图属于封面这个资源，界面只能为用到它的资源读图片；这样图片按封面读，书也不用懂封面 |
| 新建在书里的页 | 先问书落在哪里，建好后再移过去（两次写入） | 新建的写入命令没有位置参数；移动一次就够 |
| 题注 | 按出现的顺序编号，不检查是不是紧挨着图或表 | 简单可靠；写法照 §13.5 |
| 导出 | 写到第一个授权文件夹；没有授权文件夹时弹出选文件夹的对话框，提示“选好后再导出一次”。正文里的 `![[…]]` 照原样写出，不展开 | 运行中选文件夹的结果是异步到达的；展开嵌入留到以后 |
| `files.writeBlob` | 路径没有扩展名时，按图片类型补上 | 插件不知道图片的类型 |
| `place` | 只对用户的操作（拖动、在书里新建）生效；插件自己的 `resources.create/move` 不经过它 | 插件不能在处理自己的事件时再被自己打断 |

## 15. 第③步详细设计：参考文献、索引、图表目录、交叉引用（已确认，已实现）

> 范围：book.md §11 第③步。做完后能用：学术书、规范文档、教材——正文里引用文献、引用别的章和图，书后有参考文献和索引，书前有图表目录。
> 不在这一步：
> - 公式编号“式（2-3）”，随第④步公式一起做；
> - 尾注（脚注仍在每页末尾）；
> - 参见条目（索引里的“见 ××”）。

### 15.1 这一步加的角色

都由书插件提供，每个角色一个文件（§0 第 2 条）。

| 类型（短名） | 角色 | 部分 | 一本书里 | 带的逻辑 | 文件 |
|---|---|---|---|---|---|
| `references` 参考文献 | 参考文献 | 后 | 最多 1 | 文献的著录格式（GB/T 7714）、引注怎么显示、列哪些 | `references.js` |
| `reference` 文献 | 一条文献 | 不进阅读（放在参考文献下面） | 不限 | 一条文献的字段 | `references.js` |
| `index` 索引 | 索引 | 后 | 最多 1 | 收集索引词、排序、列出位置 | `index.js` |
| `figures` 图表目录 | 图表目录 | 前（目录之后） | 最多 1 | 列出全书的图和表 | `figures.js` |

交叉引用不是一页，而是正文页的本事：正文页问目录“它在书里编第几”（§15.5）。

### 15.2 先问实体书

| 问题 | 实体书的做法 | 这里照做 |
|---|---|---|
| 引用文献怎么写 | GB/T 7714 两种体系：**顺序编码制**（正文 “[3]”，表按第一次引用的顺序编号）和**著者-出版年制**（正文 “（张三，2020）”，表按著者排序） | 两种都做，参考文献页上选，默认顺序编码制 |
| 一条文献怎么写 | 著者. 题名[文献类型标识]. 出版地: 出版者, 出版年: 引文页码. | 照 GB/T 7714 的格式拼出来 |
| 文献类型 | M 专著、J 期刊、C 论文集、D 学位论文、R 报告、S 标准、P 专利、N 报纸、EB/OL 网页、Z 其他 | 照用这些标识 |
| 索引怎么排 | 中文按拼音，同音按笔画；每条后面是页码 | 按拼音排（§15.8 的 K-j）；电子书没有页码，用**章节号**代替（“第二章 · 附录 A”），点了跳过去 |
| 图表目录 | 书前分“插图目录”“表格目录”，每行：编号、题注、页码 | 照做，页码换成章节号 |
| 交叉引用 | “见第三章”“如图 2-1 所示” | 写引用，显示成编号（§15.5） |

### 15.3 参考文献 `references` 和文献 `reference`

**一条文献是一个资源**（一切都是资源）：放在参考文献页下面。它的名字就是**引注名**，比如“张三2020”。

文献的字段（照 GB/T 7714）：

| 字段 | 说明 |
|---|---|
| 类型 `type` | M、J、C、D、R、S、P、N、EB/OL、Z（下拉，显示成“专著”“期刊”……） |
| 著者 `authors` | 几位用逗号分开；超过 3 位时，显示前 3 位加“等”（英文加 “et al.”），照规范 |
| 题名 `title` | |
| 出处 `container` | 期刊名、论文集名、报纸名 |
| 版本 `edition` | 第 1 版不写 |
| 出版地 `place`、出版者 `publisher` | |
| 年 `year`；卷 `volume`；期 `issue`；页码 `pages` | |
| 网址 `url`；引用日期 `accessed`；DOI `doi` | 网页要有网址和引用日期 |

- **文献的页面**：一个表单，就是上面这些字段；下面一行预览按规范拼好的样子。
- **被嵌入**：显示按规范拼好的那一行。

**参考文献页**：

| 设置 | 选项 |
|---|---|
| 体系 `system` | 顺序编码制（默认）、著者-出版年制 |
| 列出 `list` | 只列被引用过的（默认）、全部 |

- **页面**：上面一行是设置，下面是文献表。
  - 顺序编码制：按第一次被引用的顺序，“[1] 张三. 书名[M]. 北京: 某出版社, 2020.”；
  - 著者-出版年制：按著者排序（排法同索引）。
  - 下面单独列出**没找到的引注**（正文里写了，但没有这条文献），点了打开写它的那一页。
- **被嵌入、导出**：就是这张表。

**引注的写法**（正文页、前言、后记里；写法是书插件定义的，硬性规则 5）：

| 写法 | 顺序编码制 | 著者-出版年制 |
|---|---|---|
| `[@张三2020]` | [3] | （张三，2020） |
| `[@张三2020, 第 12 页]` | [3: 12] | （张三，2020：12） |
| `[@张三2020; @李四2019]` | [3, 5] | （张三，2020；李四，2019） |

- 引注名按名字找文献：先在这一页所在的书（或子书）的参考文献下面找，找不到再往外层书找。
- 英文界面的著者-出版年制用 “(Zhang, 2020)”。
- 不在书里时，引注照原样显示成 “[张三2020]”。

### 15.4 索引 `index`

**索引词的写法**（正文页里，阅读时不显示；书插件定义的写法）：

| 写法 | 意思 |
|---|---|
| `{{索引:勾股定理}}` | 索引词“勾股定理”，位置是这一页 |
| `{{索引:三角形/勾股定理}}` | 二级：主词“三角形”下的“勾股定理” |
| `{{index:…}}`、`{{索引:…}}`（日文） | 三种语言的写法都认 |

- 这种写法和模板 `{{名字}}` 不冲突：模板的名字里不能有冒号。
- **索引页**：
  - 按拼音排序（英文按字母）；
  - 每个词后面是出现的位置，写成编号（“第二章、第三章第一节、附录 A”），没有编号的写名字；
  - 一个词在同一页出现多次只算一次；
  - 点位置打开那一页。
  - 二级词缩进放在主词下面。
- **被嵌入、导出**：一张两列的表（词、位置）。

### 15.5 交叉引用（正文页的本事）

写法就是普通的引用 `[[名字]]`。这样内核照常记着它指向谁，改名也不会断（D321、D482）。

在书里阅读时，正文页把它显示成编号，仍然可以点：

| 引用的是 | 显示成 |
|---|---|
| 这本书里的一章、一节、一页、子书、附录 | 它的编号：“第三章”“第二节”“附录 A”“第一册”；没有编号的显示名字 |
| 一张嵌在正文里、下面有题注的图片（`![[电路图]]` 下一行 `图：…`） | “图 2-1” |
| 带题注的表格所在的那一页 | 那一页的编号（表本身不是资源，第一版不能单独引用） |
| 书外的东西 | 名字（照旧） |

**怎么做**：
1. 目录算目录项时，用 K-h（§15.8）读出每一页引用了谁；
2. 目录把“这一页的每个引用该显示成什么”放进这一项的 `args.book.labels`；
3. 正文页把它们交给文字节点的 `refLabels`（K-i），外壳照着显示。

- 单独打开一页（不在书里阅读）时，照旧显示名字。
- 别的插件想知道编号，调用接口 `number`（§15.7）。

### 15.6 图表目录 `figures`

- **位置**：在“前面的部分”，目录之后。
- **页面**：两张表，“插图”和“表格”。每行：编号、题注、在哪一章（点了打开那一页）。没有图或表的那张不显示。
- **被嵌入、导出**：同样两张表。
- **数据**：目录在算目录项时已经数过每一页的图和表（§13.4.4），现在把它们连同编号一起交出来（`entries` 的返回多了 `figures`，§15.7）。

### 15.7 接口 `onedesk.book/1` 的补充

都是加字段、加动作，原来的不变，所以接口仍是 `/1`。

| 动作 | 谁实现 | 补充 |
|---|---|---|
| `outline` | 正文页等 | 多返回 `cites: [{ keys, note }]`（引注，按出现的顺序）、`terms: [{ term, sub }]`（索引词）；`figures[]` 每项多一个 `of`（题注上面那个嵌入的名字，没有就不给） |
| `entries` | 目录 | 多返回：<br>• `figures: [{ type, number, caption, item }]`；<br>• `terms: [{ term, sub, item }]`；<br>• `cites: [{ keys, note, item }]`<br>（都按阅读顺序，`item` 是所在目录项的 `key`） |
| `number`（新） | 目录 | 输入 `{ resource: 目录, targets: [资源 id] }` → `{ labels: { id: "第三章" \| "图 2-1" } }`；不在书里的不给 |
| `cite`（新） | 参考文献 | 输入 `{ resource: 参考文献页, cites: [{ keys, note }] }` → `{ labels: ["[3]", "（张三，2020）", …] }`，和输入一一对应 |

**谁问谁**（都按角色找，不写死插件名）：
- 目录要给正文页准备引注的显示 → 问这本书的**参考文献**角色的 `cite`；
- 要准备交叉引用 → 自己算（编号本来就是目录的事）。
- 参考文献、索引、图表目录要全书的数据 → 问这本书的**目录**角色的 `entries`。
- 书里没有目录时，用书插件自带的算法。

### 15.8 内核要加的通用能力

都不认识书：

| 编号 | 能力 | 内容 | 规则 |
|---|---|---|---|
| K-h | 读一个资源引用了谁 `host.resources.refs(id)` | 返回 `[{ text, target: { id, name, kind } \| null, section }]`：正文里每个 `[[…]]`、`![[…]]` 现在指向谁（和信息面板里看到的一样） | 要 `requires.resources`；只读 |
| K-i | 文字节点的 `refLabels` | `{ type: "text", format: "markdown", refLabels: { "电路图": "图 2-1" } }`：Markdown 里这些 `[[…]]` 显示成给的文字，仍然可以点、仍然按原来的目标打开 | 最多 500 项，每项 ≤ 200 字 |
| K-j | 按语言排序 `host.util.collate(texts, locale)` | 返回排好的顺序（下标数组）；中文按拼音，日文按读音表，其他按各自语言的字母顺序 | 最多 20 000 条。用 ICU4X 的 `icu_collator`（Unicode-3.0 许可，ICU4X 的其他部分已经在依赖里）；按硬性规则 9 先记进 decisions.md |

### 15.9 外壳

- 文字节点把 `refLabels` 交给 `MarkdownText`。
- 外壳文字只加内核错误和权限的说明（如果有）。

### 15.10 导出

- 参考文献、索引、图表目录也是书里的页，导出时照常按目录的顺序写出它们的嵌入内容（都是表格或列表）。
- 正文里的引注、交叉引用按书里的样子写出（“[3]”“第三章”）。

## 16. 第③步的实际做法（和 §15 不同或补充的地方）

| 项 | 实际做法 | 为什么 |
|---|---|---|
| 按语言排序 K-j | 用 `icu_collator`，只在**工作进程**（`onedesk-worker`，应用里内核运行的地方）打开内核的 `collate` 功能；窗口外壳和开发用的 devhost 里的内核按“不分大小写的字符顺序”排 | 窗口外壳链接了内核：在那里加上 ICU 会让 Tauri 重新编译，而在 exFAT 盘上、带来源标记的进程写出的文件会多出 `._*`，让 Tauri 的编译脚本失败。只放在工作进程里，`pnpm start` 的窗口编译不变 |
| 引注的位置记录 | `outline` 的 `cites` 是 `[{ keys, notes }]`（每个引注名一个说明，没有为 `null`），不是 §15.7 写的 `{ keys, note }` | `[@a, 第 1 页; @b, 第 2 页]` 每条各有说明 |
| 交叉引用的标签 | 按引用写下的文字，**和**目标现在的名字都给一份 | 读者看到的正文里，引用已经换成目标现在的名字（D321） |
| 交叉引用显示的编号 | 用完整的编号：“第三章 第二节”“Chapter 3 Section 2” | 只写“第二节”分不清是哪一章的 |
| 著者-出版年制的著者 | 中文名照写；西文名取第一个词（GB/T 7714 西文姓在前：“Smith J”）；两位以上加“等”/“et al.” | 照规范 |
| 索引的位置 | 一行能打开一个地方：点一行打开这个词出现的第一页 | 表格一行只有一个目标 |
| 没找到的引注 | 正文里显示成 `[?名字]`（著者-出版年制 `（?名字）`），参考文献页单独列出 | 让作者一眼看到 |
| 引用数据的缓存 | 每页引用了谁按“资源 id + 版本号”缓存；目标的名字每次从书的树上取 | 目标改名时，引用它的那一页版本号不变 |

## 17. 第④步详细设计：公式和计算页（已确认，已实现）

> 范围：book.md §11 第④步——“会算的书”。做完后能用：
> - 写一个公式（摄氏转华氏、BMI、评分量表）；
> - 在任何地方调用它：笔记的句子里、书的正文里，结果跟着标签页的环境变；
> - 书里的公式有编号“式（2-3）”，能被交叉引用、列进图表目录；
> - 公式本身放进书里，就是一页“计算页”。
>
> 沿用 `embed-book.md` §20 的设计（D482 时写的、D484 定为保留），本节按 §0 的角色思路重新整理，并标出改动。
>
> 不在这一步：
> - 读者在书里直接改参数试算（要“可交互的嵌入”K11，第⑤步）；
> - 参数取文书里的填写项 `@名字`（第⑦步文书）；
> - 公式调用公式；
> - 教科书式的公式排版。

### 17.1 先问实体书

| 问题 | 实体书的做法 | 这里照做 |
|---|---|---|
| 公式在书里怎么出现 | 单独一行的公式，右边或下面标编号“（2-3）”，按章编号；正文里说“由式（2-3）可得” | 正文页里单独一行嵌入公式，下面一行写 `式：`（可以接说明），编成“式（2-3）”；交叉引用显示“式（2-3）” |
| 公式的符号说明 | 公式下面“式中：C——摄氏温度，℃” | 嵌入的公式下面列出参数的说明和单位 |
| 计算示例 | 例题：“已知 C = 37，求 F”，下面写出代入和结果 | 带参数的嵌入：`![[摄氏转华氏 \| C=37]]` 显示代入的值、中间结果和结果 |
| 正文里的数 | 句子里直接写算好的数 | 行内调用 `[[=摄氏转华氏 \| C=37]]` 显示 “98.6 °F” |
| 公式目录 | 有的书在插图目录、表格目录之外另有“公式目录” | 图表目录多一张“公式”表 |

### 17.2 角色和插件

| 谁 | 担当什么 | 带的逻辑 |
|---|---|---|
| **公式**（新插件 `org.onedesk.formula`，内置，类型 `formula`） | 一个能算的资源；放进书里时担当**计算页** | 解析和计算表达式、认出参数、格式化结果；被调用时给出结果 |
| **正文页**（书插件） | 正文 | 多认一种题注 `式：`，编成“式（2-3）” |
| **目录**（书插件） | 编号 | 按章给公式编号，和图、表一样；交叉引用的标签多了“式（2-3）” |
| **图表目录**（书插件） | 图表目录 | 多一张“公式”表 |

- 公式插件**实现接口 `onedesk.book/1`**，在 `roles` 里说：`formula` 的角色是 `calc`（计算页）、在正文、按层级编号、下面不再有东西。
- 这是第一个由**别的插件**提供的书的角色，书插件一行不用改。

### 17.3 公式插件 `org.onedesk.formula`

**写法**（插件自己解析，不执行任何代码）：
- 一行或几行，每行 `名字 = 表达式`；最后一行的名字是结果。
- 表达式里用到、但前面的行没有定义的名字，就是**参数**，不用另外“添加参数”。
- 数字：`37`、`-3.5`、`1.2e3`。
- 运算：`+ - * / ^ %` 和括号；乘除也认 `×`、`÷`。
- 函数：`abs round floor ceil min max sqrt pow exp ln log10 sin cos tan`；`round(x, n)` 保留 n 位小数。
- 常数：`pi`、`e`。
- 名字：字母、数字、下划线、汉字，不以数字开头。
- 限制：最长 4000 字、最多 50 行、括号和函数嵌套最多 32 层。
- 出错说明要看得懂：“缺少参数 C”““D” 不是数字”“第 2 行：除以零”“不认识 sqr，是不是 sqrt？”。

**资源里存什么**（`body`）：

| 键 | 内容 |
|---|---|
| `text` | 公式 |
| `unit` | 结果单位，如 “°F” |
| `decimals` | 小数位，默认 2；结果按它四舍五入，不加千分位 |
| `param.<名字>.label`、`param.<名字>.unit`、`param.<名字>.default` | 每个参数的说明、单位、默认值。默认值可以写 `{{环境参数}}`，跟着环境变 |

- 公式里删掉一个参数，它的说明等留着不显示；以后又用到同名参数时会回来。

**页面**：

```
┌ 摄氏转华氏 ─────────────────────── [环境 ▾] │ 保存 ┐
│ 公式                                                  │
│   F = C * 9 / 5 + 32                                   │
│ 结果单位 [°F]   小数位 [1]                              │
│ 参数（从公式里认出）                                    │
│   C   说明 [摄氏温度]  单位 [°C]  默认值 [20]           │
│ 试算   C [37]  →  F = 98.6 °F                          │
└──────────────────────────────────────────────────────┘
```

- **试算**：
  - 每个参数一个输入框，先填好默认值，改了立刻出结果，中间结果也列出；
  - 试算的值是页面的视图状态（`view.try.<名字>`，D467），不保存。
- **说明**写在信息面板里，AI 按说明可以写出公式（产品要求 6）。

**被调用时**（`embed`，参数由内核解析好交来，§17.4）：

| 写法 | 显示 |
|---|---|
| `![[摄氏转华氏]]` | 公式，下面“式中”列出参数的说明、单位、默认值 |
| `![[摄氏转华氏 \| C=37]]` | 公式，代入的值 `C = 37 °C`，中间结果，最后 `F = 98.6 °F` |
| `[[=摄氏转华氏 \| C=37]]` | 行内：`98.6 °F` |
| `[[=摄氏转华氏]]` | 行内：用默认值算出的结果 |
| 缺参数 | 用默认值；没有默认值时报“缺少参数 C” |
| 多给了不认识的参数 | 报“没有参数 X” |

**在书里**（担当计算页）：
- 公式直接放在书下面，就是一页，按层级编号（如“第三章 摄氏转华氏”）；
- 浏览时显示的就是 `![[摄氏转华氏]]` 的样子：公式和“式中”。

### 17.4 内核：带参数的引用（K3）

| 改动 | 说明 |
|---|---|
| 解析 | 引用里 `\|` 后面的参数（D482 已经能拆出来）：`名字=值`，逗号分开；值可以是数字、文字（含逗号或首尾空格时用双引号，`\"` 转义）、`{{环境参数}}`（可以夹在文字里）。`{{…}}` 按**显示它的标签页的环境**取值，取不到的保留原文。写错（缺 `=`、引号没收尾）时整个调用不算，结果是“参数写错了” |
| 交给插件 | 解析好的参数就是 `embed(ctx, { section, args, inline })` 的 `args`（名字 → 文字），和第②步书交来的 `args` 是同一个入口；`inline: true` 表示行内调用 |
| `resource.embed` | 加 `params?`（`\|` 后面的原文，外壳原样交来）、`inline?` |
| 行内的回答 | 只收 `{ text, error? }`：一行，最多 200 字 |
| `EmbedResult` | 加 `text?`、`error?`（行内结果），`args?`（解析并填好环境值的参数，显示“这次用的参数”） |
| `RefInfo` | 加 `call?`（是不是调用：`[[=…]]`，或带参数的 `![[…]]`）、`params?`（写下的参数）。信息面板里，调用标“调用”，后面是参数 |
| 没有嵌入视图的类型 | 块：仍是卡片；行内：没有结果，外壳显示成名字链接，标“不能计算” |
| 缓存 | 同一资源、同一版本、同一节、同样参数、同一环境、同一语言的结果放在内存里，最多 1000 条；资源改了就不用旧的，任何环境参数改了全部作废 |
| `host.resources.embed` | 也收 `params`、`inline`（导出时要把行内调用写成结果） |

### 17.5 外壳

- **行内调用** `[[=…]]`：
  - 画成**结果文字**，带细虚线下划线；
  - 鼠标停留显示“摄氏转华氏（C = 37）”，点击打开公式；
  - 还没算好时显示“…”；出错时标红，停留显示原因。
  - 一页的行内调用一起取（并发），全部回来再一次画好，不让文字一个个跳。
- **带参数的块**：嵌入块标题后面加上参数，如“摄氏转华氏（C = 37）”。
- **信息面板**：“引用”和“被引用”里，调用标“调用 C=37”。

### 17.6 书插件的改动（都在原来的角色里）

| 角色 | 改动 |
|---|---|
| 正文页 | 题注多一种：`式：说明`（`Equation:`、`式：`），说明可以空。显示成“式（2-3）　说明”（英文 “Equation (2-3) …”）。`outline` 的 `figures` 多一种 `type: "equation"` |
| 目录 | 公式和图、表一样按章计数编号；交叉引用 `[[摄氏转华氏]]`（它嵌在正文里、下面有 `式：`）显示“式（2-3）” |
| 图表目录 | 多一张“公式”表：编号、说明（没有说明就写公式名）、所在章 |
| 导出 | 行内调用写成结果，例如“98.6 °F”（用 `host.resources.embed` 的 `inline`） |

### 17.7 规则对照

| 规则 | 怎么满足 |
|---|---|
| §0.1 书只负责装订 | 书不变；计算页的角色由公式插件经接口声明 |

## 18. 第④步的实际做法（和 §17 不同或补充的地方）

| 项 | 实际做法 | 为什么 |
|---|---|---|
| 参数交给插件 | 读好的参数和书交来的参数走同一个 `args`；公式插件不理会 `book` 这个键和不是文字的值 | 一个入口（§17.4） |
| 参数写错 | 结果里是 `badParams: true`，不调用插件；外壳写“参数写错了” | 内核不含界面文字 |
| 环境参数在笔记里 | 笔记在阅读时先把 `{{室温}}` 换成值，外壳看到的是 `C=25`；外壳按名字找回这个调用 | 笔记的模板照旧先填 |
| 交叉引用和调用 | 调用 `[[=…]]` 永远显示它算出的结果，不会被当成交叉引用显示成“式（1-1）” | 写调用就是要那个数 |
| 数字的舍入 | 四舍五入按“离零远的一边”（310.15 → 310.2），避开二进制小数的误差；去掉末尾的 0（77.0 → 77） | 和人手算一致 |
| 计算页里的计算页 | 公式放进书里，按层级编号；浏览时显示公式和“式中” | 照设计 |
| 测试用的程序 | 界面测试用本会话自己的编译目录里的 `onedesk-devhost` 和 `onedesk-worker` | 各个工作树共用仓库的 `target`，别的会话编译时会覆盖同名程序，测到的就是别人的代码 |

**测试**：内核 `crates/kernel/tests/subtree.rs`（调用一组）、`refs.rs` 的参数读取；公式插件 `plugins/org.onedesk.formula/main.test.ts`；书插件 `main.test.ts`（第④步一组）；外壳 `sequence-view.test.tsx`（调用的画法）；界面 `e2e/formula.spec.ts`。

### 19.3 题 `question`

**字段**：

| 字段 | 说明 |
|---|---|
| 题型 `type` | 填空（默认）、单选、多选、判断、问答 |
| 题干 `stem` | Markdown，可以有图片、公式（`![[…]]`、`[[=…]]`）。空写 `{{?}}`，一题可以几个空（练习插件定义的写法，和文书的填写项同一种） |
| 选项 `options` | 单选、多选用：一行一个，“A. 3”“B. 4”…… |
| 答案 `answers` | 一空一行；几个都对用 `\|` 隔开（`12÷3 \| 12/3`）；选择题写字母（`AC`）；判断题写“对”或“错” |
| 判题 `rule` | 按数值（默认）、按写法、按符号、老师批 |
| 分值 `points` | 默认 1；几个空平分 |
| 提示 `hint`、讲解 `explanation` | Markdown |
| 难度 `difficulty` | 1–5，可以不填 |
| 知识点 | 就用资源的**标签**（信息面板里填），不另设字段 |

**判题**（练习插件自己做）：

| 规则 | 怎么比 |
|---|---|
| 按数值 | 都当成数比：`0.5`、`1/2`、`½`、`.5` 相等；全角数字、首尾空格不算；带单位时只比数（`4 个` = `4`） |
| 按写法 | 去掉首尾空格、全角换半角后，字字相同 |
| 按符号 | `>` `<` `=` `≥` `≤`，全角半角都认 |
| 老师批 | 不自动判，交卷后显示“待批”；在作答页上点“对”“错”打分（这一步作者和学生在同一个工作区） |
| 选择题 | 选中的字母相同；多选题选对一部分得一半分（在测验设置里打开） |
| 判断题 | “对、√、T、是”和“错、×、F、否”都认 |

**页面**：
- 上面是字段；下面是“**学生看到的样子**”的预览，可以直接**试做**：填了点“检查”，显示对错。试做不留作答。

**快速出题**：

- 数字按数值判，符号按符号判。


- 填空框、选项、对错按钮**就在书上**；
- 点“**检查**”马上判，显示 ✓ ✗、正确答案和讲解；
- 点“**重做**”清空再来；
- 每次检查都记进这一页的一份作答（同一页反复做，接着用同一份作答，直到“重做”才开始新的一份）。

单独打开练习页时，就是同样的样子，加上作者用的部分：题的列表、快速出题。

### 19.7 测验页 `test`

**在书里**，显示成一张卡片：

```
第二节 单元测验
  10 题 · 满分 20 · 限时 30 分钟
  上次 17 分（第 2 次）　最高 18 分
  [开始]  [看上次的作答]
```

- “**开始**”新建一份作答，在新标签页打开作答页。
- 次数用完时，“开始”不能点，并说明原因。

**单独打开测验页**，是作者编辑测验的地方：
- 题的列表：可以拖动排序、插入大题标题、从别处引用题（一道题可以在几个测验里）；
- 快速出题；
- 设置写在信息面板（§19.5）。

**作答页**（打开作答资源）：
- 一题一题往下，填空框、选项；
- 顶上是测验名、第几次、开始时间、剩余时间（按打开页面的时刻算，不跳秒）；
- 操作栏“**交卷**”：
  - 判分，按设置给出答案和讲解；
  - 有“待批”的题，下面有“对”“错”两个按钮。
- “每题答完”时，填完一题马上显示 ✓ ✗；“交卷前不能改”时，答过的题锁定。

### 19.8 成绩单 `grades`、错题本 `mistakes`

**第一次交卷时**，“学习记录”树里自动建好一份成绩单、一份错题本（之后不再自动建）。

**成绩单**：
- 按书、按测验：做了几次、最高、最后、满分、最近一次的日期；点一行打开那次作答。
- 按知识点（题的标签）：做过几题、对了几题、正确率，从低到高排。

**错题本**：
- 列出做错过、而且之后没再做对的题：题干（前一行）、出自哪个测验或练习、错了几次、最近一次；
- 按知识点、按书分组；
- 点一行打开那道题；
- 操作栏“**再练一次**”：把这些题当一次新的作答来做；再练做对的，从错题本里拿掉（历史还在作答里）。

### 19.9 内核：可交互的嵌入（K11）

都不认识题：

| 改动 | 说明 |
|---|---|
| 嵌入里可以有表单 | `embed` 的回答可以有 `form` 节点。字段**不绑定**任何资源（不写 `bind`），值只在外壳里，属于这一处嵌入 |
| 嵌入的按钮 | 回答里可以有 `actions: [{ id, label, icon? }]`（最多 4 个），外壳画在嵌入的下面 |
| 新协议 `resource.embedAct` | `{ id, section?, params?, args?, envId?, locale?, action, values }`：用户点了按钮。内核调用这种类型的 `embedAct(ctx, { section, args, action, values })`，回答 `{ view?, actions?, message? }`：新的样子（同样检查）、按钮、提示 |
| 权限 | `embedAct` 是用户的操作：插件可以写**自己的**资源（作答），和页面事件一样记进审计；不能写嵌入它的那个资源；AI 不能调用 |
| 清单 | 声明了 `embed: true` 的类型可以注册 `embedAct`，不另设开关 |

**外壳**：
- 嵌入里的表单照常画（输入框、选项……），值记在这一处嵌入里；
- 按钮画在下面；
- 点了就发 `resource.embedAct`，用回答替换这一处的样子；有 `message` 时弹出提示。

**公式也用上它**（第④步留下的）：书里的公式下面多一行参数输入框和“算”按钮，读者改了参数马上看到结果，不保存。

### 19.10 课本目录 `lessons`：另一种目录

- 担当目录的角色：一本书里有它，就不能再有书插件的目录（装订的规矩，已有）。
- 浏览和书插件的目录一样（连续、分页、阅读位置）。
- **编号不自己算**：调用书插件的 `entries`（按书调用，书插件补上这一种调用：`{ book }`），拿到带编号的目录项。
- 在每一项上加上**进度**：
  - 练习页：“✓ 全对”“3/5”；
  - 测验页：“85 分”“未做”。
- 写在目录栏的标题后面。
- 书的页面上“继续阅读”同样回到上次的位置。

这是 §0 第 3 条的例子：换一种目录，就换来按课学习的读法，书插件一行不用改（只补了按书调用 `entries`）。

### 19.11 给 AI

- 题和测验：给题干、答案、讲解（这一步没有密封）。
- 作答、成绩单、错题本：给学生自己的答案和对错；AI 可以按错题出类似的题，“应用”后成为新的题。

### 19.12 测试（全部通过后才提交）

**内核**：
- 嵌入里的表单和按钮的检查（字段不能有 `bind`，按钮最多 4 个）；

**练习插件**：

- 测验：开始、作答、交卷、计分、限时、次数、交卷前能不能改、每题答完；
- 作答的快照；

**外壳**：嵌入里的表单、按钮、替换样子、提示；公式在书里试算。

**界面**（真内核，从“新建”开始）：

## 21. 第⑥步详细设计：版权页（发布、版次印次、只读副本、学生版和教师版、答案附录和公布）（已确认，实际做法 §22）

> 范围：book.md §11 第⑥步，`documents.md` §19.6、§19.7 的需求。做完后能用（一台电脑、两个工作区）：
> 1. 老师在“老师”工作区写好课本，在版权页上点“发布”，得到一个书的文件；
> 2. 学生在“学生”工作区导入，得到只读的课本，做练习、做测验；
> 3. 老师改课本不影响学生，出新版后学生更新，作答和错题都还在；
> 4. 老师在答案附录里选好要公布的测验，点“公布”，再印一次学生版；学生导入后自动判分。
>
> 不在这一步：网络订阅和自动更新、交回作答、全班成绩、正式考试（判题在老师那边）。

### 21.1 先问实体书

| 实体书 | 这里 |
|---|---|
| 版权页：书名、著者、出版者、**版次和印次**、书号 | 版权页这一页：这些字段，加上发布记录 |
| 内容改了出**新版**；只是再印一批是**新印次** | “发布新版”版次加一；“重新印刷”印次加一，内容就是那一版的 |
| 学生用书、**教师用书**（多了答案和教学说明） | 一次发布分出**学生版**和**教师版**两个文件 |
| 课本后的**习题答案**只在教师用书里，到时候发给学生 | **答案附录**只进教师版；“公布”时，学生版重新印一次，带上已公布的那几个测验的答案 |
| 书发出去，读者手里的书改不了 | 学生那里是**只读副本** |
| 再版后，旧书照样能看，学生的作业本还在 | 更新到新版时，作答、成绩、错题都不受影响 |

### 21.2 角色

| 角色 | 由谁提供 | 带的逻辑 |
|---|---|---|
| **版权页** `colophon`（新） | 书插件 | 版次、印次、出版信息；**发布**、**重新印刷**；发布记录；学生版和教师版各包含哪些页 |
| **答案附录** `answers`（新） | 练习插件 | 在后面的部分，编 A、B、C；**只进教师版**；列出全书的答案和讲解；选哪些测验公布，点“公布” |
| 题 | 练习插件 | 答案和讲解是“**保留字段**”（§21.5）；在学生那里没有答案时，作答“等公布” |
| 目录（导出） | 书插件 | 导出时选学生版或教师版 |

- 角色表（接口 `roles`）多一个可选属性 `edition`：`"teacher"` 表示只进教师版。答案附录这样声明，书插件只认这个属性，不认识“答案”。
- 版权页在“前面的部分”，最多一页。没有版权页的书不能发布；在书里“新建 → 版权页”就有了。

### 21.3 版权页 `colophon`

**字段**：出版者、书号（可选）、版本说明（可选）、**分不分学生版和教师版**（默认：分）。书名就是书的名字，著者取封面上的。

**页面**：
```
┌ 版权页 ─────────────────────────────────── │ 发布新版  重新印刷  保存 ┐
│ 数学三年级（上）                                                       │
│ 著者：张三　出版者：某学校数学组　书号：（无）                          │
│ 当前：第 2 版第 3 次印刷                                                │
│ 分学生版和教师版 [是]                                                   │
│ 发布记录                                                                │
│   版次  印次  版本    时间              文件                     公布到 │
│   2     3     学生版  2026-11-26 10:20  数学三年级-2.3-学生版.odpack  第一单元测验 │
│   2     3     教师版  2026-11-26 10:20  数学三年级-2.3-教师版.odpack  —     │
│   …                                                                     │
└────────────────────────────────────────────────────────────────────────┘
```

- **发布新版**（一个运行）：
  1. 版次加一、印次回到 1；
  2. 内核把这一版的书**存一份**在老师的工作区里（不能改，§21.4）；
  3. 写出两个文件（学生版、教师版）到第一个授权文件夹；
  4. 结果给出文件位置，可以“在访达中显示”。
- **重新印刷**：
  - 用**那一版存下的内容**，印次加一，再写出文件；
  - 老师已经接着改了原书也不要紧，印出来的仍是那一版；
  - 发布记录里每一版都能“重印”，给还在用旧版的学生公布答案就用它。
- **发布记录**：每次一行；点一行在访达中显示那个文件。
- 接口：版权页实现 `print({ edition?, variant })`（重印某一版），答案附录“公布”时调用它（§21.6）。

### 21.4 内核：发布与只读副本（K9）

都不认识书，只认识“一棵子树”：

| 能力 | 说明 |
|---|---|
| `host.packages.publish(root, { edition, printing, variant, exclude, path })` | 把 `root` 下面的整棵子树（加上用到的图片）写成一个**资源包文件**（`.odpack`）到授权文件夹。`exclude`：这一版不带的资源（教师版专用的页）。保留字段按 §21.5 处理。包里记着：发布人（老师工作区的编号）、根、版次、印次、版本（`student` / `teacher`）、时间。要 `requires.files` |
| 这一版的存档 | `edition` 第一次发布时，内核把子树原样存进工作区的 `packages/` 文件夹，之后的重印都从这里出；存档不能改，资源被删了也还在 |
| `host.packages.reprint(root, { edition, printing, variant, exclude, reveal, path })` | 用存档重印；`reveal`：这一次可以带出原文的保留字段（资源 → 字段） |
| `package.inspect` / `package.import`（用户操作，外壳调用） | 先看包里是什么（书名、发布人、版次印次、版本、是第一次导入还是更新），用户确认后导入 |
| 只读副本 | 导入的资源**编号不变**，`origin` 是 `subscribed`，`origin_ref` 是包的根。用户和插件都不能改、不能删其中一部分、不能往里面加东西，也不能把它们拖出去（`denied/readOnlyCopy`）；整本可以删 |
| 更新 | 同一个发布人、同一个根、更新的版次或印次：内容整体换成新的；包里没有了的资源删掉；工作区里别处引用它们的东西（作答、错题）不受影响（作答里本来就存着题的样子，第⑤步） |
| 不能导入自己发布的 | 发布人是自己时拒绝（编号会撞） |
| 记录 | 新表 `copies`（根、发布人、版次、印次、版本、导入时间），新迁移 `0017_copies.sql`，带升级测试（硬性规则 6） |

**包的格式**：一个 zip 文件（只存不压缩），里面一个 `package.json`（资源和版本信息）和 `blobs/`（用到的图片）。读写都在内核里做，用一个很小的 zip 读写器（和主进程解 `.odplugin` 的规矩一样严格：只认存储和 deflate，不认加密）。

**外壳**：
- 命令面板和“新建”菜单旁有“**导入资源包**”：选文件 → 显示包的信息 → 确认导入；
- 只读副本在树上标“只读”，信息面板显示“只读 · 来自 某某 · 第 2 版第 3 次印刷（学生版）”；
- 只读副本的页面全部只读（`Resource.readOnly`，外壳已有）。

### 21.5 保留字段和“当场判”（K10）

| 改动 | 说明 |
|---|---|
| 清单 | 字段可以声明 `withheld: true`（保留字段）：教师版照常带；**学生版不带**，除非这一次 `reveal` 了它 |
| 指纹（当场判用） | 类型可以注册 `seal(ctx)`：发布学生版时，内核问它“这个资源的保留字段要不要带指纹”，它返回 `{ checks: { 字段: [可接受的写法…] } }`（由插件先规范化，比如 `1/2` → `0.5`）。内核把每个写法加盐取哈希放进包里 |
| 原文放钥匙串 | 有指纹的字段，原文也随包带上；导入时内核把原文存进**学生工作区的钥匙串**（硬性规则 7），数据库里只有指纹 |
| `host.sealed.check(资源, 字段, 写法)` | 学生那里：用指纹判断一个（规范化过的）写法对不对 |
| `host.sealed.open(资源, 字段)` | 学生那里：从钥匙串取原文；插件只在作者定的时机调用（每题答完、交卷后） |
| 已公布 | 重印时 `reveal` 了的字段，原文直接带上，和教师版一样，不需要指纹和钥匙串 |

**练习插件怎么用**：
- 题的 `answers`、`explanation` 声明为保留字段。
- `seal`：一道题如果在**练习页**里，或在“交卷后”“每题答完”的**测验**里，就给出每空可接受的写法（按判题规则规范化）；只在“老师公布”测验里的题，不给（学生那里什么都没有，最安全）。
- 判题：有原文按原文判；没有原文但有指纹，用 `sealed.check` 判；两样都没有，这题“**等公布**”。
- 答案和讲解：到了时机，用 `sealed.open` 取来显示。

**保密程度**（要说清楚）：
- “老师公布”的测验：学生那里事先**什么都没有**，最安全。
- 练习和其他测验：指纹能被挨个试（`3 + 5` 这种很快就试出来），钥匙串里的原文懂技术的人能取出。**只适合练习**；正式考试要等网络，由老师那边判。

### 21.6 答案附录 `answers` 和“公布”

**答案附录**（练习插件提供，只进教师版）：
```
附录 A　习题答案
  第一章 练一练          1. 8　2. 8　3. <
  第二章 单元测验  [√ 公布]   1. 8　2. （问答）参考：……　讲解：……
                                              [公布]（运行）
```
- 按目录的顺序列出书里每个练习页、测验页的答案和讲解。
- 每个测验旁边一个勾“公布”。
- 第一版增加一种答案时机“**老师公布**”（测验的默认），学生版里不带它的答案。

**公布**（答案附录的运行动作）：
1. 记下勾选了哪些测验；
2. 通过接口调用这本书版权页的 `print`：用当前这一版重印学生版，`reveal` 这些测验里所有题的 `answers`、`explanation`；
3. 学生导入这次印刷后：
   - 这些题有了答案原文；
   - 练习插件收到这些题更新了的事件，把“等公布”的作答**重新判分**，进成绩单和错题本。

**给还在用旧版的学生公布**：在版权页的发布记录里那一版上点“重印”。

### 21.7 学生那边的样子

- 资源树：`📖 数学三年级（上）🔒`，下面的一切都只读。
- 书照常读（目录或课本目录），练习照常在书上做（判得了的当场判，判不了的显示“等公布”）。
- 测验照常开始、交卷；“老师公布”的测验交卷后显示“已交卷，等老师公布答案”。
- 学习记录、成绩单、错题本都在学生自己的工作区里，不受更新影响。

### 21.8 测试（全部通过后才提交）

**内核**：
- 发布：子树、图片、`exclude`、保留字段在学生版里没有；
- 存档：重印从存档出，原书改了也不影响；
- 导入：编号不变、只读、不能改、不能删一部分、不能加、不能拖出；
- 更新：新的版次或印次替换、删掉不再有的、作答不受影响；
- 拒绝导入自己发布的；
- 指纹和钥匙串：`sealed.check`、`sealed.open`；`reveal` 了就直接带原文；
- 迁移 `0017` 的升级测试。

**书插件**：版权页的字段、发布新版、重新印刷、发布记录、`print` 接口；按 `edition` 排除教师版的页；导出选版本。

**练习插件**：
- `seal` 的规范化；有原文、有指纹、都没有三种判法；
- “老师公布”时机；“等公布”；
- 公布后重新判分（事件）；
- 答案附录的列表、勾选、公布。

**外壳**：导入资源包的对话框、只读的标记、信息面板的来源。

**界面**（真内核，两个工作区，从“新建”开始）：
1. “老师”工作区：建课本（练习页、“老师公布”的测验、“交卷后”的测验、答案附录），新建版权页，点“发布新版”，得到学生版和教师版两个文件；
2. “学生”工作区：导入学生版，书只读；练习当场判；“交卷后”的测验交卷后显示答案；“老师公布”的测验交卷后“等公布”；
3. 学生工作区的数据库里查不到任何答案原文（测试直接查库）；
4. “老师”改了一道题的题干，学生那里不变；老师在答案附录里勾选测验、点“公布”，得到新印次的学生版；
5. 学生导入后：那个测验的作答自动判分，成绩单、错题本更新；改过的题干也更新了；
6. 学生的作答、错题都还在；
7. 学生工作区导入自己发布的包被拒绝（用老师工作区试）。

### 21.9 对照 §0 自查

## 22. 第⑥步的实际做法（和 §21 不同或补充的地方）

| 项 | 实际做法 | 为什么 |
|---|---|---|
| 内核接口 | `host.packages.publish`（先存档这一版，再印）和 `host.packages.reprint`（从存档印）两个；都要 `requires.files`，根必须是调用插件自己的类型 | 照 §21.4；“谁能发布”交给担当版权页的插件 |
| 存档 | `<工作区>/packages/<根>/e<版次>.odpack`，同一版只存一次（再存 `conflict/exists`） | 重印不受原书后来的修改影响 |
| 包的格式 | zip，只存不压缩，内核自带很小的读写器（CRC32 校验），里面 `package.json` 和 `blobs/<文件号>`；读的时候遇到压缩或加密的条目一律拒绝 | 不加新依赖（规则 9） |
| 学生版的保留字段 | 类型的 `seal(ctx)` 列出的字段：有写法的带指纹，空列表的只带原文（导入后进钥匙串，只能 `sealed.open`）；没列出的字段不带；`reveal` 了的原样带上。`seal` 的 `ctx.resource` 带 `parentId` | 练习的讲解要在答完后能看，又不需要指纹 |
| 指纹 | `sha256(盐 ␟ 资源 ␟ 字段 ␟ 写法)`，每个字段一个随机盐；钥匙串的名字 `sealed.<资源>.<字段>`，不出现在“密钥”列表里 | 规则 7：数据库里只有指纹 |
| 只读副本的检查 | 写入管线里一处：改、改参数、恢复历史、往里新建、拖进拖出、删一部分都拒绝（`denied/readOnlyCopy`）；整本（根）可以移动和删除 | 一处守住，用户和插件一样 |
| 删了再导入 | 副本整本删了（在废纸篓里或彻底删了）以后，同一个包可以再导入，任何印次都行；在废纸篓里的会恢复 | 学生误删后能找回 |
| 更新时根的位置 | 学生把书挪到哪里，更新后还在那里 | 根的位置是读者自己的 |
| 树上的标记 | 副本的根后面一个 🔒；副本里的节点不能拖，也不接收拖入 | 照 §21.7 |
| 信息面板 | “来源”一行：只读 · 来自 某某 · 第 2 版第 3 次印刷（学生版） | 照 §21.4 |
| 导入资源包的入口 | 命令面板和右上角设置菜单（在“导入…”旁边）；桌面版用系统的打开文件对话框（只看 `.odpack`），浏览器里输入路径 | 和“导入…”放在一起 |
| `print` 的调用 | 书插件导出动作 `print`（绑定版权页类型）；答案附录的“公布”用 `host.actions.call("org.onedesk.book:print", …, { resource: 版权页 })`，练习插件在清单里依赖书插件 | 接口调用是纯计算（K-f），写文件要在运行里，跨插件的运行调用是导出动作 |
| 重印的内容 | 重印（包括“公布”）用那一版的存档：老师之后改的题干要到下一版才到学生那里 | 照 §21.3（§21.8 第 5 条“改过的题干也更新了”和 §21.3 矛盾，按 §21.3 做） |
| 版权页的“重印哪一版” | 页面上一个“重印哪一版”的选项（发布过的版次），“重新印刷”按它，默认当前版 | 发布记录的每一行只放“在访达中显示” |
| 版权页在副本里 | 显示副本自己的版次和印次（来自导入记录），整页只读 | 存档里的版权页还是发布前的记录 |
| 目录导出 | 目录页多一个“导出版本”：教师版（全部）或学生版（不含只进教师版的页） | 照 §21.2 |
| 指纹的写法 | 按判题规则先规范化：数值按值（`1/2` = `0.5`），符号按符号（`＞` = `>`），选择按字母，判断按对错，其余按文字 | 两边用同一段代码 |
| 判题 | 有答案按答案；副本里没有答案的用指纹（`sealed.check`）；两样都没有是“等公布”（⏳），不进成绩和错题 | 照 §21.5 |
| 作答里存的题 | 答案被保留的题，作答里存的题目也不带答案和讲解（标 `held`），要显示时再从钥匙串取 | 学生的数据库里查不到答案原文 |
| 测验的答案时机 | 新增“老师公布”，新建测验默认用它；老师自己的工作区里照常判 | 照 §21.6 |
| 公布后重新判分 | 练习插件监听 `resource.changed`：一道题更新后，等它的已交作答重新判，改成绩和作答里存的题 | 照 §21.6 |
| 共用的视图检查 | `plugins/_testing/view-check.ts` 多查一条：表格的列名必须是文字（内核不接受多语言的 Label） | 这一步踩到过 |

**测试**：内核 `crates/kernel/tests/packages.rs`（发布、存档、变体、只读、更新、删除后再导入、指纹和钥匙串）和 `packages.rs` 里的 zip、指纹单元测试；书插件、练习插件的 `main.test.ts` 各加一组；外壳 `transfer-dialogs.test.tsx`；界面 `e2e/publish.spec.ts`（两个工作区）。

## 23. 第⑦步详细设计：文书（模板、填写项、签名与锁定、系列）（已确认，实际做法 §24）

> 范围：book.md §11 第⑦步，需求见 `documents.md` §1–§3、§11.4。做完后能用（一个工作区）：
> 1. 科室维护“入院记录模板”：正文里写自由文字、填写项（`{{?体温 | 数字, ℃, 35~42, 必填}}`）、环境里的值（`{{姓名}}`）、嵌入、计算；
> 2. 医生在“张三 · 第 2 次住院”环境里新建一份入院记录，选模板，在正文里直接填；BMI 跟着体重、身高变；
> 3. 写完“签名”：检查必填，正文定稿，引用的内容和环境的值取快照，之后只读；上级“审签”；
> 4. 要改只能“修订”：写理由，签名作废，回到草稿；历史里能看到每次签名时的样子；
> 5. 档案是一本书：入院记录、“病程记录”系列（点“新增一份”按模板写，按时间排）、心电图，连续阅读、导出。
>
> 不在这一步：时限和待办、插入片段（K8）、打印版式、真正的电子签名（证书、手写板）、多人同时编辑。

### 23.1 先问现实怎么做

文书不是书，现实里成熟的做法是病历书写规范、公文格式（GB/T 9704）和各种格式化的表单：

| 现实 | 这里 |
|---|---|
| **空白表格 / 病历模板**：印好的格式，留着要填的空 | **文书模板**：一个资源，正文里写好格式和空（填写项） |
| 照模板写一份，之后模板再改，已经写好的不变 | **文书**：新建时选模板，**复制**模板的正文；记下来源和那时模板的版本 |
| 空里填的是数据（体温 37.2），不只是字 | 填写项的值存成结构化数据，能检查、能计算、能被引用 |
| **签名**：写完的人签名，签了就算交了，不能再涂改；上级再**审签** | **签名**是文书自己的事：第一次签名时检查必填、正文定稿；之后每一级签一次 |
| 签了字的纸上，抄进来的检验结果就是当时的结果 | 签名时，嵌入和计算的结果、环境里的值**取快照**，之后按快照显示 |
| 要改：划掉、写明理由、签名（修订留痕） | **修订**：写理由，签名失效，回到草稿；每次签名时的样子在历史里只读保留 |
| 作废的单子盖“作废”章，不能撕掉 | **作废**：也是一个章，不能再签、不能修订 |
| **病历夹**：一个病人一次住院的所有文书，有固定顺序 | **档案就是书**（不加新东西）；文书在书里担当正文 |
| **病程记录**：同一种格式一天写一份，按时间夹在一起 | **系列**：书里的一种角色，下面是同一模板写的很多份，按时间排，“新增一份” |

“签名”“盖章”在现实里是同一类动作：在纸上加一个记号，记号一落，纸上的内容就定了。内核只提供这个通用的“签章”（K6），签几级、叫什么、什么时候检查，都是文书自己的事。

### 23.2 角色和类型

外置插件 `org.onedesk.document`（文书，D456：不进安装包，以 `.odplugin` 发布）：

| 类型 | 在书里的角色 | 带的逻辑 |
|---|---|---|
| **文书模板** `template` | 不进书（`part: "none"`；放进书里只当正文显示） | 正文的格式、填写项的写法和预览、签名级数 |
| **文书** `document` | 正文（`body`，编号按章） | 选模板、填写、阅读、签名、修订、作废、必填和范围检查；被引用时给出一节或一个填写项的值 |
| **系列** `series` | 正文里的容器（`container: true`，编号按章） | 用哪个模板、“新增一份”、按什么排、连续阅读时下面各份连成一篇 |

- 三种都是资源，信息面板照常；文书和模板每页可选环境（文书默认用新建时标签页的环境）。
- 书插件不改：档案就是书，目录照常编号、浏览、导出。
- 不新增“档案”“病案首页”类型：封面、目录已经够用（§0.3：没有需要就不加角色）。

### 23.3 文书模板 `template`

**字段**：`text`（长文字，`refs: true`）、`levels`（签名级数，一行一级，默认“书写”；例：“书写 / 审签”）。

**填写项的写法**（插件自己定，规则 5）：

```
体温 {{?体温 | 数字, ℃, 35~42, 必填}}　脉搏 {{?脉搏 | 数字, 次/分}}
过敏史 {{?过敏史 | 单选: 无/有, 默认=无}}
主诉 {{?主诉 | 长文字, 必填}}
体重 {{?体重 | 数字, kg, 默认={{体重}}}}　身高 {{?身高 | 数字, m}}　BMI [[=BMI | 体重=@体重, 身高=@身高]]
```

| 部分 | 可写的 |
|---|---|
| 名字 | 文字、数字、`_`，最多 40 个字；同一篇里不能重名 |
| 类型 | 文字（默认）、长文字、数字、日期、时间、单选（`单选: a/b/c`）、多选、是非；英文写法 `text`、`longtext`、`number`、`date`、`time`、`choice:`、`multi:`、`yesno` 也认 |
| 单位 | 数字后面的一段（`℃`、`kg`） |
| 范围 | `35~42`；超出时提醒，不拦 |
| 必填 | `必填` / `required` |
| 默认 | `默认=…`，可以是 `{{环境里的值}}` |

- `@名字`：本文的填写项，只在计算的参数里用。
- 写错的填写项（类型不认识、重名）在预览里标红，说明哪里错了。

**页面**：上面是正文编辑框和签名级数；下面是**预览**：按当前标签页的环境，像一份新文书那样显示（控件可以试填，不保存）。

**写一份**：不在模板页上放按钮（一个功能一个入口，§23.4）。模板的信息面板“被引用”里能看到用它写了哪些文书（文书的 `template` 是一个引用字段，已有的能力）。

### 23.4 文书 `document`

**字段**：`template`（引用，指向模板）、`templateRev`（复制时模板的版本）、`text`（从模板复制来的正文，`refs: true`）、`levels`（从模板复制）、`v.<名字>`（各填写项的值）。

**新建**：只有一个入口——“新建 → 文书”（在树上哪里新建就放在哪里；系列里由系列放，§23.6）。
1. 新文书（还没保存时信息面板照常）页面上只有一个“模板”选择框；
2. 选好模板，正文和签名级数复制过来，值按“默认”填好（`{{环境的值}}` 按标签页的环境取）；
3. 之后模板再改，这份文书不变。

**编辑（草稿）**：一篇带控件的文章（K4 `flow` 节点）：
- 填写项显示成控件：数字框（单位在后面）、下拉、日期、是非、长文字框；
- `{{姓名}}` 按标签页的环境显示；嵌入照常；`[[=BMI | 体重=@体重, …]]` 里的 `@体重` 换成现在填的值，改了体重 BMI 马上跟着变；
- 超出范围的值后面标“超出 35~42”；
- 正文里的自由文字也能改：操作栏“阅读 / 编辑”切到编辑时，是正文的编辑框（和笔记一样），填写项是那串写法；切回来又是带控件的文章。

**阅读**：只显示值；没填的显示灰色“未填”；超出范围的标出来。

**签名**（操作栏，页面事件，用户的操作）：
1. 第一级签名前检查：必填的没填，不能签，列出缺哪几项；超出范围的列出来，要再点一次“仍然签名”；
2. 第一级签名时**定稿**：正文里的 `{{环境的值}}`、`@填写项` 换成当时的值写进正文，然后加上签章（K6），内核给嵌入和计算取快照；
3. 签名人：一个“签名人”输入框（标签页参数），默认取环境里的 `{{签名人}}`；
4. 每一级签一次，按 `levels` 的顺序；全部签完显示“已完成”。

**修订**：已签名的文书点“修订”，填理由（必填），所有签章撤下，回到草稿；历史里每一次签名时的版本只读保留，修订记录写明谁、什么时候、为什么。

**作废**：盖一个“作废”章（K6），之后不能签名、不能修订；仍然可以阅读、被引用。

**信息面板**：签章记录（内核给出，§23.5）显示在“来源”下面：“书写 · 张三 · 2026-11-26 10:20”“审签 · 李四 · …”“修订 · 理由：…”。

**被引用**：
- `![[张三入院记录#主诉]]`：按标题取一节（和笔记一样）；
- `[[=张三入院记录 | 项=体重]]`：一个填写项的值（带单位），行内显示；
- 已签名的文书被引用时，给的是签名时的样子。

### 23.5 内核：K4 文中的填写项、K6 签章与快照

都不认识文书：

**K4 视图节点 `flow`**：
```
{ type: "flow", id, text, fields: ViewField[] }
```
- `text` 是 Markdown，里面的 `{{field:名字}}` 是控件的位置，`名字` 是 `fields` 里某个字段的 `name`；每个字段在文中出现一次；
- 字段和表单字段一样（`bind` 到 `body.<…>` 或 `param`），外壳负责未保存标记、⌘S；
- 外壳把控件画在文字中间（行内的小号控件；长文字单独一段）；
- 内核检查：字段合法、每个都在文中出现、最多 500 个。

**K6 签章**（资源上的记号，加上就定稿）：

| 能力 | 说明 |
|---|---|
| `host.resources.stamp(id, { label, signer })` | 给自己类型的资源加一个签章（页面事件或运行里，用户的操作；AI 不行）。第一个签章落下时：资源变成只读；它的嵌入和带参数引用（refs 表里的）**取快照**存起来 |
| `host.resources.unstamp(id, { reason })` | 撤下所有签章（理由必填），快照丢弃，资源恢复可改。插件的“修订”用它 |
| 只读 | 有签章的资源：改、改参数、恢复历史、删除、彻底删除都拒绝（`denied/stamped`）；可以移动、可以被引用 |
| 快照 | 显示一份有签章的资源时，外壳取它里面的嵌入和计算，带上 `within: 资源`，内核给快照，不重新算 |
| 记录 | 新表 `stamps`（资源、序号、名称、签名人、时间）和 `stamp_log`（加章、撤章、理由、当时的版本）；审计照常；新迁移 `0018_stamps.sql`，带升级测试（规则 6） |
| 协议 | `Resource.stamps`（签章列表）、`Resource.stampLog`；有签章时 `readOnly: true`；`ResourceEmbedParams.within`；文字节点和 `flow` 节点可以带 `within`（嵌入的内容里引用的东西按谁的快照取） |

- 签章的名称、签名人是插件给的文字，内核只存不解释（“作废”也是一个签章，插件自己认）。
- 内核不认识环境占位符（规则 5）：`{{…}}` 和 `@…` 由插件在第一次签名前写进正文。

**不需要 K5（从资源新建）**：模板和文书是两种类型，复制正文、记下来源是文书插件新建时自己做的（`template` 引用字段 + `templateRev`）；“用它写了几份”就是模板的“被引用”。不加新的内核能力（§0.7 不乱加东西）。

### 23.6 系列 `series`

```
📖 张三 · 第 2 次住院
   封面　目录
   入院记录（文书）
   病程记录（系列，模板：日常病程记录）
      2026-11-24 病程记录
      2026-11-25 病程记录
   心电图（图片）
```

- **字段**：`template`（引用）、`order`（按什么排：新建时间（默认）或某个填写项，比如“记录时间”）。
- **新增一份**：操作栏的“新增一份”，按模板在系列里新建一份文书，名字是“日期 + 模板名”，打开它。
- **排序**：系列实现装订落点（K-c `place`）：新的一份落在按 `order` 该在的位置；某一份的那个填写项改了，系列收到 `resource.changed` 后把它挪到该在的位置（只移动，签了名的也能移动）。
- **在书里**：系列是容器，目录照常把下面各份编进去、连续阅读；系列自己的页面列出各份（日期、状态），点一行打开。
- 只接收文书（`accepts: ["document"]`）。

### 23.7 外壳

- `flow` 节点：行内控件（文字、数字带单位、日期、时间、下拉、多选、是非），长文字单独成段；读写模式和表单一样。
- 嵌入和行内计算带 `within`：页面上和嵌入里显示有签章的资源时，传给内核。
- 信息面板：有签章的资源显示签章记录和修订记录（§23.4）；只读提示“已签名，不能修改；要改请修订”（文字由外壳按 code 配）。
- 历史面板：有签章的版本旁标出签章。
- 新的错误原因 `stamped`、`noReason`，三种语言（ja-JP 语言包升版本）。

### 23.8 测试（全部通过后才提交）

**内核**：
- `flow`：字段检查（不在文中、重复、超过上限都拒绝）；
- 签章：加章后只读（改、恢复、删除被拒，移动可以）；只能给自己的类型、只能在页面事件或运行里；AI 不行；
- 快照：加章后被嵌入的原文和公式改了，带 `within` 取到的仍是加章时的结果；撤章后又是活的；
- 撤章：理由必填；记录和审计；历史里留着加章时的版本；
- 迁移 `0018` 的升级测试。

**文书插件**：
- 填写项写法的解析（类型、单位、范围、必填、默认、英文写法、写错的提示）；
- 模板预览、从模板新建（复制、默认值、环境的值）、模板改了文书不变；
- `@名字` 进计算；必填和范围检查；签名定稿（写进正文的值）、多级签名、修订、作废；
- 被引用：一节、一个填写项的值；
- 系列：新增一份、按时间或填写项排、改了值以后挪位置；在书里的角色。

**外壳**：`flow` 的行内控件（编辑、未保存、⌘S）；`within` 的传递；签章记录。

**界面**（真内核，从“新建”开始）：
1. 建环境“张三 · 第 2 次住院”（参数：姓名、体重、签名人）；建“入院记录模板”（体温、主诉必填、体重默认 `{{体重}}`、身高、BMI 计算）和“日常病程记录模板”；
2. 新建 → 文书，选模板：姓名自动带出、体重默认填好；填身高，BMI 跟着变；
3. 不填主诉点签名：被拦，说缺“主诉”；填好、体温填 45：提示超出，“仍然签名”；
4. 签名后只读；改环境里的体重、改公式：文书显示的仍是签名时的值；审签；
5. 修订：不写理由不行；写了理由回到草稿；历史里有签名时的版本；
6. 建一本书“张三 · 第 2 次住院”，放入院记录、建“病程记录”系列，新增两份，按时间排；目录连续阅读、导出；
7. 另一篇笔记里 `[[=入院记录 | 项=体重]]` 显示签名时的体重。

## 24. 第⑦步的实际做法（和 §23 不同或补充的地方）

| 项 | 实际做法 | 为什么 |
|---|---|---|
| 签名要先保存 | 有没保存的内容时点“签名”“作废”，提示“先保存（⌘S）”；签的是保存了的内容 | 页面事件不能替外壳保存；签名后页面只读，没保存的内容会一直挂着“未保存” |
| 必填的标记 | 填写项后面写“（必填）”，控件本身不设“必填” | 外壳对必填控件会拦住保存；草稿要能填一半就保存，必填只在签名时查 |
| 新文书复制模板 | 选好模板保存后，文书插件在 `resource.changed` 里把模板的正文和签名级数复制过来（只一次） | 资源页的保存由内核做，插件只能在保存后补 |
| 默认值 | 控件里显示默认值（`默认=…`，可以取环境的值），没填就按默认；签名时写进去 | 不必为了默认值先写一次 |
| 签名时定稿 | 签名前把填写项的值、环境的值、`@名字` 写成 `signedText`（引用字段），之后阅读和被引用都用它；`text` 保留原样，修订后还能接着填 | 修订要回到能填的样子 |
| 读的时候保留换行 | 阅读视图里每一行仍是一行 | 表单的一行一项，Markdown 会把它们连起来 |
| 作废 | 一个名称是“作废”（任一种语言）的签章 | 签了名的文书内容不能改，作废只能是一个章 |
| `within` | 外壳按“正在显示的资源”（页面、嵌入里）自动带上；书的导出、AI 读嵌入也带上。文字节点不另加 `within` | 外壳本来就知道每一处引用写在哪个资源里 |
| 签章的权限 | 页面事件、命令、运行都可以（不能在事件处理函数、纯计算、AI 里） | 命令也是用户的操作 |
| 快照的范围 | 第一个签章落下时，取资源 refs 表里的嵌入和带参数引用（最多 500 个）；嵌入内容里再嵌入的不取 | 一层就够定稿；多层会很慢 |
| 历史面板 | 签章前最后一次修改的条目标“签名时” | 历史按字段记录，没有版本号可对 |
| 系列的排序 | 系列实现 `place`；新建和改了排序的填写项时，系列把那一份挪到该在的位置（移到下一份之前） | 移到同一个父节点内部不会重新落位 |
| `flow` 的外壳 | 设计系统新增 `FlowText` 组件和 token `--flow-control-width` | 规则 3：样式只在 `src/design` |
| 共用的视图检查 | `plugins/_testing/view-check.ts` 认识 `flow` 节点 | 插件测试和内核一样严格 |
| QuickJS 的保留字 | 插件文件不叫 `document.js`、语言键不用 `document.` 开头（`doc.js`、`doc.*`） | 插件检查把 `document.` 当成浏览器的全局对象 |

**测试**：内核 `crates/kernel/tests/stamps.rs`（签章只读、快照、撤章理由、权限、`flow` 检查）；文书插件 `plugins-external/org.onedesk.document/main.test.ts`；界面 `e2e/document.spec.ts`（从“新建”开始：填写、计算、签名的检查、只读和快照、审签、修订、档案和系列、引用签名后的值）。

## 25. 第⑧步详细设计：活书（步骤页、流程目录、运行记录）（已确认，实际做法 §26）

> 范围：book.md §8、§11 第⑧步，需求见 `documents.md` §25 B5（运维手册、数据报告、接口测试、入职书）。做完后能用（一个工作区）：
> 1. 写一本“发布手册”：① 查当前版本（SQL 查询）② 调健康检查（HTTP 请求，期望状态码 200）③ 等人确认 ④ 执行发布命令 ⑤ 再查版本（期望是新版本号）；
> 2. 选环境“生产”，在流程目录上点“运行”：从上到下一步步跑，结果和 ✓ ✗ 显示在每一步下面；
> 3. 到第 ③ 步停下等确认，点“继续”接着跑；某一步失败就停，修好后“从这一步继续”；
> 4. 跑完留下一份运行记录：每一步的输入、输出、✓ ✗、时间、谁跑的，可以导出成报告。
>
> 不在这一步：循环、跳转、并行、定时自动运行、多人分工（谁确认哪一步）。

### 25.1 先问现实怎么做

活书在实体书里没有现成的样子，最接近的是**操作规程**和**检查单**（航空检查单、手术安全核查表、运维手册）：

| 现实 | 这里 |
|---|---|
| 规程的每一步：做什么、用什么、做完应该看到什么 | **步骤页**：说明、要运行的东西、给它的值、期望 |
| “若……则跳过本步” | 步骤页的**条件** |
| “请确认……后再继续”，签字 | 步骤页的**等人确认** |
| 按检查单**逐项**执行，不能跳着做；出问题就停 | **流程目录**：一种目录，它的“读”就是从上到下一步步执行，失败就停 |
| 执行时填一张**记录单**：每一项做了什么、结果、谁、几点 | **运行记录**：每跑一遍一份，可以导出成报告 |
| 前一步量出的数，后一步要用 | 前面步骤的结果，后面用 `@步骤名.值名` 取 |

规程（书）本身不变；执行规程的是读它的人按检查单一项项做（流程目录）；记下来的是记录单（运行记录）。逻辑分别放在这三个角色里（§0.2）。

### 25.2 角色和类型

新的外置插件 `org.onedesk.runbook`（流程，D456）：

| 类型 | 在书里的角色 | 带的逻辑 |
|---|---|---|
| **步骤页** `step` | 正文（编号按章） | 说明、运行什么、给它的值、期望、条件、等人确认；显示最近一次的结果 |
| **流程目录** `flow` | 目录（`toc`，前面，最多一页；替换普通目录，和课本目录一样） | 按顺序一步步运行；条件跳过、等人确认、失败就停、从停的地方继续；显示每一步的状态 |
| **运行记录** `log` | 不进书（在“运行记录”树里） | 一遍运行的全部结果；导出报告 |

- 书插件、HTTP、SQL、命令等插件的类型都不改角色；它们放进书里照常是正文，能运行的照常能运行（§0.6）。
- 步骤页可以不运行任何东西（只写说明、等人确认），就是检查单上的一项人工检查。
- 编号借书插件按书调用的 `entries`，带上自己的角色表（和课本目录一样，§20）。

### 25.3 步骤页 `step`

**字段**：

| 字段 | 内容 |
|---|---|
| 说明 `text` | Markdown，`refs: true`；可以嵌入（如 `![[健康检查]]` 显示那个请求） |
| 运行 `target` | 引用：要运行的资源（HTTP 请求、SQL 查询、命令、脚本、AI 提示……任何有“运行”的资源）；可以空 |
| 给它的值 `inputs` | 每行 `名字 = 值`：值可以写 `@前面的步骤.值名`、`{{环境的值}}`；运行时代替那个资源里同名的 `{{名字}}` |
| 期望 `expect` | 每行一条，全部成立才算 ✓：`@状态码 = 200`、`@行数 > 0`、`@版本 = @发布前.版本 + 1` 不支持（不做计算，要算就放一页计算页） |
| 条件 `when` | 一条，成立才运行这一步，否则跳过：`{{环境}} ≠ 生产`、`@行数 > 0` |
| 等人确认 `confirm` | 一句话；写了就在这一步（运行之后）停下，人点“继续”才往下 |

**比较的写法**（插件自己定，规则 5）：`=`、`≠`（`!=`）、`>`、`<`、`≥`（`>=`）、`≤`（`<=`）、`包含`（`contains`）、`为空`、`不为空`；两边是 `@…`、`{{…}}` 或直接写的字；两边都像数字时按数比，否则按字比。

**值从哪里来**（`@步骤名.值名`）：
- 步骤名就是步骤页的名字；
- 值名先在被运行资源给出的**数据**里找（§25.5），找不到再在表格结果的**第一行**按列名找；`@步骤名` 本身是结果的文字（表格是第一行第一格）；
- 步骤页下面列出最近一次运行给出的**全部值名和值**，照着写就行（不用记内部名字）。

**页面**：字段在上面；下面是“最近一次”：在当前运行记录里这一步的结果（状态、用时、输出、各条期望的 ✓ ✗、可用的值）。操作栏“运行这一步”：只跑这一步（前面步骤的值取当前运行记录里的）。

**在书里**（流程目录连续显示时）：说明、被运行资源的嵌入（由说明里的 `![[…]]` 决定）、这一步在当前记录里的状态和结果。

### 25.4 流程目录 `flow`

```
┌ 发布手册 · 流程 ─────────────── [环境：生产 ▾] │ 运行  继续  新的一遍 ┐
│ 第 3 次运行 · 张三 · 2026-11-27 10:20 · 停在 ③ 等确认                     │
│  ✓ ① 查当前版本          0.4 s   版本 = 2.3.1                            │
│  ✓ ② 健康检查            0.2 s   状态码 = 200 ✓                          │
│  ⏸ ③ 确认可以发布        “看一下上面的版本和健康检查，没问题再继续”      │
│  · ④ 执行发布                                                           │
│  · ⑤ 再查版本                                                           │
│ ──────────────── 连续阅读（和目录一样） ────────────────                │
└─────────────────────────────────────────────────────────────────────────┘
```

- **编号和浏览**：和书的目录一样（借 `entries`），连续或分页阅读；每一步前面是它在当前记录里的状态：`·` 没跑、`✓`、`✗`、`⏭` 跳过、`⏸` 等确认。
- **运行**（一个运行动作）：新建一份运行记录，从第一步开始；
- **继续**：在当前记录上，从停下的那一步接着跑（等确认的：记下谁确认、几点，再往下；失败的：重跑那一步）；
- **新的一遍**：放下当前记录（留着），下次“运行”另起一份；
- **怎么走**：
  1. 按目录的顺序；
  2. 条件不成立的跳过；
  3. 运行失败或期望不成立就停；
  4. 遇到“等人确认”运行之后停下。
  不做循环、跳转、并行（不让书变成编程语言）。
- 子书、分组里的步骤照目录的顺序算在里面；不是步骤页的页（正文、图片……）不运行，只阅读。
- 用标签页的环境运行；被运行的资源也用这个环境。
- 一次“运行”或“继续”是一个运行（在运行面板里能看到、能停止）；停止时记录里写“被停止”，可以继续。

### 25.5 内核：K14 运行一个资源

都不认识书和步骤：

| 能力 | 说明 |
|---|---|
| `host.runs.call(resourceId, { params })` | 在当前运行里，运行那个资源**自己的运行**（它页面上的第一个“运行”按钮），就像用户在它的页面上点了“运行”：页面上的值照它保存的，`{{名字}}` 按环境取，`params` 里给的优先。返回 `{ status: "ok" \| "failed", output, data?, error?, ms }` |
| 权限 | 新的 `requires.runs`（“运行其他资源”）：用户在插件详情里看得到；只能在运行里用；AI 的运行里不行；嵌套最多 4 层，不能运行自己正在跑的资源 |
| 时间 | 等待被运行资源的时间不算调用方的时间（和程序、传输一样暂停计时，D361）；被运行的一方有自己的时间限制 |
| 停止 | 调用方的运行被停止，被运行的一方一起停 |
| 审计 | 记一条 `run.call`（谁、运行了什么） |
| 数据 | 运行动作的结果可以带 `data`（已有，D441），`runs.call` 原样交给调用方；HTTP、SQL、命令、脚本插件补上各自的 `data`：HTTP `{ 状态码, 耗时, 头, 正文, json? }`，SQL `{ 行数, 列, 行 }`，命令和脚本 `{ 退出码, 输出, 错误输出 }`——值名用中文、英文都给（按插件的语言文件），步骤页列出的就是这些 |

- 这些插件的改动只是在结果里多给 `data`，界面和行为不变。
- 不新增迁移：运行记录是练习作答那样的资源（`log` 类型），在插件自己的树里。

### 25.6 运行记录 `log`

- **放在哪里**：树“运行记录”里，按书分组（第一次运行时建好，和学习记录一样）；名字“发布手册 · 第 3 次运行”。
- **内容**：书、环境、开始和结束时间、谁跑的；每一步：状态、开始时间、用时、给它的值（密钥不记，规则 7）、输出（文字最多 64 KB，表格最多 200 行）、数据、期望各条的结果、确认人和时间、错误。
- **页面**：一张表（步骤、状态、用时、摘要），点一行展开看这一步的全部；“导出”把整份记录写成 Markdown 报告到授权文件夹（和书的导出一样）。
- 记录只由流程目录写；用户能改名、删除，不能改内容（页面只读）。

### 25.7 外壳

- 不需要新的视图节点：流程目录用已有的 `sequence`（每一项的标题前加状态符号），步骤页、记录页用已有的表单、文字、表格。
- 插件详情里显示新权限“运行其他资源”（三种语言）。
- 新的错误原因：`runs.notRequested`（没声明权限）、`runs.notRunnable`（那个资源没有运行）、`runs.loop`（在运行自己），三种语言（ja-JP 语言包升版本）。

### 25.8 测试（全部通过后才提交）

**内核**：
- `runs.call`：运行另一个插件的资源，拿到输出和 `data`；`params` 代替 `{{名字}}`；没声明权限、不在运行里、AI、运行自己、嵌套太深都拒绝；
- 停止调用方，被运行的一方一起停；等待时调用方不超时；
- 审计。

**流程插件**：
- 比较写法的解析和判断（数和字、`包含`、`为空`）；
- `@步骤.值名` 的查找（数据、表格第一行、文字）；
- 按顺序运行、条件跳过、失败就停、等人确认、继续（重跑失败的、记下确认人）、新的一遍；
- 运行记录的内容（不记密钥）、导出报告；
- 在书里的角色（目录、步骤正文）。

**HTTP、SQL、命令、脚本插件**：结果里的 `data`。

**界面**（真内核，从“新建”开始）：
1. 建环境“测试”（参数：`host`），建一个 HTTP 请求“健康检查”（请求测试用的本地服务）、一个脚本“查版本”（输出版本号）、一个命令“发布”（测试用的假命令）；
2. 建书“发布手册”，新建流程目录（替换目录），五个步骤页：查版本、健康检查（期望 `@状态码 = 200`）、确认、发布、再查版本（期望 `@版本 = 2.3.2`）；
3. 点“运行”：①② ✓，③ 停下等确认；点“继续”：④ 跑、⑤ ✗（版本没变）停下；
4. 改好假命令，“继续”：⑤ 重跑 ✓，记录完成；
5. 运行记录页：五步的结果、确认人；导出报告；
6. 条件：步骤 ④ 写“`{{环境}} = 生产` 才运行”，在“测试”环境里跑时 ⏭。

### 25.10 需要你定的

## 26. 第⑧步的实际做法（和 §25 不同或补充的地方）

| 项 | 实际做法 | 为什么 |
|---|---|---|
| 被运行的一方在哪里跑 | `runs.call` 在调用方的运行里执行被运行资源的动作（和 `actions.call` 同一套：自己的沙箱和授权、调用方的停止），不另起一条运行记录 | 一次“运行”“继续”就是运行面板里的一条；它的结果（`data`）要原样交回 |
| 页面参数 | 内核按标签页的环境读出被运行资源的页面，页面参数取它显示的环境值，`params` 优先；输入是页面保存的值（密钥字段不给） | 和用户在那个页面上点“运行”一样 |
| 值名 | HTTP `status / ms / body / headers / json`，SQL `rows / columns`，命令和脚本 `exitCode / stdout / stderr`；每个值同时用各语言的名字给出（`data.<名字>` 语言键，如 `状态码`、`退出码`、`输出`） | 步骤页列出的值照着写，不用记内部名字 |
| 表格结果 | 一步的“文字”是表格第一行各格连起来；`@步骤.列名` 取第一行那一列（列名、列标题都认） | 脚本、命令的结果是表格 |
| 步骤能运行的类型 | 步骤页的“运行”下拉列出 HTTP 请求、SQL 查询、命令、脚本、AI 提示 | 引用字段要写明类型才能列出选项 |
| 运行人 | 流程目录页上一个“运行人”（页面参数，默认取环境里的 `{{运行人}}`/`{{Operator}}`）；记录的开始人和确认人都用它 | 第一版没有用户身份 |
| 运行记录的位置 | “流程记录”树里（树不叫“运行记录”：外壳已有同名的运行历史视图），每本书一个“书的运行记录”文件夹（类型 `logs`） | 插件不能建内核的分组 |
| 记录里的确认 | 等确认的一步点“继续”时记下确认人和时间（状态“已确认”） | 照 §25.4 |
| 只跑一步 | 步骤页“运行这一步”写进流程目录当前的记录（没有就新建一份），前面步骤的值从那份记录取 | 照 §25.3 |
| 新的一遍 | 流程目录上的“新的一遍”只是放下当前记录（页面事件）；下一次“运行”另起一份 | 不需要运行 |
| HTTP 在测试里 | 请求的地址写真实的主机（`{{名字}}` 不是 HTTP 插件的写法，它用 `:名字`；网络授权按资源里写的地址给） | HTTP 插件自己的规则 |

**测试**：内核 `crates/kernel/tests/runcall.rs`（运行、数据、参数优先、失败、没有运行、权限、不在运行里、运行自己、停止连带）；流程插件 `plugins-external/org.onedesk.runbook/main.test.ts`；HTTP、SQL、命令、脚本插件的结果带 `data`；界面 `e2e/runbook.spec.ts`（发布手册：等确认、继续、跳过、失败停下、修好继续、运行记录、导出报告）。

## 27. 第⑨步详细设计：库存账本（业务即书的第一个例子）（已确认，实际做法 §28）

> 方向见 `docs/redesign/direction.md` §6：业务管理系统也做成书。库存管理系统，就是一本库存账本。
>
> 范围：一个仓库一本账；入库、出库、盘点；存货明细账；收发存汇总表；月末结账。做完后能用（一个工作区）：
> 1. 建一本“原料库存账”，启用表上写单位、经管人、计价方法；
> 2. 建存货档案：螺丝 M6、钢板 2mm……
> 3. 填入库单、出库单，审核后记账，存货明细账上一行行记下，结存自动算；
> 4. 月底盘点：盘点表上带出账面数，填实存数，盘盈盘亏审核后记账；
> 5. 收发存汇总表列出每种存货的期初、收入、发出、期末；结账后这个月不能再记；
> 6. 记错了只能红字冲销，不能涂改。
>
> 不在这一步：多仓库调拨、批次和保质期、条码、采购订单和销售订单、和财务总账的对接、月末一次加权平均法（先做移动加权平均和先进先出）。

### 27.1 先问现实怎么做

手工记账的库存管理已经有几百年的成熟做法（会计基础工作规范、存货核算）：

| 现实 | 这里 |
|---|---|
| **账簿启用表**：贴在账簿扉页，写单位名称、账簿名称、启用日期、经管人员、交接记录 | **启用表**（版权页的位置）：账簿的身份、计价方法、经管人和交接 |
| **账户目录**：账簿前面列出每个账户在第几页 | **存货目录**：一种目录，列出每种存货和它的结存 |
| **存货明细账**：每种存货一个账户，账页上一行一笔：日期、凭证号、摘要、收入（数量、单价、金额）、发出、结存 | **存货**（一个账户，容器）和它下面的**账页** |
| 账页写满了，“过次页”，下一页“承前页” | 账页最多 100 行，满了另起一页，第一行“承前页” |
| **原始凭证**：入库单、出库单，经手人填，保管员、审核人签字 | **入库单、出库单**：文书一样的单据，签字（签章 K6）后才能记账 |
| **记账**（过账）：记账员按审核过的凭证一笔笔登记到账页上，凭证上打“已记账”记号 | 单据上的“记账”：写进每种存货的账页，单据盖“已记账”章 |
| **记错了不能涂改**：用红字冲销原记录，再按正确的重记 | **冲销**：填一张红字单据（数量为负），引用原单据，记账 |
| **盘点**：盘点表列出账面数，实地点数，算出盘盈盘亏，审批后调账 | **盘点表**：带出账面数，填实存数，审核后记账 |
| **月末结账**：每个账户画线，写“本月合计”“本年累计”，结出余额；结账后本月不再记账 | **收发存汇总表**上的“结账”：每个账页写本月合计，这个月的单据和账页都锁住 |
| **收发存汇总表**（月报） | 汇总表：每种存货期初、收入、发出、期末 |

一本库存账 = 一个仓库。多个仓库就是多本账（实体账也是这样）。

### 27.2 角色和类型

新的外置插件 `org.onedesk.ledger`（账簿）：

| 类型 | 角色 | 部分 | 带的逻辑 |
|---|---|---|---|
| **启用表** `setup` | 新角色 `setup`，最多 1 | 前 | 单位、账簿名称、启用日期、计价方法、数量和金额的小数位、经管人员和交接记录 |
| **存货目录** `catalog` | 目录（`toc`），最多 1 | 不进阅读 | 列出存货（编码、名称、规格、单位、结存数量和金额、低于下限的标出）；点一种打开它的账 |
| **存货** `item` | 新角色 `account`（容器） | 正文 | 编码、名称、规格型号、计量单位、类别、存放地点、上下限、期初数量和单价；下面是它的账页 |
| **账页** `sheet` | 正文页 | 正文 | 一页最多 100 行；只由记账写，人不能改 |
| **入库单** `receipt`、**出库单** `issue` | 新角色 `voucher` | 不进阅读（放在单据簿里） | 单据：日期、单号、经手人、往来单位、摘要、明细行；审核、记账、冲销 |
| **盘点表** `count` | 新角色 `voucher` | 不进阅读 | 盘点日期、明细（带出账面数，填实存数，算出差额）；审核、记账 |
| **单据簿** `vouchers` | 新角色 `register`（容器） | 后 | 按月放单据（像凭证装订本）；列出单据和状态 |
| **收发存汇总表** `summary` | 新角色 `report` | 后 | 一个月一张：期初、收入、发出、期末；“结账” |

- 书插件不改；存货目录借书插件按书调用的 `entries` 编号（和课本目录、流程目录一样）。
- 一本库存账的样子：

### 27.3 单据（入库单、出库单、盘点表）

**字段**：日期、单号（自动编：入库 `RK-年月-序号`，出库 `CK-…`，盘点 `PD-…`，可以改）、经手人、往来单位（入库是供应商，出库是领用部门）、摘要、**明细行**。

**明细行**（K15 表格字段，§27.6）：

| 单据 | 每行 |
|---|---|
| 入库单 | 存货（选）、数量、单价、金额（数量 × 单价，自动算，可以改单价或金额） |
| 出库单 | 存货（选）、数量；单价和金额在记账时按计价方法算出，记账后显示 |
| 盘点表 | 存货（选，或“带出全部”）、账面数（自动）、实存数（填）、差额（自动）；盘盈按最近单价入，盘亏按计价方法出 |

**流程**（和第⑦步的文书一样用签章 K6）：
1. **草稿**：填写；
2. **审核**：检查——每行都选了存货、数量大于 0、出库不超过结存（超过时提示，再点一次仍然审核）、日期不在已结账的月份；通过后盖“审核”章，单据只读；
3. **记账**：按行写进每种存货的账页（§27.5），盖“已记账”章；
4. **冲销**：已记账的单据不能修订；在它上面点“冲销”，生成一张红字单据（数量为负，引用原单据，摘要“冲销 RK-…”），审核、记账后两笔抵消；原单据标“已冲销”。
5. 未记账的单据可以“修订”（撤下审核章，写理由），和文书一样。

### 27.4 存货 `item` 和存货目录 `catalog`

**存货的页面**：档案字段（编码、名称、规格、单位、类别、存放地点、下限、上限、期初数量、期初单价）；下面是**明细账**：它的账页按顺序连起来显示（日期、凭证号、摘要、收入、发出、结存），最后一行是现在的结存。

- 期初数量和单价只能在第一笔记账之前改；之后改要用盘点调整。
- 先进先出时，结存还按入库的批次分开（每批数量和单价），明细账下面列出。

**存货目录**：一张表（编码、名称、规格、单位、结存数量、结存金额、状态），低于下限的标“缺货预警”，高于上限的标“积压”；点一行打开那种存货。也能像目录一样连续阅读整本账。

### 27.5 记账和账页

**记一行**（每张单据的每一行，写进那种存货最后一页账页）：

| 栏 | 入库 | 出库 | 盘盈 / 盘亏 |
|---|---|---|---|
| 日期、凭证号、摘要 | 单据的 | 单据的 | 盘点表的，摘要“盘盈”“盘亏” |
| 收入：数量、单价、金额 | 单据的 | — | 盘盈数、最近单价 |
| 发出：数量、单价、金额 | — | 按计价方法算 | 盘亏数、按计价方法算 |
| 结存：数量、单价、金额 | 上一行结存 + 收入 | 上一行结存 − 发出 | 同左 |

**计价方法**（启用表里选，启用后不能改）：
- **移动加权平均**：每次收入后，结存单价 = 结存金额 ÷ 结存数量；发出单价 = 当时的结存单价。
- **先进先出**：发出时从最早的批次扣，可能跨几批，发出金额是各批之和（一行里写合计，批次明细存在这一行里）。

**账页**：
- 一页最多 100 行；满了另起一页，第一行“承前页”，上一页最后一行“过次页”（实体账的做法，也让每个资源不会无限大）；
- 账页只由记账写，人不能改（页面只读）；每一行记下来自哪张单据（点了打开单据）；
- 冲销的红字行显示为红色（负数）。

**一致**：记账是一次运行（单据上的“记账”动作），一张单据的全部行要么全写进去，要么都不写（写之前先检查，写到一半失败就把这次写的行撤掉，单据不盖章）。

### 27.6 内核：K15 表格字段

单据的明细行是一张可以填的表，内核和外壳现在没有：

| 能力 | 说明 |
|---|---|
| 字段种类 `rows` | 表单字段的一种：值是一个数组，每行是一个对象；字段带 `columns: [{ name, label, kind, options?, readOnly?, width? }]`（列的种类和普通字段一样：文字、数字、日期、下拉、引用……） |
| 外壳 | 画成一张可以编辑的表：加一行、删一行、上下移动、键盘在格子间移动；未保存标记、⌘S 和普通字段一样 |
| 内核检查 | 行数最多 1000，列最多 20，值的种类按列 |
| 计算列 | 不由内核算：页面重画时插件算好（页面 `recompute`），比如金额 = 数量 × 单价 |

- 不认识“单据”，以后任何“带明细的表单”都能用（报销单、订单、配料表）。
- 这是这一步唯一的内核改动；账页、余额、计价都在插件里（内核保持小，`direction.md` §7）。

### 27.7 收发存汇总表 `summary` 和结账

- 一个月一张（新建时选月份）；列出每种存货：期初数量和金额、本月收入、本月发出、期末数量和金额；底下合计。
- 数据从账页算（本月的行）；导出 CSV。
- **结账**（操作栏）：
  1. 检查：这个月所有单据都已记账（有没记账的列出来，不能结）；
  2. 每种存货的账页上写一行“本月合计”（和“本年累计”，12 月时）；
  3. 给这个月的单据和账页盖“已结账”章（K6），之后不能再记这个月；
  4. 汇总表本身也盖章，变成这个月的定稿报表。
- **反结账**：撤下最后一个月的结账（写理由），只能从最近一个月往回撤。

### 27.8 外壳

- `rows` 字段的可编辑表格（设计系统的组件，复用现有的数据表格样式）。
- 新的错误原因按 code 配三种语言的文字（ja-JP 语言包升版本）。

## 28. 第⑨步的实际做法（和 §27 不同或补充的地方）

| 项 | 实际做法 | 为什么 |
|---|---|---|
| 单据里算出来的栏 | 明细表（`rows` 字段）只放人填的栏：入库单“存货、数量、单价、金额”，出库单“存货、数量”，盘点表“存货、实存数”；算出来的金额、结存、账面数、差额，记账后的发出单价和金额，都列在明细表下面一张只读的小表里 | 绑定字段的值来自资源本身，插件不能往里塞算出来的值；分开显示也更清楚哪些是填的、哪些是算的 |
| 账页满了 | 第 100 行写“过次页”，下一页第一行“承前页”；一页上的记账行最多 98 行（加上第一行和过次页） | 照实体账：过次页也占一行 |
| 结账后的账页 | 结账时在每种存货最后一页写“本月合计”（12 月再写“本年累计”），这一页盖“已结账”章；下个月的记账另起一页（承前页） | 盖了章的页不能再写（K6） |
| 结账记在哪里 | 启用表的 `closed`（已结账的月份）；审核、记账都查它 | 一个地方说了算 |
| 反结账 | 只能撤最后结账的月份，而且后面的月份还没记账；撤下那个月账页上的章和合计行，撤下汇总表的章，结账后另起的只有“承前页”的空页删掉 | 不打乱账页的时间顺序 |
| 冲销 | 出库单按原来的发出金额冲回；入库单按原来的数量和金额冲回（先进先出时从最新的批次扣）；盘点表把“实存”和“账面”对调再记 | 抵消要分毫不差 |
| 盘点冲销的价格 | 盘盈冲回时按当时的计价方法出账，不一定等于原来的入账金额 | 第一版的近似；以后需要时再按原行冲 |
| 签名人 | 页面参数“签名人”，默认取环境里的 `{{签名人}}`/`{{Signer}}` | 和文书一样；第一版没有用户身份 |
| 单号 | 新单据保存后由插件编：`RK-年月-序号`（出库 `CK`、盘点 `PD`），同一本账、同一个月里连续 | 照 §27.3 |
| 存货页面 | 档案字段分两行（档案、库存），下面是明细账；先进先出时列出结存批次 | 页面不太长 |
| 汇总表导出 | 导出 CSV 到授权文件夹（插件要 `requires.files`） | 照 §27.7 |
| 账簿插件不依赖别的业务插件 | 只用书的接口找到书、借书插件的 `entries` 连续阅读 | §0.5 |
| K15 的外壳 | 设计系统新增 `RowsEditor`（加一行、删一行、上下移动、最后一格回车加一行），每格用对应种类的控件；数字栏保存成数字 | 规则 3：样式只在 `src/design` |
| 共用的视图检查 | `plugins/_testing/view-check.ts` 认识 `rows` 字段和它的列 | 插件测试和内核一样严格 |

**测试**：内核 `crates/kernel/tests/rows.rs`（列的检查、引用列的选项、保存、最多 1000 行）；设计系统 `rows-editor.test.tsx`；账簿插件 `plugins-external/org.onedesk.ledger/main.test.ts`（移动加权平均、先进先出、入库、出库、冲销、盘点、审核的检查、记账要么全写要么都不写、过次页承前页、汇总表、结账、编号）；界面 `e2e/ledger.spec.ts`（在明细表里填入库单、审核、记账；出库、冲销、盘点；存货的明细账；存货目录的预警；结账后这个月的单据被拒绝）。

## 29. 第⑩步详细设计：修订提案、差异、AI 读书的工具（用户 2026-11-26 确认：都按设计稿；实际做法见 §30）

> 方向见 `direction.md` §13、§15、§16：AI 像 Claude Code 对待代码仓库那样读、改、维护书；**AI 只提修改，不直接改**，作者确认后才生效。修订提案也是以后收件箱、程序书合并的基础。
>
> 做完后能用（一个工作区 + 一个 AI 客户端，如 Claude Code 通过 MCP，或 OneDesk 里的 AI 对话）：
> 1. AI 读一本书：目录和编号、每页担当的角色、每页的内容、引用和大纲，在书里搜索；
> 2. AI 提出一份修订提案：改几页、加几页、删几页，附说明；
> 3. 作者在“待审的修改”里看到它，逐项看**前后对照**，接受、拒绝，或改了再接受；接受后写进书，修订历史里记着“谁提的、谁同意的”；
> 4. 原文在提案之后又被改过的，标出来，按现在的原文重新对照，不会悄悄覆盖。
>
> 不在这一步：凡例（下一步，一个新角色）、收件箱和寄出回件、身份签名、书的分支。

### 29.1 先问现实怎么做

| 现实 | 这里 |
|---|---|
| **校样**：编辑和校对在校样上用校对符号标出修改，附审稿意见 | **修订提案**：一组对若干页的修改，附说明 |
| 作者逐条看：同意的照改，不同意的划掉，有的改了措辞再采纳 | 逐项**接受、拒绝、改了再接受** |
| 改完的校样留档：谁提的、谁定的 | 修订历史里记提出者和同意者，审计 |
| 两个版本**对照**：左边原文，右边改后 | **前后对照**（差异） |
| 已经付印的、已经签字的文件，改不了 | 签章的、只读副本里的资源不能作为修改目标 |
| 编辑看稿先看**目录和体例**，再看各章 | AI 先读目录（编号、角色），再按需读页 |

### 29.2 修订提案（内核 K16，通用，不认识书）

**是什么**：一个资源，内核自己的类型 `core:proposal`，放在内核的树“待审的修改”（`proposals`）里。一切都是资源（产品要求 1），所以它也有名字、说明、信息面板。

**内容**：

| 字段 | 说明 |
|---|---|
| 标题、说明 | 提出者写：改什么、为什么 |
| 提出者 | 操作者：`ai:<客户端>`（AI）、`user`、`plugin:<编号>` |
| 修改项（最多 50 项，共不超过 1 MB） | 每项是下面三种之一 |
| 状态 | 待审、部分接受、全部接受、已拒绝、已撤回 |

| 修改项 | 内容 |
|---|---|
| **改** | 资源编号、提出时的版本号（`rev`）、要改的字段（`name`、`description`、`tags`、`body.<键>` → 新值） |
| **新建** | 类型、放在哪里（父资源、在谁之前）、名字、字段值 |
| **删除** | 资源编号、提出时的版本号（删除进回收站，和用户删除一样） |

**提出时检查**（不合格的整份拒绝，说明哪一项为什么）：
- 目标存在、提出者看得到（AI 只能针对 AI 可见的资源；新建的父资源也要 AI 可见）；
- 目标不是签章的（K6）、不是只读副本（K9）；
- 只能改**页面上可编辑的字段**（和 D479 的“应用”同一个规矩：页面绑定的、不是只读的、不是受保护的、不是密钥、不是保留字段）；新建只能用已安装的类型，删除的不能是书的根、分组的根以外的东西也照常（和用户删除同样的规则）；
- 同一份提案里不能对同一个资源既改又删。

**审阅**（用户的操作，外壳的“待审的修改”页面）：
- 每一项一块：资源的名字和位置（书里的编号，有的话）、提出时的版本、现在的版本；
- 每个改的字段一个**前后对照**（§29.3）；新建的显示将要建的内容；删除的显示将要删的内容；
- 每一项：**接受**、**拒绝**、**改了再接受**（在对照的右边直接改，再接受）；
- 整份：**全部接受**、**全部拒绝**；接受时可以写一句话（同意的意见）。

**原文变了**：
- 一项提出后，目标又被改过（版本号变了）：
  - 提案改的字段和后来改的字段**不重叠**：照常接受（只写提案改的字段）；
  - **重叠**：标“原文已变”，对照改成“现在的原文 ↔ 提案”，要用户再看一次才能接受（不会悄悄覆盖别人后来的修改）；
- 目标被删了：这一项作废。

**接受时**：
- 每一项写入走写入管线，操作者是**用户**（接受的人），修订历史里这一次标“接受提案 <标题>（提出者 <提出者>）”，审计记提案编号；
- 一份提案里接受的各项在**一个事务**里写（要么都写，要么都不写）；
- 写完后提案记下每项的结果，状态变成部分接受或全部接受；提案本身不能再改（签章 K6）。

**谁能提**：
- **AI**：通过 MCP 工具和 AI 对话的工具 `propose`（§29.4）；AI 仍然不能直接写任何资源（D448 不变），只能写提案；
- **用户**：任何资源的“提出修改”（以后收件箱里别人发来的修改，也是这种提案）；
- **插件**：`host.proposals.create(...)`（只在运行里；比如 AI 工作台把一次回答里的多页修改变成一份提案）。

**开关**：工作区配置 `mcp.policy` 多一项“允许 AI 提出修改”（默认关，和其他 AI 开关一样由用户打开）；关着时 `propose` 被拒绝。

### 29.3 差异（K17）

- **内核**：`resource.at({ id, rev })` → 那个版本时的资源（名字、说明、标签、正文），用修订历史里的快照（已经有）。不在内核里算差异（内核保持小）。
- **外壳**：设计系统新增 `DiffView`：
  - 文字（`text`、`longtext`、`code`、Markdown）：按行对照，增加的行、删去的行、改了的行（行内标出改动的字）；可以切换“并排”和“上下”；
  - 其他字段：前值 → 后值；
  - 表格字段（K15）：按行对照。
- **用在**：修订提案的审阅；资源历史里“和现在比较”“两个版本比较”（信息面板的修订历史多一个“对照”）。以后书的版次对比、勘误表也用它。

### 29.4 AI 读书的工具

**原则**：AI 只读得到用户允许 AI 看的资源（`aiVisible`，D448）；工具和规则对 MCP 客户端和 OneDesk 里的 AI 对话完全一样（D480）。

**内核的通用工具**（不认识书，新增三个）：

| 工具 | 作用 |
|---|---|
| `tree` | 一个资源下面的子树（名字、类型、编号、深度、版本号），分页；看结构用 |
| `read` | 一个资源的内容：名字、说明、标签、**页面上显示的各字段**（按字段名和中文名，文字字段原样），它的引用（`[[…]]` 指向谁）；保留字段、密钥字段不给 |
| `propose` | 提出一份修订提案（§29.2）；返回提案编号；不写任何资源 |

已有的 `search` 加一个参数 `within`：只在某个资源的子树里找。

**书插件的 AI 工具**（`aiTools`，书的逻辑在书插件里，§0.5）：

| 工具 | 作用 |
|---|---|
| `book_contents` | 一本书的目录：每项的编号、标题、**角色**、部分、资源编号、层级（借目录的 `entries`）；附上各角色是什么意思（一句话），让 AI 知道哪些页能改、哪些是账页、签过名的文书等 |
| `book_page` | 一页在书里的样子：编号、角色、大纲（小标题、图表题注、索引词、引注）和内容（被嵌入时的样子） |
| `book_refs` | 一本书里所有的交叉引用、引注、索引词，哪些断了 |

其他担当角色的插件（练习、文书、账簿……）可以照样提供自己的 AI 工具（如账簿的“对账”，只读）。

**AI 读书的顺序**（写在工具说明里，AI 照着做）：先 `book_contents` 看结构 → 按需 `book_page` / `read` → 要改就 `propose`，一份提案说清楚改了什么、为什么。

### 29.5 外壳

- **“待审的修改”**：活动栏一项（有待审的时候显示数字）；树里按时间列出提案（标题、提出者、项数、状态）。
- **提案页面**（内核的页面，外壳画）：§29.2 的审阅界面，用 `DiffView`。
- **资源的信息面板**：这个资源有待审的提案时，显示“有 N 份待审的修改”，点了打开。
- **修订历史**：每条可以“和现在对照”，接受提案的那条显示提出者。
- 新的错误原因和文字（三种语言，ja-JP 语言包升版本）。

### 29.6 协议和内核

| 项 | 说明 |
|---|---|
| 内核类型 `core:proposal`，树 `proposals` | 提案的内容存在资源正文里（修改项数组）；接受、拒绝后盖签章（K6），之后只读 |
| RPC `proposal.create` / `proposal.review`（`{ id, items: [{ index, decision: "accept" \| "reject", values? }], note? }`）/ `proposal.withdraw` | `create` 给用户和插件；`review` 只给用户 |
| RPC `resource.at` | §29.3 |
| 宿主接口 `host.proposals.create` | 只在运行里 |
| MCP / AI 对话工具 `tree`、`read`、`propose`；`search.within` | §29.4 |
| 写入管线 | 接受提案的各项在一个事务里；修订记录多一个“来自提案”的标记 |
| 迁移 | 不需要新表（提案是资源；修订记录的标记放在已有的摘要里）——如果实现时发现需要索引，再加迁移并写升级测试（规则 6） |

### 29.7 测试（全部通过后才提交）

**内核**：
- 提出：各种不合格（看不到、签章的、只读副本、不可编辑的字段、保留字段、密钥、太多项）都拒绝；AI 只能提、不能直接写；开关关着时拒绝；
- 审阅：逐项接受、拒绝、改了再接受；一个事务；修订历史和审计里有提出者和同意者；
- 原文变了：不重叠照常、重叠要重看、目标删了作废；
- `resource.at`；`tree`、`read`、`search.within` 只给 AI 可见的。

**书插件**：`book_contents`、`book_page`、`book_refs` 的内容（编号、角色、大纲、断了的引用）。

**外壳**：`DiffView`（按行、行内、并排和上下、表格）；提案页面的接受、拒绝、改了再接受。

**界面**（真内核 + 测试用的 AI 客户端）：
1. 建一本书（几页正文、一页附录），允许 AI 看；
2. AI 读 `book_contents`、`book_page`，提出一份提案：改第一章的两处、新建一页“小结”、删一页草稿；
3. 用户在“待审的修改”里看到，逐项看对照：接受第一项、拒绝删除、把新建的“小结”改一句再接受；
4. 书里的内容变了；修订历史里写着“接受提案 …（提出者 测试 AI）”；
5. 再提一份改第二章的提案，提出后用户自己先改了同一段：提案标“原文已变”，重看后接受；
6. 签了名的文书、只读副本里的页，AI 提的修改被拒绝。

### 29.8 对照 §0 自查

| 原则 | 这一步怎么做到 |
|---|---|
| 1 书只负责装订 | 书不改；提案是通用的“对资源的一组修改” |
| 2 逻辑在角色里 | 书的结构和角色的意思由书插件的 AI 工具给出；各角色插件给自己的 AI 工具 |
| 4 先问现实 | 校样、审稿意见、作者采纳、两本对照 |
| 5 内核不认识书 | 提案、差异的取数、`tree`/`read` 都不认识书 |
| 内核要小 | 差异在外壳里算；提案是资源，不加表 |
| 产品要求 | 提案是资源、有信息面板；审阅只在提案页面一个入口；AI 只读得到允许的资源，只提不改；签过的、副本、密钥、保留字段都碰不到 |

### 29.9 需要你定的

1. **AI 只提修改、不直接改**，作者逐项接受或拒绝后才写进书。可以吗？
2. **修订提案是一种资源**（内核的类型，放在“待审的修改”里），以后收件箱里别人发来的修改也用它。可以吗？
3. **原文后来又被改过**：改的地方不重叠就照常接受，重叠就要重看。可以吗？
4. **差异在外壳里算**（内核只给出某个版本的内容），内核保持小。可以吗？
5. **AI 读书的工具**：内核给通用的 `tree`、`read`、`propose`，书插件给 `book_contents`、`book_page`、`book_refs`。可以吗？
6. **“允许 AI 提出修改”默认关**，由用户在 AI 设置里打开。可以吗？

## 30. 第⑩步的实际做法（和 §29 不同或补充的地方）

| 项 | 实际做法 | 为什么 |
|---|---|---|
| 提案存在哪里 | 内核类型 `core:proposal`，内核的树“待审的修改”（`proposals`，只有一层，不能建分组）；名字是标题，说明是提出者写的话，正文是 `proposer`、`status`、`items`（每项照 `ProposalChange` 存，加上提出时的版本 `rev`、提出时的原值 `was`、结果 `result`、新建出来的资源 `created`）、`reviewedBy`、`reviewComment` | 一切都是资源；不加表（规则 6 不需要新迁移） |
| 提案不能被别的路径改 | 内核的检查：只能用“提出”这一条命令建提案（`resource.create`、`page.save new:core:proposal`、插件的 `create` 都拒绝），提案的正文只能由审阅改（`denied/proposalFixed`）；审完（全部定了）或撤回后不能再审（`invalid/proposalClosed`） | §29.6 说“盖签章”，但签章的名称是界面文字，内核不含文字；内核直接挡住修改，效果一样 |
| 能改哪些字段 | 名字、说明、标签，加上页面上可编辑的文字字段（`text`、`longtext`、`code`，和 D479 的“应用”同一个函数 `editable_fields`），去掉密钥字段和保留字段（`withheld`）；值必须是文字（标签是文字的列表，名字不能空） | 和 AI 写作助手的“应用”一个规矩；数字、表格等以后需要时再放开 |
| 提出时的检查 | 目标在资源树里、提出者看得到（AI 只能针对 AI 可见的）、没签章、不在只读副本里；给了 `rev` 就必须是现在的版本（`invalid/proposalChanged`，让 AI 重读）；同一个资源只能出现一次（`proposalSameTarget`）；AI 新建必须给父资源（`proposalTarget`）；只能新建已安装的类型或分组（`proposalKind`）；最多 50 项、共 1 MB、标题 200 字、说明 4000 字 | §29.2；错误的 `item` 是第几项（从 1 数） |
| 原文变了 | 比较的是提出时记下的原值 `was` 和现在的值：提案改的字段没被别人动过就照常接受（只写这些字段）；动过就标“原文已变”，接受时必须带上现在的版本号（`basis`），否则 `conflict/proposalStale`（页面上点“接受”时带的就是页面显示时的版本，所以“看过再接受”就是重看）；目标删了，这一项“作废” | 比版本号更准：版本号变了不一定是改了同一个字段 |
| 接受时写入 | 新命令 `Review`：接受的各项（新建、修改、删除）和提案自己的新状态在**一个事务**里；操作者是用户；修订记录的 `commit_ref` 写 `proposal:<编号>`（第一版就有、一直空着的列），`resource.history` 的每一条带上 `proposal: { id, title, proposer }` 和版本号 `rev`；审计 `proposal.review` 记提出者和接受、拒绝、作废的数目 | 不需要新迁移；“谁提的、谁同意的”都在 |
| 新建的位置和可见 | 接受新建的一项时，放在 `before` 指的那一页前面（那一页还在同一个父资源下时）；父资源 AI 可见，新的这页也 AI 可见 | AI 提出的页面，接受后 AI 还能接着读 |
| 改了再接受 | 页面上每项的“改一改”打开每个字段的编辑框（名字、正文……），对照跟着变；接受时把改过的值一起交给 `proposal.review`（`values`，只能是这一项原有的字段） | §29.2 |
| 谁能提 | AI：工具 `propose`（MCP 和 AI 对话同一套工具，D480），受工作区配置 `mcp.allow_proposals`（默认关，`denied/aiProposeOff`）；用户：`proposal.create`（外壳以后的“提出修改”、收件箱都用它）；插件：`host.proposals.create(params)`，要 `requires.resources`，只在用户的操作里（页面事件、命令、运行），不能在事件处理函数、纯计算、AI 的运行里 | §29.2；和签章的规矩一样 |
| 撤回 | `proposal.withdraw`：一项都还没定的提案才能撤回 | 定了一部分的就是审阅的事了 |
| `resource.at` | 从修订记录的快照取那个版本的名字、说明、标签、正文 | §29.3 |
| AI 的 `tree` | 一个资源下面 AI 可见的子树，按树的顺序，`depth` 从 1，每页最多 500 个，`next` 接着读 | §29.4 |
| AI 的 `read` | 名字、说明、标签、版本号、位置、页面上显示的各字段（按页面的绑定，文字原样，最多 64 KB）、哪些字段能提修改（`changeable`）、引用（指向 AI 看不到的资源时只给写下的字）、是否签章、是否只读副本 | §29.4 |
| `search.within` | 只在一个资源（AI 可见）下面找 | §29.4 |
| AI 运行里的子树、嵌入、引用 | 内核原来在 AI 的运行里把 `resources.tree`、`embed`、`refs` 也交给了普通的读写分支（找不到这几个操作）；改成走各自的函数，它们本来就只给 AI 可见的 | 书插件的 AI 工具要用 |
| 书插件的 AI 工具 | `book_contents`（`{ book }`：书里任何一个资源都行，往上找到书）、`book_page`（`{ id, book? }`：别的插件的页或分组书插件读不到父资源，给 `book` 就从书里找）、`book_refs`（`{ book }`）；结果是一段 JSON 文字；每个角色一句话的意思和“先看目录、再读页、要改就提案”的说明在三种语言的语言文件里 | 书的逻辑在书插件里（§0.5） |
| 外壳 | 活动栏多一项“待审的修改”（有待审的时候显示数字）；提案页面（`PageKind::Proposal`，`proposal.get` 取数据）：提出者、说明、状态，每项的对照（修改：现在 ↔ 提案；新建：空 ↔ 提案；删除：现在 ↔ 空）、原文已变的提示、打开目标、接受、拒绝、改一改、全部接受、全部拒绝、审阅意见；资源的信息面板：“有 N 份待审的修改”，修订历史每条“和现在对照”（对话框里的 `DiffView`），接受提案写的那条标“来自提案……（提出者）”；AI 设置多一个开关 | §29.5 |
| `DiffView` | 设计系统：按行对照（最长公共子序列，前后相同的部分先去掉；连在一起的删去行和增加行一对一算“改了的行”，行内按字标出），并排和上下切换；一个值是“前 → 后”；表格按行（每行写成“列: 值 · 列: 值”再按行对照） | 差异在外壳里算，内核保持小 |
| 字段名 `comment` | 协议里提案的说明叫 `comment`（不叫 `note`） | `note` 是一个插件的名字，内核里不能出现（规则 1，`pnpm lint`） |

**测试**：内核 `crates/kernel/tests/proposals.rs`（AI 读结构和页面、`search.within`、提出、什么都没写、逐项接受拒绝和改了再接受、新建的位置和可见、修订历史和审计里的提出者和同意者；不能碰的字段、看不到的、签章的、读过后又变的、同一资源两次、太多项；开关、用户提出和撤回、插件提出、AI 不能审阅；原文变了：不重叠照常、重叠要重看、一个事务、目标删了作废；`resource.at`）；`round19.rs` 工具列表多三个；书插件 `main.test.ts`（目录的编号和角色、一页的大纲和原文、断了的引用和引注、三个工具的声明和三种语言）；设计系统 `diff-view.test.tsx`；外壳 `proposal-page.test.tsx`；界面 `e2e/proposals.spec.ts`（真内核 + 真 MCP 客户端：AI 读目录和页、提出修改；用户在“待审的修改”里接受、拒绝、改了再接受；修订历史写着提案和提出者；第二份提案提出后用户先改了同一段，标“原文已变”，重看后接受）。签了名的、只读副本里的页被拒绝，在内核测试里。


## 31. 第⑪步详细设计：凡例（用户 2026-11-26 确认：都按设计稿；实际做法见 §32）

> 方向见 `direction.md` §13.2：凡例就是书的 `CLAUDE.md`——说明本书的体例、约定、写法，人读，AI 也读。§29 已经让 AI 能读书、提修改；有了凡例，AI 改出来的东西才合这本书的规矩。
>
> 做完后能用：
> 1. 在书里新建一页“凡例”，写本书的体例（一条一条）；填“用字”表（不用 → 用）和“符号”表；
> 2. 凡例页下面自动列出本书的编排：怎么编号、引注用哪种著录、哪些部分（由目录、参考文献等角色说出来，不用手抄，不会和书对不上）；
> 3. 在凡例页上“按凡例检查”：列出全书不合用字表的地方（哪一页、哪一行），可以一键“提出修改”，变成一份修订提案，在“待审的修改”里逐项看、接受；
> 4. AI 读书时先拿到凡例（`book_contents` 里带着），也可以用 `book_check` 查不合凡例的地方，再提修改。
>
> 不在这一步：拼写和语法检查、按正则或语义的规则、多语种的用字表、凡例的版本对比（用修订历史就行）。

### 31.1 先问实体书怎么做

| 实体书 | 这里 |
|---|---|
| 凡例放在**正文前面**：序、前言之后，目录之前（辞书、古籍整理、教材、年鉴、法规汇编都有） | 角色 `conventions`，部分 `front`，一本书最多一页，不编号 |
| 一条一条写：“一、本书收词……二、本书按……排列……三、符号说明……” | 正文是 Markdown，习惯写成编号的条；不规定条目 |
| “符号说明”“略语表”：〔〕表示补字，* 表示…… | **符号表**：符号、意思 |
| 编辑部的**用字规范**、统一用词表（“统一用‘数据库’，不用‘资料库’”），排版前统一过一遍 | **用字表**：不用、用、说明；“按凡例检查”就是编辑统稿 |
| 凡例里说明编号方法、引文格式、外文译名的处理 | 能由书自己说出来的（编号、著录方法、部分）**自动列出**，不用手写；书改了它跟着变 |
| 统稿时编辑在校样上改，作者确认 | 检查出来的地方变成一份**修订提案**（§29），作者确认才改 |

### 31.2 角色：凡例（书插件的新类型，逻辑都在它自己的文件里）

| 项 | 内容 |
|---|---|
| 类型 | `org.onedesk.book:conventions`，名称“凡例”（英文 Conventions，日文 凡例），图标 `list-checks` |
| 角色 | `{ role: "conventions", part: "front", single: true, container: false, numbering: "none" }`；学生版和教师版都有 |
| 字段 | `text`（longtext，Markdown，可以引用和嵌入，和前言一样）；`terms`（表格字段 K15：`avoid` 不用、`use` 用、`note` 说明，最多 200 行）；`symbols`（表格字段：`symbol` 符号、`meaning` 意思，最多 100 行） |
| 新建时 | 正文给一个骨架（三条：“一、本书的编排……二、用字……三、符号……”，用户改），两张表空着 |
| 代码 | 新文件 `plugins/org.onedesk.book/conventions.js`：页面、嵌入、自动编排说明、检查、AI 工具；书、目录等别的文件不改（只在 `roles.js` 的角色表加一行、`main.js` 登记） |

### 31.3 页面

从上到下：
1. **正文**：和前言一样的阅读和编辑两种样子（借文字页的写法：`readable`、脚注、引用照常）；
2. **用字**：表格（不用、用、说明）；
3. **符号**：表格（符号、意思）；
4. **本书的编排**（只读，自动）：
   - 编号：由本书的**目录**说（“正文按‘第一章、第一节’编号，更深的用 1.1.1；附录编 A、B、C；图表按章编号：图 2-1”）——借目录的设置，经接口；
   - 引注：由本书的**参考文献**说（“引文按顺序编码制著录（GB/T 7714）”或“著者-出版年制”）；
   - 部分：前面的部分有哪些、正文有几章、后面的部分有哪些（借 `entries`）；
   - 其他角色：凡是实现 `onedesk.book/1` 的插件，可以对本书里自己担当的角色说一两句（新的接口动作 `conventions`，§31.6），比如账簿说“计价方法：移动加权平均；金额保留两位小数”，练习说“答案只在教师版”。
   - 没有目录、没有参考文献的，不列那一条。
5. **按凡例检查**（操作栏的按钮，§31.4）。

嵌入（书连续阅读、导出、打印时）：正文 + 两张表（空表不显示）+ 本书的编排。

### 31.4 按凡例检查

- **查什么**：本书里每一页正文（书插件的文字页：正文页、前言、后记；别的插件的页，如果它在接口里给出 `outline` 以外的“正文文字”——第一版不查，只查书插件自己的文字页）里，用字表“不用”一栏出现的地方。
- **怎么算出现**：
  - 中文：原样包含；
  - 英文等有空格的文字：整词，不分大小写（`database` 不算在 `databases` 里出现，除非“不用”写的就是 `databases`）；
  - 不查：代码块和行内代码、`[[引用]]` 和 `![[嵌入]]` 的写法、`{{填写项}}`、引注 `[@…]` 里的键；凡例页本身不查（它要写“不用 X”）。
- **结果**：一张表：页（编号和名字）、第几行、那一段（前后各 20 字，出现处标出来）、不用、应改为；可以点一行打开那一页。
- **提出修改**：按钮“提出修改”把全部结果变成**一份修订提案**（§29，`host.proposals.create`）：每一页一项，改的是这一页的正文（把那些地方换成“用”一栏的字），标题“按凡例统一用字”，说明列出用到的几条；提出者是书插件（用户自己点的）。在“待审的修改”里逐项看对照、接受或拒绝，和 AI 提的完全一样。
- **限度**：一次最多查 2000 页，每页最多报 100 处，提案最多 50 项（多的下次再查再提）；用字表最多 200 条。

### 31.5 AI

- `book_contents` 的结果多一项 `conventions`：凡例页的编号、正文（原样）、用字表、符号表、本书的编排（文字）；书里没有凡例就是 `null`。`how` 改成：“先读凡例和目录，再按需读页；写的和改的都要合凡例；要改就提案”。
- 新的 AI 工具 `book_check`（`{ book }`，只读）：和“按凡例检查”同一个函数，返回不合用字表的地方（页、行、片段、不用、应改为）。AI 可以据此提修改（它的提案还是走 `propose`，用户确认）。
- 凡例本身 AI 也能提修改（它是普通的文字和表格字段；表格字段不在可提修改的范围（§30），第一版 AI 只能提凡例正文的修改）。

### 31.6 接口 `onedesk.book/1` 加一个可选动作

| 动作 | 调用 | 返回 |
|---|---|---|
| `conventions` | 按资源调用（书里担当某个角色的一页），输入 `{}` | `{ "lines": ["计价方法：移动加权平均。", …] }`，最多 10 条，每条最多 200 字；没有要说的返回空 |

- 凡例页对书里每个“声明了角色、且实现了这个动作”的插件，每种角色只问一页（第一页）；纯计算，5 秒内答；不答、出错的跳过。
- 书插件自己的目录、参考文献也通过同一个函数说（不走接口，直接调自己的代码），保证一个规矩。
- 这一步给账簿（计价方法、金额和数量的小数位、单号的写法）、练习（答案和讲解只在教师版、判法）、文书（签名后不能改，修订要写理由）各写几句；别的插件以后照样加。
- 不兼容吗？不：可选动作，没实现的就不问（规范 §5.1 第 3 条）。

## 33. 第⑫步详细设计：身份和签名（用户 2026-11-26 确认：都按设计稿；实际做法见 §34）

> 方向见 `direction.md` §14.4、§15、§16：收件箱、书的服务器、插件市场都要知道“是谁发的、是谁签的”，而且不能伪造。现在签章的签名人只是一个名字（第⑦步），资源包的出版者只是工作区编号（第⑥步）。这一步给每个工作区一个**身份**（一对密钥），让签章和资源包带上**数字签名**，别人能验证。
>
> 这是内核的通用能力（K18），不认识书；放在这里是因为它是书的开发顺序里的一步。
>
> 做完后能用：
> 1. 在设置里建“我的身份”：名字、一对密钥（私钥只在钥匙串），看到自己的**指纹**；导出**身份卡**（一个小文件）给别人；
> 2. 别人的身份卡导入到**通讯录**；当面或电话里核对指纹后标“已核对”；
> 3. 签章自动带签名：文书签名、单据审核、版权页的印章……信息面板显示“签名有效：张三（已核对）”，内容被动过就显示“签名无效”；
> 4. 发布的资源包带出版者的签名：导入时看到“出版者 张三，签名有效，已核对 / 第一次见到”；只读副本以后只接受同一个身份发布的更新。
>
> 不在这一步：收件箱和回件（下一步）、密钥丢失后的找回和多设备同步（`direction.md` §8，先讨论）、撤销和更换密钥、书的服务器上的账号、组织的公章（多人共用一个身份）。

### 33.1 先问现实怎么做

| 现实 | 这里 |
|---|---|
| **签名、印章**：每个人的笔迹、每个单位的印章，别人照着认 | **身份**：一对密钥，私钥签、公钥验；签名不能照着仿 |
| **印鉴卡**：在银行、单位预留签名和印章的样子，以后照着核对 | **身份卡**：名字和公钥；**通讯录**里存别人的身份卡 |
| 第一次见面**核对身份证**，以后认得 | 核对**指纹**（公钥的摘要，16 组 4 位）后标“已核对”；没核对的显示“未核对” |
| 签字后改动合同，签字就不作数 | 签名对的是签章时的内容；内容变了（不可能，签章后只读；除非数据库被人改）就“签名无效” |
| 出版社在版权页上署名，盗版书冒用不了真正的出版社 | 资源包带出版者签名；只读副本只接受同一出版者的更新 |
| 公证、第三方认证 | 以后书的服务器给身份做担保（不在这一步） |

### 33.2 身份（内核 K18）

| 项 | 内容 |
|---|---|
| 密钥 | Ed25519（签名小、快、各平台都有）；私钥存钥匙串（规则 7），名字 `identity:<工作区编号>`；数据库、导出文件、资源包里**只有公钥** |
| 我的身份 | 一个工作区最多一个身份；字段：名字（必填，签名时显示）、单位（可选）、公钥、指纹、建立时间；存在工作区配置里（`identity.*`，不是资源：它属于工作区本身） |
| 建立 | 用户在“设置 → 我的身份”点“建立我的身份”，填名字；内核生成密钥；**不自动建** |
| 指纹 | 公钥 SHA-256 的前 16 字节，写成 8 组 4 位十六进制（如 `3F2A 9C1B …`），核对时念给对方听 |
| 改名字 | 可以；改了以后新签名用新名字，旧签名里记的是当时的名字 |
| 删除 | 可以（要确认，说明“以后签的章、发的书别人就不认得是你了；已经签的仍然能验证”）；删了可以再建一个新的（新的指纹） |
| 身份卡 | `<名字>.odid` 文件：`{ format: 1, name, org, publicKey, fingerprint, createdAt, signature }`——用自己的私钥签了这张卡本身，导入时验证卡没被改过 |

### 33.3 通讯录（内核的树“通讯录”，`contacts`）

- 每张导入的身份卡是一个资源：内核类型 `core:contact`，放在内核的树“通讯录”里；有名字、说明、标签、信息面板（产品要求 1）。
- 字段：名字（卡上的，可以改成自己的叫法）、单位、公钥、指纹、**是否已核对**（用户点“已核对”，要确认“你已经和对方核对过这个指纹”）、从哪里来（导入的卡、某个资源包、某个签章）。
- 同一个指纹只有一张；再导入同一个人的新卡（名字改了）就更新名字，核对状态不变。
- **自动加入**：导入资源包、遇到带签名的签章时，签名者不在通讯录里的，自动加一张“未核对”的卡（来源写明）；用户之后可以核对或删除。
- 自己的身份不在通讯录里（在设置里）。

### 33.4 签章带签名（K6 扩展）

- 盖章时（`host.resources.stamp`，不改插件接口），工作区**有身份**就自动签名；没有身份照旧盖章，只是不带签名（显示“未签名”）。
- **签的是什么**：`onedesk-stamp/1`、资源编号、版本号、内容摘要、章的名称、签名人（插件给的文字）、时间，用换行连起来；**内容摘要** = SHA-256（类型、名字、说明、标签、正文，正文按键排序的 JSON；密钥字段只有它的名字；加上签章时冻结的嵌入结果 K6）。
- 存在 `stamps` 表新加的列里：`identity`（指纹）、`identity_name`（当时的名字）、`content_hash`、`signature`。**迁移 0019**（只加列）和它的升级测试（规则 6）。
- **验证**：读资源（`resource.get` 的 `stamps`）时，每个章给出 `verified`：`valid`（签名对、内容摘要和现在一样）、`invalid`（不对）、`unsigned`（没签名）；`signedBy`：`{ name, fingerprint, known: "self" | "checked" | "unchecked" }`。
- 撤章（修订）时不需要签名；撤章记录照旧。再盖章是新的签名。
- 资源包和只读副本不带签章（K9 规则不变）。

### 33.5 资源包带签名（K9 扩展）

- 发布（版权页的“发布”）时工作区**有身份**就签名：`package.json` 多两项 `publisherKey`（公钥）、`signature`（签 `onedesk-package/1`、根、版次、印次、版本、`package.json` 去掉这两项后的 SHA-256、每个图片的哈希）。**没有身份不能发布**：发布对话框提示先建立身份（一个入口，直接跳到设置）。
- **导入预览**（`package.inspect`）多给：签名是否有效、出版者的名字和指纹、在通讯录里是“已核对 / 未核对 / 第一次见到”。
- **签名无效**的包拒绝导入（`invalid/badSignature`）；**没有签名**的旧包（第⑥步发布的）仍可导入，标“未签名”。
- **更新只读副本**：副本记下出版者的指纹；之后的更新必须是**同一个指纹**签的（否则 `invalid/otherPublisher`，现在按工作区编号判断，改成按指纹，有指纹时以指纹为准）。
- 出版者的身份卡自动加进通讯录（未核对）。

### 33.6 外壳

- **设置 → 我的身份**：没有时一个按钮“建立我的身份”（填名字、单位）；有了显示名字、单位、指纹（分组，可复制）、“导出身份卡”“改名字”“删除身份”。
- **活动栏“通讯录”**：树里列出联系人（名字、已核对的打勾）；联系人页面：名字、单位、指纹（大字分组，便于念）、来源、“已核对”开关（打开时确认）、“导出身份卡”；工具栏“导入身份卡”。
- **签章**（信息面板、文书页上的签名）：每个章旁边一个小标记：✓ 签名有效（已核对的显示名字，未核对的显示“未核对”），✗ 签名无效，— 未签名；点开看指纹。
- **导入资源包对话框**：出版者一行加签名状态和指纹。
- 三种语言的文字（ja-JP 语言包升版本）。

### 33.8 测试（全部通过后才提交）

**内核**：
- 建立、改名、删除身份；私钥只在钥匙串（数据库、导出、资源包里搜不到私钥）；指纹的写法；
- 身份卡导出、导入；被改过的卡拒绝；同一指纹只有一张；核对状态；
- 签章：有身份时签名、`valid`；没有身份 `unsigned`；数据库里改了内容（测试直接改表）→ `invalid`；改了名字后旧签名仍然 `valid` 且显示当时的名字；签名者在通讯录里自动出现；
- 资源包：签名、导入预览的状态、签名被改 → 拒绝；没签名的旧包可导入；更新只接受同一指纹；
- 迁移 0019 的升级测试。

**外壳**：我的身份（建立、指纹、导出）、通讯录页面（核对的确认）、签章的三种标记、导入对话框的签名一行。

**界面**（真内核，两个工作区）：
1. 工作区 A 建立身份“张老师”，导出身份卡；工作区 B 建立身份“李同学”，导入 A 的身份卡，核对指纹后标已核对；
2. A 写一份文书并签名：信息面板显示“签名有效：张老师（自己）”；
3. A 发布一本书；B 导入：预览显示“出版者 张老师，签名有效，已核对”；
4. 第三个工作区 C（另一个身份）用同一本书的根编号伪造一个更新包 → B 导入被拒绝；
5. 把 A 的包里改一个字节 → 导入被拒绝（签名无效）。

## 34. 第⑫步的实际做法（和 §33 不同或补充的地方）

| 项 | 实际做法 | 为什么 |
|---|---|---|
| 身份存在哪里 | 迁移 0019 的 `identity` 表（只有一行：名字、单位、公钥、建立时间），不放在工作区配置的参数里 | 配置的参数在配置页上可以手改；公钥不能被手改 |
| 私钥在钥匙串的哪里 | 账户 `<工作区编号>/#identity`；密钥名字不能含 `#`，所以插件声明什么密钥名字都碰不到它；“密钥”页不列它；删除工作区时随前缀一起删 | 规则 7；插件的 `{{secret:…}}` 只按名字代入 |
| 种子 | 32 字节系统随机数（`getrandom`），存成十六进制 | |
| 签章签什么 | `onedesk-stamp/1`、资源编号、内容摘要、章的名称、签名人、时间；**不含版本号和位置** | 签了章的资源可以移动，移动会改版本号；签名不应该因此失效 |
| 内容摘要 | SHA-256（类型、名字、说明、标签、正文、签章时冻结的嵌入结果）；第二个章用第一个章冻结的结果；写入时再算一次，和签名时不一样就拒绝（`conflict/changedOnDisk`） | 签名和写入之间内容不会悄悄变 |
| 验证 | 每次读资源时重算摘要并验签；`signedBy.known` 多一个 `unknown`（不在通讯录里，比如删掉的旧身份） | §33.4 只列了三种 |
| 签章上的身份 | 签章表记下签名时的公钥和名字；改名以后旧章仍显示当时的名字 | 和纸上的签名一样 |
| 资源包 | `package.json` 多 `publisherKey`、`signature`；签名覆盖 `package.json`（去掉签名）的 SHA-256 和图片编号；发布（新版次、重印）都要身份（`invalid/noIdentity`），出版者名字用身份的名字；`package.inspect` 多给 `signature`、`publisherIdentity`；签名不对 `badSignature`；只读副本记 `publisher_key`，有了以后只认这把钥匙（换钥匙、去掉签名都是 `otherPublisher`） | §33.5 |
| 通讯录 | 内核类型 `core:contact`、树 `contacts`；联系人的正文：公钥、指纹、单位、是否核对、来源（`card`、`package`）、原来的身份卡；建立时内核检查公钥和指纹对得上、同一指纹只有一个；公钥和指纹不能改（`invalid/badContact`；页面本身也是只读的，先被 `denied/readOnlyField` 挡住）；名字、说明、标签可以改 | 一切都是资源 |
| 身份卡 | `.odid`：名字、单位、公钥、指纹、建立时间，自己签名；导入时验证；自己的卡不能导入（`ownCard`）；同一把钥匙的新卡更新名字，核对状态不变；“导出身份卡”导出的是当初导入的那张 | §33.2 |
| 文件对话框 | 桌面版：系统的打开（`.odid`）和存储对话框（Tauri 命令 `pick_identity_card`）；浏览器预览里没有，就弹一个填路径的小框 | 界面测试在浏览器里跑 |
| 外壳 | 设置菜单和命令面板“我的身份”（外壳自己的页面 `shell:identity`：建立、改名字和单位、指纹、导出身份卡、删除身份、导入身份卡）；活动栏“通讯录”；联系人页面（指纹大字、来源、“我已经核对过这个指纹”开关，打开时要确认、导出身份卡）；信息面板的签章下面显示签名有效、无效、未签名和签名者；导入资源包的对话框显示签名者、指纹、未签名；联系人和提案不显示“AI 可见”开关 | §33.6 |
| AI | `read` 的结果多一项 `stamps`（含 `verified`、`signedBy`）；通讯录不在 AI 能看的资源树里 | §33.7 |
| 新依赖 | `ed25519-dalek` 2（BSD-3-Clause）和它带来的 `curve25519-dalek`（BSD-3-Clause）、`curve25519-dalek-derive`、`ed25519`、`signature`、`zeroize`、`fiat-crypto`、`subtle`（BSD-3-Clause）、`cpufeatures`、`rustc_version`；`getrandom` 0.3 已有（MIT/Apache-2.0） | 规则 9，见 decisions.md |

**测试**：内核 `crates/kernel/tests/identity.rs`（建立、私钥只在钥匙串、不在数据库和密钥列表里、改名、删除后钥匙也删、重建是新钥匙；身份卡导出导入、同一把钥匙一个联系人、改过的卡和自己的卡被拒、核对、钥匙不能改；签章：没身份未签名、有身份有效且是自己、移动后仍有效、改名后旧章仍有效且是旧名字、数据库里改了内容就无效、删了身份后旧章有效但“不认识”）、`packages.rs`（签名有效、出版者、改过的包拒绝、导入后出版者进通讯录、别的钥匙签的更新和去掉签名的更新被拒、真出版者的重印被接受且显示已核对、旧的未签名包在没有副本的地方可以导入、没身份不能发布）、`migration_upgrade.rs`（0018 的签章和副本升级后保留、未签名）、`identity.rs` 单元测试（指纹、签名）；外壳 `identity-page.test.tsx`（建立、指纹、导出到路径；核对要确认）；界面 `e2e/identity.spec.ts`（两个工作区：A 在设置里建立身份并导出身份卡；B 导入、核对；A 签文书，信息面板显示签名有效、是自己；A 发布，B 的导入对话框显示“Teacher Zhang 签的（已核对）”和指纹；改了一个字的包被拒绝），`e2e/publish.spec.ts` 发布前先建立身份。


## 35. 第⑬步详细设计：收件箱——收文簿、来件、回件（用户 2026-11-26 确认：都按设计稿）

> 方向见 `direction.md` §14、§16：书可以当收件箱，收到的不是邮件，而是别人发来的、**要你处理**的页面（要签的文书、要做的作业、要审的单据），处理完寄回**回件**。第一版**走文件**（存成文件，用任何方式交给对方：U 盘、聊天工具、邮件附件），先做两个场景：**老师发作业、学生交回**；**上级审签**。
>
> 已经有的：资源包和只读副本（K9）、签章（K6）、身份和签名（K18，上一步）、练习的作答记录、文书的签名、流程的等人确认。
>
> 做完后能用：
> 1. 老师在“发文簿”里写一份**发件**：收件人（从通讯录选）、事由、要做的事（“作答”）、期限，附上课本里的一张测验卷；“寄出”存成一个 `.odletter` 文件，交给学生；
> 2. 学生“收件”：看到是谁寄的（签名有效、已核对）、要做什么、什么时候截止；收下后它在学生的**收文簿**里（只读）；学生在里面做测验；“回件”存成文件交回；
> 3. 老师收下回件：发件上看到“李明 已交（得分 8/10）”，作答记录进了老师的学习记录；
> 4. 科室把一份文书寄给主任“审签”；主任在来件里看文书、签名（带身份签名）、写意见，回件；科室收下后，原文书上显示“王主任 已审签（签名有效）”。
>
> 不在这一步：书的服务器转交和加密（第一版的文件不加密，界面上提醒只交给收件人）、多人依次传阅和会签的顺序、到期提醒和通知、把修订提案寄给别人（以后照这个做）、撤回已经寄出的发件。

### 35.1 先问现实怎么做

| 现实 | 这里 |
|---|---|
| 机关的**收文簿**：来文登记（收到日期、来文单位、文号、事由、份数）、拟办、承办、办结、归档 | **收文簿**角色：一行一件来件，状态“待办 / 已回 / 逾期” |
| **发文簿**：发文登记、发给谁、要求什么时候回复 | **发文簿**角色：一行一份发件，每个收件人回了没有 |
| **公文**：文头写主送、事由、要求（请审签、请阅、请于某日前报送）；落款盖章 | **发件**：收件人、事由、要做的事、期限、附件（书里的页）；寄件人的签名（K18） |
| 收到的文件**原件不改**，在**处理单 / 批办单**上写意见、签字 | 来件里的页是**只读副本**；收件人做的事写在**自己的记录**里（作答记录、审签记录、阅办意见） |
| **回执**、作业本交回、签字的文件退回 | **回件**：只带收件人做的那部分（作答、签名、意见），寄件人签名 |
| 老师批改后**登分**，科室收到审签件**存档** | 寄件人收下回件：由担当那一页的角色处理（练习进学习记录，文书记下“已审签”） |

### 35.2 谁负责什么（按 §0）

| 事 | 归谁 |
|---|---|
| 把一棵子树打成**签了名的包**、写给谁、在对方那里**验证并放到指定的地方**成为只读副本；回件只认真正的收件人、只能回到真正的发件 | **内核**（K19，通用：“寄出和回件”，不认识作业、公文） |
| 收文簿、发文簿、发件、来件这几种页；收件人从通讯录选；状态、期限；“已阅 / 同意 / 不同意 + 意见”这种通用的处理 | **新插件** `org.onedesk.inbox`（收发文） |
| 某一页**能要别人做什么**、收件人做完**交回什么**、寄件人**收到后怎么办** | **担当那一页的角色**（练习、文书、账簿、流程……），通过新接口 `onedesk.letter/1` |

加功能就是加角色：以后哪种页能“寄出去要人处理”，就由它的插件实现这个接口；收发文插件和内核都不用改。

### 35.3 内核：寄出和回件（K19）

**文件**：`.odletter`，和资源包（§9）同一种 zip 格式，`package.json` 的 `variant` 是 `letter`（来件）或 `reply`（回件），多一项 `letter`：

| 键 | 说明 |
|---|---|
| `id` | 这份发件的编号（回件用它找到发件） |
| `subject` | 事由 |
| `note` | 附言 |
| `due` | 期限（日期，可空） |
| `to` | 收件人的指纹列表（空：谁都可以收，如发给全班的作业） |
| `tasks` | 要做的事：`[{ page, task, label }]`——哪一页、做什么（由那一页的角色给的名字，如 `answer`、`sign`、`read`）、怎么说 |
| `inReplyTo` | 回件：回的是哪份发件的 `id` |

- **必须有身份**，整个包按 §9.4 签名（K18）；没有身份不能寄出。
- **宿主接口** `host.letters.write(root, { pages, to, subject, note, due, tasks, inReplyTo?, path })`：把 `root`（发件或来件的资源）和 `pages`（要附上的页，各带它下面的子树）打成包，写到插件被授权的文件夹（和发布一样，`requires.files`）；只在用户的操作里（页面事件、命令、运行）。附上的页在包里成为发件的下级。保留字段（K10）照学生版的规矩不带出去。
- **收件**（用户的，`letter.inspect` / `letter.receive({ path, parent })`）：
  - 验证签名；有 `to` 的，自己的指纹必须在里面（否则 `notForYou`）；
  - 来件：作为**只读副本**放到 `parent` 下面——`parent` 必须是声明了 `letters: true` 的类型（清单里的新字段：这种资源“收信”，如收文簿）；
  - 回件：`inReplyTo` 必须是本工作区寄出过的发件，签名人必须是那份发件的收件人（或发件 `to` 为空）；放到那份发件下面（只读副本）；同一个人再回一次就替换上一次的；
  - 寄件人自动进通讯录（未核对，K18）。
- **记录**：迁移 0020 加表 `letters`（编号、方向 `in`/`out`、对应的资源、对方的指纹和名字、事由、期限、时间、回的哪份）；`host.letters.info(id)` 给插件读一份发件或来件的这些信息和它收到的回件列表（谁、什么时候、签名是否有效）。
- 事件：来件、回件放好后，对 `parent` 那种类型的插件发 `letter.received`（它决定怎么显示、要不要提醒）。

### 35.4 接口 `onedesk.letter/1`（收发文插件定义，各角色实现）

| 动作 | 在哪一边、对哪一页调 | 返回 |
|---|---|---|
| `tasks` | 寄件人：写发件时，对每一页 | `{ tasks: [{ task, label }] }`：这一页能要人做什么（如测验：`answer` 作答；文书：`sign` 审签、`read` 阅） |
| `todo` | 收件人：来件里的一页 | `{ state: "todo" \| "done", summary }`：做了没有（如“已交卷，8/10”“已签”） |
| `reply` | 收件人：回件时，对每一页 | `{ resources: [编号…] }`：要交回的、收件人自己的资源（作答记录、审签记录） |
| `received` | 寄件人：回件放好后，对发件里的每一页（原件） | `{ summary }`：寄件人这边怎么处理了（如“作答已进学习记录”） |

都是纯计算或用户操作里的调用；超时、出错的那一页按“不会做”处理（通用的“已阅 / 同意 / 不同意 + 意见”仍然可以）。

### 35.5 收发文插件 `org.onedesk.inbox` 的角色

| 类型 | 角色 | 页面 |
|---|---|---|
| `inbox` 收文簿 | 容器（`letters: true`），可以单独放，也可以放在书里 | 来件登记表：收到日期、寄件人（签名状态）、事由、要做的事、期限、状态（待办 / 已回 / 逾期）；工具栏“收件…”（选 `.odletter` 文件） |
| `letter` 来件 | 只读副本的根 | 文头：寄件人（✓ 签名有效、已核对）、事由、附言、期限；**要你做的**：每一页一行（做什么、状态，点开那一页去做）；通用处理：已阅 / 同意 / 不同意 + 意见；“**回件…**”：收齐各页的 `reply`，写回件文件 |
| `outbox` 发文簿 | 容器 | 发文登记表：寄出日期、事由、收件人数、已回几人、期限 |
| `sent` 发件 | 可编辑，寄出后锁定（签章 K6） | 收件人（从通讯录多选，或“任何人”）、事由、附言、期限、附件（引用书里的页）、每页要做什么（从那一页的 `tasks` 选）；“**寄出…**”写来件文件；寄出后：每个收件人一行（回了没有、什么时候、签名、各页的 `received` 摘要），点开看回件 |

“已阅 / 同意 / 不同意 + 意见”是来件自己的记录（一个小资源 `response`，放在来件下面，回件时一起交回），寄件人那边在发件里显示。

### 35.6 两个场景各角色要做的

**练习**（作业）：
- `tasks`：测验页 → `answer`（作答）；练习页 → `answer`；
- 收件人在来件里的测验卷上照常“开始”作答（作答记录本来就是收件人自己的资源）；`todo`：有交卷的作答就是 `done`（“已交卷，8/10”或“待批”）；
- `reply`：那张测验卷的最后一次交卷的作答记录；
- `received`：老师那边把回件里的作答记录放进学习记录（作答记录本来就按测验卷的编号对应，老师的原卷和学生的副本编号相同），问答题在老师这边批。

**文书**（审签）：
- `tasks`：文书 → `sign`（审签）、`read`（阅）；
- 收件人在来件里的文书副本上点“审签”：建一份**审签记录**（新类型 `signoff`：哪份文书、意见、同意与否），盖章（K6，自动带身份签名 K18）；`todo`：有审签记录就是 `done`；
- `reply`：审签记录；
- `received`：寄件人原文书的页面多一栏“审签”：“王主任 2026-11-27 同意：……（签名有效）”。原文书已经签了章也照样显示（审签记录是另外的资源）。

### 35.7 外壳

- 设置菜单“导入资源包…”改名“**导入文件…**”：认识 `.odpack`（资源包）和 `.odletter`（来件、回件）；来件的对话框：寄件人（签名、指纹、已核对 / 未核对）、事由、要做的事、期限、页数，选放到哪个收文簿（只有一个就直接用它；没有就提示先建一个）；回件的对话框：回的哪份发件、谁回的；
- 不是给你的来件、签名不对的、回件对不上发件的：说明原因，不能收；
- 三种语言（ja-JP 语言包升版本）；Tauri 的打开对话框认识 `.odletter`。

### 35.9 测试（全部通过后才提交）

**内核**：写来件和回件（签名、收件人、附上的页成为下级、保留字段不带）；没有身份不能寄；收件：签名不对、不是给你的、放到不收信的类型下面都拒绝；回件：发件不存在、不是收件人、签名不对都拒绝，同一人再回替换上一次；寄件人进通讯录；`letters` 表和 `host.letters.info`；`letter.received` 事件；迁移 0020 的升级测试。

**收发文插件**：发件的收件人、要做的事、寄出后锁定；来件的“要你做的”和状态；已阅 / 同意 / 意见；回件收齐各页；收文簿、发文簿的状态和逾期。

**练习、文书插件**：`tasks`、`todo`、`reply`、`received`；文书的审签记录。

**界面**（真内核，两个工作区）：
1. 老师（有身份）和学生（有身份，已互相导入身份卡）；老师的课本里有一张测验卷；
2. 老师写发件（收件人：学生；作答；期限），寄出；学生导入：看到老师签的、要作答、期限；收进收文簿；
3. 学生在来件里做测验、交卷；来件显示“已交卷”；回件；
4. 老师导入回件：发件上“李明 已交，8/10”；学习记录里有这份作答；
5. 科室寄一份文书给主任审签；主任审签、写意见、回件；科室收下后原文书显示“王主任 同意（签名有效）”；
6. 把来件改一个字、发给别人的来件、冒充收件人的回件：都被拒绝。

### 35.10 对照 §0 和产品要求

| 原则 | 这一步怎么做到 |
|---|---|
| 1 书只负责装订 | 书不改；收文簿、发文簿可以放在书里，也可以单独用 |
| 2 逻辑在角色里 | 收发、登记、状态在收发文插件的角色里；“能要人做什么、交回什么、收到怎么办”在担当那一页的角色里（接口 `onedesk.letter/1`） |
| 3 加功能就是加角色 | 加了收文簿、发文簿、发件、来件四种角色；以后别的页能寄出去，就是它的插件实现这个接口 |
| 4 先问现实 | 收文簿、发文簿、公文的主送和要求、处理单、回执、登分 |
| 5 内核不认识书 | 内核只认识“签了名的子树、写给谁、回给谁”，不认识作业和公文 |
| 产品要求 | 来件、发件、审签记录都是资源，有信息面板；收件只在“导入文件…”一个入口；来件不能带代码，只用收件人已经装好的插件；原件不改 |
