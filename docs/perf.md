# 性能数据

日期：2026-11-14　机器：Intel Core i7-1068NG7 @ 2.30GHz，16 GB，macOS（Darwin 25.5）。
**测量时机器负载极高**（`uptime` 负载 400–900，同时运行着多个会话的编译和测试），数值偏保守，不代表空闲机器。

## 冷启动到菜单（浏览器预览模式）

来源：`e2e/perf.spec.ts`，每次新开浏览器上下文（空 localStorage、新库），读控制台 `[onedesk] menu-ready <ms>`（`performance.now()`，自页面导航起算）。运行方式是 vite 开发服务器（未打包，每个模块单独请求），Chromium。

| 测量 | 负载 | 五次数值（ms） |
|---|---|---|
| 第 1 次 | 较低（外壳会话的 e2e 刚开始） | 1796, 1695, 1529, 1762, 1677 |
| 第 2 次 | 极高（负载 ~450） | 5152, 6110, 6715, 5600, 6152 |
| 第 3 次 | 极高（负载 ~900） | 6490, 6398, 6070, 6183, 6220 |
| 第 4 次 | 极高（负载 ~900） | 3751, 3127, 2866, 3115, 3290 |

结论：负载较低时约 1.5–1.8 秒，满足 < 2 秒；负载高时 5–7 秒，主要是开发模式逐模块加载和 CPU 争用。要确认打包后的数值，需要在空闲机器上用 `pnpm build` 的产物或桌面应用（Tauri）重测；此项**未做**。`e2e/perf.spec.ts` 只断言 < 30 秒（防卡死），不断言 2 秒，避免因机器负载误报。

## 1 万条资源搜索（内核，`src/kernel/search.test.ts`）

`pnpm exec vitest run src/kernel/search.test.ts --silent=false`，内存 sql.js 库，6 个查询各跑 7 次，断言取每个查询最快的一次 < 200ms。
