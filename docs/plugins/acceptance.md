# 插件验收清单（acceptance）

每一条都是“通过 / 不通过”，并写明怎么验。**任何一条不通过，插件不验收。**

标记：**[自动]** 由 `pnpm plugin:check <插件目录>`（或 `plugin:pack`）检查，命令失败即不通过；**[手动]** 由验收人按“怎么验”一栏看；**[测试]** 由插件自己的 `main.test.ts` 覆盖，验收人读测试确认有这一条且通过。

验收人需要的环境：一份 OneDesk 仓库检出；devhost + `pnpm dev`（workflow.md §6.1，临时数据目录、`ONEDESK_SECRET_STORE=memory`）。

## A. 包与清单

| # | 条目 | 怎么验 |
|---|---|---|
| A1 | 文件夹名等于清单 `id`；`id` 只含 `[a-z0-9._-]`、≤ 128、不以 `.` 开头结尾；官方插件以 `org.onedesk.` 开头 | [自动] + [手动] 看前缀 |
| A2 | `manifest.json` 是合法 JSON，`apiVersion` 是 `"2"`，`version` 是 semver | [自动] |
| A3 | 清单通过内核的严格校验：无未知字段，所有引用（页面、动作、命令、kind、树、设置、接口）都存在，不出现 spec.md 列出的任何拒收原因码 | [自动]；[手动] 装进 devhost 后插件页没有把它列为“被拒” |
| A4 | `name`、`description`、所有 `label`、`newName`、`hint`、`confirm` 等都是语言键，且每个键都在 `locales/en-US.json` 里 | [自动] |
| A5 | `icon` 和各处图标是存在的 lucide 图标名 | [手动] 在界面里看图标都显示出来 |
| A6 | `main` 指向存在的 `.js` 文件；包里只有 `manifest.json`、`.js`、`locales/*.json`、测试、可选 `README.md`/`CHANGELOG.md`、声明过的 `bin/` 程序 | [自动] + [手动] 列目录 |
| A7 | `requires` 只申请用到的权限：每一项都能在代码里找到对应的宿主调用；没有 `secrets.plaintext: true`（除非协调会话书面同意） | [手动] 对照清单读 `main.js` |
| A8 | `license` 是 MIT/Apache-2.0/BSD/ISC/Zlib/Unicode-3.0 之一（官方插件写 `MIT`） | [手动] |

## B. 代码与沙箱

| # | 条目 | 怎么验 |
|---|---|---|
| B1 | 只 `import` 包内文件（`./x.js`） | [自动] |
| B2 | 不用沙箱里没有的全局对象：`console`、`setTimeout`、`setInterval`、`fetch`、`XMLHttpRequest`、`window`、`document`、`localStorage`、`require`、`process` | [自动] |
| B3 | 不含 CSS/SCSS/LESS、TSX/JSX、HTML 文件；JS 里没有 `style`、`className`、`innerHTML`、写死的颜色（`#hex`）或像素（`"12px"`） | [自动] |
| B4 | `activate` 只注册处理函数，不调用宿主方法；注册的名字与清单声明完全一致 | [测试]（“注册的与清单一致”）+ [手动] 装进 devhost 后插件能激活 |
| B5 | 不在模块级变量里保存需要持久的状态（运行时可能随时重建）；持久数据放 `storage` 或资源 | [手动] 读代码 |
| B6 | 长循环检查 `ctx.cancelled()`；长时间工作报告 `ctx.progress`；等待用 `ctx.host.util.sleep`，没有忙等 | [手动] 读代码 |
| B7 | 外部世界只经 `ctx.host`；没有绕过宿主的手段（`eval` 拼代码、读包外文件等） | [手动] 读代码 |
| B8 | 内核、主进程、外壳里没有出现这个插件的 id、kind 或专有词（插件 PR 不改这些目录） | [自动]（`pnpm lint`，官方插件合并前由协调会话跑）+ [手动] 看改动的文件列表 |

## C. 界面

| # | 条目 | 怎么验 |
|---|---|---|
| C1 | 每个页面只返回四种视图节点（`form`、`text`、`table`、`link`），字段都是允许的 | [测试]（`checkView` 为空）+ [手动] devhost 里打开每个页面，没有“插件输出无效”的错误 |
| C2 | 视觉只靠设计 token：插件里没有任何颜色、尺寸、时长 | [自动]（B3） |
| C3 | 浅色和深色主题下每个页面可读、无错位 | [手动] `&theme=light` / `&theme=dark` 各看一遍每个页面 |
| C4 | 中文（`zh-CN`）和英文（`en-US`）下所有文字都已翻译，没有显示成键名（如 `field.text`） | [手动] `&lang=zh-CN` 与默认英文各看一遍：页面、按钮、新建菜单、插件页、设置、运行结果、错误提示 |
| C5 | 空状态：没有数据/新建时页面有说明下一步的文字，不是空白 | [手动] + [测试] 空状态 render 一例 |
| C6 | 错误状态：配置缺失、外部失败、权限被拒时页面或运行结果给出翻译过的说明，不崩、不出现堆栈 | [手动] 制造一次失败（如断网、填错地址） + [测试] 失败路径 |
| C7 | 未就绪/加载状态：需要先授权文件夹、先配置连接等前置条件时，页面说明并给出操作按钮 | [手动] |
| C8 | 运行结果页（`ctx.run` 存在时）表单是只读的 | [测试] |
| C9 | 按钮：主按钮最多一个 `primary`；危险操作 `danger: true` 或有 `confirm`；除 `role: "save"` 的按钮外没有别的按钮占用 `["Mod", "S"]` | [手动] 读清单 |
| C10 | 编辑资源内容只通过 `bind` + `role: "save"` 保存，不在动作里偷偷写资源 body（除非这正是动作的目的且有说明） | [手动] 读代码 |
| C11 | 一切皆资源（spec §0.1）：资源页有信息面板（名称、描述、标签、位置、时间），插件页面里没有重复的名称/描述字段 | [手动] 打开每种资源 |
| C12 | 每个标签页都能选环境（spec §0.2）：资源页清单 `usesEnv: true`；不用环境的页面有用户同意的理由 | [手动] 读清单 + 打开页面看环境选择器 |
| C13 | 天生是模板（spec §0.3）：内容里的占位符按当前环境取值，换环境结果跟着变 | [测试] 两个环境各 render 一次，结果不同 + [手动] |
| C14 | 一个功能只有一个入口（spec §0.5）：操作栏已有的功能，页面内容里没有同作用的控件 | [手动] |

## D. 安全

| # | 条目 | 怎么验 |
|---|---|---|
| D1 | 密钥只在钥匙串：密钥用 `type: "secret"` 字段输入；请求、程序环境里只用 `{{secret:名字}}` 占位符 | [手动] 读代码 + [测试] 断言请求里是占位符 |
| D2 | 数据库、清单、`storage`、资源普通字段、输出、`summary`、错误文字、artifact 里都没有明文密钥 | [手动] 在 devhost 里用一个假密钥跑一遍，查看运行结果、历史、导出文件里搜这个值 |
| D3 | 所有网络主机都声明了：`requires.network.hosts` 写死的主机，或 `fromResources` + 资源字段 `grants: "network"`；没有 `*` 式的大范围通配（`*.domain` 需说明理由） | [手动] 对照代码里所有 `network.request` / `transfer` 的网址 |
| D4 | 不访问本机地址，除非资源里由用户明确写出 | [手动] |
| D5 | 运行的外部程序都在 `requires.programs` 里；参数由数组传入，不拼 shell 命令；用户输入不会变成程序参数里的选项注入 | [手动] 读代码 |
| D6 | 文件只在授权文件夹或自己的数据文件夹里读写；删除用 `trash` 而不是 `remove`（除非是自己的临时文件） | [手动] |
| D7 | 不直接调用 AI 服务商插件、不 `uses: ["onedesk.ai.chat/1"]`、不自己画 AI 界面；AI 辅助只靠字段的 `assist` 声明（spec.md §11）；不适合 AI 写的文本字段标了 `assist: { off: true }`，有固定格式的字段写了 `format` | [手动] 读清单与代码，在应用里点一次 ✨ 看提议是否合理 |
| D8 | 给 AI 客户端的动作（`ai`）确实只读 | [手动] 读代码 |
| D9 | 测试不访问真实服务、真实数据目录或真钥匙串（只用 `vi.fn` 假宿主或 `127.0.0.1` 上的假服务器） | [手动] 读测试；可断网跑 `plugin:check` 仍通过 |

## H. 升级路径（第二个及以后的版本）

| # | 条目 | 怎么验 |
|---|---|---|
| H1 | `version` 比上一个发布版本高 | [手动] 对照上一个包 |
| H2 | `upgradesFrom` 覆盖了应当接管的旧版本（semver 范围合法） | [自动] 合法性；[手动] 范围是否正确 |
| H3 | body 结构变了的 kind 有 `migrate`，且是纯计算（不写任何东西） | [手动] 读代码 + [测试] E8 |
| H4 | 在临时数据目录里：先装上一版本并建资源，再装新版本 → 自动切换成功、资源被接管、内容正确、插件页没有“切换失败” | [手动] |
| H5 | “撤销升级”后资源回到旧版本且可用 | [手动] |
| H6 | 权限有变化时变更记录里写明；升级时界面要求重新确认 | [手动] |
| H7 | `CHANGELOG.md` 写了这个版本的变化（官方插件） | [手动] |
