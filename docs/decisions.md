## 第一个里程碑（2026-11-14，主会话）

### 运行方式与接口

- **D01 插件运行方式**：同一进程内的 TypeScript ES 模块。内置插件用静态 import；外部插件由 Rust 读取 `plugins/<dir>/` 下的 `manifest.json` 与入口文件 `index.js`，前端以 Blob URL 动态 import。两者都包装成 `PluginSource { origin, manifest, load() }`，走同一条加载路径。接口不依赖运行方式，将来可换成 Worker / 独立进程。
- **D02 视图树**：只用 `form`、`table`、`text`、`link` 四种节点。`render` 可返回单个节点或节点数组（数组 = 自上而下排列），不新增容器节点。`form` 节点在插件视图中为只读展示；可编辑表单只由宿主的通用“编辑”视图使用。
- **D03 校验**：清单、字段定义、视图树、动作输出都用 zod 校验（`src/plugin-api/schemas.ts`），清单本身是 JSON 文件。
- **D04 apiVersion**：只接受 `"1"`；其他值拒绝加载并记录原因。
- **D05 id 规则**：插件 id 为反向域名（如 `org.onedesk.link`）。kind id 全局唯一（如 `link`），重复注册拒绝。动作与视图在插件内用本地 id，全局键为 `插件id/本地id`；kind 的 `defaultAction`、`views` 写本地 id，解析到同一插件。
- **D06 动作适用的 kind**：接口摘要未说明动作如何关联 kind，动作增加可选字段 `kinds: string[]`。
- **D07 动态输入**：提示词的参数随资源变化。`action.input` 可为字段列表，或 `{ fromField: "<body 字段名>" }`，表示由资源 body 中该 `parameter` 字段生成输入表单。
- **D08 参数占位符**：全项目统一使用 `{{name}}`（名字限 `[A-Za-z_][A-Za-z0-9_]*`）。提示词插件提供占位符检查并有测试；不支持 `$name` / `:name`，出现时在编辑表单报错。
- **D09 系统能力**：接口摘要未列出“用系统浏览器打开”和“剪贴板”。放在 `ui` 下：`ui.openExternal(url)`、`ui.copyText(text)`，由宿主执行（不是插件直接操作界面）。
- **D10 资源访问范围**：插件经 `host.resources` 只能读写自己注册的 kind 的资源；外壳（shell）直接使用内核 API。
- **D11 视图状态**：`render(resource, state)` 中 `state = { revision, lastResult? }`，`lastResult` 为本次会话中该资源最近一次动作结果。`render` 可以是异步的，可读取 `host.storage`（HTTP 请求的上次响应存在插件存储里，重启后仍可见）。
- **D12 每个 kind 自动获得通用“编辑”视图**（内核按 schema 生成表单），默认视图为 `kind.views[0]`，没有则为“编辑”。
- **D13 网络**：`network.fetch(url, init)` 经宿主转发；清单 `requires.network` 声明允许的主机模式，`"*"` 表示任意主机（HTTP 请求插件需要）。未声明的地址一律拒绝（宁可误拒）。
- **D14 密钥**：补充要求取代“secrets 仅占位”。密钥只存 macOS 钥匙串（service `onedesk`，account = 密钥名），插件只能读取清单 `requires.secrets` 中声明的名字。数据库、清单、导出文件中不出现明文。设置页可增删改；卸载外部插件时询问是否删除其声明的密钥。
- **D15 停用插件的显示**：验收要求“停用后菜单项消失”，界面要求“停用插件和失效资源灰色显示、不隐藏”。决定：菜单中隐藏停用插件的资源；插件页灰色显示停用插件及“保留了 N 个资源”；“全部资源”表格和搜索结果中灰色显示这些资源，打开后提示“插件已停用”。body 不符合 schema 的资源在菜单中灰色显示并带警示图标。
- **D16 内置插件不可卸载**，只能停用；外部插件可卸载（删除插件记录与插件存储，不删除文件夹，避免误删用户文件）。

### 存储

- **D20 数据库在 Rust 侧**：rusqlite（bundled）单连接 + Mutex，前端通过 `db_select` / `db_execute` / `db_batch`（事务）命令访问。不用 tauri-plugin-sql：它是连接池，跨调用的事务不可靠，满足不了“迁移在事务中执行”。
- **D21 迁移**：`src-tauri/migrations/NNNN_name.sql`，编号递增，已发布的不再修改。版本存在 `schema_version` 表。启动时 Rust 在一个事务中逐个执行未应用的迁移，失败回滚，前端显示阻断错误页，不允许继续使用。TS 测试用同一批 SQL 文件建库。
- **D22 数据目录**：`dirs::data_dir()/onedesk`（即 `~/Library/Application Support/onedesk/`），不依赖 bundle identifier。启动时先确认目录存在（不存在则创建）。
- **D23 启动快照**：迁移前用 SQLite `VACUUM INTO` 写 `backups/onedesk-YYYYMMDD-HHMMSS.db`，只保留最近 7 份。
- **D24 搜索不用 FTS5**：中文在 FTS5 默认分词器下效果差，子串匹配反而符合预期；1 万条规模下全表扫描足够快（有性能测试）。数据量增长后再评估。
- **D25 标签**存为 JSON 数组字符串，按标签查询用 `instr(tags, '"标签"')` 精确匹配，避免多表写入。
- **D26 测试数据库安全**：TS 测试只用 sql.js 内存库；Rust 测试只用临时目录。会重建数据的集成测试需要 `ONEDESK_TEST_DB=1`，且代码拒绝打开路径中包含 `Application Support/onedesk` 或文件名为 `onedesk.db` 的数据库。

### 界面

- **D30 基础组件**：Radix UI 各原语（Dialog、DropdownMenu、Select、Tabs、Tooltip、Toast、Switch、Popover）负责交互与无障碍；外观全部用 `src/design/tokens.css` 中的 CSS 变量实现。命令面板用 cmdk（无样式）。
- **D31 样式方案**：普通 CSS + CSS 变量，类名前缀 `od-`，每个组件一个 CSS 文件放在组件旁。不用 CSS-in-JS、不用 Tailwind。除 `tokens.css` 外不允许写死颜色、像素值；不允许内联 style（拖动排序的 transform 除外）。由 `scripts/check-ui.mjs` 检查。
- **D32 图标**：只用 lucide（线性，统一 1.75 线宽）。清单 `icon` 字段填 lucide 图标名。
- **D33 文案**：界面文字集中在 `src/shell/i18n/zh-CN.ts`，组件通过 `t()` 取用。
- **D34 主题与密度**：`<html data-theme="light|dark">` 与 `data-density="comfortable|compact"`；偏好存 `app_settings`，默认跟随系统。
- **D35 路由**：外壳内部状态路由（不引入 react-router），页面：全部资源、资源、集合、插件、设置。

## 接口定稿复审（2026-11-14，主会话，依据 Fable 5.2 独立审查）

- **D50** 占位符检查：格式错误的 `{{…}}` 是错误（阻止保存）；`$name`、`${name}`、`:name` 是警告（不会被替换，正文中可能合法）。不用正则后行断言（macOS 11/12 的 WebKit 不支持）。取代 D08 中“出现时报错”。
- **D51** 平台接口增加 `app.status`、`plugins.scan`、`files.{pickFolder, exportWrite, importRead}`。组合根 `src/shell/bootstrap.ts` 是外壳中唯一可以 import `src/platform` 的文件。
- **D52** `PluginSource.error`：扫描阶段的问题（清单缺失或无法解析、入口缺失、main 越出插件目录）作为加载错误上报，不加载。
- **D53** 密钥名是全局命名空间（用户在设置页管理，如 `github_token`），名字索引存 `secret_names` 表，值只在钥匙串。卸载插件时只询问删除它声明、且没有其他已安装插件声明的密钥。
- **D54** `plugins.uninstalled` 标记卸载（文件夹保留，再次扫描不会自动重装；设置页可重新安装）。新发现的外部插件默认停用，内置插件默认启用。
- **D55** 外部插件入口是自包含的 ES 模块，`export default` 一个 PluginModule；宿主 API 通过 `activate(host)` 传入，不需要 import。
- **D56** 动作运行以 `runId` 跟踪；状态增加 `cancelled`。`actions.run` 不抛异常：未知动作、插件停用、输入无效、插件抛错、输出类型与声明不符都返回失败结果。
- **D57** 导出额外包含 `plugins.json`（启用状态、设置、插件存储），只导出不导入；导入只恢复资源和集合，保留原 id、version、时间戳和 origin；未知 kind 也导入（显示为失效资源）。集合冲突同样询问覆盖或跳过。`attachments/` 保留为空文件夹（附件功能下一阶段）。
- **D58 已知限制**：插件与宿主同进程，恶意插件理论上可绕过宿主 API 直接调用 Tauri 命令。本里程碑只运行内置插件和用户自行放入的插件，接受此限制；隔离（Worker/独立进程 + Rust 侧权限检查）列入下一阶段。
- **D59** `schema_version(version INTEGER NOT NULL)` 单行。网络主机模式：精确主机、`*.example.com`、`*`；只允许 http/https；非 2xx 正常返回，网络失败或超时（默认 30 秒）报 `unavailable`；响应头名小写，重复的用 `, ` 连接；正文按 UTF-8 文本。
- **D60** `requires.plugins`：允许读取所列插件的 kind 的资源、运行它们的动作；写入只限自己的 kind。插件收到的事件只包含它能读的 kind。插件不能把视图或动作挂到别的插件的 kind 上。
- **D61** 单一来源：kind 显示哪些视图只由 `KindDefinition.views` 决定（去掉 `ViewDefinition.kinds`）；动作出现在哪些 kind 上只由 `ActionDefinition.kinds` 决定。
- **D62** 字段值类型见 `FieldDefSchema` 注释；HTTP 头用 `longtext`，每行 `Key: Value`。create/update 拒绝不合法的 body（`validation`）；导入或 schema 变化可能产生不合法的旧数据，界面灰色显示。
- **D63** 错误：`OneDeskError(code, 中文信息)`，code ∈ not_found / validation / conflict / permission / unavailable / not_implemented / internal。Rust 命令失败返回中文字符串。
- **D64** `views.render(key, resourceId)`：ViewState 由内核构建。`ResourceQuery` 增加 group、offset，去掉 text（全文搜索只有 `Kernel.search`）。列表默认按 updatedAt 倒序；菜单顺序由外壳存在 app_settings。
- **D65** 链接和 `openExternal` 只允许 http、https、mailto。file 类型的动作输出在本里程碑只显示内容，不提供保存。
- **D66** 清单使用严格校验（未知字段报错，防止拼写错误被静默忽略）。通过宿主 API 创建资源时忽略 `id` 和 `origin`。

## 内置插件（2026-11-14，主会话汇总插件会话与审查结论）

- **D70** HTTP 请求的上次响应存在插件存储键 `response:<resourceId>`，值 `{status, statusText, durationMs, headers, body, truncated, receivedAt}`。资源删除时清除；插件激活时清理资源已不存在的键。正文超过约 1 MB 截断并提示。
- **D71** HTTP 非 2xx 是动作成功（output.message 写“服务器返回 N”）；网络失败或超时是 `unavailable` 失败，保留上一次响应。请求头名大小写不敏感合并，值只允许可见 ASCII。
- **D72** 提示词参数回退：输入为空串或未提供时用默认值；`required` 且无值报“缺少参数”；非必填且无默认值填空串。内核解析 `{fromField}` 时只把“必填且无默认值”的参数标为必填。
- **D73** 插件动作失败一律抛 `OneDeskError`（`validation` / `unavailable`），内核原样转成失败结果。
- **D74** 网址不合法时，网址插件的视图不输出 link 节点，字段按纯文本显示（防止 `javascript:` 等被渲染成链接）。

## 内核（2026-11-14，主会话汇总内核会话报告）

- **D90** 接口补充（主会话）：`Kernel.plugins.uninstalled()` 与 `reinstall(id)`，用于设置页重新安装已卸载的外部插件（D54）。
- **D91** sql.js 驱动与 TS 迁移执行器放在 `src/kernel/sqljs/`（内核一侧，无平台依赖），供测试与浏览器预览适配共用；`src/kernel/testing/` 只放测试工具。
- **D92** 组合根约定：先 `app.status()`，有 `migrationError` 时不创建内核、只显示阻断页；`createBrowserPlatform()` 是异步的。
- **D93** 性能断言口径：1 万条资源，每个查询取 7 次中最好的一次 < 200 ms（排除并行编译等外部负载造成的抖动），并打印所有测量值。空闲时实测 20–60 ms。
- **D94** 浏览器预览模式不支持导入；导出为逐个文件下载。`reference` 字段只校验为字符串，不校验目标是否存在（失效引用在界面中提示）。
- **D95** 构建：Vite 8 不再内置 esbuild，`build.minify` 使用默认压缩器（`minify: !TAURI_ENV_DEBUG`）。
- **D96** 最低系统版本改为 macOS 11.3（WebKit 14.1 起支持 flex `gap`；11.0–11.2 间距会塌陷）。取代架构文档中的 11.0。
- **D97** Rust 命令 `db_select` / `db_execute` 的 `params` 可省略（缺省 `[]`）。钥匙串调用不持有数据库锁；数据库锁中毒时自动恢复。

## 设计系统（2026-11-14，主会话汇总设计会话报告与审查）

- **D100** 主题“跟随系统”时移除 `data-theme`，由 `prefers-color-scheme` 决定；深色配色写两份（媒体查询 + `[data-theme=dark]`），因为 macOS 11/12 不支持 `light-dark()`。组件不碰 localStorage，持久化通过回调由外壳存 prefs。
- **D101** `--border-control`（≥3:1）用于输入框、下拉、复选框边框和开关关闭态轨道；`--border-strong` 只用于分隔线。`--fg-inactive`（≥4.5:1）用于灰色但可交互的项（停用插件的资源等），`--fg-disabled` 只用于真正禁用的控件。
- **D102** 可交互表格使用 `role=grid`，一个 Tab 停靠点，↑/↓/Home/End 移动行焦点；行内控件的按键与点击不触发行激活。
- **D103** 危险（danger）吐司默认不自动消失。每个 Tooltip 自带 Provider。Checkbox、Progress 用原生元素（不新增依赖）。Icon 按 lucide 名字解析（含旧名别名），未知名字显示占位图标。
- **D104** CommandPalette 默认按标签/描述/关键词过滤；外部结果（内核搜索）时传 `filter={false}`，加载中 `aria-busy`。Dialog `dismissible={false}` 时遮罩和 Esc 都不关闭。
- **D105** 额外的布局组件 `Stack`、`Text`、`Section`，让页面排版不需要一次性 CSS。组件展示页保留，外壳接管后通过 `?gallery` 打开。

## 内核加固（2026-11-14，主会话汇总内核第二轮）

- **D110** 接口补充（主会话）：`Platform.network.fetch` 的 init 增加 `redirect?: "manual" | "follow"`。白名单不含 `*` 的插件不自动跟随重定向，宿主逐跳复查 `Location`（最多 5 跳，跨源去掉 Authorization/Cookie）；浏览器预览遇到重定向直接拒绝。Tauri 下 `maxRedirections: 0` 的实际行为在联调时确认。
- **D111** 全局动作（kinds 为空）收到 resourceId 时，动作所属插件必须能读该 kind，否则 `permission`；读取范围不在插件之间传递。
- **D112** 插件 `activate()` 10 秒未完成记为激活错误，不阻塞其他插件和启动。

## 里程碑二决定（2026-11-14，用户确认）

- **D139 存储采用混合方案**。资源内容与全部历史的源头是本地 git 仓库：每个资源一个 JSON 文件；保存在防抖后合并为一次提交，提交信息记录操作者（发布版 id 或“核心”）。历史、恢复、对比都基于提交。SQLite 只作为索引和运行时缓存，可以由仓库完整重建，删除缓存不丢数据。写入统一排队，同一时间只有一个写入者。冷启动读索引；索引缺失或版本不符时从仓库重建，重建时间计入冷启动测量。取代“SQLite 为唯一源头”的做法，影响存储层与迁移规则（改为仓库格式版本，变更需迁移脚本与测试）。**待确认**：libgit2 为 GPL-2.0（带链接例外），不符合 G.8 的宽松许可证要求，需主会话确认；候选为纯 Rust 的 gitoxide（MIT/Apache-2.0），确认前不引入依赖。

- **D140 git 访问方式：调用系统 git 命令**（用户确认）。不引入 libgit2 或 gitoxide，许可证问题随之消失；D139 中的待确认项关闭。访问封装在一个接口后面，将来可以换成 gitoxide 而不影响上层。
  - 启动时检测系统 git；检测不到则提示安装，并说明原因，不静默降级。
  - 设置页允许用户指定外部 git 可执行文件的路径（用于系统 git 不在默认位置，或用户想用自己的版本）。
  - 数据仓库默认建在应用数据目录下；设置页允许用户指定一个已有的外部 git 仓库作为数据源（例如自己的远程仓库）。指定后，应用只读取和写入该仓库中属于 OneDesk 的目录，不改动仓库中的其他文件。
  - 每次保存的提交合并（防抖），不为每次按键启动进程。

- **D141 版本化是用户可选项，取代 D139 的“git 为唯一源头”**（用户确认）。默认存储为应用数据库（SQLite），源头在数据库，不需要 git。用户可以启用 git 版本化，选择本地目录、远程 git 服务器或 GitHub 仓库，并按资源类型决定哪些类型纳入版本化。纳入版本化的资源每次保存生成一次提交，记录操作者；历史、恢复、对比基于提交。关闭后已有提交保留；重新开启时历史从开启时刻开始。远程同步由用户触发或按设定间隔进行，冲突必须由用户处理，首次推送前必须提示将被推送的类型。密钥不进入仓库。D140（调用系统 git 命令、外部可执行文件路径可设置）保持有效。
  - 待定：提交防抖的默认时长；冲突处理界面的形式；版本化开启后，数据库与仓库不一致时以哪一方为准（建议数据库为准，仓库异常时提示修复）。

- **D142 D141 待定项的决定**（主会话定，用户授权）
  1. **提交防抖**：默认在最后一次修改后 5 秒提交；切换到其他资源、关闭窗口或手动“立即保存版本”时立即提交。设置里可调，范围 2–60 秒。同一次防抖内的多次修改合并为一个提交。
  2. **冲突处理**：拉取产生冲突时，冲突的资源标为“有冲突”，只读，其他资源照常使用。在“设置 → 版本化 → 冲突”中列出所有冲突，每项并排显示本地版本和远程版本，提供三个动作：采用本地、采用远程、手动合并（在资源编辑页中完成）。解决后才能继续编辑该资源。
  3. **数据库与仓库不一致**：以数据库为准。仓库不可用（路径失效、git 不可执行、远程无法连接）时，应用继续正常工作，提交进入待办队列，顶部显示提示条；恢复后自动补提交。仓库内容被外部改动（不是通过应用拉取）时，应用不自动采纳，只在设置页显示“仓库与数据库不一致”，由用户选择“以数据库为准重写仓库”（需二次确认）或“从仓库导入”（走冲突流程）。

- **D143 工作区模型：一份功能、一个数据库、窗口级切换**（用户确认，取代此前“每个工作区独立数据库、窗口内可标签切换”的草稿）。
  - 应用程序与功能只有一份。所有工作区的数据在同一个数据库中，以工作区标识隔离；跨工作区操作必须显式进行。
  - 设置分两层：全局设置由应用统一管理，工作区可覆盖任意一项，未覆盖的继承全局值。
  - 插件代码在首次安装时下载一次，保存在应用中；其他工作区启用时直接使用已下载的版本，不重复下载。启用状态与版本固定按工作区决定。
  - 工作区以窗口为单位切换，与 VS Code 一致：在当前窗口打开则整个窗口切换；新建窗口打开则两个工作区并行。每个窗口同一时间只属于一个工作区，不做窗口内标签切换。
  - 密钥按工作区标识存放于钥匙串，工作区之间互不可读。版本化（git）设置属于工作区。
  - 家庭版是新建工作区时的模板，预先启用家庭相关插件；版本只决定模板，不决定安装包数量。

- **D144 工作区数据：每个工作区一个 SQLite 文件，彻底隔离**（用户确认，取代 D143 中“一个数据库、以工作区标识隔离”的数据部分；D143 的窗口切换、设置分层、插件只安装一次、密钥与版本化规则保持有效）。
  - SQLite 中的“数据库”即一个文件，不存在单文件内的多个数据库；因此每个工作区一个文件。
  - 禁止跨工作区查询、统计、搜索和引用。全文索引按工作区文件分别建立。
  - 应用级数据（全局设置、插件包、工作区列表）存放在应用数据目录的独立文件中。
  - 跨工作区只允许显式导出和导入，导入的数据作为新数据。
  - 每个工作区文件独立迁移，打开时按各自的版本升级；迁移规则（D133）逐文件适用。
  - 删除工作区删除其文件，必须二次确认。

- **D145 引用与搜索**（用户确认“就是”）。工作区内搜索与常见软件一致；引用别人的资源只能通过发布和订阅，订阅得到跟随更新的副本并标明来源；资源引用写法为 Markdown 链接与 `[[名称]]`；失效引用显示而不静默消失。跨工作区只能是订阅形式，不构成查询或统计（与 D144 一致）。

- **D146 工作区即实例**（用户确认，补充 D144）。一个工作区基本等同于一个实例：独立的数据文件、设置覆盖、插件启用状态，是独立的运行单元。实例可以是本地实例，也可以连接远程实例（如公司服务），连接方式属于工作区设置。跨实例只通过发布和订阅（D145）。

- **D147 不同性质的工作内容分开，各在一个工作区**（用户确认）。例如给多家公司记账的财务人员，每家公司一个工作区。不对树的数量或结构作额外规定。

- **D148 工作区可选**（用户确认）。首次使用时只有一个工作区；内容差别很大时才新建。内容单一的用户只用一个工作区。

- **D149 长期方向**（用户确认）：目标是承载并逐步替代个人和工作中日常使用的大部分软件，每类软件由插件实现；替代顺序按日常使用频率排定。

- **D150 环境设置统一用参数表示**（用户确认）。保护级别、密钥引用、网络地址、插件、版本化开关、AI 策略、视觉标记都是环境参数，参数有类型（文本、数字、布尔、列表、密钥引用）。保留前缀由核心解释；保护类参数只能加严，不能放宽。

- **D151 三个概念的区别**（用户确认）：工作区是数据和运行单元，数据隔离边界，窗口级切换；工作区配置定义是应用级模板，只用于新建工作区，不含数据，修改不影响已有工作区；工作区环境是工作区内的参数和保护设置树，窗口内切换，属于该工作区的数据。工作区环境只能在工作区已启用的插件范围内停用插件，不能启用工作区未启用的插件（修正 D150 中“环境启用插件”的说法）。

- **D152 修正 D151**（用户确认）：工作区是独立实例和独立数据库；工作区的设置（深色或浅色、菜单语言等）只决定该工作区本身，覆盖全局设置。环境在标签页内使用，每个标签页可以选择自己的环境，参数只在该标签页内生效；不是窗口级或工作区级的切换。

- **D153 设置只属于工作区，没有全局设置层**（用户确认，取代 D143、D152 中“全局设置 + 工作区覆盖”的说法）。深色或浅色、菜单语言等设置保存在该工作区自己的数据库中，只影响该工作区。新建工作区时，设置的初始值来自工作区配置定义（模板）。应用级数据只包含：已下载的插件包、工作区列表、工作区配置定义。

- **D155 git 链接属于工作区设置**（用户确认）。仓库位置、外部 git 路径、纳入版本化的资源类型都保存在该工作区的设置中，不属于应用级或全局。

- **D156 分支是高级功能**（用户确认）。分支用于草稿和发布（草稿分支确认后合并到主线）。“高级模式”是工作区设置中的一项，默认关闭；关闭时界面不显示分支的创建、切换、合并，只保留主线历史、恢复和对比；开启后显示分支功能。

- **D157 新增宿主能力 `files`（待主会话确认，接口改动）**。原因：导入硬盘资源插件需要选择文件夹、列出目录、读取文件信息、在系统中显示和打开文件，现有宿主 API 没有这些能力。建议新增 `host.files`：`pickFolder()`、`list(path, {recursive})`、`stat(path)`、`reveal(path)`、`open(path)`；清单新增 `requires.files: boolean`，安装时由用户确认。该改动会改变 `src/plugin-api` 的冻结接口，需记入接口变更记录后，才能开发 `disk-file` 插件。

- **D158 插件分发与信任不在 OneDesk 中实现**（用户确认）。分发、签名、信任、审核由用户另外建设的系统负责。OneDesk 只负责：读取标准插件包，校验清单和 apiVersion，安装时展示权限声明，经用户确认后启用。取代上万插件规模要求中“分发方式、来源与信任”的待定项。

- **D161 配置树包含环境，没有特殊成员**（用户确认，关闭 D159 的待确认项）。工作区设置与环境是配置树中同等的成员。

- **D162 工作区设置与环境结构相同**（用户指出，更正此前“工作区设置没有父子关系”的说法）。工作区设置同样是树，有父子结构和继承，子节点覆盖父节点的同名参数。两者的区别只在控制范围（D160）。

- **D163 环境树与工作区配置树是两棵独立的树**（用户指出，更正 D161、D162 中“同一棵配置树”的说法）。两棵树机制相同，互不包含对方的节点；区别只在控制范围：环境树控制标签页，工作区配置树控制工作区。

- **D164 网页访问：本机作为网页服务器**（用户确认）。运行中的应用可开启网页访问，默认关闭；默认仅本机访问，开启后允许局域网访问并要求访问口令（存钥匙串）；使用加密连接；远程访问另行设计。前端增加网络访问适配，界面代码共用。

- **D165 家庭服务器作为中心**（用户提出）。家里一台常开的服务器运行无界面模式，提供网页访问、git 远程仓库（同步与备份）和定时备份；各设备通过局域网访问，以服务器为中心同步。外部访问（VPN 等）另行设计。服务器系统（macOS 或 Linux）待确认。

- **D166 外部服务器单独记录**（用户确认）。外部访问中继、插件发布与下载由单独的服务器提供，需求见 docs/design/external-server.md。服务器不保存用户数据；插件的分发和信任由该服务器承担，与 D158 一致。

- **D167 外部服务器只负责发现与连接**（用户确认，缩小 D166 的范围）。插件发布与下载不属于这台服务器，另行设计。范围见 docs/design/external-server.md。

- **D168 数据接入：插件 + 数据源资源**（用户确认）。插件提供连接能力（如 PostgreSQL、接口调用）；每条具体连接是一个数据源资源，保存非敏感配置，密钥只保存名字（值在钥匙串）。查询结果默认不复制成资源，只有用户保存的查询才成为资源。

- **D169 插件是一棵树，插件页在标签页中打开**（用户确认）。插件树与其他树互不包含；点击插件在标签页中打开插件页，包含说明、版本、启用开关、设置项、权限、加载状态和提供的类型与动作。启用状态按工作区保存（D143）。

- **D170 框架保持干净**（用户确认）。内核只保留通用机制；一个概念一种机制；不为个别功能开特例；设置放在它控制的对象上；入口只放在对象自己的页面里。见 requirements.md I.0c。

- **D171 功能尽量放在树和标签页中，少用对话框**（用户确认）。所有功能尽量安排在树与标签页两种结构中；容量大、操作简单；对话框只在必要时使用（如系统的文件选择）。

- **D172 每个标签页有结果区**（用户指出缺失）。结果区在页面下方，可拖动、可收起；按输出类型显示；结果进入该标签页的执行历史；失败原因留在结果区；可交给 AI 分析（先 Markdown 预览，可编辑后发送）。现有“一行状态”的结果面板不满足要求。见 requirements.md I.0d。

- **D173 SQL 参数用绑定方式传入**（待确认）。sqlpool 目前用字面量替换；OneDesk 改为数据库驱动的绑定，不做字符串拼接。

- **D174 SQL 插件的树与历史**（用户要求写清楚）。SQL 插件体现三棵树：资源树（SQL 与命令，含每个 SQL 下的"历史"子节点）、环境树、数据源树（数据源仍是资源，单独成树，与硬盘文件做法一致）。执行历史按 SQL 分开，点开某次执行在标签页中显示；跨 SQL 的总历史作为后续单独的树。见 docs/design/sql-plugin.md §2a。

- **D175 树、标签页、结果区类型是扩展点，插件通过依赖直接复用**（用户提出，待主会话确认接口改动）。插件可以声明提供树类型、标签页类型、结果区输出类型；依赖方通过 `requires.plugins` 直接使用对方提供的扩展点，不重复定义。依赖只能使用明确声明的扩展点。该改动扩展插件接口，需在开始相关开发前确认。见 requirements.md I.0e。

- **D176 files 能力确认**（用户确认）：宿主新增 `files`，可读取文件信息、列目录、选择文件夹、显示和打开；由 Rust 实现。不提供写入和删除。这取代 D157 的待确认状态。
- **D177 SQL 参数沿用 sqlpool 现有做法**（用户确认，取代 D173 的待确认项）。CLAUDE.md 记录 sqlpool 为字面量替换，OneDesk 沿用，不做改动。
- **D178 一个工作区一个进程**（用户确认）。

- **D180 扩展点早已决定**（用户确认）。树、标签页、结果区的类型是扩展点，见 D175。
- **D181 插件接口不因里程碑而冻结**（用户指出）。接口变更由主会话决定并记入 decisions.md。CLAUDE.md 第 10 条已相应修改。

- **D183 文件操作全部纳入，OneDesk 替代系统资源管理器**（用户确认）。文件能力包括浏览、新建、重命名、移动、复制、删除（默认进废纸篓）、打开、显示、搜索文件名。文件树是独立的一棵树。扩展 D157 与 D176 中的 `files` 能力，接口变更由主会话记入本文件。见 requirements.md I.10b-2。

- **D184 授权范围在硬盘文件插件中定义**（用户确认）。可以有多个授权文件夹，以列表管理（增加、查看、修改、移除）；移除授权不删除已登记的资源，也不删除文件。取代 D157 中“选择对话框授权并可撤销”的设计，授权列表放在插件页中。

- **D185 服务器命令是单独的插件**（用户确认）。`命令` 插件负责保存和运行服务器命令，行为与 SQL 插件的保存查询一致（分组、编辑、参数替换、历史、结果区）。它与 SQL 插件并列，不放在 SQL 插件里。第一期插件清单：硬盘文件、数据源（PostgreSQL）、SQL、命令、AI 接口、语言（中、日、英）。

- **D186 综合插件**（用户提出）。提供综合节点：可放在树的任意分组下，内含任意插件的资源，可嵌套，用户手动排列；资源不复制，移除只删除引用。点开在标签页中列出所有资源。与集合不同：集合按条件自动收集，综合节点手动排列。第一期插件清单增加“综合”，共七个。

- **D187 拖拽行为由插件决定**（用户要求）。框架只提供拖拽机制（拖动源、放置目标、视觉反馈、取消）；是否可拖、放到哪里有效、放下后的动作由插件定义。无效位置的提示由框架统一显示。见 requirements.md I.0g。

- **D190 修正 D189：可以复制 Vioros 的逻辑**（用户确认）。能用的下载、上传、网关调用逻辑可以复制到插件中。插件不依赖 Vioros 的代码库（不通过引用或包依赖），复制后的代码归 OneDesk 插件所有，之后各自维护，不互相同步。

- **D191 界面默认语言为英语**（用户确认）。英语是默认界面语言，缺失的文字回退到英语。中文和日语由语言插件提供，用户可切换。

- **D192 界面语言在工作区配置中选择，选项来自已安装的语言插件**（用户确认方向）。语言插件通过扩展点提供文字；工作区配置树的“界面语言”项列出已启用的语言；切换只影响该工作区；缺失的文字回退到英语。当前代码尚未实现，只有中文且写死在代码中。

## 重新开发的决定（2026-11-15，用户批准设计方向；详见 docs/redesign/kernel-design.md）

- **D208** 主进程-工作进程模式：主进程只管生命周期、窗口、工作进程调度和转发；每个打开的工作区一个工作进程，运行 Rust 内核库；界面只是协议的客户端。（取代或修改：D01、D20 中“前端经 SQL 命令访问数据库”）
- **D209** 插件在工作进程内的 JS 沙箱里运行，只能调用宿主 API；现在就做隔离。（取代或修改：D58）
- **D210** 清单 apiVersion "2"：能力全部写在 `contributes` 里，代码只提供行为；插件惰性激活、空闲回收，要持续关心的事件写在清单里。（取代或修改：D05、D61 的登记方式）
- **D211** 类型名写成 `插件id:类型名`；第一版的短类型名由插件在清单里声明接管。（取代或修改：D05）
- **D212** 取消 `group` 字段；分组、环境、配置项、插件状态都是资源，用 `tree + parent_id + pos` 组成树。（取代或修改：A 节资源字段）
- **D213** 所有修改经过统一写入管线；事务里不调用插件；修改历史始终在数据库里，git 是镜像。（取代或修改：I.9 中“历史基于提交”的字面意思）
- **D214** 环境、工作区配置、插件状态共用参数节点；策略按“插件状态 → 工作区配置 → 环境父链”合并，只能加严；没有环境时按最严处理。
- **D215** 动作执行与后台任务统一为“运行”；每次运行记下当时的输入快照。（取代或修改：D56）
- **D216** 表单字段可绑定资源字段并可编辑；节点可发事件；事件带未保存的内容，插件可返回对它的修改。（取代或修改：D02）
- **D217** 插件自带的界面模块直接加载到页面里（与 Vioros 现在的做法相同），不做 iframe 隔离；安装时明示并确认；自定义节点和自定义标签页是同一机制。（取代或修改：D206 的实现方式）
- **D218** 内核不内置数据库驱动；新增宿主能力 `process`，运行清单里声明过名字的外部程序；程序的获取、更新、核对由插件负责；安装时明示它不受沙箱约束。（取代或修改：m2-sql-plugin.md 中“驱动放在 src-tauri”）
- **D219** 内核不含界面文字，错误为码 + 参数；外壳自带英语作为兜底。（取代或修改：D63、D134、CLAUDE.md 约定“内核抛中文错误”）
- **D220** 停用插件的资源在树中灰色显示，不隐藏。（取代或修改：D15、验收 D.3）
- **D221** 首次启动自动创建默认工作区。（取代或修改：ui-spec §5）
- **D222** 删除资源先做标记，可在“已删除”树中恢复；另有需确认的永久删除，连历史一并清除。
- **D223** 删除 sql.js 预览模式；界面测试用浏览器连接真实内核。（取代或修改：D40、T01）
- **D224** 插件可以使用依赖方导出的扩展点；依赖按被依赖方当前启用的版本判断。（取代或修改：D60）
- **D225** 工作区和插件的文件夹只由主进程增删；网页访问只由主进程监听；工作进程不监听网络。
- **D226** （已取消，见 D255）运行模式由工作区的数量决定。
- **D227** 托盘图标与全局快捷键预留位置，首期不做。
- **D228** 没有应用级数据库。有哪些工作区看 `workspaces/` 文件夹，有哪些插件看 `plugins/` 文件夹；每个工作区文件夹里有一个小的 `workspace.json`；工作区 id 随机生成，不等于文件夹名。（取代或修改：D144、D153 中“应用级数据”）
- **D229** 取消工作区模板（工作区配置定义）。新建工作区时只复制当前工作区的配置。（取代或修改：I.0a 的“工作区配置定义”、I.10 的“家庭版模板”、D151、D154 的模板部分）

- **D311** 授权只能由用户给：操作者是插件时，写入管线拒绝新建或修改“授权地址”字段和“密钥引用”字段；升级接管不得改变这两类字段；页面事件的修改里去掉它们。（审查发现插件能往自己的资源里写地址和密钥名，从而给自己授权。）
- **D312** 安装时界面把确认框里看到的 `id`、`version`、权限指纹带回；主进程复制后对目标文件夹重新检查，不一致就删除并拒绝。每个版本带自己的权限清单和指纹，确认的是指纹。
- **D313** 自动确认只适用于主进程给出的内置插件清单；其余没见过的版本一律“已安装、未确认”。（收紧 D299 的实现。）
- **D314** 撤销升级或手动切到较旧版本时，把那个版本记为固定，避免下次扫描又自动升回去；升级批里记下升级前的活动版本；版本比较用 semver。
- **D315** 未确认版本的代码绝不激活；绑定它的资源显示为停用并说明原因。
- **D316** 重定向到别的主机时丢掉含代入密钥的请求头和 `Authorization`、`Cookie`、`Proxy-Authorization`；禁用环境里的代理设置；请求方法限定为常用的七种；插件不能设置 `Host` 等连接级请求头。
- **D317** 网络授权按“主机 + 端口”：授权地址字段得到的是该地址的主机和端口（没写端口取协议的默认端口）；清单里写死的主机不带端口时只表示 80 和 443，要别的端口必须写明。`network.allow` 的条目同理（不带端口 = 80 和 443）。（验收发现授权了 `127.0.0.1:18941` 的请求能发到同一地址的别的端口。）
- **D318** 类型字段可声明“可含密钥引用的文字”（`{ "type": "text", "secrets": true }`）：用户保存的资源里这类字段中出现的 `{{secret:名字}}`，就是用户授权这个插件使用的密钥名字，与“密钥引用”字段同等对待（插件不能写这类字段，D311）。运行时输入快照里出现、但已保存的资源里没有的名字不算授权。运行因宿主拒绝而失败时，`RunError` 带上拒绝的原因码（新增可选字段 `reason`），界面据此给出文字。（验收发现 HTTP 请求在请求头里写 `{{secret:名字}}` 一律被拒：原规则里没有任何办法让用户把一个密钥交给这种插件。）
- **D319** 清单的 `upgradesFrom` 用 Rust `semver` 的范围写法：多个条件用逗号分隔（`">=0.1.0, <0.2.0"`），空格分隔的写法被拒（`badUpgradesFrom`）。（验收时夹具用了空格写法被拒；不为此放宽内核，改夹具。）
- **D320** HTTP 请求插件里可写 `{{secret:名字}}` 的是请求头和请求体（声明 `secrets: true`）；地址字段是授权地址（`grants: network`），按 D318 两者不能同时声明，所以地址里不能写密钥引用。需要在查询串里带密钥的场景以后再议。
- **D321** 引用：正文保持用户写的原样；`refs` 行记下文字和目标 id；目标改名后由内核在读出时把已解析的 `[[旧名]]` 换成当前名称，不为此改写来源资源、不产生历史。
- **D322** `[[名称]]` 的解析：名称完全相等且未删除；多个同名时先取与来源同一父分组的，再取树上最靠前的。分组、环境、配置、插件状态节点不能被引用。
- **D323** 引用按 id 不按名称：目标永久删除后引用成为失效引用并保留；之后新建同名资源不自动接上，来源重新保存时才重新解析。引用不是授权，插件可以写这类字段。
- **D324** 导出是一个文件夹的可读 JSON（格式版本 1）；不含密钥值、界面状态、收藏与使用记录、插件存储、插件状态节点、已删除的资源。
- **D325** 导入的内容一律是新数据，放进一个新分组；一个事务，任何一条失败全部不动；先预览、带指纹确认（与安装插件同一做法）。
- **D326** 导入不带入工作区配置：本工作区的策略不被外来数据改写。环境照常导入（同名加序号）。
- **D327** `protection.readonly` 生效时运行整个被拒（运行要写运行记录）；参数本身、密钥、界面状态、插件的启用与安装不受只读限制（否则关不掉、也管不了）。`protection.no_export` 管工作区导出和结果导出；界面的“复制结果”由外壳在该策略生效时禁用。内核用 `params.known` 列出自己解释的参数，配置页和环境页据此提供添加入口。
- **D328** 结果导出只做 CSV（RFC 4180，UTF-8 带 BOM）；不覆盖已有文件。
- **D329** 导入预览列出导入后将被授权的主机（`grantHosts`）和引用到的密钥名（`secretNames`），用户确认前能看到；导入的结构一律按新建的规则校验，不信导出文件里写的树、父子关系和 `refs`。（审查发现伪造的导出能把资源放进隐藏的树、带入授权地址和密钥引用。）
- **D330** 从未解析过的引用（写的时候目标还不存在）在之后出现同名资源时自动接上：新建或改名得到该名称时，内核把“目标为空且从未指向过任何资源”的 `refs` 行按 D322 的规则解析。曾经指向过、目标被永久删除的仍不自动接（D323 不变）。（验收发现先写 `[[乙]]` 再建“乙”，引用一直显示失效，直到改动来源；这是写笔记最常见的顺序。）
- **D331** 外部程序在清单里按名字声明，分“系统的”和“插件自带的”；系统程序只在固定的六个目录里找，不读 PATH；内核不给包里的文件加执行权限。程序清单进权限指纹，多了程序要重新确认。
- **D332** `process.run` 只能在运行里调用；参数直接作为参数向量，不经过 shell；环境变量不继承工作进程的，只有调用给的加内核固定的四个。
- **D333** 取消或超时时结束整个进程组（先 SIGTERM，2 秒后 SIGKILL）；退出码非 0 不算错误。本轮每次调用跑到结束，不做长驻程序，不做系统级沙箱。
- **D334** `process.allow` 是程序名字的允许名单，合并规则与 `network.allow` 相同（各层交集，空名单禁止一切）。
- **D335** 事件订阅在清单里声明；本轮只投递插件自己类型的资源变化和自己动作的运行结束；提交后异步投递，处理函数的失败不影响触发它的写入。
- **D336** 事件处理函数里不能跑外部程序、不能发网络请求（那些只在运行里）；它的写入引起的资源变化不再投递给同一个插件（防循环）。
- **D337** 自动切换版本失败记在插件上（`switchFailure`），界面提示，直到下一次成功或用户处理；不再只写日志。
- **D338** 外部程序的环境变量里拒绝 `DYLD_*`、`LD_*`。`process.allow` 只按程序名字限制，不限制程序能做什么（声明了 `sh` 就等于任意执行，靠安装时的确认把关）。
- **D339** 已知限制：插件可以把某次运行的宿主接口存起来，在这次运行还没结束时从页面或事件处理函数里使用它（运行里才允许的能力因此短暂可用）。运行结束即失效。本轮不改，记入待办。
- **D340** 外部程序的进程组号记在工作区目录下的一个文件里；工作进程启动时、主进程发现工作进程退出后都按它清理，不留孤儿。（审查发现工作进程被强杀时外部程序会一直跑。）
- **D341** 新依赖 `libc`（MIT/Apache-2.0）：内核与主进程用它建进程组、发信号、查进程启动时间；标准库没有这些接口，替代方案是调用外部的 `kill`、`ps`，更慢也更脆。
- **D342** 清单里“请求安装别的插件”的能力写 `requires.plugins.install: true`；依赖写顶层 `depends`，导出点写顶层 `exports`（设计 §7.2 把两者都叫 `plugins`，这里分开命名）。
- **D343** 依赖按被依赖方的活动版本判断；不满足的依赖方整个停用并说明原因，满足后自动恢复。不自动安装缺的依赖，只提示。
- **D344** 会让已启用的依赖方不再满足的切换、停用、移除一律被拒并列出依赖方，由用户先处理依赖方（§7.3）。自动切换遇到这种情况不切，记为切换失败。
- **D345** 插件请求安装时内核只登记请求并通知界面；检查、确认、复制仍走与手动安装完全相同的路径，结果由界面告诉内核再交还给插件。插件无法替用户确认。
- **D346** 请求安装的文件夹必须在请求方读得到的范围内（授权的文件夹、它的包、它自己的数据目录）；同一插件同时只有一个未答复的请求，5 分钟过期。
- **D347** 依赖方因导出点能读到的类型算一项权限（`resources`，明细是类型全名），在安装确认框里列出并进指纹；依赖本身不是权限。
- **D348** 本地插件市场是内置插件，只用 `files` 和 `plugins` 两项能力；它只展示清单里的展示字段，权限由框架的确认框列出。本轮导出点只做“给类型加动作”和“读资源”两种。
- **D349** 同一插件的安装请求被拒、失败或过期后 30 秒内不能再请求（防止循环弹确认框）；等待用户答复的时间不计入动作的时间预算，但预算不因此重置。
- **D350** 本地插件市场有自己的一棵树（活动栏上一个入口），与计划写的“不新增树”不同；接受，因为入口放在插件树里需要内核为它特判。另：`requires.plugins` 从布尔改成对象（D342）是清单格式的不兼容改动，仓库里没有旧写法的包。
- **D351** 依赖方的动作在别人的类型上运行时，结果只用内核自带的输出显示，不交给页面所有者的结果页签代码（依赖方的输出不流进被依赖方）。
- **D352** 第八轮范围：宿主能力 `transfer`、导出点 `exports.trees` 与 `exports.pages`、页面上下文带页面参数、指纹换 SHA-256、`RunError.params`。“用别人的输出类型”推后：插件自己的输出类型（`contributes.outputs`）还没有，等它一起做。D339 的收紧、清单缓存、空闲回收、第一版旧库升级、`param_decls`、`ai.policy` 留到之后。
- **D353** `transfer` 是三个带进度回调的调用（`download`、`upload`、`capture`），不返回句柄；取消跟随运行的取消；只能在运行里调用。两端各按 `network`、`files`、`process` 已有的规则检查，不新增清单项。内容由宿主按块搬运，不进沙箱，没有 8 MB 上限。
- **D354** 下载和 `capture` 先写目标同目录的临时文件，成功才改名到位；下载只在 2xx 时写文件；失败、超时、取消不留文件。目标已存在时默认拒绝（`conflict/exists`），`overwrite: true` 才覆盖。
- **D355** 动作等待 `transfer.*` 和 `process.run` 返回的时间不计入动作的 60 秒预算（它们有自己的超时：`transfer` 默认 10 分钟、最长 1 小时），预算不因此重置。（第六轮留下的“`process.run` 的超时被 60 秒截断”由此解决。）
- **D356** `exports.trees` 只能导出自己的存储树。依赖方的类型用全名 `"<插件id>:<树>"` 放进去；每个插件仍只能写自己的类型，树的所有者读不到依赖方资源的内容。依赖满足但对方没导出时，只是这个类型不可用（不能新建，已有的照“插件停用”显示，`PluginDetail.unmetExports` 列出），插件其余部分照常。
- **D357** `exports.pages`：依赖方的类型用全名 `"<插件id>:<页面>"` 借用页面；渲染和页面事件由页面所有者的代码执行，对该资源只读；保存由框架做、按依赖方类型的字段校验；操作区是页面的 save/event 动作加依赖方自己的动作；结果区不出现所有者的 `view` 页签（同 D351）。这等于让所有者的代码读到这类资源，所以算依赖方的一项权限（`pages`），在安装确认框列出并进指纹；用别人的树不算权限。
- **D358** 页面上下文带页面参数：`PageContext.params` 作为 `ctx.params` 交给渲染、页面事件、重算；`PageEventResult.params` 让插件改页面参数。页面参数不进草稿，不产生“未保存”。（第七轮验收 V3。）
- **D359** 新依赖 `sha2`（MIT/Apache-2.0）：安装确认与导入确认的指纹从 FNV-1a 换成 SHA-256，防蓄意碰撞。替代方案：自己实现（易错）、`ring`（更大，许可证不在允许范围内）。库里已存的旧指纹在打开工作区时按新算法换掉，已确认的不变成未确认。
- **D360** `RunError` 只增 `params`：宿主拒绝或失败时把原因的参数（程序名、主机、策略所在的层等）带给界面，界面把名字写进文字。
- **D361** 动作等待 `transfer.*`、`process.run` 而暂停预算的时间，一次动作累计最多 1 小时；超过后 60 秒预算照常计时。（审查发现重叠的调用能让动作永不超时；D355 的补充。）
- **D362** 内核把 `http-body`、`bytes`（均 MIT）列为直接依赖：`transfer` 按块读写请求体和响应体要用它们的类型。两者原本就是 `reqwest` 的间接依赖，没有新增包。D359 补充：库里存的是已确认的权限列表而不是指纹，换算法不需要升级旧数据。
- **D363** 第九轮范围：清单缓存、空闲回收、宿主接口按调用上下文授权（收紧 D339），加第八轮验收留下的小修。第一版旧库升级推后到阶段 5：`legacyKinds` 要对应的基础插件（网址、笔记、提示词、HTTP）先按新接口做出来。
- **D364** 清单缓存 `plugins/.index` 只由主进程写：每个包记修改时间、大小和清单原文，启动时只重读变了的。内核在缓存存在时只读缓存（校验照旧由内核做），不存在时直接扫描。缓存不是数据，删掉会重建。
- **D365** 空闲回收：没有运行、宿主调用、渲染或事件处理、等待中的安装请求的插件，空闲 10 分钟后释放运行环境，用到时自动激活；不改变插件状态、不写审计。`PluginDetail.runtime` 让界面看得到。空闲时长可由工作进程的环境变量调（只为测试）。
- **D366** 每次调用拿到的宿主接口只在这次调用自己的异步链上有效；别的调用的代码用它、或这次调用结束后用它，一律 `denied/staleContext`。运行里才允许的能力不能经存下来的接口在页面或事件处理里用。
- **D367** `tree.children` 带界面语言，提供树和自供子节点的处理函数拿到 `ctx.locale`；清单声明的标签按它取值。解决树节点名不随语言变的老问题。
- **D368** 被取消、超时的搬运也写审计；`outsideGrant` 带路径、`blockedByPolicy` 带那一层的名称；网络失败的 `RunError.detail` 只留主机；进度的比例可以为空（不知道总量时不显示百分比）。
- **D369** `AuditResult` 只增 `cancelled`、`timeout` 两个值：被取消、超时的操作在审计列表里按它们显示和筛选，不并进“失败”。
- **D370** 已知限制（D366 的补充）：同一个插件里，页面或事件的代码如果等待一个由某次仍在进行的运行去完成的 promise，之后的代码会被当作那次运行，能用它存下来的宿主接口；反过来运行等待页面事件完成的 promise 后，自己的接口会被拒。引擎按“最近一次回到 JS 的是哪次调用”判断，分不开这种情况。需要插件自己两头配合且运行还没结束，危害低，本轮不改。
- **D371** 内置插件的包每次刷新清单缓存时一律重读磁盘，不沿用缓存：内置版本自动确认清单里的权限，缓存被本机别的程序改写时不能让它静默放大权限。其余包仍只比修改时间和大小（与直接改 `plugins/` 目录同等风险）。
- **D372** 第十轮范围（阶段 4 第一部分）：树与结果表格的虚拟滚动和按需分批、未保存内容的按字段合并与冲突提示、类型自供子节点、通知入口、把“只弹提示”的按钮做实或隐藏。多窗口与多工作区留到下一轮；`ui-spec.md` 还不存在，定稿随后。
- **D373** 虚拟滚动自己实现（定高行的窗口化），放在 `src/design` 的基础组件里，不加依赖；树的一层按内核的批次按需取，去掉外壳 5000 个节点的上限。
- **D374** 保存依据的修改序号落后时按字段判断：别处改的字段与这次改的没有交集就照常保存、两边都保留；有交集就拒绝（`conflict/stale`，列出字段），由用户在页面顶部的提示里选“保留我的”（保存时用 `overwrite` 指明）或“采用新的”。不静默覆盖任何一方。
- **D375** 类型自供子节点：清单类型声明 `children: true`，代码用 `kinds.handle` 的 `children` 给出节点，接在存储的子节点之后；节点可带打开目标；这些节点不可拖动、改名、删除。处理函数出错只在该节点下显示“加载失败”。
- **D376** 通知入口在状态栏，只列本次会话里出现过的提示，不落库。外壳里“点了只弹提示”的入口一律做实或隐藏，隐藏的列表交协调会话排期。
- **D377** 表格输出交给界面的行数上限从 1000 提到 1 万（超出仍标 `truncated` 并给 `total`）：界面已是虚拟滚动，1 万行不再是负担；更大的结果走导出。
- **D378** 用户要求尽快做到阶段 5：第十一轮起先做阶段 5（基础插件），阶段 4 剩下的多窗口、多工作区排到其后交叉进行。第十一轮：语言插件机制与中、日两个语言插件、网址、提示词、笔记阅读态、欢迎页；综合、集合、第一版旧库升级在第十二轮。
