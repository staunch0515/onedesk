# OneDesk 第一个里程碑：需求汇总

本文件汇总用户的原始需求和全部补充要求（按收到顺序合并）。**每个会话开始前必须读完本文件**，与 CLAUDE.md、docs/architecture.md、docs/decisions.md 一起作为依据。冲突时：后来的补充要求 > 原始需求；接口摘要没写的由主会话决定（写进 decisions.md）。

---

## A. 目标与范围（原始需求）

OneDesk 是“内核 + 插件”的桌面应用框架，个人和企业日常工作的统一入口。第一版：可用、可扩展、外观专业。

内核只抽象三件事：资源、插件（提供类型、动作、视图等能力）、视图（宿主根据声明画出界面）。所有具体功能由插件提供，内核不认识任何具体功能。

**范围**
1. 骨架：Tauri 2 + React + TypeScript，Rust 后端，本地 SQLite。包名与项目名统一 `onedesk`。
2. 内核：
   - 统一资源表：id、kind、name、group、tags、description、body（JSON）、visibility、aiVisible、version、createdAt、updatedAt、origin。
   - 资源增删改查；全文搜索（名称、描述、标签、body 文本）。
   - 分组与标签；集合只做手动的（按标签或类型），智能集合下一阶段。
   - 插件宿主：加载、启用、停用；读清单；注册 kind、action、view；校验 apiVersion。
   - 菜单：每个资源是一个菜单项；点击进入由 kind 的 schema 和默认视图生成的页面。
   - 通用视图：表单（按 schema 生成输入）、表格、文本、链接。
   - 动作执行：宿主调用 action.run，显示输出（文本、表格、链接、无），执行中和失败都有明确状态。
   - 宿主 API：resources、actions、ui、storage、notify、context；network、secrets 见补充要求（secrets 用钥匙串实现）。
3. 内置插件（与外部插件完全相同的公开接口）：
   - 网址：kind `link`，动作 `open`（系统浏览器）。浏览器配置文件只留字段。
   - 笔记：kind `note`，视图 `markdown`（阅读态）。
   - 提示词：kind `prompt`，schema 含参数定义，动作 `copy`（替换参数后复制到剪贴板）。
   - HTTP 请求：kind `http-request`，动作 `send`，视图 `response`；经宿主 network 能力发请求。
4. 不做：数据库类插件、发布、订阅与共享、AI 接口（MCP）、多设备同步、账户登录（只在接口预留位置）。

**接口摘要（用户原文）**：本次工作的唯一依据；实现见 `src/plugin-api`，与摘要的差异见 decisions.md D130。

清单（manifest）：
- id（全局唯一，如 org.example.link）、name、version、description、icon
- apiVersion：当前为 "1"
- provides：提供的 kind、action、view 列表
- requires：需要的宿主能力（network、secrets、其他插件的数据源等）
- settings：设置项定义，宿主据此画设置表单

资源条目（所有插件共用）：
- id、kind、name、group、tags、description
- body：按 kind 定义的 JSON
- visibility：private 或 public；aiVisible：布尔值
- version、createdAt、updatedAt、origin（original、subscribed、copied 之一）

kind（资源类型）：
- schema：字段列表，每个字段有名字、类型（text、number、url、reference、parameter 等）、是否必填
- defaultAction：点击时默认执行的动作 id
- views：可用视图 id 列表
- describe(resource)：返回给 AI 看的摘要和用途

action（动作）：
- id、label、input（参数定义）、output（text、table、file、link、none 之一）
- run(context, input)：执行并返回输出，不直接操作界面

view：
- render(resource, state)：返回声明式的视图树，由宿主画出来；插件不直接操作 DOM
- 视图树只用四种节点：form（字段列表）、table（列和行）、text（纯文本或 markdown）、link（href 和文字）

宿主 API（插件只能通过这些入口做事）：
- resources：按 id、kind、标签、集合读写自己类型的资源
- collections：创建和读取集合
- actions：调用其他插件提供的动作
- events：订阅资源变化、动作完成等事件
- ui：注册视图、菜单项
- storage：插件自己的键值存储，互不干扰
- secrets：按名字读取已授权的密钥（本里程碑占位）
- network：发送请求，地址必须在清单里声明（本里程碑占位）
- notify：给用户显示消息
- context：当前工作区、当前用户、调用来源（手动、定时、AI）

生命周期：安装 → 启用 → 激活（注册自己提供的能力）→ 停用 → 卸载。停用后，资源保留，但它的视图和动作不再出现。

## B. 界面与体验（原始需求）

- 第一眼像成熟、可信赖的专业软件，细节经得起推敲。
- 设计 token（颜色、字号、间距、圆角、阴影、动效时长）全部是 CSS 变量，集中在一个文件；组件只引用 token。
- 颜色：中性色为主，一个品牌强调色，语义色（成功、警告、错误、信息）。浅色/深色完整，跟随系统且可手动切换。对比度 ≥ WCAG AA。
- 字体：系统无衬线；字号阶梯 12/13/14/16/20/24，正文约 14px；数字用等宽或表格数字。
- 间距：4px 栅格；密度两档（舒适、紧凑），可切换。
- 布局：左侧固定菜单（资源目录，可分组、可折叠、可拖动排序），右侧页面内容，顶部全局搜索和主要操作。页面统一：标题区、操作区、内容区。最小 1280px 宽。
- 组件：按钮、输入框、下拉、表格、对话框、抽屉、标签页、徽标、提示条、吐司、菜单、工具提示。风格统一（圆角、阴影、边框、悬停、按下）。Radix 等无样式库做交互，外观全部用自己的 token。
- 动效：克制，只用于展开、切换、反馈，120–200ms，无弹跳。
- 键盘：全部操作可键盘完成；⌘K/Ctrl+K 命令面板（搜索资源、执行动作、切换页面）；焦点清晰可见。
- 状态：每个页面有加载中、空状态、错误状态。空状态一句话说明下一步，不放插图。错误给原因和处理方式。
- 停用的插件和失效的资源灰色显示，不隐藏（与验收第 3 条的协调见 D15）；动作执行中显示进度，失败用红色文字说明原因。
- 文案：简短、准确、动词开头，中文为主，集中管理便于多语言。
- 图标：一套统一线性图标，线宽一致。
- 不做：渐变背景、大面积强调色块、装饰性插图、弹跳动画、过度阴影。

## C. 工作要求（原始需求）

- 先写 architecture.md 草稿，再编码。先搭 token 和基础组件，再做页面；页面只能用组件拼，不写一次性样式。
- 顺序：存储层 → 资源增删改查 → 插件宿主 → 设计系统与基础组件 → 菜单和通用视图 → 内置插件 → 搜索和命令面板。每步可运行、有测试。
- 内核不得出现具体插件的名字或逻辑。内置插件只能走公开接口。
- 小步提交，提交信息写清楚做了什么、为什么。不确定就选最简单的做法，记入 decisions.md。不扩大范围。
- 完成后汇报：运行方式、测试结果、截图（浅色和深色各一张，覆盖菜单、表单、表格、空状态、错误状态）、已知限制、与接口摘要不一致的地方。

## D. 验收标准（原始需求）

1. 启动应用，菜单列出所有资源，界面符合设计要求。
2. 新建网址、提示词、笔记、HTTP 请求资源，各自点击进入正确页面并能使用。
3. 停用“HTTP 请求”插件后，菜单项消失、数据保留；重新启用后恢复。
4. 搜索能按名称、标签和正文找到资源；⌘K 命令面板可用。
5. 浅色和深色主题完整，主要页面无明显对比度或对齐问题。
6. 内核测试覆盖：资源增删改查、插件加载与清单校验、动作执行。

## E. Claude Code 工作方式（补充 1）

- CLAUDE.md 简短，只写每次都需要的；细节放 docs。
- 设计类工作（接口定稿、架构、里程碑拆解）先出方案再执行。
- 项目命令 `.claude/commands/`：`/check`、`/new-plugin`、`/review-ui`。
- `.claude/settings.json` 允许常用命令自动执行。
- 独立检查用子代理/新会话审查：内核是否混入插件逻辑；界面是否符合设计。审查者不看实现者推理，只看代码和接口摘要。
- 每步：先 `/check`，通过再提交。会话结束前把新决定写进 decisions.md，更新 CLAUDE.md 过时部分。

## F. 多会话协作（补充 2）

- 主会话：接口定稿、架构、任务拆分、合并审核、取舍。内核会话（Fable/Opus）、设计系统会话（Opus）、插件会话（Sonnet）、测试与样板会话（Haiku）、审查会话（Opus，不看实现推理）。需要时可开 Fable 会话协助架构等重要工作。
- 每个会话一个模块，独立分支/worktree；一个文件同一时间只有一个写入者；任务说明写清可改/不可改的文件。
- 接口在里程碑内不变；改接口只能由主会话决定并写进 decisions.md，再通知所有会话。
- 会话之间只通过 `docs/handoff/` 交接文件交流：完成了什么、改了哪些文件、还缺什么、需要谁确认。不清楚的先在交接文件提问，不要猜。
- 任务说明格式：目标、允许修改的文件、依赖的接口和文件（只读）、完成标准、交付物。
- 顺序：主会话先完成接口与内核骨架 → 插件和界面并行。合并前先审查，再由主会话合并，合并后跑完整 `/check`。冲突以接口摘要为准。
- 合并前检查：只改了分配范围内的文件；测试和检查通过；内核无具体插件名字或逻辑；没有绕过 token 写样式；交接文件已更新；decisions.md 已记录。

## G. 补充要求（补充 3，优先级高于前文）

1. **环境**：仅 macOS（Apple Silicon 优先，Intel 也能构建），最低版本写进 architecture.md。Node LTS + pnpm，Rust stable，版本写进 `.nvmrc`/engines 和 `rust-toolchain.toml`。根目录一条命令完成首次安装和启动（写进 CLAUDE.md）。
2. **数据**：数据库 `~/Library/Application Support/onedesk/onedesk.db`。设置里“导出全部数据”：文件夹含 `resources.json`、`collections.json`、`manifest.json`（版本、导出时间）、附件文件夹；不依赖本应用可直接阅读。“导入”：读同样结构，相同 id 询问覆盖或跳过。每次启动自动保留最近 7 份快照到 `backups/`。
3. **迁移**：版本号存数据库（`schema_version`）。每次改结构新增迁移文件（编号递增），不改已发布的。迁移在事务中执行，失败回滚并明确提示，不允许在半升级状态下使用。每个迁移都有从上一版本升级、数据不丢的测试。
4. **插件位置**：内置插件随应用发布；外部插件在 `~/Library/Application Support/onedesk/plugins/<文件夹>/manifest.json`。启动时扫描；清单错误、apiVersion 不兼容、id 重复的不加载，在设置页列出原因，不影响其他插件。内置与外部走同一条加载路径，只是来源不同。
5. **测试分层**：单元（资源 CRUD、清单校验、视图树、搜索；内核核心覆盖率 ≥ 80%）；集成（插件宿主完整生命周期、迁移）；界面测试（新建资源、打开菜单项、运行动作、搜索、切换主题，用端到端工具驱动）；视觉检查（菜单、表单、表格、空状态、错误状态，浅/深各一张，存 `docs/screenshots/`，界面改动后更新）。全部由 `/check` 运行，失败不许提交。
6. **性能**：冷启动到看到菜单 < 2 秒；1 万条资源搜索 < 200ms；动作执行时界面不冻结，显示进度。性能测试放进集成测试，有数据可对比。
7. **密钥**：只存 macOS 钥匙串，经 `secrets` 接口按名字读取；数据库、清单、导出中不能有明文。设置页可添加、修改、删除密钥。删除插件时询问是否同时删除它的密钥。
8. **依赖**：新增前在 decisions.md 写用途、替代方案、许可证；只用 MIT/Apache-2.0/BSD 等宽松许可证，其他需主会话确认；能不加就不加。
9. **阻塞**：接口不够、需求冲突、环境问题时不自行扩展接口或改范围；在 `docs/handoff/` 写阻塞说明（遇到什么、试过什么、需要什么决定），先做不依赖它的部分。
10. **不扩大范围**：开始前读 CLAUDE.md 和任务说明；范围外的问题只记到 `docs/handoff/todo.md`。

## H. 来自已有开发的经验（补充 4，必须遵守）

- **验证**：每次改动后真正运行，而不只是过测试；验收包括实际启动应用、点一遍主要流程。没运行过、没看到结果、测试没过，都如实写出，不说“完成”。改完先确认能编译再做下一步；写完一段立即跑对应测试和 lint。
- **文件与路径**：用完整路径，使用前确认目录存在（`~/Library/Application Support` 不是 `/Library/Application Support`）。写完 JSON 立即 `python3 -m json.tool` 校验。不要假设用户界面有某个菜单或选项。
- **编辑冲突**：编辑前先读最新内容；同一文件同一时间一个写入者；用脚本改了文件也要重新读取确认。
- **测试安全**：会删表或重建数据的集成测试只在专门测试库上运行，并用环境变量显式开启；测试代码拒绝在名字像正式库的数据库上运行。
- **Rust/Tauri**：多个可执行文件时 `Cargo.toml` 设 `default-run`；`DROP COLUMN` 等单独写迁移并用旧库测试；每次修改后 `cargo clippy --all-targets`，警告也要处理。
- **设计教训**：启发式安全边界“宁可误拒，不可误放”，每种拒绝都有测试；临时存放（如密码放 localStorage）要在文档标记待迁移和期限；参数语法统一（`{{name}}`），有 lint 或测试检查占位符；生成的映射文件随源码重新生成，歧义时输出警告不静默猜测；文档随代码更新（CLAUDE.md 代码地图不能过时）。
- **沟通**：对用户的说明简短，先结论后步骤；命令每条一个代码块，不夹输出。讨论设想和开发是两件事（本里程碑用户已明确要求开发）。
- **用户偏好**：用户通常不在电脑前，**尽量不要问用户**，自行决定并记录到 decisions.md。
