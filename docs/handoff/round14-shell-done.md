## 做了什么（代码）

1. **菜单图标位**（`src/design/components/dropdown-menu.tsx/.css`）：菜单里只要有一项带图标，没图标的项也留出同宽的空位，文字对齐。典型是标题栏的工作区菜单（当前的打勾，别的不打勾）。测试：`dropdown-menu.test.tsx`（2 条）。
2. **切换界面语言后，后台标签页标题立即换语言**（`workbench.tsx`）：语言变化时对非活动标签重新取页面标题。**没有写自动化测试**（现有测试夹具难以在不激活标签页的情况下断言标题；手上只验证了类型检查和既有测试不回归）。
3. 其余 ui-spec 项经对照都已实现，没有需要补的实现（见下表）。

## 主题检查（浅色、深色）

在假数据模式（`workbench.html?theme=light|dark`，1280×720）下：对活动栏的每个树区各点一遍，对所有可见文字做了对比度脚本检查（前景对有效背景，阈值 3.5）。结果：
- 没有写死的颜色（`pnpm lint` 的界面规范检查通过；`src/design` 里 tokens.css 之外没有色值）。
- 只有 3 类低对比项，都是有意的：禁用/不可用节点的灰色文字（深色 3.05、浅色 2.21，如停用的数据源 “MongoDB”，规格要求“灰色显示不隐藏”，禁用文字按 WCAG 不要求对比度）、禁用按钮的 “Save”、以及透明代码输入层（叠在高亮层上，检测误报）。
- 目视看了浅色“工作区配置”页和深色“SQL 页”：没有错位或看不清。
- **没做的**：真内核下的页面（网址、提示词、HTTP 请求与结果、综合、集合、环境、插件页、设置等）没有逐页在两种主题下看；这部分由测试会话的 `round14-light-*.png`/`round14-dark-*.png` 截图集覆盖，我没有看到那些截图。
