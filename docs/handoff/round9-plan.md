## 1. 做完是什么样

- 插件文件夹里有 1 万个包时，第二次启动不再打开任何 `manifest.json`，只读 `plugins/.index`；删掉 `.index` 后启动照常（重建）；改了某个清单、装了或移除了包，只重读变了的。
- 一个插件一段时间没被用到，它的运行环境被释放，插件页上看得到“未在运行”；再打开它的页面或运行它的动作时自动激活，存进 `storage` 的东西还在；有运行在跑时不回收。
- 插件把某次运行的 `ctx.host` 存起来，从页面事件处理里拿来用——被拒（D339 收紧）。
- 小修：新工作树里 `pnpm check` 不再因空占位文件失败；被取消的搬运有审计；提供树的节点名随界面语言变；策略拒绝的错误写明是哪一层（名字）、路径被拒写明路径；没有总量的进度不显示百分比。

## 3. 清单缓存（D364，§7.1）

- 文件 `<数据目录>/plugins/.index`，**只由主进程写**（`crates/host`，含 devhost），工作进程只读。格式（JSON，定死）：
  ```jsonc
  { "version": 1,
    "entries": [ { "dir": "<id>/<版本>", "mtime": 1794800000000, "size": 1234, "manifest": "<manifest.json 的原文>" } ] }
  ```
  `dir` 相对 `plugins/`；`mtime` 毫秒；`manifest` 是文件原文（读不了的包：没有 `manifest`，另有 `"error": "unreadable"`）。按 `dir` 排序。先写临时文件再改名。
- 主进程：启动时、安装或移除包之后、`rescan` 之前刷新——列出 `plugins/*/*/`，对每个包比较 `manifest.json` 的修改时间和大小，与缓存相同的不读文件，变了的或新增的才读，消失的去掉。缓存缺失、读不了、`version` 不认识 → 当作空缓存全部重读。内置插件复制到位之后再刷新。
- 内核：注册表的扫描在 `.index` 存在时**只读它**（不列目录、不开 `manifest.json`），清单的校验照旧由内核做；`.index` 不存在时照现在的做法直接扫描（内核自己的测试、没有主进程的场合）。`main.js`、语言文件仍在用到时从包里读。
- 内核不写、不删 `.index`；主进程不解释清单内容（除了已有的安装检查）。

## 4. 空闲回收（D365，§7.4）

- 一个插件版本的运行环境满足以下全部条件达到空闲时长后释放：没有未结束的运行、没有未返回的宿主调用、没有进行中的渲染或事件处理、没有等待答复的安装请求。空闲时长默认 10 分钟；工作进程读环境变量 `ONEDESK_PLUGIN_IDLE_MS`（只为测试和验收，最小 1000）传给内核，内核自己不读环境变量。
- 释放后下次用到（运行、渲染、页面事件、展开提供的节点、清单 `activation`/事件订阅声明的事发生）自动激活；激活失败的处理与首次激活相同。释放不是停用：插件状态不变，不写审计，不发 `plugins` 主题以外的东西。
- `PluginDetail` 只增 `runtime: "live" | "idle"`（当前活动版本有没有运行环境）；状态变化时发已有的 `plugins` 主题。外壳在插件页显示（`idle` → “未在运行，用到时自动启动”）。
- 卡死或超内存的运行环境照旧整个丢弃（不变）。

## 5. 宿主接口按上下文授权（D366，收紧 D339）

- 每次调用（一次运行、一次渲染、一次页面事件、一次事件投递、一次 `migrate`、一次树/类型处理函数）拿到的 `ctx.host` 只在**这次调用自己的异步链上**有效：别的调用的代码拿它来用 → `denied`，`reason: staleContext`；这次调用结束后再用 → 同样被拒（已有行为，原因码统一成 `staleContext`；若已有码不同，保留已有码并在交接文件写明）。
- 目的：运行里才允许的能力（`network`、`process`、`transfer`）不能经由存下来的 `ctx.host` 在页面或事件处理里用。实现方式由内核会话定（例如宿主调用按“当前正在执行的调用”而不是按调用 id 授权）；如果引擎做不到完全区分并发的异步链，写明做到了哪一步、剩下什么口子，并至少保证：页面、事件、渲染的调用**正在执行时**发出的宿主调用一律按页面/事件/渲染的权限判断。
- 合法用法不受影响：运行里 `await` 之后继续用自己的 `ctx.host`、`onProgress`/`onOutput` 回调里用。

## 6. 小修

内核：
- 被取消、超时的 `transfer.*` 也写审计（结果 `cancelled` / `timeout`）。
- `denied/outsideGrant` 的 `params` 带 `path`（调用给的路径原样，最长 200 字符）；`denied/blockedByPolicy` 的 `params` 只增 `layerName`（那一层节点的名称）。两者经 `RunError.params` 到界面。
- 网络失败时 `RunError.detail` 不含完整 URL，只留主机（第八轮审查 #7）。
- `tree.children` 的参数只增 `locale`；内核把它作为 `ctx.locale` 交给提供树和自供子节点的 `children` 处理函数；清单声明的标签按它取值（缺失回退英语）。
- `ctx.progress(fraction, message)` 的 `fraction` 允许 `null`（不知道总量）；协议 `RunProgress.fraction` 已是可选的话保持，不是则只增一个可选表示（写进交接文件）。

外壳：
- `src-tauri/build.rs` 的空占位不再盖掉真的工作进程（`todo.md`“第八轮验收留下的”第一条）：做法自定（例如占位只在 `target/<profile>/onedesk-worker` 存在时用它的副本，或让 devhost 与界面检查用 `ONEDESK_WORKER` 指定的路径），要求：全新工作树里 `pnpm check` 一遍通过，不需要先跑 `prepare-bundle.sh`。
- `tree.children` 带上当前语言；语言切换后重取树。
- 文字：`layerName`、`path` 进错误文字；没有 `fraction` 的进度不显示百分比；`staleContext`；`runtime` 的两种状态。
- 插件页上还没实现的按钮（“卸载”“检查更新”等）隐藏；没声明 `files` 的插件不显示“授权文件夹…”（第三轮验收留下的）。

插件与测试：
- `com.example.transfer` 夹具：没有 `total` 时 `ctx.progress(null, …)`。
- 市场插件：清单读得出但 `id`/`version` 与目录不符或缺必需字段的包标为“不可用”，不进下拉。

- 内核必须有的测试：有 `.index` 时扫描不列目录、不开清单（用一个只有 `.index`、没有包目录里清单文件的临时目录证明），结果与直接扫描逐项相同；`.index` 里的坏条目（`unreadable`、不是 JSON、清单不合法）各自成为对应的插件问题而不影响别的；没有 `.index` 时照旧。空闲回收：到时释放、每个不回收条件、释放后各种用到方式都能重新激活、`storage` 仍在、事件订阅在释放后仍投递、`runtime` 字段与主题。上下文授权：运行的 `ctx.host` 存起来后从页面事件、渲染、事件处理里用被拒；结束后用被拒；合法用法（`await` 之后、回调里）不受影响；并发两个运行互不串。§6 内核各项。全部用临时目录。
