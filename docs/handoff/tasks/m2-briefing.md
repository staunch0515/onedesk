# 给新会话的说明：在现有界面上扩展（里程碑二）

1. `CLAUDE.md`：仓库规则。
2. `docs/requirements.md`：需求。重点看 I.0 至 I.0g、I.2 至 I.5、I.7、I.10 至 I.10f。
3. `docs/decisions.md`：所有决定。以编号较大的为准，尤其 D139 之后。
4. `docs/architecture.md`：当前结构（已按 D181 更新）。
5. `docs/design/sql-plugin.md`、`docs/design/disk-file-plugin.md`、`docs/design/external-server.md`：各插件和服务的设计。
6. 本说明下面列出的任务文件。

## 2. 现有界面：保留，不重做

用户已确认当前界面很好。保留下面这些，不要换风格：

- **视觉**：设计 token（颜色、字号、间距、圆角、阴影、动效时长）和 `src/design` 的基础组件。不新增一次性样式。
- **布局骨架**：左侧菜单、顶部搜索和“新建”、右上角命令面板入口、页面的标题区、操作区、内容区。
- **组件**：按钮、输入框、下拉、表格、对话框、提示条、吐司、菜单、工具提示，沿用现有实现。
- **截图参照**：`docs/screenshots/light-menu-form.png`、`light-table.png`、`light-empty.png`、`light-error.png`，以及深色版本。新界面的截图要与它们在风格上一致。

## 3. 在现有界面上增加：框架结构

现有界面是单页导航。需要增加的是框架的两种结构，并把现有页面放进去：

- **树**：一个树组件，供资源树、环境树、工作区配置树、插件树、数据源树、文件树使用。树与树互不包含对方的节点（D147、D163）。
- **标签页**：资源、环境、配置、插件页都在标签页中打开。标签页的开合和顺序属于界面状态，不版本化（D159）。
- **结果区**：每个标签页的下方，可拖动、可收起（D172）。

现有的菜单可以作为资源树的第一版，逐步迁移到树组件上。现有的动作结果面板（一行状态）要换成结果区。

## 4. 扩展点（接口）

- 树、标签页、结果区的类型是扩展点，插件可以提供（D175）。
- 插件之间通过 `requires.plugins` 直接使用对方提供的扩展点（D175）。
- 占位符由插件定义，核心只按名字从环境取值（D182）。
- 拖拽由插件决定是否可拖、放到哪里有效、放下后做什么，框架只提供机制（D187）。

## 5. 不要做的

- 不要在核心里写具体插件的逻辑或名字。
- 不要为某个功能开特例；能用现有机制表达的，就用现有机制。
- 不要用对话框做可以放进树或标签页的功能；系统的文件选择除外。
- 不要为了赶进度，把两种结构退化成单页列表。
- 不要改视觉 token 来迁就新界面；有必要改时，先记决定。

5. 框架是否干净，由主会话检查：内核里不得有插件名字或逻辑。
