# 任务说明：框架核心 —— 树与标签页（里程碑二）

状态：待开始。依据：docs/requirements.md I.0a、I.0b、I.0c、I.2、I.3、I.4；docs/decisions.md D147、D160、D163、D169、D170。

## 1. 目标

框架的主体是两样通用机制：**树**和**标签页**。

每个标签页都有结果区（见 requirements.md I.0d）：动作结果显示在页面下方，可拖动、可收起，按输出类型显示，失败原因留在结果区。

所有功能尽量放在这两种结构中。内容要能容纳大量条目，操作要简单。尽量少用对话框，只在必要时使用（如系统的文件选择）。当前的外壳只有菜单和单页，需要替换为：

- **树组件（内核级通用）**：可以显示任意类型的节点树，支持父子嵌套、折叠展开、"全部展开"和"全部折叠"、拖动排序、悬停只改变自身背景、不引起相邻节点跳动。
- **标签页容器（内核级通用）**：打开的资源、环境、配置、插件页都是标签页；可以关闭、固定、一键关闭全部、记住打开状态（界面状态，不版本化）；每个标签前有类型图标。

树的内容由插件提供节点，树组件本身不认识具体类型。同一个组件被不同的树复用：资源树、环境树、工作区配置树、插件树。树与树互不包含。

## 2. 允许修改的文件

- `src/design/`：树组件和标签页组件（只使用 token，不写一次性样式）。
- `src/shell/`：布局接线（左侧树区域、标签页区域）、文案放入 `src/shell/i18n/zh-CN.ts`。
- `src/kernel/`：仅限树节点与标签页的通用数据结构（不含任何插件名字或逻辑）。

不允许修改：`src/plugin-api/` 的已冻结接口（如需改动，先写决定）；`src/plugins/` 中的插件实现。

## 3. 依赖（只读）

- docs/requirements.md 的 I.2（标签页）、I.3（导航树）、I.0b（标签页与配置）、I.0c（框架原则）。
- 现有的 `src/design/` 基础组件与 `src/shell/` 外壳。

## 4. 完成标准

1. 资源树、环境树、工作区配置树、插件树可以用同一个树组件显示；节点悬停只改自身背景，相邻节点不跳动（界面测试验证）。
2. "全部展开"和"全部折叠"在每棵树上都可用。
3. 点击资源、环境、配置项、插件，在标签页中打开对应页面；关闭、固定、一键关闭全部可用；标签页的开合和顺序在重启后恢复。
4. 标签页不版本化、不同步（界面状态）。
5. 内核中没有任何具体插件的名字或逻辑（`pnpm lint` 通过）。
6. `pnpm check` 通过；截图（浅色、深色）保存到 `docs/screenshots/`。
