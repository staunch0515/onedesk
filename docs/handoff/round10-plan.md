## 1. 做完是什么样

- 一个节点下有 2 万个子节点的树：展开立即可用，滚动流畅，页面里实际存在的行只有可见的那些；结果区 1 万行的表格同样。
- 正在编辑一条笔记（有未保存的修改）时，它被别处改了（另一个客户端、某个插件）：别处改的是别的字段（如名称）——不打扰，保存后两边的修改都在；改的是同一个字段——页面顶部出现提示，选“保留我的”或“采用新的”，不静默覆盖任何一方。
- 示例插件的一个类型自己给出子节点（清单声明，代码提供）：展开它看到插件给的节点，点开能打开对应的目标。
- 外壳里不再有“点了只弹一句提示”的按钮：能做的做实，内核还没有对应能力的隐藏并列入交接文件；状态栏有通知入口，能看到本次会话里出现过的提示。

## 4. 未保存内容的合并（D374，§9.3）

内核（保存这一侧，保证不丢）：
- `page.save` 带的 `basis`（保存所依据的修改序号）落后于当前时：算出“从 `basis` 到现在别处改过的字段”（按绑定路径，含 `name`、`description`、`tags` 和 `body.*` 的顶层字段；用历史里的版本比较）。与这次 `changes` 的字段**没有交集** → 照常保存（只写 `changes` 里的字段，别处的修改保留）；**有交集** → 拒绝：`conflict`，`reason: stale`，`params.fields` = 逗号分隔的冲突字段路径，`params.rev` = 当前修改序号。历史里已没有 `basis` 那个版本（被清理）时，按“全部字段都改过”处理。
- `PageSaveParams` 只增 `overwrite: Option<Vec<String>>`：用户选了“保留我的”的字段路径；这些字段不算冲突，直接覆盖。
- 插件经 `ctx.host.resources.update` 的写入规则不变（它们不带 `basis`）。

外壳（编辑这一侧，及时告诉用户）：
- 打开着且有未保存修改的页面收到这条资源的变化通知时，重新取页面，比较已保存的值新旧之差：别处改的字段不在草稿里 → 静默更新基准和显示；在草稿里且值不同 → 页面顶部出现提示条（基础组件，放 `src/design`），列出字段标签，两个按钮“保留我的”（记下这些字段，保存时放进 `overwrite`）、“采用新的”（把草稿里的这些字段丢掉，显示新值）。没有未保存修改的页面直接刷新。
- 保存收到 `conflict/stale`（提示条还没来得及出现的竞态）时同样出提示条，不丢草稿。

## 5. 类型自供子节点（D375，§7.2、§7.5）

- 清单：类型声明只增 `"children": true`。代码：`host.kinds.handle("<kind>", { children(ctx, node, offset) { … } })`，`ctx` 含 `locale`、`resource`（这条资源，只读）；返回与提供树的 `children` 相同的形状（`{ nodes, next? }`，节点字段与现有提供树节点一致），另允许节点带 `target`（打开目标，如 `run:<id>`、`resource:<id>`、或本插件的页面目标）；没有 `target` 的节点不可打开。
- `tree.children` 的 `parent` 是这种类型的资源时：先给存储的子节点（如果该类型 `accepts` 了什么），再给插件的节点（批次接在后面）；插件的节点键由内核加前缀区分，不与资源 id 冲突。插件没声明 `children` 却注册处理函数 → 拒绝（已有的“给清单里没有的东西注册行为”规则）。
- 插件给的节点不可拖动、不可改名、不可删除；右键只有“打开”。处理函数出错或超时 → 该节点下显示一条“加载失败”的节点（内核给状态，外壳配字），不影响别的节点。
- 展开这种节点会激活插件（惰性激活照旧）；插件停用时不显示插件的节点。

- 状态栏加通知按钮（铃铛，带未读数）：点开列出本次会话里出现过的提示（时间、级别、文字），可清空；不落库。外壳自己的提示和插件经宿主 `ui` 发的通知（内核已有的话）都进这里。
