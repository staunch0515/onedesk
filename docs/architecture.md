# OneDesk 架构（截至 D181）

本文件描述当前的整体结构。具体需求见 docs/requirements.md，所有决定见 docs/decisions.md。两者冲突时，以 decisions.md 中较新的决定为准。

## 1. 定位

OneDesk 是“内核 + 插件”的工作入口。内核只提供通用机制：资源、插件、树、标签页、结果区、参数、历史、权限。所有具体功能（网址、笔记、提示词、HTTP 请求、SQL、硬盘文件……）都由插件提供。

## 2. 运行形态

- **桌面应用**（Tauri 2，仅 macOS 起步）：带窗口的界面，连接本机的工作区。
- **家庭服务器**（D165）：同一套后台，无界面运行，提供网页访问、git 远程、备份。服务器不需要显示器和桌面窗口。
- **网页访问**（D164）：运行中的应用（桌面版或服务器版）把界面以网页形式提供。默认仅本机，可开启局域网访问，访问需要口令。
- **外部服务器**（D167）：只负责让设备找到家里的服务器并连接，不保存用户数据。文档见 docs/design/external-server.md。

## 3. 数据与工作区

- 一个应用，多个工作区。工作区是独立的实例：一个工作区一个 SQLite 数据库文件，数据、搜索索引、历史、环境、收藏都在其中（D144）。
- 工作区之间完全隔离：不允许跨工作区查询、统计、搜索或引用。跨工作区只能通过显式的导出和导入，或通过发布和订阅（D145）。
- 应用级数据只包含：已下载的插件包、工作区列表、工作区配置定义（模板）。
- 一个工作区一个进程（D178）。
- 工作区设置只属于工作区，没有全局设置层（D153）。新建工作区时，设置来自模板，或复制一个现有工作区的设置（D154）。
- 工作区是否纳入多设备同步、是否开启 git 版本化，都是工作区设置。

## 4. 版本化（git，可选）

- 默认不用 git，数据库是源头（D141）。
- 用户可以为工作区启用 git：选择本地目录、远程 git 服务器或 GitHub 仓库。访问方式是调用系统 git 命令，外部 git 路径可设置（D140）。
- 按资源类型决定哪些纳入版本化（D141）。纳入的类型每次保存生成一次提交，记录操作者（D139 / D141）。
- 提交防抖默认 5 秒；切换资源、关闭窗口或手动保存时立即提交（D142）。
- 拉取冲突：冲突资源只读，在“设置 → 版本化 → 冲突”中比较并选择（D142）。
- 分支是高级功能，默认关闭，由工作区的“高级模式”开启（D156）。分支用于草稿和发布。

## 5. 树、标签页、结果区

- **树**和**标签页**是框架的主体结构（I.0c）。功能尽量放在这两种结构中，少用对话框。
- 树的种类（D147、D163）：资源树（资源和分组）、环境树、工作区配置树、插件树、数据源树（数据源仍是资源，单独成树）。树与树互不包含对方的节点。
- 同一个树组件被所有树复用；树的内容由插件提供节点，树组件不认识具体类型。
- **标签页**：资源、环境、配置、插件页都在标签页中打开。标签页只是资源的显示，开合和顺序属于界面状态，不版本化、不同步（D159）。
- **结果区**：每个标签页都有，位于页面下方，可拖动、可收起。动作结果显示在这里，按输出类型呈现；结果进入该标签页的执行历史（D172）。
- **环境**：在标签页内使用，每个标签页可以选择自己的环境（D152）。环境树和工作区配置树的机制相同，区别只在控制范围（D160）。

## 6. 参数、环境与保护

- 环境的所有设置都用参数表示：保护级别、密钥引用、允许的网络地址、版本化开关、AI 使用策略、视觉标记等（D150）。
- 参数有类型：文本、数字、布尔、列表、密钥引用（只存名字，值在钥匙串）。
- 以保留前缀命名的参数（如 `protection.*`、`network.*`）由核心解释；保护类参数只能加严，不能放宽（D150）。
- SQL 插件的参数语法和替换方式沿用 sqlpool 现有做法（D177）。

## 7. 插件

- **身份**：稳定 id（如 `org.example.http-request`）标识插件本身；发布版 id（如 `org.example.http-request@1.2.0`）标识某个版本（D142 之前的身份规则，见 docs/design 与插件接口文档）。
- **版本**：同一插件的多个版本可以同时存在于本机，同一时间只启用一个；可以固定版本；升级前保留旧版本，可回退（插件接口文档）。
- **资源记录**：每个资源记录创建和最后编辑它的发布版 id；核心界面的编辑记为“核心”（插件接口文档）。
- **启用状态**：按工作区保存（D143）。插件页在标签页中打开，包含说明、版本、启用开关、设置项、权限、加载状态和提供的扩展点（D169）。
- **扩展点**：插件可以提供新的 kind、动作、视图、树类型、标签页类型、结果区输出类型（D175）。
- **依赖复用**：插件通过 `requires.plugins` 声明依赖，依赖方直接使用对方提供的扩展点，不重复定义（D175）。依赖只能使用明确声明的扩展点。
- **宿主能力**：网络、密钥、存储、通知、文件（D176，`files`：选择文件夹、列目录、读取元数据、显示、打开；不提供写入和删除）。
- **语言**：界面语言也是插件（D179）。
- **分发与信任**：由用户另外建设的系统负责（D158）。OneDesk 只读取标准插件包，校验清单和 apiVersion，安装时展示权限，经用户确认后启用。
- **规模**：按上万个插件设计：启动时只读清单建立索引，插件在第一次使用时激活（插件接口文档）。

## 8. 内核

- **资源库**：统一资源表，字段包括类型、名称、分组、标签、正文（JSON）、可见性、AI 可用、版本、时间戳、创建和编辑的插件版本。
- **搜索**：多个搜索词同时满足才算命中；很短的词也能搜到。目标：1 万条 < 200 ms。
- **引用**：Markdown 链接与 `[[名称]]`；失效引用显示而不静默消失（D145）。
- **执行历史**：按资源分开，每个可运行资源保留最近 200 次，记录参数、耗时、行数、错误（I.5）。
- **插件宿主**：生命周期 安装 → 启用 → 激活 → 停用 → 卸载，按工作区；失败的插件记录原因，不影响其他插件。

## 9. 测试

- 单元：资源增删改查、清单校验、树与标签页的数据结构、搜索。
- 集成：插件生命周期、迁移（升级数据不丢）、依赖复用。
- 界面：树操作、标签页、结果区、新建与运行、搜索、主题切换。截图保存到 docs/screenshots/。
- 性能：1 万条搜索，冷启动。
- 全部由 `pnpm check` 统一运行。
